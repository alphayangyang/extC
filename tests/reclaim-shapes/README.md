# `tests/reclaim-shapes/` —— 区域回收的**行为基线**

配套机制文档：[`docs/RECLAMATION.md`](../../docs/RECLAMATION.md)。
形状来源：该文档「要解决的问题」那一节 + [`prototype-reclaim/README.md`](../../prototype-reclaim/README.md)「压力版」。

## 这个目录的语义

**只钉判据，不做门禁。** 它把「区域回收」要覆盖的现实形状写成小的 `.extc` 程序，
逐条记录**当前的实际行为**：哪些判据已经成立（绿），哪些还没有（红）。

* `./run.sh` **永远返回 0**，红条目在表里标出来（同 `tests/arena-soundness/` 的口径：
  这是证据，不是回归判据）⇒ **不接进 `check.sh` 的门禁计数**。
* 每个形状 = 一次 `extc` + 一次 `gcc` + 一次运行，整体 < 1s；峰值内存取
  `/usr/bin/time -v` 的 `Maximum resident set size`。
* **开关下的判据单独一组**：`./run-switch.sh`（`EXTC_RECLAIM=1`）是**门禁** —— 只在开关
  打开时成立的断言放那里；关掉开关（`EXTC_RECLAIM=0 ./run-switch.sh`）它必须红。
  两个脚本的分工见下面「开关」一节。

## 开关（`EXTC_RECLAIM=1`）：哪些条目与开关无关，哪些只在开关下成立

`EXTC_RECLAIM=1` 只换**运行期**（codegen 发射 `src/back/reclaim.c` 的那段文本：位图 slab 分配、
指针赋值计数、`owns` 守卫、区域清扫），不改语义。所以：

| 条目 | 开关关 | 开关开 | 判据归属 |
|---|---|---|---|
| `cond_save`（`saved=7`）| 绿 | 绿 | **与开关无关**：语义钉在两处都成立 |
| `cyclic_shape`（fwd=back / tree / cache）| 绿 | 绿 | **与开关无关**：有环语义一样对 |
| `reject_deep_store*`（编译期拒）| 绿 | 绿 | **与开关无关**：这是前端判据 |
| `promote_place`（生成物归属）| 绿 | 绿 | **与开关无关**：提权归属由 codegen 的 arena 站点定 |
| 曾经的 SEGV 用例（见下）| — | **必须绿** | **只在开关下成立**：开关才引入 `owns` 守卫 |
| `scale_growth` N→4N（峰值比）| **红**（≈3.0×）| **绿**（≈1.0×）| **只在开关下成立**：界与轮数解耦 |
| `cyclic_pressure` N→4N（峰值比）| **红**（≈3.45×）| **绿**（≈1.0×）| **只在开关下成立**：**环**垃圾计数永不归零，只有清扫能收（见下「清扫真正上场的证据」）|
| `shard_bands`（分片=8 vs 1 的语义；分片=8 的 N→4N 峰值比）| **红**（峰值比 ≈3.9×）| **绿**（输出逐字一致；峰值比 ≈1.0×）| **只在开关下成立**：①e —— 分片只换存储/登记/清扫的切分，不换语义；每片压力下限均分后总量上界不变 |
| `struct_copy` N→4N（峰值比）| **红**（≈3.75×）| **绿**（≈1.0×）| **只在开关下成立**：①f —— 整值存储里藏着的引用叶子，只有开关的记账路径才会 `inc` + 登记跨区边；开关关时既没计数也没清扫，存储不回收 |

曾经的 SEGV 用例 = `tests/heap/loan`、`tests/heap/plate`、`tests/cabi/heapmain`、
`tests/coro/iterator_protocol`：板/池/栈/C 返回的指针不是 rc 槽，开关把计数挂在指针赋值上后这些
形状都会经过 `inc`/`dec`/`register`；`owns` 守卫必须一个字节都不碰（否则 `slabOf` 的按位与会
找到一段无关内存，板的 4 GiB 保留区甚至没 commit ⇒ SEGV）。

### `EXTC_RC_NOCOUNT=1`（无计数模式）与 ①l

`bounded_churn.extc`（①l）问的是"去掉计数会不会让**低于 floor 的 churn** 无界"：每轮分配一个
小对象、上一轮立刻不可达，总分配随轮数线性涨而活集是常数。两种模式都必须 ~1.0×；
判据的牙用"无计数 + 不触发清扫"（`-DEXTC_RC_FLOOR=1TiB`）验（2.70× ⇒ 红）。
`live_churn.extc`（①m）判的是**绝对**峰值：活集 `live_n` 个 16 B 结点 + 同量级 churn，
上界 4×活集字节 + 4 MiB（两档：20 万 / 80 万）。相对涨幅由 ①/①l 判，两条互补。

**默认是无计数**；`EXTC_RC_NOCOUNT=0` 恢复计数模式，那一档同样必须 **31/0**（门禁项 `gate-reclaim-count`，默认那一档由 `gate-reclaim-switch` 覆盖）。

### `./gate-shard.sh`（门禁，分片旋钮）

分片（`EXTC_RC_SHARDS`）是 codegen 的**第四条发射路径**（区域键 = 基址 + 片号）。
`run-shard.sh` 是证据脚本（停顿/峰值/吞吐对照），**门禁是 `gate-shard.sh`**：旋钮非空转
（1 与 8 的生成物必须不同）+ 输出逐字一致（两个规模）+ 分片=8 下 N vs 4N 峰值比 < 1.5。
跑 `check.sh` 的 `gate-shard` 项。

峰值 RSS 是**跨环境**的读数（分配器与内核的高水位、页面粒度都在里面），而这条判据要钉的是
「界随轮数**涨**」这个性质 ⇒ 判据 ③ 红了**才**复测一对，两对里各取较小值；复测仍越线才判红，
FAIL 行打出首对/复测的原始 KB 与 `SHARDS=1` 的 4N 峰值（只看比值分不清「真没回收」还是
「别的膨胀」）。复测救回来的照样留一行「注」。自检「闸门有牙」用 `SHARD_RATIO_MAX=0.5` 压线。

### `./run-switch.sh`（门禁，`EXTC_RECLAIM=1`）

判据：`scale_growth` N vs 4N 峰值比 **< 1.5**；`cyclic_pressure` N vs 4N 峰值比 **< 1.5**
且默认/开关下输出逐字一致；`cross_region` N vs 4N 峰值比 **< 1.5**、跨区登记量（`rs_hwm`）
不随轮数增长；`cross_region_elem` N vs 4N 峰值比 **< 1.5**、且生成物里**下标槽**
（`s.kids[...]`）的跨区边要么登记、要么走保守路径（`storeRefUnknown`）；`unknown_host` 的
生成物里**宿主证不出来**的那条槽必须是 `storeRefUnknown`（或登记了真 owner），不许是
`storeRefOwned(..., owner=0)`；`cond_save` /
`cyclic_shape` 语义不变；上表四个曾经的 SEGV 用例 **rc=0** 且输出逐字不变；
①e `EXTC_RC_SHARDS=8` 与 `=1` 语义逐字一致、分片=8 下 N vs 4N 峰值比仍 **< 1.5**；
①f `struct_copy` N vs 4N 峰值比 **< 1.5**、`ok=true`，且生成物里把 `keeper` 存进 `s.w.n`
的那一条是**逐叶记账**（`storeRefOwned`，owner = 容器对象 `s`），不是裸的
`s->w = (wrap){.n = keeper};`；①i `persist_nodes`（真实语料最小化版）开档/关档都 rc=0 且 5 行
输出逐字一致；①j `hole_c` / `caller_frame` 开档/关档都 rc=0 且输出逐字正确；①k `owed_home`
探针观察到的**清扫次数 > 0**（内层帧给外层家区域分配 ⇒ 那只区域真的被收，见下「C 洞」）。
实测（`通过 30，失败 0`）：

|---|---|---|---|---|

| `scale_growth` 开关开 | 4.98 MB | 4.98 MB | **1.00×** | 绿（`run-switch.sh` exit 0）|
| `cyclic_pressure` 开关关 | 10.04 MB | 34.61 MB | **3.45×** | 红 |
| `cyclic_pressure` 开关开 | 7.86 MB | 7.79 MB | **0.99×** | 绿 |
| `cross_region` 开关关 | 4.61 MB | 13.79 MB | **2.99×** | 红 |

| `cross_region_elem` 开关关 | 105.36 MB | 417.11 MB | **3.96×** | 红 |

### 下标槽里的跨区边（⑧）

⑦ 的洞在**纯地方基**（`s.next`）上，codegen 能静态认出宿主 `s`；⑧ 把同一条边放进**下标槽**
（`s.kids[0]`）——槽的存储仍在 `s` 的载荷里（内联数组元素），宿主还是 `s`，但基表达式是 `a[i]`，
上一轮只认 `p->f` / `*p` ⇒ 不登记 ⇒ 清扫的种子少一条 ⇒ 只经这条边可达的对象被过早收 ⇒ UAF
（ASan 下 `SEGV`，地址落在空闲链槽号上；非 ASan 直接 `rc=139`）。

修法（安全优先，无写屏障）：codegen 用 `cgSlotHost` 沿**值投影**（字段 / 内联数组 / `ref [N]T`
元素）找宿主，三态出口 —— 找得到且基表达式可重复求值 ⇒ 登记跨区边（`storeRefOwned`）；
槽在静态声明的存储里 ⇒ 不用管（根表覆盖）；**追不到**（视图元素、带调用的基表达式……）⇒
那条槽不再"照常扫"： `extc_rc_storeRefUnknown` 把**目标对象所在区域**整个标成 `noSweep`
（此后只靠计数归零回收，宁可少收，也不在种子不完整时释放）。

⑨ `unknown_host.extc` 专钉第三态：`(*id(a)).next = a` 的宿主是一个**调用结果**，既登记不上、
根表里也没有 —— 生成物里这一条必须是 `storeRefUnknown`，绝不许落回 `storeRefOwned(..., owner=0)`
（那是"既没登记、也没退出清扫"，seed 缺一条还照常扫）。视图元素 `v[i].f = x` 走同一档。

### 整值存储里的引用叶子（⑪）

⑦/⑧/⑨ 讲的是**宿主怎么找**；⑪ 是同一个"槽被写进但没记账"的**另一种赋值形状**：宿主明明
证得出来，但目标槽的类型不是 `ref T` 而是**一个装着引用的结构体值**：

```extc
s.w = wrap { n: keeper }        /* 生成物（修之前）：s->w = (wrap){.n = keeper}; */
```

`cgIsRefType(target->type)` 对 `wrap` 为假 ⇒ 赋值被当成**数据字段赋值**，发一条裸的 C 复合
字面量拷贝：它**既不 `inc`、也不登记跨区边**。两个出口都会漏：

* **计数**：结构体槽成为"看不见的持有者"。它不 `inc` 目标，唯一可见持有者一放手（覆盖/置空），
  目标计数归零当场回收，而槽还指着它 ⇒ 悬垂（`var b: wrap = wrap { n: keeper }` 的声明也是
  同一个出口：C 初始化一条 `inc` 都不发）；
* **跨区种子**：`s.w.n → keeper` 是一条跨区堆→堆入边，清扫的种子 = 根 + 登记位。没有登记 ⇒
  目标区域的清扫把还被 `s.w.n` 指着的对象当垃圾放掉 —— ⑪ 的判据就走这一半。

**判据怎么造的**（`struct_copy.extc`，手法照 ⑧）：`s`（`box`）在 region 2（循环体，每轮新建），
`keeper = t` 把 `t`（`node`）提到 region 1，随后 `keeper = null`、`t` 又挂自环 ⇒ 计数永不归零、
根表里也没有 `t`，唯一的回收者是 region 1 的区域清扫。垃圾按 16 B/轮攒到 1 MiB 下限（约 6.5 万轮）
触发清扫；`pad = new big`（64 B，与 `node` 的 16 B **不同尺寸档**）保证放掉的槽不会被这次分配复用
⇒ `(*q).next` 读到空闲链槽号（实测地址 `0xf`）⇒ ASan `SEGV` / 非 ASan `rc=139`。为了让 region 1
的**第一次**清扫就真能收到东西（而不是先触发一次空扫把自学习阈值翻倍），`box` 带一格 48 B 的
`pad`：region 2 以 64 B/轮先到阈值，先撤销"来源对象死亡"的登记位，随后 region 1 才扫
（否则峰值会多出一段与"谁先到阈值"有关的瞬态，实测 1.19×；现在 0.99×）。

**修法**（与 `a7e2642` 同一精神，无写屏障）：整值存储不再发整块裸拷，而是**拆回逐条引用槽
赋值** —— codegen 先把目标地址与值各求值一次（`T *d = &(tgt); T v = val;`），再沿值投影
（字段 / 内联数组元素，`cgValueRefStore` + `rcLeafPaths`）对每个引用叶子发
`extc_rc_storeRefOwned((void **)&d.leaf, v.leaf, owner)`（宿主证不出来 ⇒ `storeRefUnknown`，
目标区域退出清扫），最后 `*d = v` 补齐非引用字段。声明（`var b: wrap = ...`）走同一套，叶子
用 `initRef`（新槽只加一）。宿主就是 `cgSlotHost` 那三态，`s.w` 传给运行期的 owner 正是容器
对象 `s` ⇒ 登记位落在 `t` 所在区域，`regionFree` 时按来源撤销（不粘）。

* **枚举不出叶子**的整值存储（目标类型里含枚举负载、泛型实参带引用）：进不去逐叶展开，发一条
  运行期入口 `extc_rc_storeStructCons` —— 整块拷好后把目标里每个"是活槽"的字都当候选引用，
  **只加不减** + 登记（或宿主证不出来时让那些区域退出清扫）。方向与 `EXTC_RC_CONSERVATIVE`
  的标记一致：认错一个字的代价必须是"多留一会儿"，不能是"少算一次"。
* **不在这一轮里**的形状（没做成判据、也没声称完好）：`@overwrite` 单元、协程帧、全局的整值槽。
  它们各有别的机制/保守档（`@overwrite` 的绑定本身是引用槽、走 `initRef`；协程帧与枚举不出来的
  存储让**整个函数的触发关闭**；全局在这套根表里只做登记），但这一轮没有逐条验证它们内部的
  引用叶子记账 —— 与下面「已知边界」同一口径：**没测到 ≠ 已证伪**。

### 已知边界（**不是洞**）——只做"传值临时量"的那些出口

判据钉的是**具名存储槽**上的整值拷贝（赋值 + 声明），因为那是能造出红、也确实修掉的那一档
（`struct_copy.extc` + `var b: wrap = mk(t)` 两个出口，后者修前 ASan `SEGV` @`0x9`）。真正剩下
**没记账、也不该按本轮口径记账**的只有**纯临时量**：按值实参、按值返回的表达式结果本身 ——
它的引用叶子同样不 `inc`，但**也不 `dec`**：临时量不是持有者、不宣告寿命，只是把值搬过去；
值一旦落进具名槽，落地那一步就记账了。这一档因此偏**泄漏**（宁可晚收），与 ⑪ 修掉的"少算一次"
方向相反。

**试过的构造与实测**（`EXTC_RECLAIM=1` + ASan；修前 = `e449edf` 的编译器）：

| 构造 | 修前 | 修后 | 读法 |
|---|---|---|---|
| `take(wrap { n: t })` 按值传参，被调者调用期间读 `w.n` | 不崩 | 不崩 | 临时量只在调用窗口里活；窗口内产生它的可见持有者还活着 |
| 按值返回 `mk(k) -> wrap` **落进** `var b: wrap = mk(t)` | **红**（`SEGV` @`0x9`）| 绿（`got=0`）| 落地就是具名槽 ⇒ 本轮 ST_VAR 记账点覆盖它 |
| `let e: maybe = mk(t)`（带引用**载荷**的枚举）| 不崩 | 不崩 | 修前被被调者形参自己的 `initRef` 抬着；修后另走 `storeStructCons` 保守档 |
| `t = null` 后读 `b.n`（局部绑定 + 结构体槽同时持有）| 不崩 | 不崩 | 局部绑定自己 `inc` 且**不在块退出时 `dec`** ⇒ 计数不归零 |

**为什么纯临时量读不出红（推理，不是"没测到"）**：悬垂要有两条路之一成立 —— **计数归零**，
或**清扫漏种子**。跨区种子这一半：临时量作为**实参**时，调用窗口内产生它的持有者还活着
（且它自己不 `dec`）；作为**返回值**时，值要么立刻落进具名槽（已记账）、要么被立刻读掉（读的
那一刻产生它的被调者局部量还活着）。计数这一半的兜底是**局部绑定**：`var t = ...` 永远 `inc`、
且**永不在块退出时 `dec`** ⇒ "唯一可见持有者放手 ⇒ 归零"这个前提在传值路径上造不出来。上一轮
⑪ 的探针"没能复现"正是这个原因：**计数**那一半被局部绑定抬着，只有**清扫**那一半（不看计数）
才能把它露出来 —— 本轮照 ⑧ 的手法把清扫那一半做成了判据。

**没测到 ≠ 已证伪**：上表是推理 + 探针，不是对全部传值形状的证明。真要把这一档钉死，需要的是
"临时量生命周期"的静态判据（值在哪一步落地、落地前有谁持有），那是另一轮的事；这一轮不虚报
判据、也不放宽 ⑪ 的判据去覆盖它。

### 跨帧存储的方向（②）

被拒的是「**更深的局部 → 更浅的容器**」：块里的局部对象（深度 2）把 `ref` 存进外层容器
（深度 1）⇒ 引用会活得比它指的东西长。反方向（外层局部存进更深的块容器）编译器**放行**，
那条不会悬垂 —— 判据钉的是会悬垂的那一侧。

直接形式与经被调者形式是同一个洞的两个出口：`stash` 只**发布**约束，调用点拿具体深度判。

### 提权看得见什么、看不见什么（④）

生成物里看得见的是**归属（placement）**：会逃逸的那一份 `new` 从一开始就分配进外层区域
（`extc_arena_alloc(&__extc_a[1], ...)` 出现在循环体内），不逃逸的那一份留在循环体区域
（`__extc_a[2]`，循环每轮 `release`）。`run.sh` 断言两个 arena 下标不同、且循环体区域的
`release` 在缩进 8 空格那一层出现而外层区域的没有。

**看不见**的是运行期的搬移：机制说的「先落当前区、真实逃逸时把那一份转移过去、地址不变」
在今日 codegen 里**没有对应的运行期动作**（没有 promote/transfer 调用）。所以这里断言的是
「存储确实归到了外层区域」，**不是**「发生了一次搬移」—— 不硬造。

### 有环形状（③）

`next/prev` 与 `parent/left/right` 天然互指 ⇒ 每对相邻节点就是一个环 ⇒ 引用计数永远不归零，
只能靠区域清扫（机制文档「四层」里的第四层；`EXTC_RECLAIM=1` 发射的运行期实现了它 ——
**真正上场的证据**见下面 ⑥）。缓存与索引是**跨结构引用**，对应 prototype-reclaim 里
「记忆集/跨区登记」要处理的那类边。

规模取 8 个节点（秒级）；峰值只有进程底噪量级，所以这里**不设上界** —— 规模行为由 ⑤/⑥ 管。

### 红的那条（⑤）

`scale_growth.extc` 与 `cond_save.extc` 是同一个形状（条件保存），只是轮数由 argv 给：
`run.sh` 跑 `200000` 与 `800000` 两次。每一轮 `new` 出来的存储都可能进 `saved` ⇒ 被提到函数层
区域，函数返回前整片不回收 ⇒ 峰值 RSS 随轮数线性增长。

这正是 `RECLAMATION.md` 要解决的问题：「不可达但仍占存储的对象，其总量有界，且这个界与循环
轮数无关」。**开关关**时界与轮数有关 ⇒ 红；**开关打开**（`EXTC_RECLAIM=1`）后计数归零当场回收
+ 区域清扫兜环 ⇒ 峰值与轮数无关（实测 2.99× → 1.00×），这一条在
[`run-switch.sh`](run-switch.sh) 里被固化成门禁断言。

## 有环 + 大压力（⑥）：清扫真正上场的证据

⑤ 是**无环**的：每一轮的 `p` 只有一个持有者（`saved`），覆盖就归零 ⇒ **计数归零一层就够，
清扫从头到尾没参与**。⑥ 补的正是缺的那半：垃圾是**环**，计数**永远不归零**。

### 形状：为什么必须靠清扫

`cyclic_pressure.extc` 复刻 [`prototype-reclaim/stress.c`](../../prototype-reclaim/stress.c)
那个业务形状：**64 个桶（每桶 ≤8 节点）的双向链表 + 1024 槽缓存（第二持有者）+ 2 万项索引
（跨结构引用）+ 带父指针的树（每 16 轮挂一个）**。

环垃圾的来源是**桶满时整条链退役**：

```extc
pushFront(ref w, b, p)                       // p.next = 旧头、旧头.prev = p
if i % 64 == 0 { cachePut(ref w, c, b) }
if w.bkSize[b] > 8 { retireChain(ref w, b) } // 链头挂到 w.retire，桶清空；链内 next/prev 不动
```

退役链的**每个节点都还有入边**（`a.next=b` 与 `b.prev=a` 互指），计数永远 ≥1 ⇒
`extc_rc_holdUpd` 一次 `dec` 都到不了 0，**一个槽也放不掉**；同时它已经不在任何根之下
（唯一的外部引用 `w.retire` 被下一次退役覆盖）⇒ 是**不可达的环**。四层里能收它的只有
**区域清扫**。这跟 `stress.c` 里「引用计数在环面前几乎归零」是同一件事。

树的根槽是**定长环** `tree[256]`，每 16 轮占一格、每 256 个节点另起一代。理由：extC 的标记
按对象的**全部**指针字段走（`next/prev/child/parent`），如果让每个树节点都从上一个取 parent、
根槽又无界增长，那么只要最后一个节点还活着，就能沿 `parent` 走回全部历史节点 ⇒ 整条祖先链
永远是活的、内存照样涨。定长环 + 换代把祖先深度钉在 256 以内；换掉的那一代 child/parent
互指仍在 ⇒ 又是一批不可达的环垃圾。

### 语言约束：原型能随便写、extC 必须绕的地方

| 写法 | 结果 | 原因 |
|---|---|---|
| `(*head).prev = p`（`head` 是本地 `?mut ref`，`p` 是循环体局部）| **拒** | 解引用**不产生存储**：目的地的槽深度按保守读法取 0（`slotDepth(EX_DEREF) = targetDepth(head)`），而本地的被指物寿命未知 ⇒ 循环体局部（深度 2）存不进去 |
| `a.next = p`（`a` 是本帧的 `var a = new node`）| 过 | 目的地是本帧已知的存储 |
| `link(a, p)`（`fn link(n: mut ref node, p: mut ref node)`）| 过 | 判定推迟到调用点，目的地是形参 |
| 同一个循环体局部 `p` 连续传给**两个**「会存进外层」的 helper | 第二处**拒** | 报 `argument 3 ... points into a deeper scope (depth 2) ... (depth 1)` |
| `ref w.bkHead[b]`（数组元素取引用）| 拒 | 只有变量与字段能取引用 ⇒ 传 `ref w`，在 helper 里下标 |

最终写法：**每个新对象只经由一个 helper 的一次调用完成逃逸**（`p`→`pushFront`、
`e`→`idxPut`、`t`→`treePut`），需要「第二持有者」时让 helper 从**帧内字段**
（`w.bkHead[b]`）里取那份引用，而不是把循环体局部再传一次。这条正是原型与 extC 的差异：
原型里 `init_ref(&g_head[b]->prev, nd)` 随手就写，extC 里要给目的地一个**本帧已知的深度**。

### 数字 1：N vs 4N 峰值（门禁）

`run-switch.sh` 的 ①b；输出逐字一致（`rounds/retired/live/fwd/back/idx/cache/hits/depth/tree`）。

| 场景 | N=200000 | N=800000（4N）| 比值 |
|---|---|---|---|
| `EXTC_RECLAIM` 关 | 10.04 MB | 34.61 MB | **3.45×**（红，> 2）|
| `EXTC_RECLAIM=1` | 7.61 MB | 7.61 MB | **1.00×**（绿，< 1.5）|

默认与开关下输出**逐字一致** ⇒ 回收只换运行期、不改语义。

### 数字 2：清扫真的上场了吗（`run-evidence.sh`）

「峰值被压住」有两个可能：计数归零收掉了，或者清扫收掉了。**同一份生成物**只动清扫的
触发阈值（生成物里的运行期是 `#ifndef EXTC_RC_FLOOR` 守卫的宏），因果就闭合了：

| 变体 | N=200000 | N=800000 | 比值 | 读法 |
|---|---|---|---|---|
| 开关关（无回收运行期）| 10.04 MB | 34.61 MB | 3.45× | 基线 |
| 开关开 + **清扫永不触发**（`-DEXTC_RC_FLOOR=1 TiB`）| 17.92 MB | 63.54 MB | **3.55×** | 环垃圾计数永不归零 ⇒ 计数那层一个也收不掉；峰值**重新随轮数涨** |
| 开关开（默认阈值 1 MiB）| 7.61 MB | 7.61 MB | **1.00×** | 界是清扫给的（因果闭合）|

直接数（`gdb` 断点 `extc_rc_sweep`，N=800000、开关开）：**清扫被调用 28 次**。
三份变体的 N/4N 输出都与期望逐字一致。

### 数字 3：三方对照（同 N / 4N，48 字节节点）

| 实现 | 耗时 ms（N / 4N）| 峰值 RSS（N / 4N）| 是否随轮数增长 |
|---|---|---|---|
| extC 默认（开关关）| 8 / 17 | 10.11 / 34.67 MB | **是**（3.45×）|
| extC `EXTC_RECLAIM=1` | 52 / 183 | **7.61 / 7.61 MB** | 否（1.00×）|
| C 原型 `stress.c` 分片=1 | 11 / 27 | 9.48 / 9.48 MB | 否（1.00×）|
| C 原型 `stress.c` 分片=8 | 16 / 41 | 13.67 / 15.67 MB | 否（1.15×）|
| C 原型 `stress.c` 分片=8（200 万轮）| 90 | 16.61 MB | 否 |

原型参数 `N 1024 64 20000 48 <分片>`（缓存 1024 / 每 64 轮 / 索引 2 万项），与 extC 形状的
旋钮对齐；`/usr/bin/time -v` 的 Maximum resident 计。**两边都做到了「有环也不漏」**，
extC 侧峰值甚至略低（7.6 vs 9.5 MB）。

### 差距与原因（extC 比原型慢 3.2×/4.5×）

callgrind，N=800000：extC 开关开 **3.805 G 条指令**，清扫从不触发 **3.581 G**（94%），
开关关 **0.116 G**；C 原型分片=8 **0.621 G**。也就是说：

* **清扫+标记只占开关开那一跑的 ~6%**（`-DEXTC_RC_FLOOR=1 TiB` 只省下 6%）——
  慢的不是清扫，是**每次分配都要付的固定开销**；
* `main` 自身 2.523 G（66%）：清扫触发写在**每个分配点**的语句前缀里，根表是当场物化的
  复合字面量 `(void *[]){ … 1410 项 … }`（1024 缓存 + 256 树根 + 128 桶 + 少量局部）。
  87 万次分配 × ~1410 个槽 ≈ **12 亿次装载/存储**，几乎全在这里。原型只在**真的要扫**时
  （28 次）才凑根表。
* `extc_rc_ownLower` + `extc_rc_ownSlab` = 0.616 G（16%）：计数/登记前必须问 `owns`
  （slab 注册表二分 + 槽首/占用位校验）——**健全性要付的钱**：板/池/栈/C 返回的指针不是
  rc 槽，原型假定「所有指针都是 slab 指针」，extC 不行。
* `extc_rc_holdUpd` + `inc/storeRef` ≈ 0.35 G（9%）：计数。
* 每轮指令：extC 开关开 ≈ 4 757，原型分片=8 ≈ 776（**6.1×**）；吞吐差（4.5×）小于指令差，
  说明 extC 那段根表物化被 GCC 向量化得不错。

**`slab_final.c` 有而这里还没有的**（都在 `RECLAMATION.md`「要做的」清单上）：

* **计数按编译期收窄**：extC 在**每个**指针赋值上发 `inc`/`dec`；原型靠静态唯一性证明
  （`EVENT`/`NOHOLD`）省掉大部分。这是最大的一笔税，也是上面 9% 的直接来源。
* **触发点与根表按需化**：原型按内存压力、在触发时才凑根；extC 的阶段①做成「每个分配点
  前物化全量根表」⇒ 固定开销压过清扫本身（见上）。
* **分片旋钮**：`EXTC_RC_SHARDS=N`（默认 1 = 现有行为）已接进编译器：一个逻辑区域切成 N 个
  **运行期区域**，每片自己的 slab 链、自己的跨区登记位图（`rsbit`，即原型每片的入边集）、自己
  的标记栈，可以单独清扫。停顿分布采样还没做（见下「分片」一节）。
* **事件回收**（静态唯一性下当场回收）与 **环的可观测性**（让「这里真有环」可统计，
  自学习退场更准）。

**已经对齐的**：位图 slab、槽空闲链、饱和计数、`rsbit` 跨区登记（持久去重、释放清位）、
`owns` 守卫（原型没有）、自学习退场（空扫翻倍）、静态根表由编译器给。

## 分片（`EXTC_RC_SHARDS=N`）：停顿旋钮

**停顿 ∝ 被扫区域的可达集**，所以把区域切小、每次只收一片，就是停顿旋钮
（[`docs/RECLAMATION.md`](../../docs/RECLAMATION.md) 第四节）。实现方式：

* **一个逻辑区域切成 N 个运行期区域**。区域由 arena 的**地址**认领；第 k 片的认领键是
  「地址 + k」（键只比不读），分配点、触发点、帧销毁点的键都由同一处算出。分片不改运行期
  文本一个字 —— 跨区登记、来源侧撤销、按区域清扫都是已有的机制，**片就是区域**。
* **片号按分配点定**（`rcSite++ % N`），不按存活集/对象数。同一处 `new` 造出来的东西
  （一条链、一个环、一代树结点）始终落在同一片，片内链条与环保持完整；跨片引用由
  `storeRefOwned` 登记到**目标所在那一片**的 `rsbit` 上，播种与清扫都不跨片。
* **一次触发只收一片**，挑的是垃圾最多的那一片（`bytes - live`）：收完它的占用掉下来，
  下一次自然轮到别的片，不需要额外状态。每片的压力下限 = 总下限 / N，所以**总量上界不因
  片数改变**，片多只让每片收得更勤、每次更小。
* **N=1 时每条发射路径都走原来的那条分支**：生成 C 与接线前逐字节相同（`run-shard.sh` ①
  对全部可编译语料 `cmp`，diff=0）。

两条反着做就错的约束（都是原型量出来的，写进 `codegen.c` 的注释）：

1. **跨区登记必须跟着片走。** 登记位属于**目标槽所在的片**；只分存储不分登记，清扫播种就会
   跨片漏种子。片是运行期区域 ⇒ 每个 slab 的 `rsbit`/`rscnt` 天然只属于一片。
2. **绝不能按存活集大小切。** 按对象数/存活集均分会把链与环拆到两片：跨片登记位一置，
   整条环垃圾都成了种子 ⇒ 界随轮数涨（原型实测吞吐也变差）。所以切法是「分配点 → 片号」。

### 三组数字（`run-shard.sh`，N=100 万，REPS=3）

「最大单次清扫耗时」的测法：在**同一份生成物**上插一个计时外壳
（[`tools/rc-pause-probe.py`](../../tools/rc-pause-probe.py)），记录每次 `extc_rc_collect`
的墙钟并取最大值；回收判据一个字不动，两档用同一把尺子。峰值取 `/usr/bin/time -v`，
吞吐取同一程序墙钟的最快一次。

**有利形状 `shard_bands`（8 条独立链 = 8 个分配点 ⇒ 结构边界 = 片边界）**

| 片数 | 最大单次清扫 | 峰值 RSS | 吞吐（墙钟）|
|---|---|---|---|
| 1 | 548.7 µs | 4.29 MB | 437 ms |
| **8** | **218.9 µs（0.40×）** | 10.86 MB（2.53×）| 762 ms（1.74×）|

**反面对照 `cyclic_pressure`（20 万结点来自同一个分配点，切不开）**

| 片数 | 最大单次清扫 | 峰值 RSS | 吞吐（墙钟）|
|---|---|---|---|
| 1 | 1224.5 µs | 7.86 MB | 101 ms |
| 8 | 1211.4 µs（0.99×）| 10.29 MB（1.31×）| 127 ms（1.26×）|

两档输出都**逐字一致**；分片=8 下 N vs 4N 的峰值比仍在界内（`shard_bands` 1.01×、
`cyclic_pressure` 1.00×）。

**取舍与原型的关系**：`shard_bands` 上的方向与
[`prototype-reclaim/README.md`](../../prototype-reclaim/README.md)「最终版」那张表**同向**
—— 分片 1→8 是最大停顿 406.7→81.7 µs（好）、峰值 RSS 17→18 MiB（略差）、耗时 49.6→61.9 ms
（差）；这里是 548.7→218.9 µs、4.29→10.86 MB、437→762 ms。峰值变差有两个来源：每片至少
一只 1 MiB slab 的底噪，以及每片一套标记栈/记账。

`cyclic_pressure` 上**最大停顿压不下来**（总停顿是变好的），原因不是分片写错了，而是这一
形状**切不开**：那条主结构的链与环不能被拆到两片（拆了跨片登记位会把整条环当种子 ⇒ 界随
轮数涨），所以它整条留在一片里，剩下的片只拿到索引与树；另外自学习退场在小片上更早遇到
「一次扫一无所获 ⇒ 阈值翻倍」，会把某一次清扫攒大。要拿到分片的停顿收益，形状要像
`shard_bands` 那样**每个结构一个分配点** —— 这正是机制文档那句「分片是纪律」的意思。

## C 洞：静态根表看不见调用帧的活引用（①i / ①j）

⑧/⑨/⑪ 修的都是"**槽被写了但没记账**"（种子少一条边）；这一档是**种子根本没机会完整**：
根表按**词法作用域**拼（本帧局部 + 形参 + 全局），而清扫的正确性要求"**调用栈上活引用的完整
集合**"。内层帧给**外层区域**分配时，外层帧的局部量指着同一片区域里的对象，而它们**不在内层
帧的根表里** ⇒ 内层帧一次清扫把外层帧还持有的对象整片放掉 ⇒ 真悬垂 UAF。

> **✗✗ 不是**"让 `extc_rc_sweep` 遇 `hold != 0` 就当活的"。环垃圾的 `hold` 永远 ≥1，那等于
> 废掉清扫、环再也收不掉 —— 是换一个更大的洞。

### 形状（三条，都是"外层区域 + 内层触发"）

| 形状 | 洞的出口 | 修之前 |
| --- | --- | --- |
| `hole_c/hole_c.extc`（最小递归，深度 16）| 递归 `build` 的家 arena 就是 `main` 的 `&__extc_a[1]`（一路传下来，**同一个区域**）；触发点根表**直接为空**（`maybeCollect(区域, (void *const *)0, 0)`）| rc=139（ASan SEGV）|
| `hole_c/caller_frame.extc`（非递归）| `main` 手里的链头是活引用，被调 `fresh()` 只负责 `new`、它的根表只按自己词法作用域拼 ⇒ 同一签名 | rc=124（挂住）|
| `persist_nodes.extc`（**真实语料**：`bench/oi/persist/p3834_nodes.extc` 最小化，N=50000 / Q=1000）| 递归 `update` 的根表是 `{ z, prev }`，本帧新造的 `n` 由**父帧的局部量**持有 ⇒ 内层触发把父帧还建着的子树放掉 | rc=139 |

`persist_nodes` 的规模有硬理由：根数组 `new [50001]?ref pnode` = 400008 B ⇒ 槽取整到
**512 KiB**（≤512 KiB ⇒ 普通 slab，不是超大块），所以它钉的是这个洞本身，不掺 ①g 那次
"槽 > 512 KiB 不 trap"的修复。N=50000 是"纯净 HEAD 也照样 rc=139"的最小规模。

### 修法（a）：**触发点只在「本帧拥有」的区域上下手**（已落地）

判据 `rcFrameOwnsArena`（`src/back/codegen.c`）：家 arena（`(*__extc_home)`：调用者一路传下来的
那只）⇒ **不触发**；线程本地 arena（`extc_tls_arena`：整条 worker 调用链共用的那只）⇒ **不触发**；
协程帧本来就 `rcRootsUnreliable`。只有本帧自己的块 arena（`&__extc_a[lvl]`，`lvl >= 1`）照常触发
—— 外层帧拿不到指向它的引用（更深的局部 → 更浅的容器被 checker 拒，会逃逸的值一开始就分配进
家 arena），所以本帧根表对那块区域是完整种子。`@overwrite` 走同一判据的对应形式：判据是
`loc && !planUsesHome(f)` —— 格子在本帧且本函数**不收** home 时，格子的 `home` 才是本帧的
`&__extc_a[1]`；本函数收 home（格子的 `home` = 调用者的家）、或 `owLocal` 为假（codegen 期才
生成的泛型实例）⇒ 格子在**外层帧**上，不触发。

生成物层面看得出来：`hole_c` 的开档生成物里 `build` 的分配点**一条 `extc_rc_maybeCollect`
都不发**（修之前是 `maybeCollect(区域, (void *const *)0, 0)`）；`persist_nodes` 的 `update`
里原先那条 `{ z, prev }` 触发消失，只剩 `main` 自己块 arena 上的两条（那两条是安全的，
`main` 触发时没有更深的帧活着）。

### 修法（a′）：把被收窄掉的能力**部分**拿回来 —— 子集 **A + B**（已落地）

(a) 只损失清扫机会、不损失健全，但它把「内层帧给外层（家）区域分配」这一档整个关掉了
（全语料 130/136 个被移除触发点都是它）。**A + B 把这一档的一部分收回来**，仍然**不引入
运行期根栈**：

* **A —— `main` 是家 arena 的例外（~5 行）**：`main` 没有调用者，它的家 arena 就是它自己的
  `&__extc_a[1]`（`genFunc` 里 `extc_arena *__extc_home = &__extc_a[1];`）⇒ 静态根表对它是
  **完整**的。`rcFrameOwnsArena` 现在对 `main` 的 `ARENA_HOME` 返回真；`@overwrite` 的对应
  判据同步成 `loc && (!rcFuncUsesHome || inMain)`。收益：`tests/escape-fuzz` 里 6 个
  「只有 `main` 的 home 触发」的程序恢复清扫能力。
* **B —— 欠收标志 + **拥有者在调用返回后/下一次调用前**用自己的静态根表收一次（~30 行）**：
  内层帧**不自己扫**外层区域，只在区域上记一笔「欠一次收集」（记账本身就带 `shouldSweep`
  压力判据，没过线的分配连账都不记）；**拥有它的那一帧**在下一次把这只 arena 当被调者的家
  arena 传出去**之前**，用自己的静态根表销账（`extc_rc_checkOwed`）。`main` 的家 arena 也走
  这条销账路径（A 让它同时是「拥有者」）。

**B 必须守住的健全性不变量（这是 B 的全部理由）**：

> **收集发生时，收集者不能有活跃的被调者子树** —— 那一刻它的静态根表（本帧局部 + 形参 +
> 全局）就是**完整**的种子。因此**不需要**帧级「根不可靠」标记（那是整条根栈才需要的）。

销账点因此只落在「上一批被调者已返回、这一批还没进入」的调用之前。欠收标志一辈子没被销掉
（拥有者此后再不发起调用）时，那只区域等到帧销毁才还 —— **上界放松，不是悬垂**。

**唯一凭据（`run-switch.sh` ①k）**：`owed_home.extc` —— `build` 只往调用者的家 arena 分配
（自己的块 arena 零 rc 分配点），`main` 每轮覆盖上一轮的链 ⇒ 家区域里攒下不可达的链。判据
不是「生成物里有触发」（弱判据），而是 `tools/rc-pause-probe.py` 观察到的**清扫次数 > 0**：

| ①k `owed_home`（N=64 轮 × 20000 节点）| 清扫次数 | 输出 |
| --- | --- | --- |
| (a) 之后（修之前）| **0**（一次都没扫；探针插桩版报 `sweeps=0`）| `n = 20000` |
| A + B 之后 | **20** | `n = 20000` |

`EXTC_RECLAIM=0 ./run-switch.sh` 时这条仍红（运行期不发射、探针插不进去 ⇒ 清扫次数 0）。

**硬指标（`bench/stress/stress.extc` 峰值，`/usr/bin/time -v` 的 Maximum resident set size，
各 3 次）**：

| 档 | KB | MB |
| --- | --- | --- |
| ① `19fd567` 之前（有 home 触发）| 10 860 / 10 924 / 10 860 | 10.86–10.92 |
| ② (a) 之后（不触发）| 23 532 | 23.53 |
| ③ `EXTC_RECLAIM=0`（整块关掉回收）| 16 620–16 684 | 16.23 |
| **④ A + B 之后** | **10 860 / 10 860 / 10 924** | **10.60–10.67 MiB / 10.86–10.92 MB** |

③ 那一行是加权项：② 比「整块关掉回收」还差 42%，说明损失不是「退化成无回收」，而是 rc slab
攒在**没人扫的 home 区域**里。④ 回到 ①的量级 ⇒ 子集 A+B **够用，不需要上整条根栈（C）**。
（`bench/heavy/bt.extc`、`tests/reclaim-shapes/persist_nodes.extc`、
`bench/oi/persist/p3834_nodes.extc` 三个洞判据开档/关档都仍然 rc=0、输出逐字一致。）

### 清扫能力**没有被整体废掉**：护栏数字（改前 = 改后）

判据：`cross_region`（有跨区登记，垃圾靠计数 + 清扫）与 `cyclic_pressure`（**环**垃圾，计数
永不归零，只有清扫能收）的**清扫次数与 `rs_*` 计数不得归零**。用 `tools/rc-pause-probe.py`
（插桩只测不改判据）与 `EXTC_RC_STATS=1` 实测，N=200000：

| 形状 | 清扫次数 | `rs_inc` | `rs_dec` | `rs_live` | `rs_hwm` |
| --- | --- | --- | --- | --- | --- |
| `cross_region` 改前 | **4** | 200000 | 196611 | 3389 | 65537 |
| `cross_region` 改后 | **4** | 200000 | 196611 | 3389 | 65537 |
| `cyclic_pressure` 改前 | **8** | 0 | 0 | 0 | 0 |
| `cyclic_pressure` 改后 | **8** | 0 | 0 | 0 | 0 |

两形状的生成物逐字节没变（它们的分配点都在 `main` 自己的块 arena 上），所以数字**完全一致**、
一个都没归零；输出也逐字一致。`run-switch.sh` ①/①b/①c/①e/①f 的峰值判据全绿（见上表）。

### 代价与后续（**如实记，不掩饰**）

* **损失（上界放松，不是悬垂）**：(a) 只把「内层帧给外层（家）区域分配」这一档整个关掉了。
  A+B 之后这一档**一部分已经收回**（`main` 的家 arena 直接认，其余走欠收销账）；仍旧损失的是
  「拥有者此后再不发起调用」的形状（`hole_c` / `caller_frame` / `persist_nodes` 都是单次入口
  或最后一次调用）：那只区域整片等到帧销毁才还 —— 仍是**上界放松**，不是悬垂。
  **全量语料实测**（1221 个 `.extc`，修前 208 个程序有触发）：(a) 把 110 个程序的开档触发全部
  移除；A+B 之后这 110 个里被移除的触发点重新以「欠收 + 拥有者销账」的形态回来（130 个
  「内层帧给外层区域分配」的触发点 + 6 个 `main` 自己的）。
  **唯一有可测峰值回归的 `bench/stress/stress.extc`（10.92 MB → 23.60 MB）已经回到
  10.86–10.92 MB**；其余程序的 Δ 都在底噪内。
* **后续 (b)：运行期根栈 —— 本轮**不做**，也不再需要**。B 用「拥有者在没有活跃被调者子树时
  销账」这一条不变量替代了根栈要解决的唯一问题（外层帧的活引用不在内层帧的表里）；A+B 的
  `stress` 峰值已经回到修前量级。若将来要覆盖 `parTls`（TLS 一档，语料里没有正向程序）或
  「拥有者一辈子不再调用」的形状，根栈仍是那条路：调用前登记、返回后撤销外层帧在本区的活
  引用，代价是每次调用 O(1) 的压/弹栈与运行期根表物化（入口守卫省下的 −56.3% 会付回去一部分）。
* **`main` 的家 arena 现在**特例认它**（子集 A）**：`main` 是唯一「家 arena 就是自己帧的
  arena = `&__extc_a[1]`」的函数，没有调用者 ⇒ 根表对它完整。其余函数的家 arena 一律走
  B 的欠收销账。
* **信任的边界**：`rcFrameOwnsArena` 的安全侧依据是"跨帧存储的坏方向被 checker 拒 + 逃逸值
  提权进家 arena"——这是对 checker 现有保证的信任，不是本轮新证的定理；`parTls` 那一档只按
  "与家 arena 同构"推理收紧（且**不发欠收**），语料里没有正向并行程序可实测。
