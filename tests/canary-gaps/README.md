# tests/canary-gaps/ —— **缺口有据可查**（故意**不**并进套件）

这里的每个文件**今天编不过**，但**应当是合法的**：它们是 `PLAN §0.4` 里开着的缺陷
（`#60` / `#61` / `#62`）的**最小/稳定复现**。

规矩（跟这个目录以前那批一样）：
- 它们**不进** `tests/run.sh` / `check.sh` —— 因为套件必须全绿，而这里的文件是"红的"；
- 但也不许删：它们是"这个洞真的存在"的证据 ✓
- **修好之后**：把它挪进 `examples/`（或 `tests/` 里该去的地方）当正例，并回来删掉这里的副本 ✓

⚠️ 复现时**必须套超时**（`timeout 20`）—— 顺带记：另一个洞曾经让编译器**挂住**（见 `PLAN #59`）✓

⚠️⚠️ **复现方式有个坑，我自己先踩了一次**：`#61`/`#62` 是**生成的 C 编不过**，
而 `extc f.extc -o out.c` **返回 0**（`-o` 的语义就是「吐出 C」，gcc 是下一步的事）✗
⇒ 必须写成 **`extc --run f.extc`**（或 `-o` 之后再自己 `gcc`）：

    timeout 20 ./build/extc --run tests/canary-gaps/generic_match_variant.extc

这就是本仓库反复记的那条：**「`-o` 成功」≠「生成的 C 编得过」** ✓
（`#60` 不一样：它在**检查器**里就被拒 ⇒ 两种调用都返回非 0 ✓）
