# 攻击库记账：**哪些名字被动过、为什么**

> `BASELINE` 必须**只有名字**（`check.sh` 拿它跟"实际通过的集合" `diff`，
> 多一行注释就会报"通过集合变了" ✗ —— 2026-09-23 踩过）。
> 所以理由写在这里，**不要**写进 `BASELINE` ✓

`BASELINE` 是「本来就安全、所以**允许**通过」的白名单；**其余全部必须被挡**。
所以：

- 名单里**删掉**一个名字 = 编译器**更严**（一个原本放行的程序现在被挡）✓
- 名单里**加进**一个名字 = 需要**极小心**：加错了就是把洞记成功劳 ✗

⚠️ **两栏都会说谎，两个方向都抓到过**：

| 方向 | 实例 | 教训 |
|---|---|---|
| **误拒记成功劳** | 2026-09-22 `h8_launder` | 它其实是**同层安全**的程序，老编译器误拒、攻击库却当成"挡住了"记功 ✗ ⇒ 按"真的安全"记账，并另立 `tests/errors/stash_view_from_deeper.extc` 顶住安全边界 |
| **漏报记成安全** | 2026-09-23 `h4_oob` | 见下 ↓ |

## 2026-09-23 · 移除 `h4_oob`（PLAN #4 修好）

`tests/attacks/h4_oob.extc` 的标题就是「**④ 字面量越界**」：

```extc
var b: [4]i32
b[10] = 1          // 长度是编译期常数 ⇒ 这一条**能证明**
```

它以前**编得过**（运行时才 trap）—— 于是一条**编译期就能证明的错误**
被记成了"已知安全"，正是 `PLAN #4`。修好之后它被**编译期**挡下：

```
error: index 10 is not inside `[4]i32` (length 4)
```

⇒ 从基线里删掉。**删掉是变严的证据，不是放松** ✓

同族的 `tests/traps/index_out_of_range.extc` 用的是**运行时下标**（`a[i]`，`i` 算出来的），
证明不了 ⇒ 照旧走运行时 trap 带位置 —— 那一条**没有**受影响 ✓
