## 2. 本轮**实测**的两条窄化

### `D1`：元素槽 vs 真栈槽（D 的窄化）
* **窄在哪里**：`acTargetSlotIsHeap == false` 的写法里，**目标最外层是下标**（`arr[i%8] = p`）时
  不再要求"槽里的全部值都随本迭代死"—— 理由是"这个槽属于一个（局部）数组对象，槽随它一起死"。
* **实测**：**确实让 `carray_slot` 变 idle**（`391 → 0`），**八条对照全部仍发 rc**
  （397/391/396/422/394/390/396/395）……
* **但动态界把它否掉**：idle 后 `carray_slot` 的 **N vs 4N = 2.12×**（50k 2220 KB → 200k 4716 KB），
  而回收档同规模是 **1.70×** —— 每轮被覆盖下来的 `p`（自环 ⇒ 计数归不了零）没人收，
  攒在帧 arena 里 ⇒ **会破界**。`--run` stdout 一致（`n=20000 sink=159964`），但内存随规模涨。
* **结论**：**不可走**（`D1` 是"会破界"，不是"安全兑现"）。**同时记一条教训**：
  "八条对照仍发 rc"是必要不充分——真正拦住它的是 `gate-idle-bounded` 的 N vs 4N 那一格。

### `E3`：下标表达式的更一般扫描（E 的窄化）
* **窄在哪里**：`NE2` 只认"下标就是标识符"；`E3` 扩到"下标是 `i % 8` / `i + 1` 这类**一元/二元表达式**
  且里面出现了**在本循环体内被赋值**的标识符"。
* **实测**：在 9 个 D/E 形状上，`E3` 单独（以及 `D1,E3`）**一个新 idle 都不多**（与 base 逐格相同）
  ⇒ **兑现 0**，没有收益可算。
* 关联：`task-38` 已经实测过 `E4`＝"任意元素目的地"⇒ 把 `fixed_slot_overwrite` 判 idle（**1.56×**）⇒
  对照当场红。所以 E 这一族"再往下放"的方向是**危险的**，`NE2` 的"下标随循环推进"已是安全边界。

## 3. 提出了、但**本轮没实现**⇒**未测到**（不是"安全"也不是"会破"）

`evidence-first` 第 5 条：下面这几条我**不写进实测结论**，只写清缺什么事实：

| 窄化假设 | 窄在哪里 | 缺什么事实（→ 影响面） |
|---|---|---|
| `D2` "该槽随后不再被读" | 槽的存储如果之后没人读，里面的引用活着也不会被再取用 ⇒ 可放行 | 需要**每个名字/叶路径的读集合**（def-use 台账）—— 新事实，影响面待评估 |
| `D3` "该槽在写之前已死" | 槽自身的生命周期已经结束（块内最后一次写之后不再用）⇒ 无需按"值随迭代死"要求 | 需要**槽的活跃区间**（同样要数据流台账） |
| `C1` "宿主是本帧新建对象的字段投影" | 宿主不是 `new` 本身，而是它的字段/元素（`p.child`），根还是本帧新局部量 ⇒ 可当"本帧新建"看 | 需要把 `idleFresh` 沿**投影**传播（现有台账只记绑定名）；判度：**中**，无需新冻结字段（待实现验证） |
| `G1` "单实现闭合（该 dyn 调用点只有一个实现）" | 去虚化后按单实现判 | 需要**dyn 调用点的实现计数/效果签名** —— 检查器里没有这份事实；**判断**：这是**死结**（要跨模块/链接期信息，超出本 ② 判据的范围），如实标死结 |
| `H1` "重用的存储不存在跨轮引用" | `@overwrite` 复用格时，若旧对象不被任何**跨轮**引用持有 ⇒ 覆盖不丢根 | 需要**跨轮活跃性**（谁是跨迭代的持有者）—— 与 `D2/D3` 同一类新事实 |

## 4. 排序与一句话结论

* 可安全兑现的**新**窄化：**0 条**。唯一实测能 idle 的形状（`carray_slot`，173.7 µs）被动态界否掉。
* ⇒ **本件负结果**：D/E/C/G/H 这一族**本轮没有安全可兑现的窄化**；榜首形状的链头是
  C×2 / D×4 / E×1 / A×2 / F×1，其中 D 的最便宜窄化（`D1`）**已实测排除**。
* 下一件若还要打这一族：只有 **`D2`/`D3`（槽的 def-use / 活跃区间）** 与 **`C1`（新鲜性沿投影传播）**
  还没试过 —— 前两条**需要一份新的读/活跃区间台账**（标"影响面待评估"，实现前请 Lead 先评），
  `C1` 用现有事实可能做得出来（判度中），但**本轮没有实测**，不能算兑现。
* 需要新冻结字段的：**本轮 0 条**（`C1` 也只需本地台账，待实现确认）。

# task-41：`C1` 实测 + `D2`/`D3` 影响面评估

## A. `C1`（宿主是本帧新建对象的字段投影）—— **实测：兑现 0**
副本 `/tmp/n41`（`EXTC_PROBE_N41`），基线 = 当前绿点。两个变体都实现了：
* `C1`：宿主不是新局部量、但目的地是**投影**（`(*p).f` 形态）时放行；
* `C1u`：**上界** —— 任何投影宿主都不再要求"本帧新建"（比 `C1` 宽得多）。

实测（rc 计数，base / C1 / C1u 三列完全一致）：

| 形状 | base | `C1` | `C1u` | 结论 |
|---|---|---|---|---|
| `cyclic_pressure`（B 节 491.1） | 422 | 422 | 422 | **没兑现** |
| `shard_bands`（198.5） | 420 | 420 | 420 | **没兑现** |
| `live_churn` / `cross_region` / `scale_growth` / `owed_home` / `slot_elem_known` / `carray_slot` / `digraph` | 396/397/391/398/405/391/534 | 同 | 同 | 没兑现，且八条对照照旧 |

**为什么**：C 之后**下一条理由立刻接手**（实测原文）：`cyclic_pressure` →
`line 171: a reference is assigned to a stack slot (…)`；`shard_bands` → `line 111` 同一句。
真正的卡点不是 C，而是**形参的宿主身份**：`link(a, b)` 里的 `(*a).next = b`，`a` 是形参，
调用方（`pushFront`/`headPush`）每轮传进来的确实是新对象 —— 这要的是**跨过程的"形参新鲜性"**
（每个调用点都传"本迭代新建"的实参），不是"本帧的字段投影"。`C1` 连它的上界都动不了榜首族。
⇒ **`C1` 单独不值得开**（兑现 0）；若要做，应改名为 **`C2`：参数新鲜性从调用点传播**（新事实：
调用点实参的 `idleFresh`，跨过程），影响面待评估。

## B. `D2`/`D3` 影响面评估（**只评估，未实现** ⇒ 以下是判断，不是实测）

**① 要加什么事实**：一份**每个（绑定, 叶路径）的读集合与赋值点序列**（走查里新增一张本地表；
不一定要进冻结字段 —— 但 `D2` 需要"写之后到下一次写之前有没有读"，即 **def-use/活跃区间**，
属于数据流，跨语句、跨分支，比现有"逐语句记录"重；`D3` 需要"槽在写之前已死"，同一张表够用）。

**② 谁受影响**：`idleStoreQualified` 的 (b′) 后处理（D 的唯一判据点）会改为"槽的生命周期 /
读窗口"判据；`RECLAMATION.md` 的 (c) 条（"没有丢引用的操作"里 D 的表述）要同步改写；
不碰 A/NB/NE2/F 的既有条目。

**③ 能兑现什么（含"钉住的必须仍发 rc"）**：D 出现在 `live_churn`(447.8 B 节)、`cross_region`(393.6)、
`scale_growth`(125.8)、`cyclic_pressure`(491.1，链 = C→B→D)、`shard_bands`、`carray_slot`(173.7)、
`slot_elem_unknown`(177.0)、`digraph`(139.0)、`owed_home`(261.0，E→D)、`struct_copy_slot`(157.8) 等。
**`live_churn`/`cross_region`/`scale_growth` 是被钉住的对照**：读源码可见它们的 D 站点正是
"槽的读发生在**本迭代之外**"——
* `cross_region`：`keeper = t`（循环里）→ 唯一的读在**循环之后**（`(*keeper).val`）；
* `live_churn`：`head = c` → 读发生在**下一轮**（`c.next = head`）。
⇒ 只要 `D2`（"该槽随后不再被读"）按"本迭代窗口"实现，**这两条就会变 idle ⇒ 直接不可走**；
若按"整个函数剩余期"实现，则它们仍然发 rc，但那时 `D2` 能兑现的形状大概率所剩无几
（语料里 D 站点几乎都是游标/keeper 这类"跨迭代还活着"的槽）。
**④ 风险与不确定性**：新表是数据流事实，最容易在**分支/循环回边**上算错；网兜是八条对照 +
`gate-idle-bounded` 的 N vs 4N（task-40 的教训：对照全活是**必要不充分**）+ ASan 全语料 + 电池。
另外 `D1` 已实测破界（2.12×）⇒ D 这一族的"便宜方向"已经被排除。

**结论：不值得开（本轮）** —— 理由三条：**(a)** `D2` 的两种口径里，能兑现的口径会让
`cross_region`/`live_churn` 判 idle（钉住的对照 ⇒ 不可走），不破对照的口径几乎没有兑现面；
**(b)** `D3` 在语料里找不到"写之前已死"的 D 站点（那些槽都是跨迭代的游标/keeper）；
**(c)** 成本是**新的读/活跃区间数据流表**（现有事实不够），而 D 的最便宜窄化 `D1` 已实测破界
（`carray_slot` N vs 4N = **2.12×**）。若非要开，建议先只做 `D3` 并把三条钉住的对照当**前置红判据**
（先注入它们的"必须仍发 rc"断言，再实现）。

# task-42：评估 `C2`（跨过程参数新鲜性）—— **上界实测：兑现 0 ⇒ 不可走**

副本 `/tmp/n42`（`EXTC_PROBE_N42`），基线 = 当前绿点。`C2u` = **上界**：**任何形参**宿主都不再要求

| 形状 | B 节 max µs | base rc | `C2u` rc | `C2u` 后 idle？ |

## B. `C2` 影响面评估（只写；结论：**不值得开**）

**① 要加什么事实**：一份**跨过程的参数新鲜性摘要** —— 每个函数、每个形参："**所有调用点**传进来的
实参，在调用者的循环深度上都是 `idleFresh`（本迭代新建）"。这要：调用点↔形参位置映射、
每个调用者自己的 `idleFresh` 台账、以及在**调用图上的不动点**（与 `planFnAcyclic`/`planCallee`
同类，递归/间接调用都要处理）。**不是** AST 冻结字段，但要给 plan 侧加一张每函数表 ⇒
**影响面待评估**（要 Lead 先评）。

**② 谁受影响**：`(a)` 后处理里的 C 分支（宿主新鲜性）由一个**跨函数输入**决定；
`planFnReclaimIdle`/`scanUnitReclaim`（②的整单元合取）要吃这份摘要；
`RECLAMATION.md` 的 (a) 条措辞要改（"宿主是本帧新局部量" → "…或**所有调用点**传入的实参都是
本迭代新建的"）；不碰 A/NB/NE2/F 的既有条目。

**③ 能兑现什么（含钉住的对照）**：**实测 0 µs** —— 即使把**所有**形参都放行（上界），
`cyclic_pressure`（491.1）与 `shard_bands`（198.5）仍然非 idle，因为下一条是 **D**。
三条钉住的对照（`live_churn`/`cross_region`/`scale_growth`）在 `C2u` 下**仍发 rc** ✓
（所以 `C2` 本身不破对照）—— **但这不构成开的理由**：收益要连 D 一起解，而 D 已判不可走。
若将来 `D` 那条被解掉，`C2` 的账面收益才是 491.1 + 198.5 ≈ **690 µs**（`PAUSE-CORPUS.md` B 节口径）。

**④ 风险与网兜**：跨过程摘要在**递归 / 间接调用 / `mut ref` 别名**上最容易算错（一个"漏算的调用点"
就会把不新鲜的实参当新鲜 ⇒ 少收 ⇒ 界涨）；网兜 = 八条对照 + `gate-idle-bounded` 的 **N vs 4N**
（`task-40` 的教训：对照全活是**必要不充分**）+ ASan 全语料 + 电池。但当前收益为 0 ⇒
**风险/收益不成比例**。

**结论：不值得开（`C2` 不可走）** —— 理由：(a) 上界实测 `NEW_IDLE=0`，榜首族的链是 **C→D**，
`C2` 单独不解任何形状；(b) 与它组合才能兑现的 `D` 已在 `task-40/41` 实测不可走；
(c) 成本是跨过程不动点 + plan 侧新表（影响面待评估），而收益为 0。
