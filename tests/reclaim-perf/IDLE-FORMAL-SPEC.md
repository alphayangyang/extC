# 判 idle 的**最大健全不动点**（形式化规格）

> 目的：把"什么情况下可以整单元不发射回收运行期"写成**一个语义性质**，再给出该性质在**一个明确的
> 抽象域**里的**最大健全近似**（greatest fixed point），并逐条算清当前实现相对它**丢了什么**。
> 实现的任务因此变成"算这个不动点"，而不是"再加一条规则"。

## 1. 语义性质（要判的东西）

固定一个单元 `D`（一组函数）。对输入规模 `n`：

* `Live(D)(n)`：程序运行中的**活对象**字节数（从根可达）；
* `Garbage(D)(n)`：**不可达但未释放**的字节数；
* `PeakOff(D)(n)`：关掉回收运行期时的峰值内存（关档下"垃圾永不释放"成立）。

**安全性质**（判 idle 的真条件）：

```
Safe(D)  ⟺  ∃c. ∀n. Garbage(D)(n) ≤ c          （垃圾有界，与 n 无关）
```

为什么是它：`PeakOff = Live + Garbage`，而开档下 `Garbage ≤ 常数`（回收器会收），所以
`Safe(D)` ⟺ 关档不会因垃圾累积而爆内存 ⟺ 不发射回收运行期是安全的。**注意它不要求
`Live` 有界**——活集随 n 涨是程序自己的事（`rg_walk_chain` 就是这一类）。

不可判定性：`Garbage` 是堆可达性，任意别名/改链/递归下不可判定。所以下面求**最大的健全近似**。

## 2. 垃圾从哪来（把性质化成一条**逐站点**条件）

设每个 `new` 站点 `a` 有一个"存储域"：`a` 所在的最内层循环体 `L(a)`（没有则函数体）对应的 arena。

* 在 `L(a)` 结尾（回边）时，`a` 分配的每个对象 `o` 只有两种下场：
  **(i) `o` 从根可达**（活着，不算垃圾）；**(ii) `o` 的存储随 `L(a)` 的 arena 一起释放**（不算垃圾）。
* 若既不可达、存储又不在该 arena 里（被**提升**到更长寿的层，例如被条件地存进长命槽），
  它就在每一轮留下一个垃圾 ⇒ 随 n 涨。

⇒ **充要（在"垃圾只由循环累积"的常规形态下）**：

```
Safe(D)  ⟺  ∀ 循环 L、∀ new 站点 a ∈ L、∀ 对象 o ∈ Alloc(a):
                o 在 L 回边处可达   ∨   storage(o) 属于 L 的 arena
```

后半句是**逃逸分析**的事（`planArenaLevel`：对象最终落在哪一层）；前半句是**可达性**的事。
判 idle 要证的是：**凡是被提升（存储活过本轮）的对象，在回边处都还可达** ——
等价地：**每一次"丢引用"都不丢最后一个根**。

> 这条把"不丢根"（A 维）与"不累积"（B 维）**合成了一条**：不丢根就是"可达性"那一半，
> 不累积就是"存储就在本轮 arena"那一半；两者都只是 §1 的分解，不是并列的两套规则。

## 3. 抽象域（能表达什么，就决定了范围的上界）

**根**：`Roots = {参数, 本帧局部量, 长命字段}` ∪ `{@fresh, @iter}`。

**抽象值**：`A(s) ⊆ Origins`，`Origins = Roots ∪ 绑定名`，语义
"**`s` 里的每个取值都满足下面任一条**"：

| 元素 | 含义 |
|---|---|
| `r`（绑定名/根）| 该值**从 `r` 沿稳定字段可达**（投影）|
| `@iter` | 该值的**存储就在当前迭代的 arena**（随本轮释放）|
| `@fresh` | 该值是**本帧新分配**的对象 |

**两条辅助事实**（各自都是**最大不动点**，与 `A` 一起解，互相引用）：

* `Stable(T,f)`：结构类型 `T` 的字段 `f` **只被"值是新对象、宿主也是新对象"的存储写过**
  ⇒ 这条链**只会被创建，不会被改指**；
* `Ret(r)`：`r` 历次持有的对象**都还可达**（`r` 自己是一条"不会丢尾巴"的链）。

**传递函数**（对每条引用存储 `s := v`，以及它对应的"旧值"）：

```
v = null                     ⇒ 无约束
v = new T                    ⇒ @fresh  （且 a 在本迭代 arena ⇒ @iter）
v = x   (标识符)              ⇒ A(x)
v = (*x).f₁…fₙ               ⇒ 若 ∀i. Stable(Tᵢ,fᵢ) 且 r ∈ A(x)  ⇒ r ∈ A(s)
v = 调用结果                   ⇒ ∅        （跨过程：见 §5 L3）
s := v 的**旧值**             ⇒ 必须仍可达：∃r ∈ A(s) ∧ Ret(r)（"链上的位"）
                                 或 新值链住旧值：`v.g = 旧值` 且 v 无条件执行（细化 i）
**链接入结构**（缺了就丢范围）：对 `h.f := v`，若 r ∈ A(h) ∧ Stable(T,f)
                                ⇒ r ∈ A(v 这个对象)     ← "新结点被链进 r 的结构 ⇒ 它成为 r 的投影"
```

**精度定理（要算出的"最大范围"）**：上述算子是**单调**的（传递函数对 `A`/`Stable`/`Ret` 单调），
所以在**下降**迭代（从 ⊤ 开始、只删）下的**最大不动点 `A*`** 存在且可计算，并且

```
∀ 健全不变量 A′ (在本域内):  A′ ⊆ A*        （余归纳的标准结论）
```

⇒ **`A*` 就是本域内最精确的健全判据**：判 idle ⟺ `A*` 满足 §2 的逐站点条件。
超出 `A*` 的范围**不是"再加规则"能拿到的**，只能**扩大抽象域**（§5 的 L1–L5），
每一项都对应"域变大 ⇒ 不动点只可能更大 ⇒ 范围只可能更大"，且各自有代价与判据。

**健全性论证（概要）**：`A*(s) ∋ r` 归纳地给出一条**见证**：从 `r` 到 `s` 当前值的字段路径
`π`，且 `π` 上每个字段 `Stable`（不会被改指）、`Ret(r)`（`r` 不会丢尾巴）。于是：
① 覆盖 `s` 时旧值仍有见证路径 ⇒ 不丢根；② 被提升的对象只要有见证路径就在回边处可达 ⇒
不累积。两条合起来给出 §2 ⇒ §1。

## 4. 当前实现丢了什么（把"范围不够"算成账，而不是感觉）

| # | 缺失 | 属于 | 代价（现在挡住的形状）|
|---|---|---|---|
| **L1** | "链接入结构"传递（§3 加粗那条）| 域内**传递不完备** ⇒ 不动点比 `A*` 小 | `rg_grow_tail`（`tail = p`：新结点已链进 `head` 的链）|
| **L2** | 字段按**字段名**记，不按 **（结构类型, 字段）** | 域内**键太粗** ⇒ `Stable` 与规则 A 误判 | `rg_scan_graph`（`next` 同时属于 `node`/`edge`，3 处站点）|
| **L3** | 跨过程：被调者的 宿主/值 新鲜性没有**函数摘要** | **域外**（本域只到函数级）| `rg_insert_hash`、`spectrum_p2/p4`（宿主是形参）|
| **L4** | 元素槽路径按 `"[]"` 命名（不分下标、不分基址）| 域内**键太粗** | `rg_walk_tree`（局部聚合元素槽 `stack[top]`）、`rg_walk_buckets` 的元素写 |
| **L5** | `@iter`（存储随本轮死）没有独立事实：B 维靠"值的 arena 层 ≥ 循环层"近似 | 域内**精度损失** | 部分"值随本轮死"的形状被判否 |

⇒ 现有八条规则 = `A*` 的一个**健全但不是最大**的子集；**L1/L2/L4 是本域内的精度损失**
（补齐即得 `A*`，不需要新机制），**L3 是域外**（要扩域 = 加摘要，是**扩大域**而不是补丁）。

## 5. 实现与验收（照 §3 算，不逐条加规则）

1. 把 `idleSolveProj` 重写成 §3 的**完整传递函数**（含 L1），一次求 `A*`；
2. 键改成 `(结构类型, 字段)`（L2）与 `(基址, 下标表达式)`（L4）—— 类型本来就在 AST 上；
3. `@iter` 立成事实（L5），B 维改问它；
4. `Stable` / `Ret` 与 `A` **同一次下降迭代**（互相引用，单调）。
5. **预测的收益**（用于验收，而不是事后解释）：L1+L2+L4+L5 ⇒ `rg_grow_tail`、`rg_scan_graph`、
   `rg_walk_buckets`、`rg_walk_tree` 应当转 idle；L3 ⇒ `rg_insert_hash`、`spectrum_p2/p4`。
   实际每步复跑：变化面 → 每个翻转形状的**界**（判 idle 后峰值 ≤ 付钱档）与语义 → 四条绊线
   （`scale_growth`/`cross_region`/`cyclic_pressure`/`outer_alloc_inner_write`）→ 六条护栏 → 电池。
