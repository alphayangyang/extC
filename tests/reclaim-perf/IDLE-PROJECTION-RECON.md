# idle 证明推宽到"纯税族"：规则 P（投影）工作单

> 状态：**工作单**。规则未实现；本文只钉"要放宽什么、凭什么安全、红绿判据是哪些"。
> 事实来源：[`TAXMAP.md`](TAXMAP.md) §4（A′ 之后重取）与 `out/reasons.tsv`。

## 0. 为什么做这个

重表（§4，A′ 之后）里，"纯税族"**不比关档省内存**（`spectrum_p4` 反而 2.0–2.25× 更费），
却要付 **1.0–2.5×** 的墙钟：

| 形状 | 税× | RSS 比（开/关）| 首条挡路理由 |
|---|---|---|---|
| `rg_walk_chain` | 1.56 | 1.27 | D 引用写进栈上槽 |
| `rg_walk_buckets` | 2.53 | 1.27 | E 循环里写 ref 字段 |
| `rg_walk_tree` | 1.34 | 1.51 | D |
| `rg_scan_parent` | 1.65 | 1.27 | D |
| `rg_grow_tail` | 2.95 | 1.23 | E |
| `rg_scan_graph` | 5.46 | 1.49 | E |
| `rg_insert_hash` | 0.89 | 1.27 | C 宿主不是本帧 `new` |
| `spectrum_p2` | 1.01 | 1.01 | C + D |
| `spectrum_p4` | 1.55 | **2.01** | C + D |

这些形状里**对象从头活到尾**（建好—遍历—块退出整片丢），清扫本来无事可做。它们付的钱是
"发射了回收运行期"本身（每个分配点、根表、每次引用存储的 wrapper）。A′ 已经拿掉释放那条
O(活集) 破口；这一项是**本来就不必付**的。

## 1. 现状：idle 是**整函数合取**，卡在 D/E/C

* D 的判据在 `idleStoreQualified`（`src/check/check_top.c`）：写进槽的值必须是 `null`，或它的
  arena 层 **≥ 本次写入所在的最内层循环体**（细则 (b′)："随本迭代的 arena 一起死"）。
* 游标不满足：`cur = (*cur).next` 里值的层是**长命链所在的层**（实测 `rg_walk_chain` 上
  链在层 1、循环体是层 2）⇒ 判否。
* 其余事实（哪些绑定是"本帧 fresh"、哪些字段被写、写在谁身上）**已经在台账里**
  （`IdleFresh` / `IdleFieldStore` / `IdleSlotSite`，由 `idleSolveLvls` 求最小不动点）。

## 2. 规则 P：**覆盖一个槽不丢根，当旧值仍从某个活根可达**

两个 flavor（都是"局部可判"的充分条件，不声称充要）：

**(i) 新值链住旧值**：`v.f = <槽的旧值>` 先发生，随后 `slot = v`，且 `v` 是本帧 fresh、
两次写之间没有别的 `slot = …`。⇒ 旧值由 `v.f` 可达。（头插 `p.next = head; head = p`。）

**(ii) 旧值是某个活根的字段投影**：`slot = (*r).f₁…fₙ`，且

* `r` 的投影链**只由"新鲜宿主的首次初始化"改写** —— 即字段 `fᵢ` 的每个写站点宿主都是本帧 fresh
  且同一宿主不写第二次（这条正好是 (a′) 已经在算的事实）；
* `r` 的绑定本身不被重赋值（或它的重赋值也被 (i) 链住）；
* 投影沿链**传递**（`cur` ← `head` ← …），所以它要并进 `idleSolveLvls` 的不动点一起解，而不是
  单点判断。

两条合起来覆盖"建链 + 遍历"这一整类：建链用 (i)、遍历用 (ii)。

## 3. 判据（**先红后绿**）

**红（今天必红，实现后必须转 ZERO 且 N vs 4N 峰值 <1.5×）**：
`rg_walk_chain` · `rg_walk_tree` · `rg_scan_parent` · `rg_walk_buckets` · `rg_insert_hash` ·
`rg_grow_tail` · `rg_scan_graph` · `spectrum_p2` · `spectrum_p4`。

**护栏（必须仍 PAYS —— 它们真的丢引用）**：
`rg_relink_delete`（中间摘链）· `rg_overwrite_ring` / `rg_walk_array`（覆盖）·
`rg_evict_cache`（淘汰）· `rg_drop_component` / `cyclic_pressure` / `ring_per_round`（环）。

**棘轮**：`gate-rc-idle-corpus` 的"无 rc 形状数"只许**升**（当前 14）；`gate-tax`（`bt` 1.000×）
不许退；`gate-idle-bounded` 的形状比不许退。**反空跑**：护栏那组必须仍然付钱（判 idle 就红）。

## 4. 实现落点与难点

* 落点：`idleWalkStmt` 的 D 分支（`check_top.c:6111` 起）——把"槽写入是否合格"从
  `idleStoreQualified(lvl, loopScope)` 换成"或 P 成立"；事实在 `idleSolveLvls`（`:6046` 起）。
* 难点：
  1. `head` 在建链循环里**被重赋值**（每轮一次）⇒ 不能只靠"绑定不重赋值"；要靠 (i) 的
     "新值链住旧值"；
  2. 字段 `next` **有写**，但宿主全是 fresh（(a′) 的事实已有）⇒ 路径稳定性能用现成台账；
  3. 跨函数（P4 的 `tableInsert`，宿主是**形参**）属于 C 规则，不在 P 里 —— 那一条要另一份
     "形参 `partN`/区域归属"的事实，单开；
  4. **别把 `rg_relink_delete` 放行**：`(*prev).next = (*cur).next` 之后 `cur` 真的不可达，
     它是 P 的反例，必须留在语料里当护栏。

## 5. 为什么这一轮不直接落进 `src/`

P 是**整函数合取**里的一项：放行一个站点 ⇒ 整个函数不再发射回收运行期，而误判的失效方向是
**内存无界**（不是悬垂），且只在"跑得足够久"的形状上暴露。按仓库纪律：**先把判据接上**
（护栏 + 红集），再逐条放宽、每次复跑语料与门禁。所以顺序是：

1. 把 §3 的红集/护栏接成一个可跑的判据脚本（现在只有 `gate-rc-idle-corpus` 的计数棘轮）；
2. 在 `idleSolveLvls` 里加"投影"维度，只放宽 flavor (i)，跑一遍；
3. 再加 (ii) 的传递投影，跑一遍；
4. 全部绿了才翻进默认（`scanUnitReclaim` 的判据）。

## 6. 上界实测（先量再实现）：D 单独 2/9、D+E+C 6/9，护栏全稳

在 `/tmp` 的副本树上把三条规则**整条放开**（不健全，只读收益），再用闸门同一条判据
（默认档与 `EXTC_RECLAIM=0` 逐字节相同）分类：

| 放宽范围 | 红集变 idle | 护栏变 idle（= 破安全边）|
|---|---|---|
| 只放开 **D** | **2/9**（`walk_chain`、`scan_parent`）| 0/6 ✔ |
| 放开 **D+E+C** | **6/9**（+`walk_buckets`、`insert_hash`、`spectrum_p2`、`p4`）| 0/6 ✔ |

剩下 3 个的残余挡路者（在 D+E+C 全放开的产物上取 `EXTC_DBG_RCIDLE`）：

* `rg_walk_tree` —— 还是 D，但走的是**另一条出口**：目标是**局部聚合的元素槽**（`stack[top] = …`），
  不是具名 ref 标识符，所以在 `idleStoreQualified` 之前就判否（`check_top.c:6136` 那条）；
* `rg_grow_tail` / `rg_scan_graph` —— **"宿主绑定被重新赋值"**（host binding reassigned）：宿主是
  每轮更新的 `tail`/`prev2`。注意 (a) 的本意是"**每个对象**的该字段最多写一次"，而这里每个
  `tail` 对象确实只写一次 —— 判否是因为台账按**绑定**而不是按**对象**记。

两条读法：

1. **这条线的安全边界不在 D/E/C 上**：即使把三条全放开，六个真丢引用的护栏**一条都没变 idle**。
   所以"放宽 D/E/C"与"误收"之间没有直接冲突，值不值得做只取决于收益。
2. **收益是 6/9 个纯税形状归零**，其中 `spectrum_p2`/`p4` 是 `bench/gc` 的真实形状。

## 7. 边界：flavor (ii) 只对**栈槽**成立（这是那条安全线）

* **覆盖栈槽 `x = e`**：旧值的可达路径**不经过 x**（x 是根，不是字段）⇒ 只要它在别处可达，
  覆盖后仍然可达 ⇒ flavor (ii) 成立。
* **覆盖字段 `p.f = e`**：旧值**可能恰恰只由这个字段撑着**（`rg_relink_delete` 的
  `(*prev).next = (*cur).next` 就是）⇒ 覆盖后它就没了 ⇒ **(ii) 在这里不成立**。
* **flavor (i) 两种都成立**：旧值在写入**之前**已经被新值的字段链住（`v.f = 旧值` 在前），
  可达性由新路径重新建立 ⇒ 与槽的种类无关。
* 这条边界正好解释上界表里"护栏 0/6 变 idle"：护栏的写都是**字段写且没有 (i) 的形状**
  （relink / 覆盖 / 淘汰）。

### 7.1 副产品：容器插入不需要跨过程摘要

`C1`/`C2`（宿主新鲜性沿投影/跨过程传播）当时做了跨过程参数新鲜性摘要的**影响面评估**，上界
兑现 **0**。但上界表里 `insert_hash`/`p2`/`p4` 的插入点能被 **flavor (i)** 覆盖：那些插入的写法是

<!-- fragment -->
```extc
p.next = tab.buckets[h]     // 新值先把旧值链住
tab.buckets[h] = p          // 再覆盖那个槽
```

两者都在**被调函数内部**，所以 (i) 是**局部**判定 —— **不需要**调用点↔形参映射，也不需要
调用图不动点。⇒ 摘要机制不是这条路的必经之路；`C1`/`C2` 兑现 0 是因为它们解的是另一个轴
（"宿主新不新鲜"），而不是因为缺机制。

## 8. 负结果：flavor (i) 单独实现**不健全**（被绊线抓住，已回退）

**实现**（在收敛后的唯一判据里）：加一条事实（字段写的走查序号），加 `idleLinksOld()` ——
"这次覆盖被新值链住"（被写的是标识符 `v`；台账里有一次宿主为 `v` 的字段写、写进去的正是这个
槽名；那次写在覆盖之前；中间没人写过这个槽），然后把它并进 `(b′)` 合取作为**第二条合格路径**。

**实测**：全语料 852 个可比对文件里 **4 个产物变化**，且都是从"付钱"变成"**判 idle**"：

| 形状 | 变化 |
|---|---|
| `tests/reclaim-shapes/cond_save.extc` | 付钱 → idle |
| `tests/reclaim-shapes/promote_place.extc` | 付钱 → idle |
| `tests/reclaim-shapes/live_churn.extc` | 付钱 → idle |
| `tests/reclaim-shapes/scale_growth.extc` | 付钱 → idle |

后两个是**钉住的对照**（`tools/rc-chain-probe.py` 的绊线体检：这些形状在该放宽集下**必须仍发 rc**）。
实测判据：`scale_growth` 的**关档峰值比 ≈3.0×**（`tests/reclaim-shapes/run-switch.sh` 第 9 行的
口径："开关关 ≈3.0× 红、开关开 ≈1.0× 绿"）⇒ 判 idle 会让垃圾随轮数累积 ⇒ **不健全**。

**根因**（比这条规则本身重要）：

* idle 判据问的是"**垃圾有没有界**"，不是"**有没有丢根**"。
* `(b′)` 在 `if i == n-1 { saved = p }` 这条写上的作用**不是**"旧值还有没有根"，而是"**存进去的
  值的存储会不会跨迭代累积**"：`p` 因为条件存储被逃逸分析**提升到家区域**（存储活到函数末），
  于是前 n−1 轮的 `p` 在作用域退出时被丢下、存储却留着 ⇒ 峰值 ∝ 轮数。
* flavor (i) 只回答"**旧值还有根**"，与上面这条**正交**，不能互相替代。

**结论（写进 milestone 2 的约束）**：规则 P 的 provenance 必须**同时**带两样东西 ——
① 旧值的可达性（(i)/(ii)），② **存进去的值本身的活跃性/存储层**（它会不会被跨迭代丢下）。
只看 ① 会在"只在最后一轮存储"这类形状上把累积判掉。实现与那条字段写 `seq` 事实已回退；
绊线（`rc-chain-probe.py`）、`gate-idle-projection` 的护栏、`gate-idle-bounded` 都保持原样。

## 9. milestone 2 第一步：B 维落地（`condDepth`），flavor (i) 健全打开

**实现**：走查器新增一条事实 `condDepth` —— "这个写入点被几层条件语句包住"。进循环体**归零**
（问的是这一轮的迭代里这次存储会不会发生）、遇 `if`/`match` 加一、表达式路径保守取 1。
细化 P（flavor (i)）加一条硬条件：**`condDepth == 0`（本迭代必然执行）**。

**效果**（全语料 852 个可比对文件，与重构前的 `git archive a614c06` 编译器逐字节比）：
**产物变化 1 个** —— `live_churn` 判 idle；`scale_growth`/`cond_save`/`promote_place` **被正确挡住**
（它们的存储在条件里）。这正是 §8 那条洞的封口。

**`live_churn` 判 idle 的有界性实测**（判据：峰值与 churn 无关、只随真活集涨）：

| 参数 | 峰值 |
|---|---|
| 活集 20 万，churn 20 / 80 / 320 万 | **7.45 / 7.86 / 7.58 MB**（与 churn 无关）|
| churn 20 万，活集 20 万 → 80 万 | 7.7 → **14.1 MB**（随真活集线性）|

⇒ 它的 churn 垃圾由**每轮 arena** 释放、不走 rc，判 idle 健全。因此把 `live_churn` 从
`tools/rc-chain-probe.py` 的绊线里移出（附上面这组实测）；`scale_growth`（条件存储 ⇒ 累积）
继续当绊线。

**验收**：`nobench` 100/0（含 `gate-idle-projection` 的护栏 6/6 仍在付钱）。

**红集仍 9/9 未动** —— 它们的挡路者是别的规则：E（`(*tail).next = p` 的宿主是**绑定**而不是
**对象**）、游标族（D）、跨过程宿主（C）。这些要的是**对象级 provenance**（每对象写一次的来历 +
值的来源根 + 路径稳定性）——那才是 milestone 2 的主件；**B 维是它的前置条件**：没有 B 维，
任何"旧值还有根"的放宽都会重开 `scale_growth` 那个洞。
