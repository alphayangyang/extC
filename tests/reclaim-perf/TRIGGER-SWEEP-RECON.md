## 1. 触发判据在哪、由什么决定（引行号）

**判据 = 运行期压力公式**（不是 codegen 算好的阈值）。全在 `src/back/reclaim.c` 的发射文本里：

| 位置 | 行号 | 内容 |
|---|---|---|
| `extc_rc_thrUpd` | **reclaim.c:1182** | `scale = r->scale > 0 ? r->scale : 1;`<br>`thr = r->live * 2;`<br>`if (thr < r->floor) thr = r->floor;`<br>`if (scale > 1 && thr > INT64_MAX / scale) { r->thr = 0; return; }`<br>`r->thr = thr * scale;` |
| `extc_rc_shouldSweep` | **reclaim.c:1189** | `if (r->noSweep) return 0;` / `#if EXTC_RC_SWEEP_FREE` → `return 0;` / `return r->bytes > r->thr;` |
| `collect` 收尾（更新 `live`/`scale`）| **reclaim.c:1230–1237** | `freed == 0` ⇒ `scale ×= 2`（上限 `EXTC_RC_SCALE_MAX`）；`freed > 0` ⇒ `scale = 0`；`r->live = r->bytes; extc_rc_thrUpd(r);` |
| `extc_rc_maybeCollect` | **reclaim.c:1244** | 触发入口：`if (!extc_rc_shouldSweep(r)) return -1;` 然后 `collect` |
| `floor` 默认 | **reclaim.c:68–69** | `#define EXTC_RC_FLOOR ((int64_t)1 << 20)`（= 1 MiB）|
| `EXTC_RC_SCALE_MAX` | **reclaim.c:71–72** | `((int64_t)1 << 40)` |
| `extc_rc_regionFloor` | **reclaim.c:927** | 运行期设每区 `floor` 并重算 `thr` |
| **发射点（调用的位置）** | **codegen.c:3343 / 3348** | `{ if (extc_rc_shouldSweep(r)) extc_rc_maybeCollect(r, roots, n); }`（分片变体在内）|
| 分片时 floor 均分 | **codegen.c:3356** | `EXTC_RC_FLOOR / N`（"总量仍是 FLOOR，片多只让每片收得更勤"）|

**结论**：阈值 = `max(2 × live, floor) × scale`
* `live` = **上一次清扫后的占用字节**（`reclaim.c:1236`），所以"2×"是"堆长到活集两倍再收"；
* `floor` 是 1 MiB 的内存压力下限（小堆时它主导）；
* `scale` 是**自学习退场**：一次清扫颗粒无收就把阈值翻倍（学"这里没有环"），收到东西就复位 —— 上限 2^40。
  ⇒ 自带"越收不到越少收"的行为，参数化时要注意它会**放大**外部旋钮。

**现成开关**：`EXTC_RC_SWEEP_FREE`（编译期，**整段关掉触发**）、`EXTC_RC_TIME/STATS/PAUSE/NOCOUNT`
（诊断/计数），**没有任何旋钮能改阈值**（`2` 与 `floor` 都是字面量/宏）；运行期开关也没有。
⇒ 要"放宽触发"就必须参数化。

## 2. 参数化改法（**只改生成物副本；`src/` 不动**）

工具：`/tmp/trig/trig.py`（准备阶段产物；正式测时可挪进 `tools/`）。

```sh
# 生成物 → 参数化 → 编译（对每个形状、每个 M 各一次）
EXTC_RECLAIM=1 build/extc -O2 -I stdlib -w -o /tmp/trig/S.c <shape>.extc
python3 /tmp/trig/trig.py /tmp/trig/S.c /tmp/trig/S.M4.c 4
cc -O2 -fwrapv -o /tmp/trig/S.M4 /tmp/trig/S.M4.c
```

改法（把**最终阈值**乘 M，M = 1/2/4）：

```c
    r->thr = thr * scale;
    if (M > 1) {          /* 只改副本：堆长到 M× 阈值再收 */
        if (r->thr > 0 && thr > INT64_MAX / (scale * (int64_t)M)) r->thr = 0;
        else r->thr = r->thr * (int64_t)M;
    }
```

* **为什么乘在最终阈值上**：这样 `live` 主导时 = 把"2×"抬到 `2M×`，`floor` 主导时 = 把 1 MiB 抬到 `M` MiB
  —— 两种情形都真的"让它多长一会儿"，只有一个旋钮。
* **锚点唯一性**：`r->thr = thr * scale;\n}` 在生成物里唯一 ✓（`trig.py` 会断言）。
* **溢出**：保留原 `thr*scale` 的溢出判断，再对 `×M` 加一道同样的保护（超界 ⇒ `thr = 0`，即"一分配就收"，
  方向安全）。
* **正确性抽查（已做，非计时）**：`M=1` 与未改默认档在 `digraph` N=1000 / `human_a` N=200 上
  **stdout 逐字节一致** ✓（`M=1` 时 `if (1 > 1)` 整段编掉）；**未记录任何时间、未用 `taskset -c 6`** ✓。

## 3. 预期代价（写清楚，量完按它对账）

这条旋钮**只改"什么时候收"**，不改"收什么"，所以：

* **次数**：阈值 ×M ⇒ 触发间隔大致 ×M ⇒ **collect 次数约降到 1/M**（`scale` 自学习会在此基础上再放大）。
* **浮动垃圾 / 峰值 RSS ↑**：最坏情形多留 `(M−1) ×`（阈值相对量）的垃圾；RSS 大致随 M 上升，
  直到 `floor` 与 `scale` 的封顶。**这是这条路的成本项，必须与"少收几次"一起报**。
* **单次停顿不一定变小**：`mark` 的工作量 ∝ 活闭包（与堆大小无关），但**清扫面 ∝ 堆槽数**（随 M 长），
  所以每次 collect 的 `sweep` 分量会随 M 变大 —— 这正是 `SHARDS=4` 那次"次数 156→90 却
  **p50 1.95 ms / max 29.6 ms 更差**"的同一机制（少收 ≠ 每次更小）。⇒ 要同时报 **Σ停顿** 与
  **p50/p99/max**，不能只看墙钟。
* **自学习交互**：放宽后单次清扫更容易收到东西 ⇒ `scale` 复位更频繁（"更少收"的效应可能被抵消一部分）；
  反之若某形状本来扫不到东西，`scale` 会翻倍放大旋钮 ⇒ 内存可能无界上涨（方向是**内存涨**，不是悬垂）。

## 一句话结论

**"少收几次"省不出墙钟（0.98–1.06×，落在 `M=1` 对照档 ±2% 的噪声内，方向甚至偏慢），代价却是
峰值 RSS ×1.25–2.48 与单次停顿 p50 ×2.0–4.2、max ×1.0–4.0** —— 与 Go 那边"关掉 GC 只省 1.4% 墙钟"
同一结论：**差距不在触发次数上**。

## 机制（与"SHARDS=4 更差"同一件事）

阈值 ×M ⇒ 触发间隔 ×M ⇒ 次数 ~1/M ✓（实测 −50%…−86%）。但：
* **`mark` 的工作量 ∝ 活闭包**（与堆大小无关）⇒ 次数少了不代表每次更小；
* **`sweep` 的工作量 ∝ 堆槽数**，而堆随 M 长大 ⇒ 每次 collect 的清扫面更大
  ⇒ **单次 p50/max 反而变差**（`digraph` p50 169.6 → 362.4 → 572.2 µs；`human_a` p50 ×2.0 → ×4.2）；
* 因此 **Σ停顿**在 `digraph` 上确实降了（−53%/−67%，因为次数降得更多），但在 `human_a` 上**反而升**（+4%/+9%）
  —— 少收 ≠ 总停顿一定降；
* **墙钟几乎不动**：Σ停顿只占 `digraph` 墙钟 ≈11%、`human_a` ≈17%，而 Σ 的下降（或上升）都被
  "每次分配更多内存/更多缺页/更大工作集"抵消（RSS ×1.4–2.5）。

## 与 Go 对接

* 我们：把 collect 次数从 156 压到 22（−86%），**墙钟只动 ±2–3%，RSS 涨 1.48×**；
* Go：关掉 GC 只省 **1.4%** 墙钟（CPU 口径 6%）。
⇒ **两边同向**：这轮的目标（"少收几次"）在两条实现里都换不出吞吐；要缩小差距得看**每条 collect
本身的成本**（我们已量：`mark` ≈13–14 ns/活对象、`sweep` 上界 −7%…−15%）与**根本不进入回收**那条路
（② 已把 3 形状 + 1 真实语料做到不发 rc）。

**三段式**：**已覆盖**：三档 × 两形状的墙钟/RSS/次数/Σ停顿/p50/p99/max（5 次中位）、`M=1` 对照、
stdout 五档一致、关诊断 stderr 0 字节、跑前跑后 load。**未覆盖**：`M` 更大的档（×8）、与分片档
（`SHARDS`）叠加、Go 侧同口径的逐档对照（那是 `gcbench` 的半边）。**残留风险**：墙钟差异 2–5% 与
`M=1` 对照档的噪声同量级 ⇒ "省不出墙钟"的结论是"没有可见收益"，不是"精确为 0"。
