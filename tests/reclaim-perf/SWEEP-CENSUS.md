# 清扫结构普查（`task-22` 结构量半）—— `digraph` 的清扫代价里"结构"占多少

**只出数，不选路。** 本文件给的是**结构量**（与负载无关的那半）：每次清扫扫过多少槽、释放的对象
里有多少属于"整片死掉的结构"、以及分区后的**区域尺寸分布**与**每区固定开销**。
**时长与停顿投影是外推，那一半等安静机器单独跑**（见 §5 的公式与"未量"清单）。

复跑入口：`tools/rc-sweep-census.py`（**只插到生成物副本**，不碰发射器 ⇒ 编译器产物逐字节不变）

```sh
EXTC_RECLAIM=1 build/extc -O2 -I stdlib -w -o dg.c bench/gc/src/digraph.extc
python3 tools/rc-sweep-census.py --gid-off 8 --gpin-off 72 --node-ss 80 dg.c > dg.cen.c
cc -std=c11 -fwrapv -O2 dg.cen.c -o dg.cen
EXTC_SWEEP_CENSUS=1 EXTC_SWEEP_CENSUS_OUT=/tmp/cen ./dg.cen 250000 20261013   # 1M 同理
```

## 0. 判据（先立）

| 判据 | 证据 |
|---|---|
| **编译器产物逐字节不变** | `cmp dg.c <pin 的生成物>` ⇒ 相同（插桩在副本上；关掉 `EXTC_SWEEP_CENSUS` 时插桩程序也**一行不多**，stderr 0 字节、stdout 与开时逐字相同）|
| **诊断自身有牙** | `--gpin-off 0`（读 `id` 的低字节）⇒ `CENSUS-FAIL: gpin 字段不是 0/1 —— 偏移不对（读到了别的字节）`，**exit 3**、程序中止（stdout 0 行）⇒ 不是静默给 0 |
| **内部一致性断言** | `freed == popcount(occ & ~mark)`、`freeSlot 记账数 == 清扫返回的 freed`、释放的槽必须在死集里且未被标记 —— 任一不成立即 exit 3 |

## 2. ①可覆盖比例：**今天 = 0**，但"结构"本身占每次清扫的 ~22%

**今天（实测，两个口径都是 0）**：
* `digraph` 生成物里 `extc_rc_storeRefOwnedRelease(` 的**调用点 = 0**（生成物里只出现定义行 1 处）；
* `EXTC_RC_STATS=1` @1M：`releases=0 release_slots=0` ⇒ ①运行期**一次也没走到**。

⇒ **以今天的①判据，digraph 的清扫里 ①可覆盖 = 0%**（证明根本没成立；不是"跑了但没收"）。

**结构上的机会（用程序自己的 `gpin` 事实，不新造分析）**：`digraph` 自己就把"无跨组入边"的组标成
`gpin == false` 再丢；探针按 `node.gid` / `node.gpin` 分类每一次释放：

* **被释放的 node 里 100% 落在 `gpin==0` 的组**（250k：243 702/243 702；1M：982 587/982 587；`gpin==1` 的 0 个）
  ⇒ "**整片独占死**"这件事在数据上**确实存在**，只是编译器没有它的静态证明。
* 按**扫过槽数**口径：每次清扫释放的槽 / 扫过的槽 = **0.232（250k）/ 0.216（1M）**
  ⇒ 若这些结构住进自己的区域并被整区丢弃，**本区每次清扫要扫的槽数减少约 22%**（外推见 §5）。

## 4. 每区固定开销（实测，这是分区的**主要代价**）

在**同一份发射出来的运行期**上跑 `K` 个区域、每个只放 1 个 node 尺寸对象：

```text
K=1     slabs=1      rss_delta_kb=28       per_region_slabs=1.00 per_region_rss_kb=28.00
K=10    slabs=10     rss_delta_kb=284      per_region_slabs=1.00 per_region_rss_kb=28.40
K=100   slabs=100    rss_delta_kb=2536     per_region_slabs=1.00 per_region_rss_kb=25.36
K=1000  slabs=1000   rss_delta_kb=25148    per_region_slabs=1.00 per_region_rss_kb=25.15
K=5000  slabs=5000   rss_delta_kb=125492   per_region_slabs=1.00 per_region_rss_kb=25.10
K=20000 slabs=20000  rss_delta_kb=501644   per_region_slabs=1.00 per_region_rss_kb=25.08
```

⇒ **每个区域固定 = 1 块 1 MiB slab + ≈25 KB RSS**（线性到 2 万个区域；`slab` 是按
`EXTC_RC_SLAB_BITS=20` 对齐的整块分配，区域里放不满也照占一块）。
⇒ **摊薄条件（可判定）**：区域的活跃槽数要 ≥ 半个 slab 的容量才不浪费一半 ——
80 B 尺寸类 ≥ **6 553 槽**、32 B 尺寸类 ≥ **16 384 槽**。node 尺寸类放 1–6 个对象的"每组一个区"
比这个门槛小三个数量级。

## 5. 投影公式与"实测 / 外推"清单

**外推公式**（只用上面这些**实测**结构量与 `task-21` 的**实测**单次停顿）：

```text
今天的单次清扫停顿      P_now  ≈ (每槽扫描成本 × slots_scan) + (每对象成本 × freed)     [成本项待安静窗口实测]
按批分区后              P_proj ≈ 每槽扫描成本 × slots_scan × (1 − dead_share) + 整区丢弃成本(O(slab))
其中 dead_share（实测） = 0.232 @250k / 0.216 @1M
⇒ 单次停顿的**结构下界**是 P_now 的 ≈77–78%（−22%），不是数量级下降
```

**必须成立什么（可判定条件）**：
1. **粒度必须是"批/生命期"，不能是"每组一个区"**：后者的区域尺寸（3–6 槽）比摊薄门槛（6 553 槽）
   小三个数量级 ⇒ 每区白占 1 MiB slab + 25 KB。按 250k 的活对象数（占用中位 21 891、均值
   14.5 对象/组 ⇒ ≈1 510 个活组）算，per-group 区域要多 ≈1 510 × 25 KB ≈ **38 MB**（1M 上限档
   ≈185 MB）—— 相对今天 `digraph` @250k 的 3.2 MB 是数量级恶化（**这是外推，公式如上**）。
2. **同时活跃区域数 ≤ `EXTC_RC_REG_MAX = 512`**（实现上限；超了不登记 ⇒ 只泄漏到帧结束）。
3. **区域里的结构必须能被整区丢弃**（今天的机制是 `regionDrop` 按帧/层发；专属层要能在"这一批
   死了"那一刻发）—— 是否拿得到这一刻，正是 `task-20` 要证的；今天的①判据在 digraph 上**没有**
   给出任何这样的点（§2）。

**已实测**：§1–§4 的每个数、`dead_share`、组/分量尺寸、每区固定开销、`①调用点=0`。
**未量（等安静窗口）**：每槽扫描成本、每对象 `freeSlot` 成本、`regionDrop` 成本、`collect` 的
mark 相耗时、逐次停顿分布（p50/p90/p99/max）、以及按上面公式算出的 `P_proj` 分布。

## 6. 支持 / 反对分区（各带数或写"未量"）

**支持**：
* 被释放的对象**成片死**：均值 14.5 对象/分量（含边），100% 的 node 落在 `gpin==0` 的独占死组里 ⇒
  ①想抓的"结构"在数据上真实存在；
* 每次清扫的**扫过槽数**里有 21.6–23.2% 是当场释放的 ⇒ 分区后本区扫描面直接少这一块（外推 −22%）；
* 每批尺寸（12–21k 槽）**超过摊薄门槛**（6 553 槽）⇒ "按批一个区"在 slab 粒度上可行；
* 释放侧从"每对象一次 `freeSlot`"变成"每区一次 `regionDrop`"（代价项待实测，结构上是 O(slab)）。

**反对 / 代价**：
* **今天的①在 digraph 上零覆盖**（0 调用点 / `releases=0`）⇒ 要靠①的现有证明直接落地，收益是 0；
  必须把"独占死"的证明**扩到 gpin 这类运行期事实**（那就是新分析，需要另立任务）；
* **每区 1 MiB slab + ≈25 KB RSS**；"每组一个区"在此粒度上不可行（38–185 MB 外推）；
* `EXTC_RC_REG_MAX = 512` 的区域注册上限：同时活跃区域数一旦超了，超出部分不登记 ⇒ 只泄漏；
* 局部修正开销（已死结构被别的活对象引用时的登记/撤销）**未量**；
* 分区后 `digraph` 的**清扫次数不变**（146→156 那次是触发相位，见 README §11.6）⇒ 收益只来自
  单次变便宜，不来自变少。

## 7. 时长半：`collect` 两相 + 逐次分布（实测；pin md5 `180e74b9…`，`taskset -c 6`，10 次运行）

量法：`tools/rc-sweep-census.py` 的**只量时长模式**（`EXTC_SWEEP_TIME=1`）—— 除两次
`clock_gettime(CLOCK_MONOTONIC)` 外**一次扫描都不多做**（结构量模式会多扫一遍位图，实测把
`sweep_ns` 抬高约 20%，所以两者分开跑）。分位是"一次运行内所有清扫/标记"的分位，取 10 次运行的**中位**。

| 规模 | `sweep` p50 | p90 | p99 | max | `sweep` 合计 | `mark` p50 | `mark` 合计 | `collect` 合计 | 墙钟 | **`collect` 占墙钟** |
|---|---|---|---|---|---|---|---|---|---|---|
| 250k | **60.5 µs** | 71.0 µs | 143.1 µs | 143.1 µs | 2.65 ms | **140.4 µs** | 5.19 ms | **7.84 ms** | 47.2–48.8 ms（中位 47.9）| **≈16.4%** |
| 1M | **42.8 µs** | 160.0 µs | 263.2 µs | 346.3 µs | 12.16 ms | **127.9 µs** | 42.16 ms | **54.32 ms** | 493.6–501.0 ms（中位 497）| **≈10.9%** |

**两个相分开看，对判定的意义完全不同**：

* `collect` 里 **`mark` 是更大的那一半**（250k 5.19 vs 2.65 ms；1M 42.2 vs 12.2 ms）——
  而**分区只作用于 `sweep`**（`mark` 走的是活对象，死结构本来就不被标）。
* 每次清扫的**扫过槽数**（实测）：250k 恒定 67 707；1M 中位 67 707（尾段 159 439）。
  ⇒ 有效"每槽扫描成本" ≈ `sweep_ns / slots_scan`：250k ≈ 0.89 ns/槽、1M ≈ 0.61 ns/槽
  （含 `freeSlot` 的每对象代价，是**有效均值**不是拟合常数；`slots_scan` 与 `freed` 在真实
  轨迹里共线，二元回归不稳，不做常数外推）。

## 8. 合成实验：**"每批一个专属区域 + 整区丢弃"今天更慢**（手工构造，不是编译器生成的形状）

`tools/rc-batch-region-exp.c` + `tools/rc-batch-region-exp.sh`：照 §1 的实测组成手工构造
（每批 4 874 个 80 B + 10 840 个 32 B；常驻活集 1 614 个；50 轮），四个变体只在"怎么回收"上不同：

| 变体 | 做什么 | p50/轮 | 50 轮合计 | 峰值 RSS | minor page faults |
|---|---|---|---|---|---|
| **A（今天）** | 共用一个区域：每轮 `collect(区域, 活根)` | **≈220 µs** | ≈11.5 ms | 2.98 MB | **416** |
| **B（假设）** | 每批进自己的区域，死时 `regionFree` | **≈325 µs（+49%）** | ≈17.1 ms | 2.98 MB | **9 493** |
| C（对照） | 只分配、从不回收（区域无限涨） | ≈398 µs | ≈20.6 ms | 41.9 MB | — |
| D（对照） | 只做 `regionNew` + 2 块 slab + `regionFree` | **9.8 µs** | 0.53 ms | 2.09 MB | 517 |

**结论（实测）**：B 比 A 慢 **≈49%/轮**；而"新建/丢弃两块 slab 的 API 成本"（D）只有 **9.8 µs**
⇒ 慢的不是 slab 的建毁，是 **B 每轮都在冷内存上分配整批（9 493 vs 416 次缺页）**：
共用一个区域时槽是复用的（热页、空闲链），专属区域每批都要重新触碰 ~0.74 MB 的新页。
**⇒ 要让"按批分区"真的赢，前提是 `regionDrop` 的 slab 能回到按尺寸类的池子里复用（今天没有这个机制）**；
即便有了，省下的也只是 `sweep` 里属于死结构的那一块（≈22% × sweep）——@250k 约
**0.6 ms / 47.9 ms ≈ 1.3% 墙钟**；`mark`（≈10.8% 墙钟）不受分区影响。

## 9. `P_proj` 与一句话结论（**外推**，标注清楚）

```text
P_proj(sweep) ≈ P_now(sweep) × (1 − dead_share)          dead_share = 0.232 @250k / 0.216 @1M
墙钟收益      ≈ (sweep 占墙钟) × dead_share
              = 5.5% × 0.232 ≈ 1.3%   @250k（sweep 2.65 ms / 墙钟 47.9 ms）
              = 2.4% × 0.216 ≈ 0.5%   @1M  （sweep 12.16 ms / 墙钟 497 ms）
前提（今天都不成立）：
  ① 被分区管理的是"整片独占死"的结构（digraph 上①的静态证明 = 0 个点；gpin 是运行期事实）；
  ② slab 能复用（否则合成实验实测 −49%/轮，见 §8）；
  ③ 同时活跃区域数 ≤ EXTC_RC_REG_MAX=512。
```

**一句话（实测 vs 外推分开）**：**实测**——`digraph` 今天 `collect` 占墙钟 16.4%/10.9%，其中
`mark` 占三分之二、`sweep` 占三分之一；每次清扫扫过 67.7k 槽、其中 21.6–23.2% 是当场释放的、
且被释放的 node **100%** 落在程序自己判为"独占死"（`gpin==0`）的组里；**①的静态证明在 digraph
上 0 个点**；手工合成"每批专属区域"反而 **+49%/轮**（冷内存缺页），除非 slab 池化。
**外推**——若 ① 的替代路线成立且 slab 可复用，`digraph` 的墙钟收益上限约 **1.3%（250k）/ 0.5%（1M）**，
因为分区只吃掉 `sweep` 里那一块；"每组一个区"已判不可行（+38 MB@250k，见 §5）。
