# 硬件脏位 / 页粒度观测：真实价格勘察（`PAGE-DIRTY-RECON`，只勘察；`src/` 零改动）

全部在 `/tmp/pagedirty/` 的副本与独立小 C 程序里做。口径：`digraph` 与 `cyclic_pressure` @N=100000；
**关诊断 stderr 0 字节**、程序自身 **stdout 与默认档逐字节一致** ✓、`src/` 零改动 ✓。
计时授权：`taskset -c 6`、5 次中位、**跑前 load 记录在 §2**。

## 0. 一句话结论

**内核通道可用且便宜，但"页"这个粒度在我们的形状上太粗 ⇒ 负结果**，被**层 1** 挡住：
`digraph` 每周期脏页 **153** 个，但脏页上**实际住着 8 287 个占用槽**（实测 **54.2 槽/脏页**），
而同一周期 `mark` 只走 **≈5 991 个活槽** ⇒ **脏页重扫 = 活集扫描的 1.38 倍**（判据要求 ≤20%，
**超 6.9 倍**）；`cyclic_pressure` 更极端：**100% 的占用槽都落在脏页上**（重扫 ≈ 整堆）。
层 2 的 soft-dirty 通道本身没问题（粒度 4 KiB 精确、成本 ≈22 µs/周期 ≈ p50 的 13%），
所以挡住这条路的**不是内核接口，而是粒度**。

## 1. 层 1：结构量（`/tmp/pagedirty/pd.py` 只插生成物副本）

每次 ref 存储取 `slot>>12`（页）/`slot>>9`（512 B 块），**按周期去重**。`digraph` @100k（19 个周期）：

| 量 | p50 | max |
|---|---|---|
| 每周期**不同脏页数** | **153** | 153（19 个周期都在 152–153）|
| 每周期**不同脏块数**（512 B）| 1 204 | 1 204 |
| 区域占用槽总数 | 21 850 | 21 856 |
| **mark 每周期走到的活槽位** | **5 991** | 6 163 |
| **脏页上的占用槽位**（= 重扫脏页要摸的槽）| **8 287** | 8 299 |
| **每脏页槽位数**（实测，不是估算）| **54.2** | — |
| 脏页重扫 / 活集扫描 | **1.38×** ✗ | — |

`cyclic_pressure` @100k（4 个周期）：脏页 262/354/…、**脏页上的占用槽 = 全部占用槽**
（26 057 / 49 335 ⇒ 91–99.9 槽/脏页）⇒ **重扫脏页 ≈ 重扫整堆**，相对活集（25 545 / 41 205）**≈1.0–1.2×** ✗。

**判据对照**（要 ≤ 活集扫描的 20%）：`digraph` 实测 **138%**、`cp` **~100–120%** ⇒ **超 5–7 倍** ✗。

**附带口径提醒**：按"死对象**自身**所在页"数，只有 **114 849 / 303 199 ≈ 38%** 的死对象落在本周期脏页上
⇒ **脏页只能当"找变更"的旁路，不能替代标记**（这条与 `task-22` 的"清扫面"结论一致）。

## 2. 层 2：内核 soft-dirty / pagemap 的真伪与成本（独立小 C，`/tmp/pagedirty/pd_kernel.c`）

| 检查 | 结果 |
|---|---|
| soft-dirty 是否可用 | **可用**：mmap 2 200 页、只写每 7 页（315 页）⇒ 报告 soft-dirty = **315**（精确，无假阳）|
| 清除 | 写 `/proc/self/clear_refs` 的 `4` ⇒ 再扫 = **0** ✓ |
| 扫描成本（pread pagemap + 计数）| **≈5.7 ns/页**（2 200 页：pread+计数 ≈12.5 µs；其中计数循环 ≈0.36 ns/页）|
| 清除成本 | **≈9.5–10 µs/次**（固定开销）|
| **每周期总账** | 2 200 页 ≈ **22 µs**；我们的 1M `digraph` 峰值 RSS 8.7 MB ≈ 2 200 页 ⇒ **≈22 µs/周期** |
| 与停顿 p50（172 µs）比 | **≈12.8%** ✓（但**随堆页数线性增长**，不随活集走）|
| pagemap 权限 | **PFN 位被清零**（pfn0=2 200）⇒ 只读得到 present/soft-dirty，读不到物理页号（对脏位够用）|
| THP | `transparent_hugepage/enabled = [madvise]`、`AnonHugePages: 0 kB` ⇒ **未使用大页**，粒度仍是 4 KiB ✓（两个相隔 3 MiB 的写都被独立置位）|
| 堆是否连续 | **不连续**：`/proc/self/maps` 里 rw 匿名/堆区段多个（小程序 5 段）⇒ 集成时需要枚举 maps |
| 跑前 load | **0.90**（`taskset -c 6`，5 次取中位）|

## 3. 层 3：未做（如实记）

层 3（真程序里"内核 soft-dirty 计数"与"层 1 插桩计数"交叉验证）**未做**：层 1 已经用同一份插桩
把"页粒度能不能省"判负（1.38× > 20%），交叉验证不再影响结论。**未查清**：soft-dirty 在内存回收/
迁移下被内核自行清位的情形（本机无内核文档、未做压力场景）。

## 4. 判据与裁决（先写死的那条）

判据：层 1 **≤ 活集扫描的 20%**、层 2 成本 ≪ p50 172 µs、层 3 两来源吻合 ⇒ 值得往下设计。
实测：**层 1 = 138%（digraph）/ ~100–120%（cp）** ✗；层 2 = 22 µs（≈13% p50）✓；层 3 未做。
⇒ **负结果，挡门 = "页数太多 / 粒度太粗"（层 1）**；**内核通道本身没问题**（层 2 通过），
THP **不是**挡门（未使用大页）。若将来堆布局变成"活对象密集、页内几乎全是活对象"，
这条路的账才会翻过来 —— 那是布局改动，不是观测机制改动。

## 5. 未覆盖 / 残留风险

* **未做**：层 3 交叉验证；`mprotect`/缺页式观测（另一种无屏障通道）的代价；把 soft-dirty 接到运行期的集成。
* **未查清**：soft-dirty 在回收/迁移下被清位的实际影响（只按文献风险记录）。
* **残留风险**：层 1 的"脏页槽位"是**按周期去重的并集**，没有区分"写几次"；`cp` 只有 4 个周期，
  分布样本薄；结论只覆盖这两个形状。
