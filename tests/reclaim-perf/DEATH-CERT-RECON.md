# 运行时死亡证明：可行性勘察（`DEATH-CERT-RECON`，只勘察；`src/` 零改动）

口径：`build/extc` md5 **`e4c3a86960149e2d89dc22b9c1ebdef0`**；探针只插**生成物副本**（`/tmp/deathcert/dc.py` →
`/tmp/deathcert/dg.cnt.dc`），`EXTC_RC_NOCOUNT=0` **在编译期**给编译器（生成物里就是
`#define EXTC_RC_NOCOUNT 0`，即"计数 + 提前回收"档）。形状 `digraph` @ **N=100000**（19 次 `collect`、
引用存储 **11 528 460** 次）。**未跑计时**（本件判据全是结构量）；`src/` 与工作树零改动 ✓。

**定义（照抄任务书，未自由发挥）**：虚拟根 r，根引用算 r 的出边；`d(v)` = 精确总入度（含根边）；
扫 S 内出边得 `d_S(v)`；`e_S(v) = d(v) − d_S(v)`；`B = {v ∈ S : e_S(v) > 0}`；
`A = Reach_{G[S]}(B)`（**从 B 出发沿 S 内出边**的可达集）；`D_S = S \ A`。
方向：外部入边**只许高估**（`hold` 饱和即高估方向 ✓）。证明用"路径最后一次离开 S"的口径 ✓。

## 0. 一句话结论

**机制本身成立且验证很便宜，但"账本"不成立、信息代价超标 ⇒ 这条路当前不可行**，被挡在
**③ 信息代价**（以及它前面的"现有 `hold` 账本被系统性高估"）这一条上：
用**理想账本**（精确入度）时，抽样死分量里 **99.95% 的对象可被证死**（70 678 / 70 714），
验证工作量 **≈2.86 次访问/被证死对象**、且 **S 外零遍历** ✓；但用**现成的 `hold` 账本**时
**覆盖率 = 0**（3.39 MB 抽样死字节一个也没证出），根因是
**单区域档下 `rsIncN == 0` ⇒ `freeSlot` 不走 `unlinkChildren`，被清扫放掉的对象的出边
从不去减它们目标的 `hold`** ⇒ `hold` 单调膨胀：**303 199 / 303 199 个死者 `hold` 都严格大于
精确入度**（超额合计 5 014 370，均 +16.5）⇒ `B = S ⇒ A = S ⇒ D_S = ∅`。
要修账本就得在**每次边消失**时减计数（含 `freeSlot` 无条件 `unlinkChildren`），而"旧值非空"的
引用变化占**总存储的 96.6%**（11 133 198 / 11 528 460）⇒ **③ 的 ≤5% 线上差 ~20 倍** ✗。
