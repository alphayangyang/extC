# 类型模型：值、引用、复合

Status: **design**（2026-11-04）。这是提案，尚未实施；实施顺序进[待做清单](TODO.md)。

一句话：**存储的所有权只有一种（place），类型的形态只有三类（值、引用、复合），运行期多态只有一种载体。**

本文只回答"一个值是什么形状、它能不能拥有存储、它失效时听谁的"。存储本身住哪儿（帧、板块、对象表）在[内存模型](MEMORY-MODEL.md)；区域的释放规则在[回收机制与待做](RECLAMATION.md)。

## 一、三类

| 类 | 例子 | 有字节吗 | 指向别处吗 | 能拥有存储吗 | 赋值时发生什么 |
|---|---|---|---|---|---|
| **值** | `i64`、`f64`、`bool`、`u8`、`fn(...)` 指针 | 是，几个字节 | 否 | 否 | 位拷贝 |
| **引用** | `ref T`、`mut ref T`、`?ref T`、`slice<T>`、`ndview<T>`、槽句柄 | 是一个"从哪儿开始"的坐标 | **是** | 否 | 复制坐标 |
| **复合** | `struct`、`enum`、定长数组、闭包、`any` | 是，若干字段 | 看字段 | 默认拥有（`@noCopy` 则不可拷） | 逐字段拷贝，或禁止 |

三条判据，以后分类只看它们：

- 它是不是"别人的东西的坐标"？是 → **引用**。
- 它是不是"一串有字段的数据"？是 → **复合**。
- 都不是 → **值**。

`impl` 挂在任何一类上都可以（标量可以有方法，视图可以有方法，复合当然可以）。方法归属不改变类型属于哪一类。

**为什么是三类而不是两类或四类。** 这三类是三个正交问题的答案：有没有自己的字节、是不是指着别处、有没有字段与方法。两类合成不了（把引用并进复合，就要给"没有字段的复合"单开特例）；四类没必要——"句柄"看着像第四类，其实是**引用 + 世代号**，"视图"是**引用 + 长度或形状**，都落在已有的引用规则里。

## 二、`slice` 就是"引用 + 长度"

这一条把半页规则消掉了：

| 看起来是新东西 | 实际是 |
|---|---|
| `slice<T>` | 引用 + 长度 |
| `ndview<T>` | 引用 + 形状与步长 |
| 槽句柄（`pool`/`dyn` 那种） | 引用 + 世代号 |

由此直接得到三条，不用再单独规定：

1. **视图不拥有存储**，所以"要不要一份自己的字节"只有一个判断：`view()` 是看，`snapshot()` 是拿一份自己的。二者不是一个类型的两种模式，是两种不同的东西。
2. **视图失效 = 引用失效**，只有一条寿命规则：引用不能比它指着的 place 活得久。提前归还（显式收缩、重置）不是编译期能完全证明的，所以由运行期的"冻结位"把它变成确定性错误，而不是静默读到旧字节。
3. **池不是第五种身份，是一类 place**。槽表 + 世代 + 板块只是"提供存储并按代作废"的地方；句柄只是引用它的一种坐标。所以"池应该是用户能写的库"在类型模型里是成立的：它不新增类型形态，只新增一个 place 供应商。

## 三、载体：`any` 是复合，且 `dyn` 与它同一表示

`any` 是一个复合类型，字段是"一个描述符指针 + 一份载荷"：载荷 ≤ 8 字节时内联在值里，超过就放在区域的一块存储里。装箱即快照——**载体拥有它的载荷**，所以它从不参与寿命检查、不需要冻结位、也不会悬垂。

`dyn Trait` 是同一种表示，只是描述符换了一种视图：

| | 描述符里放什么 | 怎么调用 | 每次开销 |
|---|---|---|---|
| `dyn Trait`（名义） | 该 trait 的方法槽 | 一次间接：`描述符 → 槽 → 函数` | 原型 0.89 ns，语言实现约 1.5 ns |
| `any`（结构） | 全类型描述符：字段表 + 名字到槽的映射 | 具体类型已知时直接调用；按名字时才查表 | 候选 ≤8：0.69 ns（热循环常被内联）；12 / 40 个候选：2.0 / 4.0 ns |

于是"动态"只有一个入口、两种看法：**名义视图**保证"这个值一定实现了某组方法"，**结构视图**允许"调用任何同名方法，不存在就 trap"。给一个类型登记方法只发生在一处；`any` 不再是一种独立的生命周期，它只是"一个带描述符的复合值"。

成本预算（同一台机器，钉核、`-O2`、多轮取最小）：

| 操作 | 每次 |
|---|---|
| 装箱 + 拆箱（载荷 ≤ 8 字节，内联） | 0.59 ns |
| 装箱 16 字节结构体（走区域） | 5.4 ns |
| 动态派发（候选 ≤8） | 0.69–0.9 ns，被内联时更低 |
| 动态派发（12 / 40 个候选，排序表 + 二分） | 2.0 / 4.0 ns |
| 静态调用 | ≈ 0（内联） |

装箱那 5.4 ns 里大头是分配与缺页：一千万次装箱就是 160 MB，全部留在区域里直到块退出。所以**热循环里不要反复装箱**；要更进一步就得让箱子有死亡时间，那是引用计数的活，不在当前范围内。

## 四、两条跨类规则

整套模型只有这两条规则，其余都是推论。

**规则一：引用不能比它指着的 place 活得久。** 编译期用深度检查证明大部分情况；证明不了的（提前把存储还回去）在运行期用冻结位变成确定性错误。**错的方向永远是"trap"，不是"静默读旧字节"。**

**规则二：复合默认按值拷贝；`@noCopy` 的复合不能被拷贝，只能借或移动。** 移动 = 位搬 + 源位置标死。这条今天还缺，缺它的后果很具体：把一个字符串重新赋值（`s = s + t`）会留下旧存储当垃圾、并且是 O(n²) 的时间——而同样的形状在 C++ 里是一次移动赋值。

由此得到每个语法位置发生什么：

| 写法 | 值 | 引用 | 复合（默认可拷） | `@noCopy` 复合 |
|---|---|---|---|---|
| `var x = e` | 位拷贝 | 复制坐标，受规则一约束 | 逐字段拷贝（或移动临时量） | 移动（源不再是 place） |
| 传参 | 位拷贝 | 复制坐标 | 逐字段拷贝，或按签名借出 | 只能借：`ref`/`mut ref` |
| 返回 | 位拷贝 | 只能返回比函数活的 | 逐字段拷贝 | 移动 |
| 字段赋值 | 位拷贝 | 复制坐标 | 逐字段拷贝，旧值不留痕迹 | 移动 |
| 放进载体（`any`/`dyn`） | 装箱 | 装箱（载荷是坐标时，深挖成快照） | 装箱即快照 | 装箱即快照 |

最后一行是模型里唯一"静默复制"的地方，所以它单独有预算（上一节的表）和一条纪律：**热循环里别装箱**。

## 五、性能与元数据预算

面向对象不等于每处都多一层。四条硬规则，缺一条就会被"元数据膨胀"反噬：

1. **多态住在包装器里，不住在对象里。** 复合值的布局里没有虚表指针；多态只发生在 16 字节的载体上。所以"这个类型没有被子类化/装箱"时，为它付的元数据是 **0 字节**。
2. **描述符按需存在。** 一个类型只有在被装箱、被打印、被比较、被序列化、或通过载体被调用时，才需要描述符；其余类型不发射任何元数据。这是"存在"与"不存在"的区别，不是"多一点少一点"。
3. **静态派发永远优先且零成本**：具体类型上的方法调用就是一次直接调用，内联后归零。只有接收者本身是载体时才走描述符。
4. **装箱有上限**：≤8 字节内联、不分配；超过就进区域，代价就是一行的 5.4 ns。不允许"为了动态性而给每个值加头"。

## 六、现有特性归位

| 现有 | 属于 | 动作 |
|---|---|---|
| `vector` / `varArray` | 复合（字段含引用） | 二合一，一个名字，另一个当实现细节 |
| `hashMap` / `linmap` / `map` | 复合 | 对外一个家族，元素少时自动走线性 |
| `string` / `stringio` | 复合 | 合并，缓冲写入口只留一处 |
| `json` 的两套 | 复合 + 载体遍历 | 解析与输出保留两种用途，删重复的字段遍历 |
| `pool`、槽句柄、`@poolObject` | place 供应商 + 引用 | 池变纯库；句柄归入引用；取消编译器对"哪个类型拥有池"的硬编码 |
| 引用计数层 | —— | 删除：没有所有权图就不需要它 |
| `dyn` 与 `any` 两套派发 | 一个载体、两种视图 | 描述符合一张表，派发共用一条路径 |
| 闭包、函数指针 | 复合 / 值 | 不新增类型形态，符合现状 |
| 元素引用 `ref v[i]` | 引用 | 归入引用类，按 place 的寿命检查 |
| 定长数组、枚举 | 复合 | 不新增 `impl [N]T`：数组的方法走视图 |

## 七、三处待拍板

1. **载体的所有权**：装箱时一律"拥有 + 快照"（安全、简单、每次 5.4 ns），还是允许"载体里放引用"（便宜，但要和规则一重新对齐）。建议一律拥有，把借用留在 `ref`/视图里。
2. **定长数组与枚举算不算复合**：建议算，因此数组不能自我引用，方法挂在视图上。
3. **标量能不能有方法**：建议能（统一、便宜，实现已有），否则"给 `i64` 加一个工具方法"就得靠自由函数。

## 八、判断"该不该加"的五问

任何新特性先过这五问，答不上来就不加：

1. **它属于哪一类？** 答"哪类都不属于"＝ 不加。
2. **它能写成库吗？** 能，就不进编译器（池、哈希表、序列化都属这类）。
3. **它的失效规则与规则一、规则二冲突吗？** 冲突就改现有规则，不许再开第三条。
4. **热路径上它加几次间接、几个字节？** 答不出数字就不加。
5. **它的答案和现有的哪个重复？** 重复就先合并，再加。

## 十、三句话

1. **形态只有三类**：值是字节、引用是坐标、复合是字段；视图与句柄都是引用。
2. **所有权只有一处**：place 拥有存储，引用只借，载体只快照。
3. **多态只有一个入口**：装着描述符的复合值；对象布局里没有虚表。
