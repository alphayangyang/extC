# clang -Weverything 允许关闭的类别 —— 理由逐条写在 docs/WARNINGS.md §3.1
# 规矩：只有「对生成物结构上无解」的类别能进这里
#      「只是还没做」的（unused-function / unused-variable / used-but-marked-unused /
#       unreachable-code / jump-misses-init / missing-noreturn）**不许**加进来
dollar-in-identifier-extension
reserved-identifier
padded
declaration-after-statement
tentative-definition-compat
unsafe-buffer-usage
cast-align
switch-default
comma
# clang 自己的可达性分析：不在 -Wall 里，官方明说会有误报；实测它把预置文本里
# `case EXTC_D_F32: printf(...); return;` 的 return 报成"永远不会执行"，而那个 return 明显可达
unreachable-code
unreachable-code-return
# 警告原文是 "jump ... is incompatible with C++"：生成物是 C11，epilogue 用 goto __extc_ret
# 统一出口（跳过的都是非 VLA 的初始化）；这条是给"C 代码也想交给 C++ 编译器"准备的
jump-misses-init
# 语言的 `==` 作用于 f64 就是 IEEE 相等；clang 建议的"用 epsilon"会**改变语义**（NaN、-0.0 的行为都变）
# 生成物里出现它的地方只有结构相等的运行时（`extc_eq` 的 F32/F64 两支）
float-equal
# extC 的 `ref T` 在生成的 C 里就是 `T *`（语言里没有 const），而描述符把操作数作为 `const void *` 交出来；
# 用户的 `==` 若按 `ref` 取参，适配器就必须丢掉 const 才能调用它（改成"先拷进局部"能免掉，但每个适配器多一行）
cast-qual
# `{0}` 对"首成员是枚举"的聚合体就是 C 的惯用零初始化；clang 这条是说它在 C++ 里非法（生成物是 C11）。
# 改写成"点名第一个变体"能消掉它，但实测会让 tour 的 board 初始化膨胀成嵌套复合字面量：
#   多 492 字节代码，而且更难读 —— 与"少生成、好读"的方向相反，所以进清单
implicit-int-enum-cast
