## 2026-12-01 · 块级归还接到 mutator 路径：空块在轮末就还，不再等 settle

**症状。** 11-30 的页级归还只把「块内的空页」还给 OS；块本身（512 KiB 的 slab）仍只在 `extc_rc_settle` 里被摘掉，而 `extc_rc_settle` 只有 `extc_rc_collect` 走。真实程序的分配触发路径是 `extc_rc_alloc` → `extc_rc_maybeCollect` → `extc_rc_sweepStep`，从不经过 settle ⇒ 一个从不显式 collect 的程序会把峰值时的整块容量钉在堆上，页归还只能把每块缩到「含活对象的页」。自动路径探针 `/tmp/pg/pages6.c`（64 MB 峰值、零 root、之后 140 万次分配、只调 `extc_rc_maybeCollect`）在改动前：slabs 64 → 64、`slabRel=0`、RSS 43,788 kB 不降。

**结构。** `src/back/reclaim.c`：①删除 `ExtcRcRegion.shrinkDue` 字段与三处使用（`sweepBegin` 清零、`sweepStep` 置位、`settle` 消费）——「轮末就是归还点」之后这个标志没有语义；②`extc_rc_sweepStep` 收尾分支把置位换成调用：`extc_rc_slabShrink(r)`（3915）+ `extc_rc_fqDrainAuto()`（3916）+ 原有的 `extc_rc_pageTrimStep(...)`（3917），三者都在同一个被计时的步内 ⇒ 归还成本进 `[step]`/`[histo]` 的停顿分布；③新宏 `EXTC_RC_SHRINK_MIN_SLACK (8 << 20)` 与 `extc_rc_slabShrink` 体首早退 `if (r->capBytes - (int64_t)r->bytes < (int64_t)EXTC_RC_SHRINK_MIN_SLACK) return 0;   /* skip:shrink-slack */`（1900）；④`capBytes` 的累加/递减从 `#if EXTC_RC_PAGE_TRIM` 移出改无条件（885 / 1929）——`PAGE_TRIM=0` 时它恒为 0，slack 闸门会把块归还永久拦住。

为什么只能在轮末：清扫游标可能停在链上任意一块，摘块的前提是游标已清空，所以摘链固定在收尾分支；`settle` 不再摘块。为什么要有 slack 闸门：容量只比占用多一点时，摘块换来的是「munmap 512 KiB → 之后重新 carve」，抖动会赢；8 MiB 是容量界上抬的常数。全在冷路径，**不引入写屏障**。
