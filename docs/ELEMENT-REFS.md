# 元素引用（对容器里的东西取引用）

这份文档回答一个问题：**库里的容器能不能把手里的元素"借"给调用方，而不是拷一份出去。**
答案分三步：先给稳定存储上的元素引用（不用新概念），再给可增长容器一个显式的借用区间，
把"长寿命别名"留到最后、用世代号兜底。明确不做的是 Rust 式借用检查 —— 这门语言允许别名，
视图是窗口而不是快照。

## 缺的是什么

语言对"看内容"这件事已经有两套说法：帧里的存储能借出视图（`slice<T>`，拷贝为零），拥有
身份的存储用句柄访问（`dyn`、值池的槽）。两套都缺一角：

- **视图借不到容器里。** 想让调用方直接读容器，唯一的路是拷一份出来；在循环里拷、又只读一遍，
  代价是"每次拷贝都活到函数退出"—— 二十万轮约 52 MB，随轮数线性涨。
- **句柄绕不开间接。** 读-改-写一条记录要两次探测加一次整值进出拷贝。四个 workload 的横评里，
  唯一落后的那一项（回收轴，约 8%）差的正是这个：C++ 的下标返回引用，一次探测、零拷贝。

所以缺的不是能力，而是**一条"这个位置里的东西，地址是稳的"的说法**。

## 为什么现在取不到

对位置取引用只接受有稳定地址、且被名字或指针点名的表达式：变量、字段、解引用。下标不在其中 ——
被检查过的下标访问交出的是值。根本原因是**可增长容器的存储会搬家**：扩容要向池原地加长，
装不下时由分配器换一块更大的；静态上没有东西能证明"我手里这个地址在下次扩容后还成立"。

## 三条设计（按落地成本排序）

### 一、稳定存储上的元素引用

对"地址在生命周期内不会变"的存储，直接允许 `ref v[i]` 与 `mut ref v[i]`：定长数组、帧里
`new` 出来的切片、以及它们的视图。引用的有效期跟视图同一条规则 —— 不超过存储所在的位置，
位置退出即失效，越界与越活越界都是编译错误。

这条不需要新概念：只是放宽"对哪些位置可以取引用"，深度取自存储的所有者。收益是"拷出去、
改一改、写回来"这一大类形状直接消失。

### 二、可增长容器的借用区间

可增长容器要借元素，就得把"借的这段时间里不换存储"说出来。写法是显式区间：

```
borrow v as e {
    ...  e 可以读、可以按元素写（若声明为 mut） ...
}
```

区间内**这个名字**只能用只读的方式（另一个视图、只读方法），任何可能换存储的动作都是编译错误；
出区间引用失效。这是名字级的语法约束，不需要别名分析，因此能落在一个没有借用检查的语言里。
区间可以只读（`borrow v as e`）也可以可写（`borrow mut v as e`），后者禁止区间外同时用同一个名字。

### 三、世代校验的元素引用

要给"长寿命别名"留一条路，就让引用自带容器的存储世代号：扩容、缩容、清空、释放都换一代，
解引用时一条比较，对不上就是**响亮 trap**（带位置的诊断），而不是静默读写野内存。

代价是每次访问一条检查；这与语言里已有的下标越界检查同一品味。它不该是默认写法，只该在
"确实要存下这个引用、又不想拷一份"的地方用。

## 失效规则（三条共同的合同）

| 借自 | 什么时候失效 | 谁保证 |
|---|---|---|
| 定长数组、帧里 `new` 的切片 | 所在位置退出 | 静态（深度检查） |
| 可增长容器（借用区间） | 出区间 | 静态（作用域 + 名字级只读约束） |
| 可增长容器（世代引用） | 容器换存储的动作 | 动态（世代比较，失配即 trap） |

别名照旧允许：两个 `mut ref` 可以指向同一个元素 —— 与语言其它部分一致。并发不因此变松：
`par` 里"每个 worker 只写自己那一格"的规则仍在，元素引用不提供任何跨线程的许可。

## 落地顺序与判据

1. **稳定存储的元素引用。** 放宽位置文法 + 深度取自存储所有者；诊断"这个位置没有稳定地址"
   （例如对容器直接取引用时提示改用借用区间）。判据：定长数组、帧内切片、它们的视图上能取读写
   引用并且改得回去；位置退出后再用是编译错误；既有回归不降；ASan 一格干净。
2. **借用区间。** 文法 + 名字级只读约束 + "区间内换存储"的拒绝。判据：区间内读、区间内按元素写、
   区间内 `push` 必须被拒、区间外恢复正常。
3. **世代引用。** 只在有真实需求时做；判据是"扩容后再解引用必须 trap，而不是读到旧内容"，
   并量出它相对拷贝的收益。

## 现在的进度

第一步（稳定存储）已经落地：定长数组 `[N]T` 的元素是位置，`ref a[i]` / `mut ref a[i]` 可用，
越界在取引用处报错或 trap，跨帧返回仍是编译错误。视图的元素与可增长容器的元素继续拒绝，诊断
会说明存储可能搬家。

接下来按同一份判据往前走：本帧 `new T[n]` 得到的切片与视图（存储同样不搬家），然后是借用
区间、再然后是世代校验的形态。
