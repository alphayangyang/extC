# 注释规范（Doxygen）

适用：`src/`（C）· `stdlib/`（extC）· `tools/`（Python docstring）· `tests/`。

## 一条铁律：注释只写"现在是什么"

注释里**不许**出现下面这些（把它们写在围栏里，是为了让闸门跳过本节的引例）：

```
历史与变更：  以前 · 原来 · 曾经 · 回退 · 一开始 · 那次 · 一度
决策编号：    定案 <N> · PLAN #<N>
实测史：      实测过 · 实测出 · 量过 · 测过
对旧实现的评价：旧版是错的 · 这样更干净
```

**历史只进 [`CHANGELOG.md`](CHANGELOG.md)。** 验收里有闸门盯着这一类词。

## 只讲身边这段代码

注释是给**读这段代码的人**看的，不是导航：

- **不写跨文件的位置引用**（"见 `foo.c:123`"、"这个函数在 `bar.c` 里被调用"）——别的文件会动，引用跟着烂。
  同一份文件内指路可以，但要说清名字，不要写行号。
- **不写"为什么当初这么改"**——那是历史。
- **不写变更记录**（`/* 2026-10-09: 修了 X */`）。要记，进 [`CHANGELOG.md`](CHANGELOG.md)。

## 格式：说明 · 参数 · 返回值 · 使用例

写在**声明处**（头文件里的原型，或函数定义前）。**函数体内只留不显然的不变量**，不做叙事。

```c
/**
 * @brief 一句话说清它做什么（动词开头，一个句子）。
 *
 * 需要时补一段：前置条件、不变量、复杂度。**不写为什么当初这么改。**
 *
 * @param rid  参数名 + 它是什么、合法范围。
 * @param n    每个参数一行，跟声明顺序一致。
 * @return     返回值是什么、什么时候失败。**`void` 不写 `@return`。**
 *
 * @code
 *   // 使用例：能跑的最小片段
 * @endcode
 */
```

extC 用**同一形状**（`/** ... */` + `@brief` / `@param` / `@return` / `@code`），两种语言的注释可以互相照抄。

## 使用例是**判据**，不是散文

- extC 的 `@code` 块必须**能编译并运行**；C 的至少过一遍 `cc -fsyntax-only`。
- 验收里有闸门检查活文档里的示例；**宁可不写例子，也不要写一个没被检查过的例子**——没闸门的例子会先烂。

## 不该有的注释

- 复述代码表面的注释（`i = i + 1  /* 自增 i */`）。
- 被注释掉的代码。删掉——git 里有。
