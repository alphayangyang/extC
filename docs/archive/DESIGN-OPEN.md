## 0. 工作约定（踩出来的，先照做）

* **一轮只开一个母题**；
* 判据先行；**先 `make` 再看结果**；**rc 不要过管道**（`cmd | head; echo $?` 拿到的是 `head` 的）；
* **AST 冻结**：分析结论进 `plan` 侧表（`planSet*`），AST 节点只能由解析器写；
* 产物指纹基准在 `tools/codegen-baseline-*.sha256`（改动后逐份比对并**逐条解释**变化）；
* **判据不是质量依据**（覆盖率不可知）——质量看"改这段代码安不安全"；
* **子代理干活效果好**：给它自包含施工单 + 要求它**自己核实事实** + 报告里列出不确定。

## 1. 母题 1：可见性 vs 书写负担（语义有多少要写进名字/类型）

### 1.1 大对象用哪种语义（当下最关心的）

问题：`string` / `varArray` / `hashMap` 这些**大对象**该值语义还是句柄语义？

**关键区分**：**不可变的**大对象能"看起来像值、用起来像值"（共享**不可观测** ⇒ O(1) 共享且无歧义）；
**可变的**大对象不行（共享 ⇒ 不是值；深拷 ⇒ 隐藏 O(n) + 隐藏分配）。

| 类型 | 建议 | 理由 |
|---|---|---|
| **`string`** | **不可变值语义** + 显式 **`StringBuilder`** | O(1) 共享、无隐藏分配、直觉正确 |
| **`varArray` / `hashMap`** | **句柄语义，但共享必须显式**（`var b = a` ⇒ 报错，要求 `.clone()` / `.share()`）| 可变 ⇒ 只能二选一 ⇒ 让**选择可见** |
| 小 struct（`point`、配置…）| 纯值语义（现状）| 便宜、无歧义 |
| `view<T>` / `ref T` | 别名（拼写可见）| — |

**两阶段迁移**（低风险）：① 先**只加 `StringBuilder` + 写规则**（纯新增，不动 `string`）→ ② 再迁调用点、最后把 `string` 定成不可变。

**搁置（2026-10-09）**：ⓐ `string` 改不可变 / ⓑ 可变容器"共享必须显式" / ⓒ 只写文档规则——**三选一暂不做决定**，作者要再想。

> ⚠️ **搁置 ≠ 忘记**：本节是这件事的唯一记录，**不要再开新文档讨论它**。下次从这里接着想。

### 1.2 `slice<T>` 的拼写（"别名要能从拼写看出来"）

`slice<T>` 是**拼写成值的引用**——STL 的混乱多由它产生（容器内脏是它、`sub()` 返回它）。
**建议改名 `view<T>`**（零语义改动，面广）；`slice` 留给切片**操作**（`a[0..5]`）。

**已定（2026-10-09）：改，单独一个纯机械 commit。**

理由：零语义风险、token 级、越早越便宜（代码还在长）。
**不和语义改动混在一个 commit 里**（否则 review 不了）；顺序排在"两个真 bug"之后，避免大 diff 淹没小修复。

### 1.3 `mut` 权限模型

现状推论：**想写就回源头重新借** ⇒ 借了一百万次之后想写，得翻找源头并改一整条链。

| 方案 | 写法 | 保住 | 丢掉 |
|---|---|---|---|
| **A′（推荐）** 权限挂**根** | 就地 `var w: mut ref T = mut p`（编译器查**根**是否可变）| 签名可见性（看不见 `mut` ⇒ 写不了你的东西）| 一点点实现复杂度（要追踪视图的根——extC 的深度/逃逸分析本来就有）|
| **B′** 完全 C 化 | 指针默认可写 + `@readonly` opt-in | 最简单、最像 C | "看不见 `mut` ⇒ 写不了"这条可见性 |
| **C′** 现状 + 指路 | 仍改 N 处，但诊断直达 + `--suggest-mut` | 零语义风险 | 痛还在 |

**安全性论证（A′）**：它**不放松"能写什么"**（真正只读的根——`ref` 参数/`let` 根/`@frozen`——照样 `mut` 不了，**编译期拒**）；
放松的只是"**形式**"（不必一路写 `mut`）。丢的是可读性，不是内存安全——内存安全由逃逸/深度/place/世代保证。
**并发**：`mut` 位**从来不是**数据竞争防线（今天两线程各持 `mut ref` 也合法）⇒ 并发要给保证请用 **`@frozen` + `Thread` effects**（审计 R12/R13 同族）。

**已定（2026-10-09）：方向选 A′，但以判据为门槛。**

⚠️ **"健全性未验证"这条顾虑是对的，而且能指出具体位置**：A′ 把"能不能写"从「**类型里看得见**」挪到了
「**分析算得出来**」——也就是挪进了**判根**。而"分析有洞"在这个仓库有前科：2026-09-30 审计的 22 条 P0 里，
逃逸/深度分析的洞是重灾区（P0-1 借用经局部拷贝/结构体字面量/deref 拷贝洗白 · P0-2 调用点深度把 0 当未设置 ·
P0-5 · P0-16 · P0-17 · P0-6e）。

**门槛（三条，从便宜到贵）**：

1. **先建红判据**：一组"把只读根洗白成可写视图"的攻击形状（字段 / 局部拷贝 / 结构体字面量 / deref 拷贝 /
   函数返回 / 容器 / 协程）——**复用 [`tools/escape-corpus/`](../tools/escape-corpus/) + 逃逸闸门**，加 mut 洗白那一类。
   建不出红 ⇒ 今天没有这个洞；建出红 ⇒ 这就是 A′ 的规格。
2. **把规则写成类型判定**（纸上）：路径的权限怎么算、"根"怎么定义。**写不成判定 ⇒ 还没准备好实现。**
3. **差分裁判**：参考判定器 vs C 检查器。

⇒ **没有红判据之前不实现 A′。**

### 1.4 `!` / `@unchecked` 的收尾四问（修复已落地，只差这些）

| # | 问题 | 建议 |
|---|---|---|
| ① | `@unchecked` 是否也关掉：pool 死句柄 · parallel 输出长度 · 递归深度 · 用户 `trap()` · "未返回"兜底？| **全关，不做例外清单**（2026-10-09 作者**改判**，否决原先"保留这几类"的建议）|
| ② | **行为收紧**：不纯 `!` 走 hoist ⇒ `while f()! { }`、`g() + f()!` 被拒 | **要修**（语句表达式 `({t=f(); assert; t;})` 单次求值，或"每实例 unwrap 助手"）|
| ③ | `o! = v`（赋值目标）没有常设判据 | **补判据** |
| ④ | `tests/hostile/missym_call` 期望从 `rc=139` 改成 `trap:` | **接受**（新语义下 `!` 先 trap 是对的）|

**已定（2026-10-09）**——四条全定，① 按作者改判：

* **原则**：**`@unchecked` = 最开放的签字，后果用户承担**。一个标签的语义必须**确定**，不能带"这几类不关"的特权清单；
  **`!` = 语法糖，trap 是合理的**。
* **代价照实写进手册**：`@unchecked` 下**过期的池句柄会变成真 UAF**，而不是响亮的 trap。
* ② **要修，且一修两治**：`!` 的 hoist 同时造成「**无故拒绝**合法写法」（`while f()! {}`）与
  「**静默丢弃**」（`p.get(h)!.x = v` 编译通过、写没了）——后者违反"**不存在静默退化的路径**"。
* ③ 补 `o! = v` 判据。
* ⚠️ **一处实现边界（待作者确认）**：`trap()` 是**作者显式写下的动作**（只是借用检查机制）。
  本文按「**它照旧生效**」记录；若要连它一起关，需明说。

## 2. 母题 2：默认行为 + 显式逃生门（失败怎么走）

### 2.1 失败处理 S0–S4（已改判 + 经独立评审修订）

**已定案**：**不用 effects**（effects 写起来极贵，只给"既证明不了也处理不了"的边界）；
**放弃 longjmp / `recover`**（跳过块 arena 清理）。

**终局形态：隐式传播**

* 失败载体 = **纯值** `struct err { code: i64  file: slice<u8>  line: i64 }`
  （**不用 `dyn Err`**——评审指出：dyn 载荷绑当前 place 池 ⇒ 跨 zone 传播句柄会死；且 dyn 需要 `makesPool` 隐藏参数，而 `@export` 禁止隐藏参数）；
* 传播走**普通返回**（**不跳栈** ⇒ 每层块 arena/zone 清理照常）；
* **mayFail 进 `fn` 类型**，但**由编译器推断**（作者零负担——这是与 effects 的根本区别）；
* 处理点 `catch { e => … }` 或 `if let`；**未处理 ⇒ 到入口 trap**（带 `file:line`）。

**评审指出的两个硬点（必须先解决）**：

1. `?` **只在 4 个语句位置合法**（`examples/try-positions.extc`）⇒ 隐式传播要在**任意表达式位置**都能查通道（`while` 条件/短路/下标 ⇒ 要么语句化（危险），要么用语句表达式）；
2. **间接调用**（fn 指针 · `dyn` · 泛型实例）必须靠类型里的 mayFail 才能闭合（[`topics/C-ABI.md`](topics/C-ABI.md) 记着 fn 槽签名"拷到局部就丢"）。

**顺序**：S0（`!` 修好，已做）→ **S1 checked 原语** → S1b trap 统计（**改到编译器侧**：下标来源分析，产物正则测不到）→ S2 `if let` → S3 `?` 允许错误转换（**要显式声明**，不要隐式 blanket）→ **S4 隐式传播**（大，单独排期）。

**验收缺口（评审指出）**：golden 已降级为**观察** ⇒ 不能当判据；"B 类 trap = 0"是**下游改代码**的数字 ⇒ 补语言级判据（"含外部输入下标的示例不再 trap"）；S4 要补"**错误跨 zone 后 `message()` 仍可读**"。

**已定（2026-10-09）：先 S1 + S1b。**

理由：① S1 是**纯 stdlib 新增、零语言改动**，S4 最后定成什么样都不会让它作废；
② S1b 的**数字是 S4 设计的输入**（先知道有多少 trap 是输入相关可恢复的，才知道隐式传播要覆盖什么）；
③ S4 是唯一需要**设计定稿**的一件，**等数据再设计**比现在凭空设计好。
⇒ **S1/S1b 不是绕路，是 S4 的前置测量。**

### 2.2 已定案（不要重开）

* **null 保持 fatal**（安全代码本该写不出 null 解引用；`!` 现已是 trap；给 undefined 对**指针**不成立，且会把"证明被违反"变成静默错码）；
* `?ref` 的值出口清单：`??` · `?` · `if p != null`（**零运行期检查**）· `if let`（待做）· C 互操作 `dl::sym -> ?ref void`。
