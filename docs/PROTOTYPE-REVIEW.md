# 原型复核：`prototype-reclaim/` 里到底有没有「停顿」的现成方案

> **一句话结论：部分有 —— 但缺的正是"让停顿不随被扫活闭包增长"的那一半。**
> 原型给了把**单次停顿切小**的两条现成手段（**区域局部清扫**、**分片暂停旋钮**）和一条让停顿**归零**的条件方案
> （**无环时事件回收 ⇒ 清扫 0 次**，外加**自学习退场**）；它**没有**增量/分步（无预算、无继续点）、
> **没有**并发/后台、**没有**并发写屏障 —— 它自己的计时把整次 `collect` 都算作一次停顿（`prototype-reclaim/sim.c:389-408`），
> README 也明说"要微秒级停顿必须付屏障"（`prototype-reclaim/README.md:362`）。
> 对今天 `digraph` 那类**单一巨大活闭包**（WCC 1000‰，`bench/gc/PAUSE-CORPUS.md:40` 判"不适合切"），
> 原型的两条切分手段都不成立：今天实测 `EXTC_RC_SHARDS=4` 反而更差（p50 258.5 → 1950.5 µs，`bench/gc/DIGRAPH.md:557,562`）。

**这是只读复核**：没有改 `src/`、`tests/`，没有碰 `docs/CHANGELOG.md`；未跑新计时（任务说不需要），
§3.2 复用 `prototype-reclaim/run.sh` 在 2026-10-13 的落盘输出（1 样本）。
**本文件放哪**：新建 `docs/PROTOTYPE-REVIEW.md`（没有动 `docs/RECLAMATION.md` —— 它在别人的在途改动里）。

## 1. 原型是什么（用 `sim.c` 的实际代码说话）

`sim.c` 自己声明是三层拼接（`sim.c:1-6`）：第 1 段"**逐字**取自 extc 输出的 arena 运行时"（`sim.c:36-72`），
第 2 段是"提案要加的东西"（`sim.c:82-277`），第 3 段是"按 codegen 的样子手写的工作负载"（`sim.c:279-430`）。

### 1.1 分层

| 层 | 是什么 | 代码 |
|---|---|---|
| **区域** | 逻辑区域 = 块链；负载里是 `extc_arena __extc_a[4]`：`[1]` 桶区、`[2]` 解析区、`[3]` 索引区（`sim.c:323,335,351,363`）| `sim.c:41`（today 的 `extc_arena{top,spare}`）、`sim.c:91-92`（提案的 `PR{cur,all,freel,bytes,nblocks,nslabs}` × `NREG=4`）|
| **块** | (i) `base`：`extc_ablock` 打包多对象 + bump（`sim.c:40,69-71`），块按需倍增、上限 1 MiB（`sim.c:39,64`），`spare` 复用一块（`sim.c:46-47,61`）；(ii) `solo/ev`：`extc_pblock` **一块一对象**，块头带 `self`/`mark`/`rid`/`rsmark`/`vmark`/`td`（`sim.c:85-86`）| `sim.c:58-72`、`sim.c:94-116` |
| **对象** | 24–32 B 的 `node_hdr{key,val,next,nf}`（`sim.c:284-285`）；每类一张类型描述符 `extc_typedesc{nptr,off[2]}`（`sim.c:84`），`TD_NODE`/`TD_INODE` 在 `sim.c:289-290` | `sim.c:284-290` |
| **回收** | 见 1.3 | `sim.c:175-277` |

### 1.2 工作负载（决定所有停顿数字的形状）

64 桶 × 每桶 ≤8 的有界符号表（`sim.c:280-281`）+ 每轮解析 3 个临时节点（`sim.c:337-349`）+ 可选缓存槽
（`sim.c:358-359`）+ 可选 20 万项跨区索引链（`sim.c:361-370`）；淘汰尾节点就是"死一个对象"（`sim.c:373-381`）。
指针赋值同时维护持有者计数 `nf`（`storep`，`sim.c:298-303`，**饱和三点式**、饱和值当"不确定"，README:123-124 [文档]）。

### 1.3 回收算法（原型里一共这几条）

1. **整片区域释放**：`extc_arena_release` 逐个 `free` 块（`sim.c:43-53`）；slab 版把整链还空闲链（`sim.c:122-124`）。
2. **区域局部标记-清扫**：`extc_sweep` 从给定根标记，只清被扫区域（`sim.c:175-193`）；用**全局世代号**避免清别的区域的标记位（`sim.c:76,177`）；标记栈动态增长（`sim.c:74-80`）。
3. **全局标记-清扫对照**（`gc` 模式）：一次标两个区域、一起扫（`sim.c:196-218`）。
4. **记忆集播种的区域清扫**：跨区写时登记到"目标区域的入边集"（`sim.c:223-235`）；扫某区域时只从**本区域根 + 本区域入边集**出发，**碰到区外对象就停**（`sim.c:243-250`）；另有全根自检（`sim.c:254-261`）。
5. **事件回收**：淘汰尾节点时若持有者计数恰为 1，当场 O(1) 摘链释放（`sim.c:156-162,376-381`）。
6. **块转交 `extc_promote`**（`sim.c:164-172`）：提案里有，工作负载里没调用（`unused` 标注）。
7. **触发策略**：`垃圾 ≥ max(可达集, 256 KiB)`（`sim.c:282,382-388`）—— 触发量跟着**可达集**走，不跟占用走。

另外 `slab.c` / `slab_final.c` / `slab_shard.c` 是同一设计的位图 slab 版（元数据与载荷分开、每 slab 两张位图 + 登记位图 + 每槽持有计数，`slab_final.c:40,57,89`），并加了两件本复核关心的东西：
**分片**（`NSHARD`，`slab_shard.c:241,250,283-305`；`slab_final.c:167,204,300-324`）与**自学习退场**
（一次清扫一无所获就把该片阈值 ×4，`slab_final.c:169,304,319`）。

### 1.4 模式（`sim.c:313-315`，`run.sh:31` 只跑前四个）

`base`（今天生成物：打包块 + 整片释放）· `solo`（一块一对象，不回收）· `sweep`（+区域清扫）· `ev`（+事件回收）
· `sweepc`（只计数）· `gc`（全局标记-清除对照）· `rs`/`rsev`/`rsr`/`rsl`（记忆集 / +事件 / +空闲链复用 / 位图 slab）。

## 2. 逐项：原型有没有"让暂停不随活集增长"的东西

### (a) 增量/分步标记或清扫 —— **没有**
- **无预算、无继续点**：标记是 `while (MKN)` 一口气把工作栈跑空（`sim.c:181-185`；记忆集版 `sim.c:247-252`；全局版 `sim.c:203-207`）；
  清扫是一次链表遍历（`sim.c:186-189`、`sim.c:264-266`）。每次 collect 从 `MKN = 0` 重新开始（`sim.c:178,242`），
  **没有可恢复状态**。`prototype-reclaim/*.c` 全文 grep `budget|预算|限额|每步|step|resume|继续点|incremental` = **0 命中**。[源码]
- **分片 ≠ 分步**：分片是**空间切分**（一次只收一个分片，`slab_shard.c:283` 注释"本轮只收一个分片（可控停顿）"，
  `slab_final.c:307-324`），不是把一个分片的标记/清扫**摊到多次暂停**里。[源码]
- README 自己把"限制每次回收的块数（G1 的暂停预算 + 选区）"列为**没走的那条路**：`README.md:221` [文档]。

### (b) 写屏障/脏集 —— **有"存储时记一笔"，但不是并发/增量屏障**
- 有的部分：`storep` 每次指针写都增减持有者计数（`sim.c:298-303`）；`store_rs` 每次跨区写把**目标**登记进目标区域的入边集
  （`sim.c:232-235`），slab 版只登记 1 bit、释放槽时清掉（`slab_final.c:174-181`）。**这是货真价实的写时记账**，也是
  README 算"指针赋值约 0.11 ns/次"的那笔税（`README.md:674-675` [文档]）。
- 缺的部分：这些记账**只用于**（i）事件回收判据（`sim.c:379`：`was == 1`）与（ii）区域标记的**种子**
  （`sim.c:244`、`slab_final.c:224-227`）——**不是**三色/增量更新/SATB 屏障，也没有"脏集 = 下次要重标的目标"这层语义。
  标记每次仍从**完整根集 + 完整入边集**开始（`sim.c:243-244`）。[源码]
- 原型文档对这件事的定位很清楚：`README.md:362` [文档]"无屏障 ⇒ 吞吐与内存可以赢，但**停顿 ∝ 可达集**；要微秒级停顿必须付屏障"；
  `README.md:371-372` [文档]分片"不动语义、**不加屏障**"。
- **值多少（实测/文档）**：入边集在最不利场景只省 ~2×、停顿几乎不动（`README.md:217-219` [文档]）；
  "维护唯一性判据"的代价 = `sweepc` 与 `sweep` 的差值（`README.md:155-156` [文档]）。

### (c) 并发/后台线程 —— **没有**
- 三个原型目录的所有 `.c` 里没有 `pthread`/`atomic`/`thread`（grep 0 命中）；唯一的 "并发"字样是 README 在讲 Go
  （`README.md:361` [文档]）。[源码]
- 因此原型的"停顿"就是**单线程 stop-the-world 的整个 collect**（§3）。[源码]
- 对照组：今天的 extC 同样是"无并发、无写屏障"（`bench/gc/DIGRAPH.md:542` [文档]）。

### (d) 整块/区域一次性释放 —— **有**
- `extc_arena_release` 一整个块链顺序归还（`sim.c:43-53`），slab 版还空闲链（`sim.c:122-124`），
  解析区每轮整片释放（`sim.c:336`），函数退出 `extc_arena_destroy`（`sim.c:415-421`）。[源码]
- 这条是 `base`/`solo` 停顿=0 的**原因**：它们压根不回收（`sim.c:321` `dolive = g_mode >= 2`）。[源码]
- 对"停顿"的意义是**反面的**：它让"不回收"看起来很快，但内存无界（本次重跑：`base` N=4M 峰值 RSS 127 984 KiB，1 样本 [实测]）。

### (e) 静态证明"不必回收"（编译期裁剪）—— **原型没有编译期分析；只把"静态唯一性"当输入模拟**
- `sim.c:376-379` 的唯一性判定是**运行期**读计数：`was = cur->nf; ... if ((g_mode==4||7) && was == 1) extc_free_solo(...)`；
  README:687 [文档]直说："探针里由代码直接判（**模拟**静态唯一性证明）"。[源码+文档]
- 自动那半条是**动态**的：`slab_final.c:169,304,319` 的 `sweep_factor`——一次清扫一无所获就把该分片阈值 ×4
  （"学到这里没有环"），真收到东西则复位；README:547-548,569-571 [文档] 报"清扫次数固定 16、无环程序永不进清扫"。
  **这是经验退场，不是证明**。[源码]
- 结论：原型把"事件回收"的**机制位**占了（唯一持有者当场释放），但**没提供**判定它的编译期分析；
  编译器侧的静态裁剪是今天 `tests/reclaim-elide/` 那条线，不属于原型。

### (f) 暂停计量与 pacing —— **计量有（量整次 collect），pacing 是触发阈值、不是暂停预算**
- **量什么**：`pauses{max_ns,total_ns,n}` + `padd`（`sim.c:292-293`）。窗口是 `sim.c:389`（`a = now_ns()`）
  → `sim.c:408`（`padd(&P, now_ns()-a)`），**包住整个 collect**：建根表（`sim.c:390-393`）→ 标记 + 清扫
  （`sim.c:394-404`，含 `sweep_rs` 的 verify 段，若开 `VERIFY`）→ 写回触发量。打印在 `sim.c:426`
  （`最大停顿=P.max_ns/1000.0 µs`、`停顿总=P.total_ns/1e6 ms`）。[源码]
- **分相计时只在 `sweep_rs` 路径累加**（`sim.c:240-272` 的 `g_t_push/mark/verify/free/recount`），所以 `sweep`/`ev`
  两模式的"阶段ms"恒为 0.00（本次重跑输出可见 [实测]）。[源码]
- **pacing**：触发阈值 `垃圾 ≥ max(可达集, 256 KiB)`（`sim.c:282,382-388`），slab 版是内存压力
  `bytes > max(2×上次清扫后存活, 1 MiB/分片) × 自学习因子`（`slab_final.c:203,295-306`）。
  它决定**什么时候**扫，**没有任何东西**限制"这次扫多久"。[源码]
- 三条派生量都在同一份输出里：`slab.c:233,281-282`、`slab_shard.c:294-304`、`slab_final.c:308-323,332-334`
  （后者连 p50/p90/p99/max 分布都打了）。[源码]

## 3. 实测停顿是多少、量的是哪一段

### 3.1 原型侧：文档记录的（`prototype-reclaim/README.md`，**[文档]**，机器/时刻不明）
- 冷/热分离：`region` 最大停顿 **5.1 → 5.5 µs**，而冷数据从 468 KiB 涨到 30 000 KiB（**64×**）；同负载 `global` 一直
  **9 968–14 652 µs**（`README.md:50-56`）。原因写明"全局回收每次都要从根遍历全部存活对象"（`README.md:57-58`）。
- 真实负载（40 万轮）：`region` 47.3 µs / 5.48 ms 总，`region+ev` **2.6 µs / 0.20 ms**，`global` 147.3 µs / 20.68 ms（`README.md:68-73`）；
  200 万轮 `region+ev` **4.4 µs** vs `global` 459.2 µs（`README.md:77-80`）。
- 手写生成物（40 万轮）：`base`/`solo` 0（不回收），`sweep` 147 µs / 3.13 ms，`ev` **0 / 0**（`README.md:101-104`）；
  400 万轮 `sweep` 283 µs / 31.6 ms、`ev` 0（`README.md:108-112`）。
- 最不利矩阵（含真全局 GC 对照）：`ev` 单次停顿 **14.8 ms**（大索引）、**23.6 ms**（对象 512 B）；
  同场景 `gc` 70.5 / 84.1 ms（`README.md:166-176`）⇒ 文档自己承认"'微秒级停顿'在这个场景下**不成立**"（`README.md:181-182`）。
- 分片旋钮（最不利，50 万轮）：1 834.6 → **143.3 µs**（分片 32）、200 万轮档 2 552 → **168 µs**（分片 16）
  （`README.md:377-384,388-392`）；README:399 总结"分片把最不利停顿从 2.55 ms 压到 168 µs（15×），**全程零屏障**"。
- 停顿分布（压力版，200 万轮）：分片 8/16/32 的 p50 = **354.8 / 163.9 / 82.5 µs**，max 564.0 / 293.4 / 290.5 µs（`README.md:604-608`）。
- 规模行为（8 分片，存活 100 万→800 万）：最大停顿 **382.8 → 425.5 → 397.6 → 367.8 µs**，README:569 [文档] 称"**停顿也不随 N 增长**"。

### 3.4 能不能同口径比
- **能比的部分**：两边量的都是"**一次完整 collect 的墙钟**"（原型 `sim.c:389-408`；今天 `DIGRAPH.md:542`），
  且两边都是**单线程 STW、无并发、无屏障**。所以"停顿与什么成正比"这条**标度关系**可以直接对照：
  原型 `README.md:362` [文档] 说"停顿 ∝ 可达集"，今天 `MARK-MODEL.md:29,187` [实测] 说"停顿 ≈ 13–14 ns × 活闭包" —— **同一条定律**。
- **不能直接比的部分**：负载不同（原型的 64 桶符号表 vs `digraph` 的 14 077 节点 / 22 万条边）、实现不同
  （`sim.c` 是 malloc-per-object 的手写模拟，`README.md:684`；今天是位图 slab + 生成的 C），
  Go 那 11 µs 更是**不同口径**（并发标记不在 STW 里，`DIGRAPH.md:543`）。
  ⇒ **绝对值不可直接比；比例/方向可以。** ✗ 拿"原型 143.3 µs"去减"今天 1950.5 µs"没有意义。

## 4. 一句话回答用户

**原型"部分有"方案，但缺的正是决定 Go 那 11 µs 的两项。**
- **有（值多少）**：① **整片区域释放** —— 让"本地区域"的回收 O(1)（`sim.c:43-53,122-124`），代价是内存（本机今天重跑：`base` 4M 轮峰值 RSS 127 984 KiB [实测]）；
  ② **区域局部清扫** —— 停顿只 ∝ 被扫区域的**可达集**，不随别的区域/堆大小走：冷数据 ×64，停顿 5.1→5.7 µs（`README.md:50-56` [文档]，本机今天 5.1→5.7 µs [实测]）；
  ③ **分片** —— 停顿的显式旋钮，最不利 2 552 → 168 µs（15×，`README.md:388-399` [文档]），且"不入边集一起分就会触底"（`README.md:403` [文档]）；
  ④ **事件回收 + 自学习退场** —— 无环程序**清扫 0 次 ⇒ 停顿 0**（`sim.c:376-381`、`slab_final.c:169,304,319`；本机今天 `sim ev` 0 清扫/0 停顿 [实测]）。
- **没有（缺的正是哪几项）**：⑤ 增量/分步（无预算、无继续点，(a)）；⑥ 并发/后台线程 ((c))；⑦ 并发/增量写屏障 ((b) 的并发那一半)。
  原型自己的文档把这两件事说死了：`README.md:362` "要微秒级停顿必须付屏障"、`README.md:221` 把 G1 式"暂停预算 + 选区"列为**未采用**。
- **对今天的目标形状（`digraph`）更弱**：它是对外那两条切分手段都不成立的一格 —— **单一巨大活闭包**（WCC 1000‰，`PAUSE-CORPUS.md:40`），
  今天实测分片反而把 p50 从 258.5 µs 推到 1950.5 µs（`DIGRAPH.md:557,562`）。
  ⇒ **要打 Go 的 11 µs，原型里没有现成的路；现有两条（区域清扫、分片）今天已经落地了**（分片旋钮 = `src/main.c:348` 的
  `EXTC_RC_SHARDS`；默认回收档 = 无计数、只靠清扫，`src/back/codegen.c:10095-10110`），**而且在这格无效。**
  真正缺的是 (a)+(c)（以及支撑 (c) 的屏障 (b)）——这与 `MARK-MODEL.md:187` 的结论一致。[推理，但有源码+实测支撑]

## 5. 补充：`prototype-heap/`、`prototype-python/`

- **`prototype-heap/`**（`prototype-heap/README.md:1-31`）答的是**另一件事**：4 GiB 连续板 + `mmap`/`mprotect` 借出 + `dlopen` 插件的边界检查。
  **与 GC 停顿无关**：里面唯一的"暂停级"数字是 `mprotect` 固定代价 **369 / 376 µs**（64 MiB），
  且它按**区间大小**走、会引起别的线程 TLB 抖动（`prototype-heap/README.md:16,30`）——这是零拷贝借出的代价，不是回收停顿。
  ⇒ 对"停顿"问题**没有可借的方案**。[文档]
- **`prototype-python/`**（`prototype-python/README.md:1-13`）是**作废的第一版编译器草稿**，自己写明"不要再往这里加功能"。
  ⇒ **没有任何**回收/停顿设计。[文档]
