# 核心：六条不许破的决定

extC 现在有 61,366 行 C、31 个标准库模块、544 个公开成员。这个规模不是问题本身：问题是**同一件事
有几种答案**（可增长序列三种、映射三种、输出四种、并行两种、生命周期五种）。这一页写下不许破的
决定，和"什么不算核心"。下面的数字都是实测，口径见[体量收敛](TRIM.md)。

## 一、六条决定

| # | 决定 | 为什么不许破 |
|---|---|---|
| 1 | **值、引用、载体**三类，只有两条跨类规则：引用不得比它的地方长寿；复合默认按值拷贝，`@noCopy` 只能借或移动。 | 这两条是全部安全性论证的前提。多一条规则就多一处"检查器要认识某个库"的特例。 |
| 2 | **语义绑标签，不绑类型名**：`@noCopy`/`@value`/`@drop`/`@place`/`@buffer`/`@frozen`。编译器里没有 `if (名字 == "string")`。 | 按名字派发让"用户写不出编译器写的东西"，也让新类型永远二等。 |
| 3 | **块是唯一的批量回收边界**：离开块整片归还；增长型容器自带板块、换缓冲时当场归还。 | 没有 `free`、没有追踪回收器、没有逐对象释放。上界是"程序文本的函数"，不是运行时猜测。 |
| 4 | **回收是编译期决定**：静态证明成立的函数不发射回收代码；真实业务三形状的产物与关闭回收逐字节相同。 | 这是论文的核心主张，也是"没有收集器"这句话的全部内容。 |
| 5 | **每个需求一个答案**。新增一种"同一件事的第二种写法"必须先删掉一种。 | 决策点数量是复杂度的真正度量；糖越多，诊断与文档越难保持一致。 |
| 6 | **安全不 UB 优先于性能，性能优先于心智模型**：证明不了的用确定性 trap（越界、陈旧 `dyn`、冻结缓冲），绝不静默读旧字节或静默继续。 | 静默错误比崩溃贵得多；而能静态免费的绝不放到运行期。 |

## 二、预算表

| 项 | 现在 | 上限 | 说明 |
|---|---|---|---|
| 标准库模块 | 31 | 20 | 合并原则见 [TRIM](TRIM.md)：一组"同一件事"最多留一个模块 |
| 公开成员 | 411 | 300 | `@private` 才是默认；公开面每加一个要有判据 |
| 编译器 C 代码 | 61,366 行 | 55,000 | 删机制（计数层、池特权）应让它变小 |
| 关键字 | 32 | 30 | 软关键字不算，硬关键字只减不增 |
| 内建函数 | 40+ | 40 | 池原语、`any` 原语都算；能下沉到库的下沉 |
| 每个需求的答案数 | 2–4 | 1 | 可增长序列、映射、JSON、输出、并行各是一组 |

预算不是"以后再说"：**任何新增都要先指出这一项被哪个删除抵消**。

## 三、什么不算核心

以下都是**允许不存在**的东西，所以它们不能反过来要求核心为它们让步：

- 反射、运行期类型构造、动态 arity 的可调用值（只有 `Fn0/Fn1/Fn2` 分档）。
- 变参（真要就给编译期检查的格式串，不给运行期打包）。
- 宏系统、插件、用户自解析 AST（改语义的糖必须进编译器；其余走预处理器）。
- 重载 `=`（`=` 是语句；覆盖语义由 `drop`/`clone` 钩子定制）。
- Rust 式借用检查、`unsafe`、逐对象 `free`。
- 多线程本身的**语法**（第一版不给用户可见的线程；`par` 的 fork-join 够用）。
  多线程**回收**不是这一类：它暂缓，但规则已经被现有模型决定了 —— 对象在哪块 arena 就由
  哪块 arena 回收，而"引用不过线程"让每块 arena 只被一个线程碰，于是收集器不需要跨线程
  同步。见 [`PARALLEL.md`](PARALLEL.md) 的"线程与回收"一节。

## 四、判断"该不该加"的五个问题

按顺序问，任何一个是"是"就要重新设计：

1. 它是不是**已有答案的另一种写法**？
2. 它会不会让检查器认识某个具体的库类型？
3. 它能不能用已有的标签 + 库写出来？
4. 它的失败模式是"编译错误/确定性 trap"，还是"看运气"？
5. 它会不会让预算表的某一项变差而没有对应的删除？

## 五、三句话

**安全靠静态证明与确定性 trap，不靠运行期猜测。语义挂在标签上，不挂在名字上。一个需求只留一个答案。**
