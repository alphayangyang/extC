# 起步：构建 · 测试 · 验收 · 编译器用法

面向要写 extC 的人。需要数字时跑 `make status` 现取，**不要把通过/失败数抄进文档**。

## 1. 依赖

| 要做什么 | 需要 |
|---|---|
| `make` | `make`、C 编译器（变量 `CC`，默认 `gcc`）、`find`、`mkdir` |
| `./tests/run.sh` · `./check.sh quick` | 另需 `python3`（并行器与闸门脚本） |
| `./check.sh`（完整模式） | 基准脚本另用 `g++`、`rustc`、`go` |

C 编译器不是只给测试用：`--run` / `--build` / `--check-c` 都调用它，可用环境变量 `$CC` 换成 `clang` 等。

## 2. 构建

| 命令 | 做什么 | 产物 |
|---|---|---|
| `make` | 默认目标 `all`，只构建编译器 | `build/extc` |
| `make test` | 构建后跑 `./tests/run.sh` | — |
| `make status` | 跑 `./tests/run.sh` 与 `./check.sh quick`，再报未 push 的 commit 数 | `build/status-tests.log`、`build/status-check.log` |
| `make clean` | 删掉整个 `build/` | — |

产物位置：

- 编译器二进制：`build/extc`。
- 目标文件：`build/obj/`，按源码的子目录分目录（`build/obj/front/`、`build/obj/back/` …）。
- `stdlib/prelude.extc` 被嵌进编译器：先生成 `build/prelude_data.c`，再和其余目标文件一起链接。

`./tests/run.sh` 自己开头会先跑一次 `make -s`，所以直接跑它也会构建。

## 3. 常用命令

| 命令 | 内容 |
|---|---|
| `./build/extc <file.extc>` | 只生成 C，写到 stdout |
| `./build/extc --run <file.extc>` | 生成 C、编译、运行 |
| `./tests/run.sh` | 回归：正例 / 反例 / trap 三套 + arena、警告、ASan、注解套件 |
| `./check.sh quick` | `./tests/run.sh` + 一批闸门 + 各子系统套件；不跑基准 |
| `./check.sh` | quick 的全部，另加全语料 `--check-c`、正例生成物 ASan+UBSan、生成物快照、全部基准 |

通过标准：`./tests/run.sh`、`./check.sh quick`、`./check.sh` 都以末行 `通过 N，失败 0` 报告，并且退出码为 0 当且仅当失败数为 0。

## 4. 编译器用法

用法：`./build/extc [options] <file.extc>`。

**全部开关见 [`flags.md`](flags.md)** —— 那一页由编译器自己的 `--help` 生成，不一致时验收会红。
下面是几条最常用的：

| 选项 | 作用 |
|---|---|
| `-o <file>` | 生成的 C 写到这个文件（默认写到 stdout） |
| `--run` / `--build` | 生成 → 编译；`--run` 再运行它 |
| `--check-c` | 生成后做一次 `-fsyntax-only` |
| `-O0` … `-O3` · `-march=native` | 传给 C 编译器的优化与移植开关 |
| `-I` · `-L` · `-l` · `--ccflag` · `--pkg-config` | 模块搜索与链接 |
| `-w` · `--dump-tokens` · `--dump-effects` · `--no-line-map` | 警告与中间产物 |

退出码：成功 `0` · 程序编不过 `1` · 命令行本身错 `2` · `--run` 返回被运行程序的退出码。

## 5. 三条最小用法

先写一个文件 `hello.extc`：

```extc
use std::io

fn main() -> i32 {
    io::cout << "hello, extC\n"
    return 0
}
```

**只生成 C**：

```console
$ ./build/extc hello.extc | head -4
/* Generated by the extC compiler -- do not edit by hand.
 * The generated C is deliberately boring: no macro tricks, no clever optimizations.
 * `#line` directives map the C compiler's errors back to the .extc source lines.
 */
```

`| head -4` 只是截断展示（生成的 C 有几百行）；要落盘用 `./build/extc -o hello.c hello.extc`。默认生成的 C 带 `#line` 指回源码行，`--no-line-map` 可关掉。

**只编译，不运行**：

```console
$ ./build/extc --build -o hello hello.extc
$ echo $?
0
```

`-o hello` 给出二进制路径；生成的 C 仍在 `build/hello.c`。不给 `-o` 时二进制是 `build/hello`。

**生成、编译并运行**：

```console
$ ./build/extc --run hello.extc
hello, extC
```

产物落在 `build/hello.c` 与 `build/hello`；被运行程序的退出码就是 `extc` 的退出码。

## 6. 链接开关怎么用

`extern!` 只声明符号，库要由链接开关给。准备两个文件：

```c
/* helper.c */
int helper_answer(void) { return 42; }
```

```extc
/* link.extc */
extern!("helper") fn helper_answer() -> i32

fn main() -> i32 {
    return helper_answer() - 42
}
```

```console
$ ./build/extc --run --ccflag helper.c link.extc      # 把 C 源文件直接编进这次链接
$ echo $?
0
$ cc -shared -fPIC -o libhelper.so helper.c           # 或者先做成共享库
$ ./build/extc --build -L . -l helper -o link link.extc
$ echo $?
0
```

不给 `-l helper` 时链接失败（`undefined reference to helper_answer`，退出码 1），所以 flag 是承重的。同理 `--pkg-config zlib` 会替 `-l z` 与 zlib 的头文件开关。

## 7. 验收体系

### 7.1 `./tests/run.sh`

按顺序：

| 顺序 | 内容 | 判据 |
|---|---|---|
| 1 | `make -s` | 构建失败整体失败 |
| 2 | `python3 tools/parrun.py`：`examples/*.extc`（正例）· `tests/errors/*.extc`（反例）· `tests/traps/*.extc`（运行时反例） | 正例要编译并跑对；反例必须被编译期挡住；运行时反例必须真的 trap 且带源码位置 |
| 3 | `tests/arena/run.sh` | 按块细化，150MB 上限下内存不许涨 |
| 4 | `tests/warnings/run.sh` | 该响的警告要响、正例语料零误报、`-w` 能关 |
| 5 | `tests/asan/run.sh` | 内存安全形状在 ASan 下跑得干净 |
| 6 | `tests/annot/run.sh` | `@inline` / `@unchecked` 真的生效，写错的编译期报错 |

### 7.2 `./check.sh quick`

先构建，跑 `./tests/run.sh`，再跑下列各类；任何一节失败都让整体变红：

| 类别 | 内容 |
|---|---|
| 闸门 | 规模（任何输入都要给结论，不许崩也不许挂）、逃逸健全性、实例接线、差分（extC 与等价 C 结论一致） |
| 断言版全量 | `EXTC_DBG=1 ./tests/run.sh`：断言与兜底一旦被走到就 abort |
| 子系统套件 | arena · 警告 · 泛型 · impl · dyn · 协程 · IO · extern · 链接开关 · `@frozen` · C-ABI · 攻击 `.so` · 契约验证 · 包工具 · 哈希/UUID · JSON · `f"…"` · WebSocket · Base64 · 事件循环 · `@noCopy` · 运算符重载 · 构造函数 · 模块 · ASan · 池 · 哈希表 · STL · 线性容器 · 文件 · 命令行参数 … |
| 元闸门 | 手册文体与覆盖 · 驱动开关页与 `--help` 一致 · 公开面清单 · `stdlib/INDEX` · 类型分支穷尽性 · AST 冻结 · 只读边界 · include guard · 并发守卫 … |
| 攻击库 | 通过集合与 `tests/attacks/BASELINE` 逐行对比，多一条少一条都算红 |

### 7.3 `./check.sh`（完整模式）另含什么

| 额外内容 | 说明 |
|---|---|
| 全语料 `--check-c` | `tools/gate_checkc.py --scope full`：全部正例生成物过 gcc 与 clang 的 `-c -O2` |
| 正例生成物 ASan+UBSan | `tools/gate_asan_corpus.py --scope full`：真跑，不是只编译 |
| 生成物快照 | `tools/golden.sh`：观察项，与冻结哈希的差异不作为判据，判据只有「必须是合法 C」 |
| 基准 | `bench/run.sh`（extC vs C）· `bench/heavy/` · `bench/dyn/*` · `bench/stl/` · `bench/app/` · `bench/stress/` · `bench/compile/` · `bench/oi/` · `bench/oi/persist/` |

### 7.4 数字从哪来

`make status` 依次打印三行：`tests/run.sh` 的末行与退出码、`./check.sh quick` 的末行与退出码、未 push 的 commit 数。两条命令的完整输出落进 `build/status-tests.log` 与 `build/status-check.log`。数字由命令产生，本文不写死。
