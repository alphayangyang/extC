# 编译器内部结构

这一页讲**编译器现在是怎么组织的**，给要改它的人看。

## 流水线

一次编译按固定顺序走五步：

| 步骤 | 做什么 |
|---|---|
| **词法** | 源码变成 token 表 |
| **解析** | token 变成抽象语法树（递归下降） |
| **模块加载** | 按 `use` 把用到的模块读进来，解析限定名、去重 |
| **检查** | 名字解析、类型推断、借用与逃逸检查，并把分析结论写进"编译计划" |
| **代码生成** | 按编译计划发射 C 源码文本 |

prelude 是**嵌进编译器二进制**的：构建时由一个小工具把它的源码转成一份 C 数组，编译器启动即拥有它，
不需要外部文件。

## 分层与职责

源码按依赖方向分层，越靠下越不知道上面的事：

| 层 | 管什么 |
|---|---|
| **基础设施** | arena（按作用域分配、整块回收）、可增长缓冲、向量、诊断输出、计时 |
| **前端** | 词法器与解析器：把文本变成语法树 |
| **语法树** | 节点的数据形状。只描述语法，**不存分析结论** |
| **类型表** | 类型的驻留、相等判定、渲染、内建类型 |
| **编译计划** | 代码生成**唯一**的读取口：分析阶段产出的东西放这里 |
| **检查器** | 类型检查与借用检查；它写编译计划 |
| **后端** | 代码生成、模块重命名与链接、协程、池与板、域、prelude 嵌入 |

层与层之间的方向由闸门看住：上层可以依赖下层，反过来不行。

## 一条硬规矩：语法树是冻结的

**语法树节点只由解析器写。** 分析阶段（类型、借用、逃逸、代码生成的准备工作）得到的任何结论
都写进**编译计划**的侧表，代码生成只通过编译计划提供的读取口看它们。

这条规矩让"谁在什么时候写什么"变得可判定：一旦分析结论混进语法树，就很难说清某个字段在某个时刻是否已经算好。
验收里有两个闸门盯着它：一个看语法树不再新增分析字段，一个看代码生成不绕过编译计划直接读分析状态。

## 代码生成不做决定

代码生成的契约是**装配**，不是判断：它不推断类型、不查名字、不决定谁存在。

**"谁存在"由需求闭包决定**：先扫一遍这一份编译单元真正缺什么（声明了哪些外部原语、用了哪些内建、
有没有容器要池、有没有协程），然后再发射对应的运行期代码与辅助函数。没被需要的部分根本不进产物。

于是同一份生成物里只会出现"先全发一遍再删掉"，不会夹带没人用的东西。

## 生成物长什么样

- **单个编译单元**：一次编译只产出一份 C，多模块也一样（模块被重命名后合成到一起）。
- **所有内部函数是 `static`**，不留跨单元符号。
- **每一段 C 前面有 `#line` 指回源码行**，于是 C 编译器的报错直接落在 `.extc` 的行号上。
  这个映射可以用 `--no-line-map` 关掉。
- 产物是**给人读的**：不用宏技巧，不做花哨优化。

## 验收体系

**测试套件**覆盖各个语言面：示例、反例（必须编不过）、trap（必须带位置地失败），
以及泛型、模块、池、协程、注解、运算符重载等专题套件。`tests/run.sh` 把它们跑一遍。

**闸门**是另一层，挡的是"测试全绿但不代表没坏"的那些情况：

| 闸门 | 挡什么 |
|---|---|
| 全语料生成物必须能编过 | 生成物是非法 C，或有可疑告警（gcc 与 clang 各一遍） |
| 正例生成物跑 sanitizer | 生成物有未定义行为却"看起来正常" |
| 差分 fuzz | 静默算错：extC 与等价 C 的结论必须一致 |
| 规模与嵌套 | 编译器自己被深嵌套或大输入搞崩、搞挂 |
| 逃逸健全性 | 该被拒绝的借用与逃逸形状必须被拒绝（语料必须"编不过"） |
| 语法树冻结 | 分析结论不许回流进语法树；代码生成不许绕过编译计划 |
| 层序 | 上层依赖下层可以，反过来不行 |

**闸门用棘轮**：每个已知问题都必须登记在它的"已知坏"基线里，而基线里已经不再出现的条目会让闸门**变红**。
所以基线只许变短——修好一条就得从基线里删掉那一条，否则闸门会提醒你。

套件与闸门由 `check.sh` 组织：`quick` 跑快的那批，完整模式另外包含基准（需要 C++ 与 Rust 工具链）。
耗时的那部分走并行执行器，输出按提交顺序回放，保证与串行结果一致。

## 构建产物

| 产物 | 是什么 |
|---|---|
| `build/extc` | 编译器本体（只依赖 C11 标准库） |
| `build/obj/` | 目标文件树，按源码子目录分层 |
| `build/prelude_data.c` | prelude 源码转成的 C 数组，链接进编译器 |

构建带自动头文件依赖，改头文件会重编所有受影响的目标文件。**不要去掉它**：否则会得到新旧 ABI 混在一起的产物，
症状看起来像代码 bug。
