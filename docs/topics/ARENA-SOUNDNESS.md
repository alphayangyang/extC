## 1. 形式模型（照抄 `ARENA-FORMAL.md` §1，但把**实现真正用的抽象**写准）

### 1.1 区域与层号

- **区域** = 一次 `extc_arena` 实例。生成 C 里每个函数一个 `extc_arena __extc_a[maxLv+1]`，
  `__extc_a[k]`（`k ≥ 1`）就是"第 k 层词法块"的区域（`codegen.c:2118`）；
  `maxLv = 1 + blkMaxOfBlock(f->body)`（`codegen.c:2108`）。
- **区域树**：`__extc_a[k]` 的父是 `__extc_a[k-1]`（"父子平行块链"是**物理**上是分开的链表，
  但**寿命**上严格嵌套：出第 k 层块一定在第 k-1 层块之内）。
- **回收**：
  - 出第 k 层块 ⇒ `extc_arena_release(&__extc_a[k])`（`codegen.c:1748`，进块时也防御性清一次 `:1745`）；
  - `break`/`continue` 下沉到循环层（`codegen.c:1917-1923`）；
  - **函数任何出口**统一放掉 `1..maxLv` 全部层（`codegen.c:2182-2191` 的 `__extc_ret:` 标签）。
- **家区域**：`needsHome` 的函数多收一只 `extc_arena *__extc_home`（`codegen.c:2012-2023`），
  调用点由检查器算好传哪只（`Expr.arenaArg`：`ARENA_HOME` ⇒ `__extc_home`；
  `k ≥ 1` ⇒ `&__extc_a[k]`，翻译在 `codegen.c:1521-1526`）。

| 记号 | 含义 | 实现里的对应 |
|---|---|---|
| `d(v)` | 值 `v` 里**所有活指针**所指对象的最大层号（**越小活得越久**） | 检查器的记账（`exprRefDepth` / `Sym.refDepth` / 字段表） |
| `at(p)` | 地方 `p` 的存储所在层 | `storeLayer()`（`check_escape.c:72-84`） |
| `deref` 悬垂 | 读一个指向**已 release 区域**的指针 | ASan `heap-use-after-free` |

### 1.2 判据（检查器实际用的那两条）

```c
/* check_escape.c:520-541 —— 存进去之前问"被指对象活不活得够久" */
int d = exprRefDepth(c, val);
if (d <= at) return false;          /* 放行 */
else ckError(...);                  /* 拒绝 */
```

**记法约定（关键）**：数字**越小 = 活得越久**，所以

> ⚠️ **"记小了"就是洞，"记大了"只是误拒。** 检查器的全部正确性都压在
> 「记账 ≥ 真实层号」这**一个方向**上。

### 1.3 要证的命题（定理 3，`ARENA-FORMAL.md:181-195`）

> 若每个分配点 `S` 的区域 `α_S` 与每个存储边的深度都满足约束系统（§3.2 的 C1–C5），
> 且实现按 `α` 分配，则所有 trace 安全。

**它的证明依赖一条不变量**（原文 §3.5 的不变量 I，改写成"层号"语言）：

> **INV-H（上界性）**：检查器为**任何**表达式 `e`、**任何**绑定 `x` 记录的深度 `D`，
> 都满足 `D ≥ d(e)` / `D ≥ d(x)`（真实层号）。
> **INV-M（单调性）**：`D` 只允许往**变大**（更保守）的方向被改写。

`ARENA-FORMAL.md` §6.6 其实把这两条写成了纪律（"(S3) 不变式：任何能让某个值的内容发生变化的
规则，都必须把写进去的东西的深度**取上界记回那个值**（`max`，不是覆盖）"）——
**本文证明的就是：实现里有三处直接违反 `max`，写成了覆盖。** ✗

## 2. 定理 3 为什么是对的（把前提摊开）

设 `I(σ)` = "对内存里每个活着的槽位 `p`，它持有的指针所指对象 `o` 满足 `λ(reg(o)) = live`"。

1. **分配**：`new`/`alloc` 拿到的地址与区域**同生共死** ⇒ 新对象只在区域活着时可读。
2. **存储** `p.f := e`：若 `d(e) ≤ at(p)`（检查器放行），且 `d(e)` 是上界（**INV-H**），
   则被指区域的祖先链 ⊆ `p` 所在区域的祖先链 ⇒ `p` 活着时它一定活着 ✓。
3. **拷贝 / 返回 / 跨帧**：只搬指针 ⇒ 需要 `d(被拷的东西) ≤ at(落点)`，仍然靠 INV-H ✓。
4. **回收**：区域按块 LIFO，`⊒` 传递 ⇒ 不凭空产生悬垂 ✓。

⇒ **定理 3 成立 ⟺ INV-H ∧ INV-M**。而 `ARENA-FORMAL.md` §6.2 的"定理 6.2（线性化 sound）"
把这件事归到 `(S3) 的上界性`，方向判断完全正确；
**漏的是"这个不变式在代码里没有被维护"** —— 下面就是账单。

## 3. 记账有哪些数（谁写、谁读、答哪个问题）

| 字段 | 写点 | 读点 | 它答的问题 |
|---|---|---|---|

| `Sym.fields[4].depth` / `otherDepth` | `check_top.c:873-913`（4 处） | `check_escape.c:140-144`（`h.p` 读那一格） | 逐字段版 (b)；`otherDepth` = 归不到某一格的兜底 |

**读法不对称（这是最容易看漏的一处）**：
`exprRefDepth` 的**早退**条件是 `typeContainsRef(类型)`，而 `typeContainsRef` 对

⇒ 一个类型是 `mut ref i32` 的值，在 `exprRefDepth` 眼里是"**里面不可能有引用**"⇒ 返回 **0** ✗
（真值 = 它指着的东西的层号）。

## 4. 证伪：三条具体的"记小了"

### 4.1 违例 ①：整值读取用"一个数"，而那个数被**强更新**压小过

```c
/* check_top.c:878-883 —— 把整根的记账深度**重新算**成 max(otherDepth, 各字段) */
static void refreshRootDepth(Sym *s) {
    int m = s->otherDepth;
    for (int i = 0; i < s->nfields; i++)
        if (s->fields[i].depth > m) m = s->fields[i].depth;
    s->refDepth = m;                 /* ← 覆盖，不是 max(旧值, m) ✗ */
}
```

配套的两处"只改一格、却动了整根"的写法：

- `check_escape.c:335`（换指向那一支）：`slot0->refDepth = exprRefDepth(c, v);` —— 覆盖；
- `check_stmt.c:398`（引用型目标的赋值）：`vs->refDepth = d2;` —— 覆盖。

⇒ 于是「**先把深的存进 A 格、再往 B 格写一个浅的**」会把整根压成浅的，
而**浅的那一格并没有抹掉 A 格里还活着的指针** ⇒ `exprRefDepth(x)` = 0 ✗（真值 ≥ 1）。
`ARENA-FORMAL.md` §6.6 明写这条纪律是 `max`，实现是**覆盖** ✗✗

### 4.2 违例 ②：整值读取只读一个数，**不看字段表**

```c
/* check_escape.c:124-135 —— `EX_IDENT` 的深度 */
Sym *sy = lookup(c, e->u.ident.name);
if (sy && ... typeContainsRef(...)) d = sy->refDepth;   /* ← 只看这一个数 ✗ */
else d = placeDepth(c, e);
```

而 `h.p` 这条**逐字段**路径是**另算**的（`:140-144` 读字段表）。
两条路径的口径不一致 ⇒ "整值拷贝"（`var h2 = h`）带走的那个数可能比任何一格的都小 ✗

### 4.3 违例 ③：把"深度"当成"**表达式自己**多深"，而不是"**它指着什么**多深"

- `exprRefDepth` 对 `TY_REF` 型早退返回 0（§3 末）。
- "藏在字面量里的分配点"没算进来：`inner { v: mknode() }` 的深度 = 0，
  可 `mknode()` 在调用点被算成"深度 0"，而它实际分配到**当前块**那只 arena
  （`check_stmt.c:221-224` 的"有家被调者 ⇒ 深度 = 当前层"**只覆盖初始化式直接是调用**的情形，
  不覆盖"藏在结构体字面量 / 枚举载荷 / 数组字面量里"的调用）✗

## 5. 反例（7 个，全部实测）

> 全部满足：**检查器接受**（`rc=0`）→ gcc 编过 → 运行时 ASan 报 UAF，且 `freed by` 栈里有
> `extc_arena_release`。复现脚本：`/tmp/hunt2/x.sh prog.extc`（编译 + ASan + 跑）。

### 反例 A · 字段表过期（`stack-use-after-scope`，最小形状）

```extc
struct inner { v: mut ref i32 }
struct box   { c: inner }

fn leak(p: mut ref i32) -> inner {
    var b: box = { c: { v: p } }     // 字段格 "c" 建出来 = 0
    var local: i32 = 5
    b.c = { v: ref local }           // 非引用型目标的赋值：**只动整根**，不动 "c" 那一格
    return b.c                       // 读那一格 = 0 ⇒ 0 ≤ at=0 ⇒ 放行 ✗
}
fn main() -> i32 { var x: i32 = 1  let r = leak(ref x)  println("r.v = ", r.v)  return 0 }
```
生成 C：`return b.c;`，而 `.v = &(local)`（`local` 是 `leak` 的栈局部）。
ASan：`stack-use-after-return ... 'local' ... frame leak`。
**违反 ①③**：非引用型目标的赋值**完全不更新字段表**（见下）。

### 反例 B · "浅引用值"把整根压小（`heap-use-after-free`，最小形状）

```extc
struct box { p: ?ref i32  q: ?ref i32 }

fn f() -> box {
    var h2: box = { p: null, q: null }
    var x = alloc<i32>(1)            // EX_GENCALL：arenaLevel = refDepth = 当前层 = 1
    *x = 42
    var h: box = { p: null, q: x }   // 字段格 q = 1（alloc 记对了）
    var h3 = h                       // 整值拷贝：带走的 refDepth 按"一个数"算
    h3.p = null                      // ← 把根压成 0（覆盖，不是 max）
    return h3                        // 0 ≤ 0 ⇒ 放行 ✗
}
fn main() -> i32 { let r = f()  println("r.q = ", *(r.q!))  return 0 }
```
生成 C（`/tmp/hunt2/out/apex.c`）：
```c
static box f(extc_arena *__extc_home) {
    extc_arena __extc_a[2] = {0};
    int32_t * x = extc_arena_alloc(&__extc_a[1], ...);   /* 层 1 */
    box h  = (box){.p=NULL, .q=x};
    box h3 = h;                 /* 指针被拷走 */
    h3.p   = NULL;              /* 只清 p */
    __extc_ret_v = h3;
    extc_arena_release(&__extc_a[1]);   /* ← q 还指着这里 */
    return __extc_ret_v;
}
```
ASan：`heap-use-after-free`，`freed by extc_arena_release`。**违反 ①②**。
（把 `h3.p = null` 删掉 ⇒ **被正确拒绝**；把 `alloc` 换成 `new` ⇒ `ARENA_HOME`，**接受且干净**——
这条对照说明洞正好落在"覆盖"那一句上 ✓）

### 反例 C · `if/else` 合流把一格的深度抹掉（`heap-use-after-free`）

```extc
fn f(c: i32) -> box {
    var out: box = { p: null, q: null }
    {
        var x = alloc<i32>(1)
        *x = 42
        var h: box = { p: null, q: null }
        if c == 1 { h.q = x } else { h.q = null }   // then 支记 2；else 支记 0 并覆盖
        out = h                                     // 合流后视角 = 0 ⇒ 放行 ✗
    }
    return out
}
```
ASan：`heap-use-after-free`（`x` 所在 `__extc_a[2]` 在出块时 release）。**违反 ①**
（`else` 支的 `null` 把它覆盖掉；把 `else` 支删掉 ⇒ **被正确拒绝**）。
同型变体：`pB2_refif`（引用型绑定版）、`pG4_matchjoin`（`match` 两臂）、`pG3_ifassign`
（整值赋值版，`check_stmt.c:398` 的覆盖）。

### 反例 D · 元素写把 `otherDepth` 覆盖掉（`heap-use-after-free`）

```extc
fn f() -> [2]?ref i32 {
    var out: [2]?ref i32
    {
        var a: [2]?ref i32
        var x = alloc<i32>(1)
        *x = 42
        a[1] = x                            // 进 otherDepth = 2
        a[0] = null                         // 元素写走 field==NULL 那一支 ⇒ otherDepth = 0（覆盖）✗
        out = a
    }
    return out
}
```
`check_top.c:897` 的注释说 `otherDepth` "只增不减 ✓ 保守 ✓"，但这一支对**元素写**也生效，
而元素写**不会**让别的元素失效 ✗。ASan：`heap-use-after-free`。
（删掉 `a[0] = null` ⇒ **被正确拒绝**。）

### 反例 E · 藏在结构体字面量里的"有家被调者"（`heap-use-after-free`）

```extc
fn F() {
    var junk: mut ref node = new node         // 让 F 自己有一帧 arena
    var keep: box = { r: null }
    {
        var b: box = { r: mknode() }          // mknode 有家 ⇒ 分配到**当前块**那只 arena
        keep = b                              // 字面量的记账深度 = 0（见 §4.3）⇒ 放行 ✗

    println("keep.r = ", keep.r!.value)       // 悬垂 ✗

```
ASan：`heap-use-after-free`。**违反 ③**。

### 反例 F · `@overwrite` 的复用格活过了它赖以分配的那只 arena（`heap-use-after-free`）

```extc
fn work(n: i32) -> i32 {
    @overwrite var tmp = new [8]i32
    tmp[0] = n
    return tmp[0]
}
fn main() -> i32 {
    var i: i32 = 0
    while i < 3 { println("work = ", work(i))  i = i + 1 }
    return 0
}
```
`@overwrite` 的存储被定在**层 1**（`check_expr.c:786` 的 `reuse ? 1 : ...`），
而层 1 在**每次函数返回**都被 release（`codegen.c:2186-2187`）；
可复用格子是**普通局部**、可能住在**调用者帧**里（`check_top.c:1764` 的 `owLocal`，
`codegen.c:2128-2139`）⇒ 第二次执行同一个调用点时，格子非 NULL，
生成的代码就对着**已 free 的块** `memset`（`codegen.c:1796-1798`）✗
ASan：`heap-use-after-free`，`WRITE of size 32 in memset`，`freed by extc_arena_release`。

### 反例 G · `origin` 过期 ⇒ `promoteInto` 用旧事实"证明"了安全（`heap-use-after-free`）

```extc
fn g(h: mut ref box) {
    var n = new i32            // n ∈ 家 arena
    var x = alloc<i32>(1)      // x ∈ 本帧层 1
    var s: box = { p: n, q: n }
    s.q = x                    // 字段写**不刷新** s 的 origin（仍是 {p:n,q:n}）
    *h = s                     // promoteInto 顺着过期 origin 说"全是 new ⇒ 提到家即可"
}                              // ⇒ 把 s.refDepth 改成 0，而 s.q 实际指向层 1 ✗
fn main() -> i32 { var out: box = { p: null, q: null }  g(ref out)  println(*(out.q!))  return 0 }
```
`noteOrigin` 只在**声明**（`check_stmt.c:204`）和**引用型换指向**（`:341`）时记，
非引用型绑定的**字段写**不刷新它 ✗（`check_escape.c:325-327` 的 `sy->origin = ...`）。
ASan：`heap-use-after-free`。**对照**：origin 里没有 `new` 时（`{p:x, q:x}`）⇒ **被正确拒绝** ✓

# 9. 在现有框架下"保 soundness + 尽量精确"的改造清单

> 目标写准一点（这是本文档与 `ARENA-FORMAL.md` 的接口）：
> **①** 对每个被接受的程序，`∀ trace` 安全（soundness，硬约束）；
> **②** 在 ① 之下，**接受集最大**（`ARENA-FORMAL.md` 定理 8.1 的"相对完备性"）；
> **③** 在 ①② 之下，**每次分配取"能接受的最浅层"**（内存最小，推论 3.1 的最小解）。
>
> ⚠️ 关键：**②③ 都不是 soundness 逼出来的** —— 由**命题 7.1**（放大区域永远安全）
> 与**推论 7.2**（任何被拒的安全程序都有重写），框架里"不够精确"从来不等于"不安全"。
> ⇒ **精确性在这个框架里只买一样东西：内存。** 所以下面的取舍一律按"**这段内存值不值这个复杂度**"来判。

## 9.1 先分清两件事（混起来就会做错决定）

| 量 | 含义 | 谁该保证 |
|---|---|---|
| `D(e)`、`Sym.refDepth`、字段表 | "这个值里所有活指针**最深**的那一只" | **必须是上界**（`D ≥ d`）。**记小 = 洞**，记大 = 只费内存 |
| `at(p)`、`Expr.arenaLevel`、`arenaArg` | "这次分配/这个槽位放在**哪一层**" | **必须是解**（满足约束的那只）。这里要的是**最小**（最浅） |

⇒ 两件事的正确方向**相反**：`D` 越大越安全，`at` 越小越省内存。
今天所有洞都在**前者**（把 `D` 记小了）；所有误拒都在**后者**（把 `at` 选长了）。

⇒ **改造原则**：
> **`D` 一律只许往大走（由单调数据流算），`at` 一律求最小解。**
> 绝不用"把 `D` 调小"来换取"看起来更精确"——那正是（反例 A/B/C/D/G）的形状。

## 9.2 为什么今天必然出这些洞（不是手滑）

今天 `D` 是**在单遍检查里、用破坏性赋值边查边维护**的：
`refreshRootDepth`（`check_top.c:882`）、`check_stmt.c:335/398`、`noteFieldDepthWrite`（`check_top.c:896-913`）、
`promoteInto2`（`check_escape.c:364-366`）—— 五处各写各的，**没有一处是"取上界"**，
而控制流合流（`if`/`while`/`match`）**没有任何 join**。

> **结论**：这不是"再小心一点"能守住的，而是**架构决定的**：
> 单遍 + 破坏性更新 + 无 join ⇒ `D` 只可能在**某条路径上**变小 ⇒ 迟早有洞。
> ⇒ 想"保 soundness"，`D` 必须换成**单调数据流的不动点**（下面 T1-②）。

## 9.3 分档（每档都标：动的是 `D` 还是 `at`、买到了什么）

### 档 0 · 不变量修复（**必须做**，几乎零成本，零精度损失）

| # | 改哪 | 怎么改 | 为什么是"精确"而不是"更保守" |
|---|---|---|---|
| 0-a | `check_escape.c:96` | `TY_REF` 不许走"类型里没有引用 ⇒ 0"那条早退，走 `placeDepth` | 把**记错**改成**记对** ⇒ 只可能更精确 |
| 0-b | `check_top.c:882` | `refreshRootDepth`：`m = max(旧 refDepth, otherDepth, 各字段)`，**不许降** | 同上（旧值是保守的下界，取 max 只会更真） |
| 0-c | `check_stmt.c:335` / `:398` | 同样取 `max`，不许覆盖 | 同上 |
| 0-d | `check_top.c:897` | 元素写（`field == NULL`）**不许清表**，取 max | 现在的"清表"是**凭空丢事实**，只可能更不精确 |

| 3-b | **字段表做全**：不是 4 格 + `otherDepth`，而是**所有静态字段各一格**（静态字段数有界 ⇒ 成本可控）；元素写取 max 不清表（= 0-d） | 现在"表满 ⇒ 兜底格只增不减 ⇒ 误拒"是**已知**的精度损失；做全只增精度 |

| 3-d | **`for`/`while` 体单独一只区域**（块级细化再细一档） | 现在"提升到函数层"= 整个函数变成一个自动清理的堆（`定案 63` 已认可的代价）。有了"每轮一块"的区域，**同一段代码内存上界从"函数级"降到"一次迭代级"**且**不需要多拒任何程序** |

## 9.4 我的判断（按"值不值"排）

| 优先级 | 做什么 | 为什么 |
|---|---|---|
| **P0（不做就不 sound）** | 档 0 四条 + 1-a + 1-c | 全是"记错/漏一条路径"，**改完只可能更精确或不变**；实测数字：档 0 ⇒ 7/9 转正、256 通过 / 1 失败；1-a ⇒ 4 条转正 |

| **P3（值得做但要单独评估）** | 3-b / 3-c | 3-b 成本线性、收益是误拒面；3-c 是**架构级**（"单遍检查"→"先算摘要再照解检查"），`ARENA-FORMAL` §8.3 已经把代价列全（报错形状、不动点×实例数、上限+响亮报错）——**只有 3-c 能同时拿到 ② 和 ③** |

## 9.5 一句话回答"哪些要改"

> **① 四条不变量修复（档 0）必须做，且不花精度；**
> **② 三个"看不见某个语法形状"的谓词去重（档 1）必须做，也不花精度；**
> **③ 两处"家 arena"的语义订正（档 2）必须做，而且它只放宽不收紧；**

> 框架给的精确性从来不在 `D` 那一侧，而在 `at` 那一侧（命题 7.1 + 最小解）。

# 10. `@overwrite` 的修法（2026-09-23，方案 A/B2 落地验证）

## 10.1 病根：糖把**两个寿命不同的东西**绑在一起

`@overwrite` 想说的其实是两件事，糖把它们写成了两个各自算死的常量：

| 想说什么 | 谁决定 | 旧代码怎么定 |
|---|---|---|
| ① 存储**只有一块**（跨多次执行复用） | **格子的寿命** | 格子放**调用者**帧（`check_top.c:1764` 的 `owLocal`）|
| ② 存储**放哪只 arena** | 分配点 | `arenaRefAt(nx->arenaLevel)`（`codegen.c:1789`）→ **被调者自己的层 1** |

两者**没有任何地方保证一致** ⇒ 第二次执行同一个调用点时，格子里的 `p` 还指着上一轮
已被 `extc_arena_release` 放掉的块 ⇒ 对着已 free 的内存 `memset` ✗

```
fn work(n: i32) -> i32 { @overwrite var tmp = new [8]i32  tmp[0] = n  return tmp[0] }
while i < 3000000 { s = s + work(i)  i = i + 1 }
  旧 → ASan: heap-use-after-free（WRITE of size 32 in memset, freed by extc_arena_release）
  新 → ASan 干净 ✓
```

⚠️ **不带 ASan 时它伪装成"正常工作"**（RSS 1.6MB 纹丝不动）—— 因为 glibc 把刚 free 的
那块又还回来了，等于默默往同一块内存上写 ✓ 这类"UB 伪装成正常"最难查 ✓

## 10.2 修法（落地版 = 方案 B2，`/tmp/fixA2` 实测）

**一句话：格子和它管的存储必须同生共死。** 具体：

1. **格子永远住本帧**（`check_top.c` 的 `owLocal` 恒 `true`）⇒ 删掉"调用者代备格子"那条路，
   连带**删掉被调者的隐藏参数** `extc_owcell *__extc_owarg%d`（签名变干净）✓
2. **`home` 字段进格子**（`extc_owcell { void *p; int64_t cap; extc_arena *home; }`），
   `home` 由**格子的主人**填：
   - 这个函数**有家 arena** ⇒ `__extc_home`（活过本次调用）⇒ **跨调用复用真的成立** ✓
   - 否则 ⇒ `&__extc_a[1]`（本帧第 1 层，一定活到这条语句执行完）⇒ **永不 NULL** ✓
3. 分配点 `ar` 从 `arenaRefAt(nx->arenaLevel)` 换成 `(*__owc->home)` ⇒ 两个寿命对齐 ✓
4. **只要有格子，arena 数组就必须吐**（哪怕这个函数自己一次都不分配 —— `main` 里放一个
   `@overwrite` 变量正是这一档；漏了就是 `__extc_a` 未声明 ✗）⇒ `noArena` 的判据要加上这一条 ✓
5. `extc_owcell` 的 typedef **按需吐，且必须排在 `extc_arena` 之后**（它含 `extc_arena *`）✗

**验收（实测数字）**

| 判据 | 结果 |
|---|---|
| 3M 轮同一个调用点（原反例） | **ASan 干净** ✓（旧：heap-use-after-free）|
| 一次调用内分配次数 | **1**（循环里跨轮复用，不抖动）✓ |
| `tests/run.sh` | **257 通过 / 0 失败** ✓ |
| `tests/asan/` · `tests/arena/` | 8/8 · 5/5 全绿 ✓ |
| 攻击库基线 | **一字不动**（7 条已知安全 + 其余全挡）✓ |
| **golden（基线 = 修前编译器）** | 95 个里**只有 `examples/overwrite` 变了**，且差异**恰好**是三件该变的事：typedef 多一个字段、隐藏参数消失、调用点不再传格子 ✓ |

## 10.3 诚实记账：丢了什么

- **丢了"跨调用复用"**：旧设计让调用者备格子、被调者复用 ⇒ 每次调用**一块都不分配**。
  但那份复用**不可能 sound**（buffer 必须活过被调者返回，而它不在调用者帧里）⇒
  它买到的"零分配"是拿**悬垂**换的 ✗ ⇒ 丢掉它不算亏 ✓
- **代价**：`@overwrite` 现在**每次调用分配一块**（一次调用内仍然只一块）。实测
  `while i<1000 { stash(ref d, i) }`：旧 `ALLOCS=1`（但**写的是已 free 的内存**），
  新 `ALLOCS=1000` ✓ 差了 1000 次 malloc，换来的是**正确**。
- **想要回"零分配"的正路**（不是回到旧形状）：把 buffer 放在**调用者**的作用域里、
  显式传进去 —— 也就是 §10.4 那个方向 ✓

## 10.4 顺带修掉的两个真缺陷（今天两个编译器都中招）

| 现象 | 复现 | 原因 |
|---|---|---|
| **一个函数里两个 `@overwrite` 站点 ⇒ 生成的 C 编不过** | `fn two(){ @overwrite var p=… @overwrite var q=… }` ⇒ `error: redefinition of '__owc'`（gcc）| 临时名写死 `__owc`（`codegen.c`）⇒ 改成按站点编号 `__owc%d` ✓ |
| **绑定名恰好叫 `p` ⇒ 空指针** | `@overwrite var p = new [4]i32` ⇒ `void *p = …; p = (array_4_i32 *)p;` **自赋值** ⇒ ASan SEGV | 临时名 `void *p` **遮蔽**了同名绑定 ⇒ 改成 `__owp%d` ✓ |

这两条与悬垂无关，但都在同一条码路上，且都**只在特定命名/多站点时出现** ⇒ 一起修 ✓

## 10.5 还没做的一件（值得单独拍板）

**"跨调用复用"要不要作为一等需求支持？** 如果要，正路是：

> 让 buffer 住在**调用者**的作用域里 —— 也就是 `stash(ref d, ref pool)` 这种
> **显式把 buffer 传进去**的形状；或者给 `@overwrite` 引入一只**独立的区域参数**
> （像家 arena 那样，但语义是"这块存储属于你"），由调用点按 §2-a 那条规则选，
> 于是"选得对不对"就回到 checker 已有的判据上 ✓

✗ **不要**回到"调用者备格子 + 被调者分配"那条路 —— 那正是 §10.1 的病根 ✓

# 12. 路径敏感的 arena 选择（"下沉"）—— 设计 + 实测（2026-09-23，主人提的）

> 主人的原话：「既然现在函数也是调用的时候才判断 arena，那变量甚至每一个对象不也可以这样吗……
> 就是类似于**下沉**」→ 对齐之后：**同一个 `new` 站点的不同执行路径，按"这一次实际会走到哪个
> 目的地"选层**，而不是把最坏那一档施加给所有路径。

## 12.1 问题是真的（实测）

| 形状 | 分配点选了哪只 | 200 万轮 RSS |
|---|---|---|
| 循环里 `new`，**只读不外存** | `__extc_a[2]`（循环体）| **1.6 MB** |
| 同一个 `new`，代码里多一条 `if keep==1 { head = n }` | `__extc_a[1]`（函数体）| **33.2 MB** |

⇒ 多出来的 **31.6 MB 全是白攒的**：`keep != 1` 时那些对象一个都不需要活着，
却因为"**另一条分支**可能要用"而被提升到函数层。

**根因**：`arenaLevel = min(当前块, 所有目的地)` —— 取**最浅**那只。
这在健全性上是对的（对象得活过所有受体），但**只要有一条分支要浅的，所有路径都付账** ✗

## 12.2 正确的对偶：按路径取"这条路径真正需要的那一层"

- `ex1`（循环里 `new`，`if keep==1 { head = n }`）：`keep==1` ⇒ 层 1；`keep!=1` ⇒ 层 2 ✓
- `ex2`（只存进**更深**的块）：不变（本来就不用提升）✓
- `ex3`（一条路径存进**调用者的对象**）：必须进家 ⇒ 不变 ✓
- `ps2`（没有外存路）：不变 ✓

⚠️ **只有"某条路径的目的地比其他路径更浅"时才有差异**；否则**逐字节不变** ——
`ex2/ex3/ps2` 就是这三行判据。

## 12.3 落地形态（已在原型里跑通）

1. **`Expr` 加三样**：`arenaOrigDepth`（站点出生时的块深，**不能拿 `arenaLevel` 当基准 —— 它已被提升改小**）、
   `arenaLevelAlt`（备用层）、`arenaLevelAltCond`（条件）
2. **检查期**：维护一条**分支条件栈**（进 `if`/`else` 的体就压、出就弹；`while` **不压** ——
   循环条件在体内恒真，区分不了"这一轮走哪条"）。存储时把"这次存储的目的地层"与
   "夹在分配点与存储点之间的那个条件"记到分配点上
3. **codegen**：吐 `(*(cond ? &__extc_a[浅] : &__extc_a[深]))` ⇒ 走别的分支时对象住得更深 ⇒ 更早回收 ✓

**生成的 C（原型实测）**：
```c
extc_arena_alloc(&(*((keep == 1) ? &__extc_a[1] : &__extc_a[2])), …)
```

## 12.4 ⭐ 三条**必须**的护栏（每一条都是被实测逼出来的）

| # | 护栏 | 不做的后果 |
|---|---|---|
| **①** | 备用层必须落在 `__extc_a[1..maxLv]` 里，越界**一律退回单层** | 越界写（比不优化危险得多）✗ 实测撞到过 `__extc_a[3]` 超出上限 |
| **②** | 条件必须 `repeatablePure`（三元在 C 里求值两次）| 有副作用的条件会跑两遍 ✗ |
| **③** | ⚠️ **条件所在的作用域必须严格比分配点更外** | `lookup` 沿作用域链找，**同层"声明在使用之后"也找得到** ⇒ `{ var a = new node }  var flag = 1  if flag == 1 {…}` 里会选中那个 `if`，而 `flag` 在分配点还没声明 ⇒ 生成的 C **`undeclared` 编译失败** ✗（`examples/store-promotion.extc` 当场抓到）|

**方向铁律**：新机制**只许把层放深**（备用层比正式层深），**绝不许放浅** ——
放浅需要整个新的证明，见 §11.4。

| **1** | **"备用层"的基准搞错** | 我一开始拿 `arenaLevel` 当基准，但它**已被提升改小** ⇒ 判据恒假 | 必须用"站点出生时的块深"（`arenaOrigDepth`）✓ 已解决 |
| **2** | **越界** | 算出过 `__extc_a[3]`，而该函数的数组只有 `[0..2]` ⇒ 生成的 C 越界写 | 加了护栏①（越界退回单层）—— **这条护栏是真正必需的** ✓ |
| **3** | **两条码路** | 存储有"普通赋值"与"**引用型目标**"两支；只接前者 ⇒ `ps1` 根本不触发 | 两支都要接 ✓（上一轮强更新也是死在这里）|
| **4** | **条件的作用域** | 生成的条件引用了**声明在分配点之后**的变量 ⇒ gcc `undeclared`（`store-promotion` 当场抓到）| 需要"声明序"判据 ✓ 设计已给（给 `Sym` 加 `declIdx`）|
| **5** | **挑条件的判据反复写错** | `f->depth <= at` / `<` 、`scopes.len` vs `scopes.len+1` —— 我在这上面来回改了 **5 次**都没稳定下来 | ⇒ **这就是没做出来的直接原因**：判据没有先写成一份"可独立验证的小函数"，而是直接在两个大函数里试 ✗ |
| **6** | **机械文本编辑反复弄坏文件** | 用脚本按字符串替换改 `check_*.c` / `codegen.c`，**四次**出现"替换漏一处 ⇒ 留下半截语法" ⇒ 编译不过，然后我花轮次去修清理事故 | ⇒ **教训**：这种改动应当**一次只改一处 + 每处立刻编译**，或者干脆重写整个函数；不要批量正则 ✗ |

### 唯一一次真正看到收益

在**卡点 4/5 之间**的那个中间版本上，`ps1` 生成出了正确的三元：
```c
extc_arena_alloc(&(*((keep == 1) ? &__extc_a[1] : &__extc_a[2])), …)
```
⇒ 证明**这个设计是能实现的**；它没留下来，是因为加了"声明序"判据（卡点 4）之后
判据又在卡点 5 上被我改坏，之后为了不放过洞我没有再放宽任何一条 ⇒ 收益消失。

### 下一次的正确做法（我建议的顺序）

1. **先写判据，写成独立可测的小函数**：
   `CondFrame *pickCond(condStack, allocDepth, allocDeclSeq)` ——
   只做三个比较（`f->depth <= storeDepth`、`repeatablePure`、`f->declSeqAt <= allocDeclSeq`），
   给它写一个**单独的调试开关**把每次判定打出来（`EXTC_DBG_PICK`），先在 `ps1` 上把"该选中哪一帧"确认死。
2. **再动 `promoteInto`**：只加"记备用层""的一个入口（`markAltOnExpr`），改完**立刻编译**。
3. **最后动 codegen**：`arenaPickAt` 三行，改完立刻拿 `ps1` + `store-promotion` + `ex_base` 三个靶子对拍。
4. **不要用批量正则**；每一处替换后 `make` 一次（编译不过就立刻回退那一处）✓

### 原 §12.5 的旧结论（保留，作为设计备忘）

- ✓ 机制、护栏、codegen 全部在原型里跑通，`ex1` 那种最理想的形状能生成正确的三元；
- ✓ 加机制**之前**验过"只记不用 ⇒ golden 逐字节不变"（92/95 文件）；
- ✗ 但护栏 ③ 要求"条件所在作用域严格在分配点之外"，而**最常见的那一档**
  （分配点在 `if` **之前**、循环体里）恰恰是**同层** ⇒ **收益归零**
- ⇒ 我**没有**为了让它生效而放宽 ③ —— 放宽就是 §11.3 那条教训的重演（"255/0 不是证据"）

**要真正拿到这 31.6 MB，需要补的一件事**：给 `Sym` 加一个"**声明序**"（当前作用域里第几个声明的），
把护栏 ③ 从"作用域比分配点外"精确到"**声明在分配点之前**"。这是一处**小而局部**的改动，
判据明确（`ps1` 的 `keep=0` 33.2MB → 1.6MB，且 `store-promotion` 必须仍然编译通过）。
