# 定长热路径 + 溢出冷路径（设想）

> **状态：设想，未定案。** 2026-10-04 提出（起因：`std::loop` 的定时表容量 64 撞了悬崖 ——
> 40 个任务 50ms、200 个任务 460ms，超出的走 `add` 失败兜底变成忙等）。
> 本文不是计划、不是承诺，只是把已经想到的与**尚未想清**的放在一处。

## 一句话

热路径用**定长数组**（零分配、cache 里、可预测），冷路径用**容器**接溢出（摊还、没有上限），
两者之间**成批回填** —— 常见情况一次分配都不发生，罕见情况也不撞上限。

这形状不新：数据结构版的 Small Buffer Optimization；线程池的"本地队列 + 全局队列"；
分配器的"线程缓存 + 中央空闲表"；内核的 per-CPU 环 + 溢出链。

## 已有的判断

* **必须区分两种"静态"**：常驻的固定表（该会长）vs 每轮的栈缓冲（本来就该定长，
  改成容器就是每轮一次分配，纯亏）。当前例子：`timers.at[1024]`（常驻，该改）
  与 `pump` 里的 `tags: [32]i64`/`due: [32]i64`（每轮，保持定长）。
* **"溢出队列"只对事件批字面成立**：level-triggered 的 epoll 事件没取完下轮还会报，
  内核就是那个队列；**按 deadline 的溢出必须是优先级**（堆/有序），FIFO 会让早到的 deadline 晚发。
* **不变式**：inline 里装的必须是"最小的那批"（否则 `next()` 拿错值）；回填只在 inline 排空时
  **成批**搬 —— 摊还的关键在成批，不在"异步"。
* **取消别扫两层**：用惰性世代（弹出时发现是旧世代就丢），与 pool 的世代检查同一套。

## 尚未想清

1. **两层状态机是 bug 的产地**：转换点（inline 满 → 溢出 → 排空 → 回填 → 再排空）与取消横跨
   两层的组合，判据要写成**矩阵**才放心；单层实现作为对照留着？
2. **回填粒度**：一次搬多少？搬满 inline？还是搬固定块？与 `epoll_wait` 的批大小是否该同源？
3. **`shrink` 的时机**：两层都空才缩；但"空"是瞬时事实，抖动负载下会不会反复 malloc/munmap？
   需要一条滞后（比如连续 N 轮为空才缩）。
4. **它和 arena/zone 的关系**：容器内的内存在哪个 zone？协程里第一次触发溢出，那块内存属于谁？
   这一条不解决，两层结构在协程里会踩到与 `VECTOR-GC.md` 同一个问题。

## 附：与协程挂起的关系（2026-10-04 补充）

写 `wss` 夹具时撞到"**跨 `yield` 的局部视图不能指向别人的存储**"（C 栈在挂起时没了）。
查代码才发现：**这条限制的最小版本语言里早就解了** ——

> `check_top.c:4416`：*A global is depth 0: it outlives every frame. Two consequences follow from
> that one fact without any special rule for globals: the escape rule already rejects storing
> something local into a global, and a global of fixed size needs no arena, because it is a C static.*

也就是说：**global（或任何 depth-0 的存储）的视图本来就能跨 `yield`**。我们撞墙是因为把会话缓冲
挂在了 `main` 的局部结构体上（那是"别人的栈"）。**正解不是"重取视图"那套样板，而是把进程寿命的
状态真的声明成进程寿命的**（全局）。

真正还缺的是它的**推广**：不是全局、但**被 plate 拥有**的存储（同一进程寿命，但不是 C static）。
那需要类型系统能表达"这个引用指向谁拥有的存储"（现在的 arena 模型是**按作用域**的，不是**按归属**的）。
判据：等"重取视图"的样板开始反复出现，就该做这一格。
