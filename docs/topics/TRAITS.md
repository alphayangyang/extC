# trait / dyn：设计定稿与第一期实施清单

> **状态：第一期已定案待实现**（2026-09-26 与作者逐条确认）。
> 第二、三期只在本文末尾记录范围，不在此实现。

## 一、已定的七条决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 拼写 **`impl Codec for circle { … }`** | 与既有 `impl circle { … }`（固有方法）只差一个 `for` 子句；作者口径「rust 是对的」 |
| 2 | **`Self` = trait 的隐式类型参数** | 顺着"首字母大写 = 类型参数"的既有规则，复用泛型实例化与实例期检查；不引入新关键字 |
| 3 | trait **可声明关联函数**（无 `self`），但它们**永不动态分发** | object safety 的第一条，提前写死 |
| 4 | 第一期**禁止跨 trait 撞名**（两个 trait 在同一类型上声明同名方法 ⇒ 报错并指名两者） | 一个类型一份方法集（既有规则）；将来若做"精确匹配重载"可单向放宽 |
| 5 | trait 方法可见性 = **声明 trait 的模块被引入** | 沿用 `impl` 的既有规则（本会话落地：没 `use` 就没有这些方法） |
| 6 | 孤儿规则：**trait 与类型至少一个来自本程序** | 比 Rust 宽、比无规则稳；程序级方法集下冲突会编译报错 |
| 7 | 第一期**不允许**同一 `(trait, 类型)` 多次实现 | 规则一句话；将来放宽只影响查找规则 |

## 二、第一期的范围

**语法**：`trait Name { fn … }`（只有签名）· `impl Name for Type { … }` · 直接调用（静态分发）。
**六条检查**：实现齐全（缺哪几个列出来）· 签名逐项相符 · `(trait, 类型)` 唯一 · 与**固有方法**撞名 ·
跨 trait 撞名 · `Self` 越界使用（trait/impl 块之外出现即报错）。
**生成**：为每个 `(trait, 类型)` 发一张 **C 静态方法表**（槽位顺序 = **trait 声明顺序**，键 = mangled `trait$type`），
但**没有任何代码使用它** ⇒ 生成物里不应出现函数指针调用，性能与今天完全一致。
**明确不做**：`T: Trait` 上界 · `dyn Trait` 值 · 关联类型/常量 · trait 默认方法（会让 trait 体里第一次出现函数体）·
动态分发 · 运行期注册。

## 四、第二、三期（范围记录，不在本期实现）

- **第二期**：`dyn` 值落池（**对象表模式**）+ 方法表进池 + 取用前校验 `gen` + 补齐 **O5 类型身份**
  （陈旧 dyn 值 trap，而不是跳到另一个实现上）。前置已就绪：池模式（`extc_pool_new_table` / `extc_pool_kind`）、
  `reset` 换代、对象表模式禁 `give`/`resize`（含 `_raw`）。
- **第三期**：开放注册 + 动态链接（前置：接口文件 + ABI 冻结 + 卸载墓碑）。

## 五、两条相关但独立的记录

- **函数重载**：定位 = "把运算符那套**形状键**从右操作数推广到全部参数，**只认精确匹配**"。
  性质 = **单调**（新增重载只会让原本非法的调用变合法，不会改变已有绑定）⇒ **随时可加、无迁移成本**；
  代价 = 库命名可能留后缀（`hashI64` 是活证据）。**第一期不需要它**；若将来有了它，决策 4 可单向放宽为
  "签名不同即重载，签名相同才是重复定义"。
- **object safety**：第一期就要写下"哪些方法将来不能被动态分发"（泛型方法、返回 `Self` 的方法、无 `self` 的
  关联函数），否则第二期会遇到"这个 trait 用不了 dyn"的意外。
