## 一句话

**Python 的"轮椅"主要来自四件事**：字符串插值、表达式位置的 `if`/`match`、容器字面量+推导式+解构、
以及一批"顺手就在那儿"的 stdlib。我们缺的不是能力，是**写起来的手感**——而且其中两条**最贵的
恰好是最便宜的**（编译期格式串、字符串方法），另两条才是语言级（表达式位置的构造、调用约定）。

## 优先级建议（按"每天用几次 ÷ 补起来的代价"）

| 序 | 做什么 | 量 | 依据 |
|---|---|---|---|
| **1** | **编译期格式串 `{}`** | 小（设计已定：字面量 + 编译期展开） | ① 是最高频的一格，而且它是"**拿 Python 的舒适、不拿它的运行时惊喜**"的完美例子：编译期查参数、运行时零成本 |
| **2** | **表达式位置的 `if`/`match`**（含用户提的 `if let` 部分匹配） | 中 | ② 与"`match` 是语句"是同一格；`if let` 可复用 match 的臂解析（≈150–200 行） |
| **3** | **stdlib 补齐**：字符串方法（`split`/`join`/`trim`/`replace`）+ `enumerate`/`zip` + `vector::of(...)` | **最小** | 便宜且**立刻减少行数**；不含语言改动 ⇒ 可以随时插队 |
| **4** | **容器字面量 + 解构**（含 ④ 那个"含引用元素"的默认形状） | 中 | 语言级，但能一次性消掉一大片 `new` + `while` |
| **5** | **默认参数 / 具名实参** | 大（调用约定） | ⑦ 最贵、频率最低，放最后 |

## 判断（与事实分开）

1. **别把"缺手感"误读成"该变成 Python"**：⑧ 那条（异常 vs `result`/`trap`）我们的选择是**可检查**，
   换来的是"错误不会在凌晨三点才炸" ✓ 不该退。
2. **①②③ 是手感，不是哲学**：它们与我们的检查哲学**不冲突**（格式串在编译期展开就行），
   而且 ①③ 里有两条**根本不需要语言改动**（stdlib 能补）。
3. **④⑤ 这类"语言规则"要分开看**：⑤（`let` 不能绑可写视图）是**提示清楚**的规则，代价只是"想一下"；
   ④（含引用元素没有零值）则会**逼用户写 `new`**——它是"写起来的默认路径"问题，值得专门找一个
   漂亮形状（比如容器字面量顺带解决它）。
4. **行数 3× 这个数字本身**要谨慎引用：这段 Python 是"数据搬运"型代码，而**这类代码正是 Python 最轮椅的
   地方**；我们的强项（协议、位运算、内存、并发）不在这个坐标系里。
