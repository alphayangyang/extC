# 按需发射（worklist）实施方案（2026-10-05）

> 第 1 步的施工方案。目标：**在发射之前决定"谁存在"**，让生成的 C 里不可能有死代码。
> 前提与验收数据见 `CODEGEN-ARCH.md`（附录二 + E1 实测）。**动手前先回答文末"必须先回答的问题"。**

## 一、为什么这一步是纯重构（这就是"零回退"的底气）

死代码**今天已经被删掉了**（M1：6917 个 static 函数，0 个没人调用 ✓）。
所以按需发射**不改变可观测输出** ⇒ **414 份产物指纹应当逐字节不变** ✓✓
⇒ 每一步都能用一个 `diff` 判生死，不需要"跑跑看" ✗。

**收益在别处**：文本扫描层退场（成本不再随产物规模增长）、`need*` 旗子退休、发射顺序不再决定事实。

## 二、发射的现状：三类东西，三种"谁存在"的判定

| 类别 | 今天怎么决定 | 目标 |
|---|---|---|
| **函数/泛型实例/原型** | **先全发**，之后由 `dropUnreferenced` 的函数段按 `countGet(name) != 2` 删 | 需求闭包 |
| **描述符行** | 已经是半按需的（`descRef` 发号；`SCALAR_DESC` 行"发了再删"）✓ | 收进闭包 |
| **运行时块/原语** | 15 个 `need*` 旗子（**发射途中顺带置位** ⇒ 顺序敏感 ✗） | 收进闭包 |
| **函数体内的局部/载荷绑定** | `dropUnusedLocals`（**在活函数内部**，按需发射帮不上 ✗） | **本轮不动**（另立项）|

## 三、worklist 的形状

```
起点集合 S0 = { main, @export 的函数, 模块 init 入口, 被驱动的入口 }
worklist W = S0
while W 非空:
    e = W.pop()
    if e 已发射: continue
    发射 e（原型 + 定义 / 描述符行 / 运行时片段）
    在这次发射**过程中**记录它引用的实体 ⇒ 全部推入 W
```

**关键性质**：发射某个实体**只依赖名字**，不依赖别的实体的文本 ⇒ 可以按任意顺序发射 ✓
（这正是现在做不到的地方：现在的删除判定依赖"整篇文本"✗）。

**闭包要覆盖的引用边**（每一条都要在发射时登记）：
函数/方法调用 · 泛型实例引用 · 描述符（含**嵌套字段类型**的描述符 ✓ 递归）· 运行时原语 ·
运行时**块**（块 ⇐ 它的任一原语/片段被引用 ✓ 这正是替换旗子的地方）· 模块级全局与其 init。

## 四、子步（每步都有判生死的数据）

| 步 | 做什么 | 期望指纹 | 期望 M1 | 可回退性 |
|---|---|---|---|---|
| **W0** | **只加仪表**：数出"今天删除 pass 实际删了多少个实体"（函数/描述符/原语各多少），并把它挂到现有调试开关（`EXTC_DBG_PRIM` 同族） | **不变** ✓ | 0 | 无风险（只加计数）|
| **W1** | **登记 API**：发射实体时就地登记 `{name, kind, block, span}`；删除端**优先用登记信息**，行形识别降级为兜底 | **不变** ✓ | 0 | 小（双路径并存 ⇒ 可对照）|
| **W2** | **worklist**：加需求闭包；**先只对"运行时块"生效**（替换 15 个旗子） | 只在旗子判错的产物上变（预期：**仅 BG-1 那类**）| 0 | 中（可开关切换回旗子）|
| **W3** | worklist 覆盖**函数/实例/描述符** ⇒ 删除 pass 的函数段与描述符段**退场** | **应当不变** ✓（因为今天它们删掉的正是这些）| 0 | 中 |
| **W4** | 删掉 `dropRuntimeDefs` 的行形识别与 anchor 技巧（保留 `dropUnusedLocals`） | **不变** ✓ | 0 | 小 |

**每一步的判据是同一个三元组**：`指纹 diff` + `M1 计数` + `gcc -O2 时间/字节`（M2 的两个数）✓。

## 五、回退最小化的两个手法

1. **旧机制当"预言机"**：W2/W3 期间**保留**删除 pass，但把它的删除次数**打印出来**。
   如果按需发射真的做对了，删除次数会**掉到 0** ✓ ⇒ "新机制是否生效"变成一个**可观测的数字**，
   而不是靠赌 ✓✓（这是本方案最重要的设计：**让新机制通过旧机制的"闲置"来自证**）。
2. **双路径并存 + 开关**：W1/W2 都保留旧路径，用编译期开关切换；任一步指纹不符 ⇒ 单个开关回退 ✓。

**Q4 发射顺序**：三段——原型/typedef →（描述符）→ **body pool**（"definitions from here on"）→

## 六之五、与 AST/parser 的对接（用户特别提示，已核）

* **codegen 只读 AST** ✓：它不写任何 AST 节点成员（写了会撞 AST 冻结闸门 ✗）；
* **需要的新事实来自 plan 侧表** ✓：`planDynTable(f)`（5849）就是活例子，另有 `used` / `makesPool` /
  `coroNeedsZone` 等既有事实 ✓；
* **worklist 本身是 codegen 内部结构**（发射期的需求集合）⇒ **不需要动 AST、plan 或 parser** ✓✓
  —— 若将来某个事实要跨 pass 存活，规矩是先例说的那条：**进 plan 侧表**，不进 AST 字段 ✗。

## 六之六、W1 已落：登记 API（2026-10-05）

**做了什么**：运行时原语块（原来 4 个字符串字面量、9,675 B）变成 `src/back/codegen.c` 的
`PRIM_BLOCK[]` 表：**61 行 = 34 个定义 + 27 段脚手架**（注释 / 空行 / `#if/#else/#endif` 骨架）。
发射时 `primEmit` 就地登记 `PrimEnt{name, kind, off, span}`；删除端 `dropPrimReg` **只用登记信息**
（判据与旧扫描同一套：全篇提及数 == span 内提及数；宏按 `#ifdef` guard 不算使用、`#define` 行算自身）。
旧的行形扫描整体保留为**兜底**，`EXTC_DBG_PRIMSCAN=1` 可整段回退（单开关）✓。

| 判据 | 期望 | 实测 |
|---|---|---|
| 414 份指纹 vs `tools/codegen-baseline-2026-10-05.sha256` | 逐字节不变 | **414/414 不变** ✓ |
| `EXTC_DBG_DCE=1` 删除条数 | 13,923 不变 | **13,923** ✓（prim 8,332 / func 5,466 / scoped 125）|
| `./check.sh quick` | 72/0 | **72/0** ✓ |
| `tools/golden.sh` | 全部合法 C | **414/414 合法** ✓ |

**两个实现细节**：

* 表里**不写裸 `EXTC_*` 字面量**：宏行的名字由 `primEmit` 从它自己的 `#define` 行读出
  （`tools/check_switches.py` 把任何裸字面量当编译器开关，要求写进 `--help`）。
* `__extc_dying` 从"块内一行 + 手工 `DeadDef`"变成块内一个普通实体（它有括号，行形扫描看不见它）；
  标 `quiet` ⇒ 不计入 `[dce] prim`，读数与 8,332 基线保持可比。

**W1 挖出的坑（W2 的入口条件）**：旧扫描的窗口 `[rp, rp + strlen(primText))` 每次重启都重置，
块被裁剪后**越过块尾**伸进后面的文本 —— 它因此顺手删掉 pool 运行期头部的 `extc_pool_capacity`
（全语料 2 份产物）。登记式删除的范围**限定在块内**，为保持 W1 指纹不变，这 2 份由兜底扫描继续负责。
⇒ **W2 要让 `prim → 0`，必须先把 pool 运行期（`poolsEmitRuntime`）纳入登记/闭包**，
并逐条解释这 2 份产物的变化。

## 六之七、W2a 已落：原语块按需发射（块内删除 → 0，2026-10-05）

**做法**：块在 `primEmit` 里组装到自己的缓冲区（`g.prim`），**不写进 `out`**；8 轮 `dropUnreferenced`
收敛后 `primSplice` 做需求闭包（成品文本 + 脚手架 + 还活着的定义之间迭代到不动点，判据与旧 pass 同一套），
再把存活的部分拼进 `primA`；脚手架永远发，所以「丢掉一个定义」留下的字节与旧 pass 一致。
旧行形 pass 随后跑一次：块内=预言机（必须 0），块外=兜底。

**计数账**：旧 8,332 = 8,323（wl）+ 2（prim-out）+ 7（`extc_desc_text` 现在归顶层 DeadDef 那一遍）。
