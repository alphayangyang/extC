# GENERICS.md —— **泛型组合矩阵**：T 出现的位置 × 特性

> 建它的原因：主人问「泛型现在怎么这么多 bug」—— 一量确实：`PLAN §0.4` 表内 **64 格有 22 格**
> 与泛型/实例化相关（≈1/3）✗ 而 2026-09-24 一天之内又撞出 **#60 #61 #62** 三条 ✓
>
> **盲区的两条根因**（都可复现，不是猜的）：
> 1. **覆盖太窄**：语料里 `varArray<i32>` 30 次、`varArray<i64>` 17 次、`mapI64<V>` 16 次
>    —— 可 `tests/map/` 里 `V` **清一色 `i32`** ⇒「值是字符串的 map」这条路**从没被走过** ✗
> 2. **绕开的写法被记成了「设计」**：`stdlib` 的 `mapI64::get` 写成
>    `if .. { return none }` + `return some(self.vals[i])`，注释里写成"形状选择"——
>    其实那正是**绕开 #60/#61 的产物** ✓ **作者本人是绕过者，所以记不起来**
>
> ⇒ 对策不是"再修三个补丁"，而是**把"我没试过"变成"机器每次都试"**：
> 把两个维度交叉成表，**每格一个用例**，落成常设套件 `tests/genmatrix/` ✓

## 1. 判据的铁律

⚠️⚠️ **必须编译生成的 C** ⇒ 一律用 `extc --run`（或 `-o` 之后再 `gcc`）。
理由：`#61`/`#62` 在 `extc f.extc -o out.c` 下**返回 0**（`-o` 的语义就是"吐出 C"）✗
—— 写这个套件时我自己先被骗过一次 ✓（本项目反复记的那条：**"`-o` 成功" ≠ "生成的 C 编得过"**）

## 3. 还没覆盖的格（**诚实的洞**，不是"没问题"）

- **跨模块**的泛型（`use` 之后实例化）—— 现在一格都没有 ✗
- **`result<T,E>`** 的构造与 `match`（今天只覆盖了 `?T`）
- **泛型 × 引用参数**（`ref T` / `mut ref T` 作为 T）· **泛型 × 泛型枚举**（`?option<T>`）
- **泛型 × 逃逸/arena 提升**（有 `tests/arena*` 与层号哨兵管着，但矩阵里该点出来）
- **泛型 × `@overwrite`** · **泛型 × extern/库边界**

⇒ 规矩：**每加一个特性（或每修一个洞），回来给这张表加一列/一格** ✓

## 4. 怎么用

```sh
bash tests/genmatrix/run.sh        # 11 项：8 个格 + 3 条已知缺口（反向断言）
```

套件是**两半**（见 `tests/genmatrix/run.sh`）：

1. `tests/genmatrix/*.extc` —— 必须编过 + 跑对（`// expect:` 子串匹配）；
2. `tests/canary-gaps/*.extc` —— 必须**仍然坏**，而且坏在**记着的那句话**上。
   ⚠️ 哪天某一条**编过了**，这一节**当场 FAIL**，逼着你去把它挪进 `genmatrix/`、
   删掉 `canary-gaps/` 里的副本，并把 `§0.4` 那一格划掉、计数改掉 ✓
   （规矩出自 `tests/generics/run.sh`：断言"不该存在的行为"时，行为一改好就**必须**删断言 ✗）

## 5. 与账本的关系

- `§0.4` 的 `#60` / `#61` / `#62` 就是第 2 节里那三个 ❌；
- 修掉一格 ⇒ 那个 cell 从 `canary-gaps/` **搬进** `genmatrix/`，并把本表那一格改成 ✅ ✓
- 三条都修掉之后，**"写一个泛型容器"需要的能力就齐了**（返回 `?V` · match 变体 ·
