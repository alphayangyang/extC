# 边界层（Heap）

> **一句话**：宿主与外来代码（`dlopen` 的模块、C ABI 的另一侧）之间**只传值**，宿主指针一个都不过去；
> 跨界的数据一律住在宿主拥有的一只 **Heap**（一块**连续板**）里，外来代码拿到的是**板内指针** ——
> 它照常按指针语义工作，而那些指针全部落在宿主的这块板里。数据比代码活得久，
> 所以 `dlclose` 也能做得干净。

## 0. 为什么要有这一层

宿主与外来代码的麻烦从来不是"怎么调用"，而是四件事同时成立：

1. 谁**拥有**跨界的那些字节；
2. 谁可能**别名**谁（外来代码能不能拿到宿主变量的地址）；
3. 它们各自**活多久**（宿主的作用域 arena 可能比模块早结束，模块代码可能比数据早消失）；
4. 出错的**后果**（C 里是踩内存，最坏是跳到已经卸载的代码里）。

三层的分工就是按"谁用"切的：

| 层 | 给谁用 | 结构 | 寿命 | 检验 |
|---|---|---|---|---|
| arena | 自己人（同一线程、同一作用域） | bump | 词法作用域 | 逃逸/深度分析（编译期） |
| pool | 自己人（需要稳定身份、异构） | 槽 + 世代 | 显式 drop | 每次访问查世代 ⇒ 用旧的必 trap |
| **Heap** | **外来代码（模块 / C ABI）** | **一块连续板，槽里全是指针** | **open … close（Arena 兜底）** | **进门只查区间（起点 + 长度），没有世代** |

Heap 少检验是**故意的**：它面向的是"隔着一层协议说话"的另一侧，世代与别名那套在边界上本来就用不上
——因为**跨界的东西只有值**，详见 §1。

## 1. 核心不变量：只传值，且指针只指向板内

> **宿主的地址永远不出界；模块能碰的内存，全是它自己申请、由宿主发出去的。**

这条一立，§0 里第 1、2 两条的麻烦就消失了：不存在"谁拥有"，因为所有权一直在宿主手上（Heap 里）；
不存在"别名"，因为给出的是副本（或一块专供它的新内存）。

由此推出两条**操作规则**：

* **借出即入板**：要跨界的东西**先拷进板**，模块拿到的指针**全部落在板内**。
  ⇒ 宿主那边一次区间检查（起点 + 长度）就知道"这是不是我发的内存"。板内记账可以用偏移，
  **但接口是指针** —— 偏移是宿主自己的事，模块不该看见它。
* **跨界视图必须指向 Heap 内部**。extC 的视图就是 `{ptr, len}`，一个指向宿主 arena 的视图跨界，
  等于把宿主的地址递出去了 —— 破掉整条不变量。做法可以很轻：给视图加一个"在 Heap 里"的标记位
  （与 `Thread=` 一个路数），边界处查这个位。

**拷贝先做对象级**（就是上面那条"借出即入板"），页级以后再说。两条按 2026-09-29 的结论：

* **可写借出是默认**。C 的常态就是 in/out 参数（`read`、`qsort`、`snprintf`），一律要求只读会把合法的
  接口一起禁掉。危险从来不是"写"，而是"**留住**" —— 而留住由"借出即入板 + close 即 munmap"兜住。
* **只读借出是可选硬保证**：大输入不想拷，就 `mprotect(PROT_READ)` 借出去，模块写它是缺页 ——
  由内核保证，不是靠约定。代价随区间大小走，**它与拷贝的交叉点由测量决定**（原型里量过一次，
  但那是旋钮不是常数）。页级 CoW 是这条路的延伸（缺页时拷一页而不是报错），真需要再上。

## 1.5 为什么边界是安全的

链条很短，但每一步都得成立：

1. **插件为宿主效力**，它不自己跑 ⇒ **每一次进入都是宿主发起的**；
2. 于是**参数是宿主选的**，宿主知道自己递了什么、那东西在哪；
3. **没有环境权限**：不靠符号 interposition（§2）、没有"按名字要全局变量"这回事（宿主也不知道模块
   想要什么名字）、模块也拿不到任何隐式可达的宿主状态；
4. ⇒ **它能碰的宿主内存，只有宿主亲手递给它的那些**；再叠上"借出即入板"，那些内存全落在板内；
5. ⇒ 返回路径上**一次区间检查**就把"这是不是我的内存"问清楚了。

一句话：**这不是沙箱，是能力模型**。它不保证模块不谎报、不保证它不踩自己的内存 —— 那由外部库负责
（§7 写明）。它保证的是"**模块的 bug 碰不到宿主内部**"。

## 1.6 为什么是连续板（以及为什么不能是相对地址）

连续不是实现细节，它一次给出四个性质：

* **校验一次比较**：`base <= p < base + size`（视图再加一次长度比较）。板一旦不连续，这一步就退化成
  查表，前面所有"少检验"的话都不成立。
* **`close` 即 `munmap`** ⇒ "留住了指针、板关了之后再用"是**硬缺页**，不是悄悄读到别人的内存。
* **自主分配 + 整体回收**：槽与空闲链都在板里（与 pool 同一只板），`close` 一次全还，不需要逐个析构。
* **内部用偏移、外部给指针**：板不动 ⇒ 宿主拿偏移记账天然稳定；模块看见的永远是 `base + 偏移`。

**增长靠预留，不靠搬移**：一次 `mmap` 保留一大段**连续**虚拟地址（先不 commit），用到哪 commit 到哪
⇒ 永远是一块连续区、校验永远一次比较、`close` 仍然一次 `munmap`。代价只有一条：**保留多大就是硬上限**
（多大是调参），超了 `alloc` 返回 `NULL`，照 C 的老规矩。

**相对地址不行，理由与性能无关**：模块是**宿主编译出来的 C 代码**，里面的 `p->x`、`p[i]` 生成的就是
绝对地址；要让它搬家后仍然对，只有两条路 —— 让模块按自定义指针表示编译（那就不是 C ABI 了），或者
搬移时把所有指针改一遍（要求你知道每个指针住在哪，对任意 C 代码做不到）。VM 那套之所以行，恰恰因为
它的指令与编译器**自己控制每一个指针**。

## 2. 假嵌入：接口形态

不要靠符号 interposition（那套要 `--allow-shlib-undefined` 之类的东西，且行为随链接器漂）。明说：

```extc
/* 宿主提供，模块只用这一张表。头一个字段是大小/版本，老模块配新宿主 ⇒ 干净拒绝，不是默默错读。
 * 这一版是**今天就能编的**拼法（C-ABI.md §9.9 的 ①②③④ 都落地之后复核过；能跑的那份在
 * tests/cabi/heapmain.extc + heapmod.c）：`@frozen` 让布局成为对 C 的承诺，槽上的 `effects`
 * 让"我不留你的指针"有地方写。 */
@frozen struct extc_heap_api {
    size: u64                                          /* 表的大小；宿主按它决定哪些字段存在 */
    ctx:  ?ref void                                    /* 这是哪一只板：模块原样传回来 */
    alloc: fn(u64, ?ref void) -> ref u8 effects Addr=0 Cont=0    /* 申请，返回**板内指针** */
    free:  fn(ref u8, ?ref void) -> i32 effects Addr=0 Cont=0
    copyIn: fn(ref u8, ref u8, u64, ?ref void) -> u64 effects Addr=0 Cont=0   /* 宿主把一块内存拷进来 */
    copyOut: fn(ref u8, ref u8, u64, ?ref void) -> i32 effects Addr=0 Cont=0  /* 模块要的结果拷回宿主 */
    len: fn(?ref void) -> i64 effects Addr=0 Cont=0
}
```

```extc
/* 宿主侧：dlopen ⇒ 取 init ⇒ 把表交出去 ⇒ 之后只通过板内指针说话 */
var h: ?ref void = dl::open("plugin.so")
var raw: ?ref void = dl::sym(h, "init")
var init: fn(mut ref extc_heap_api) -> ref u8 = fn(mut ref extc_heap_api) -> ref u8(raw)
var p: ref u8 = init(ref api)          /* 模块记住这张表；它自己不再找宿主符号 */

/* 宿主一次区间检查，然后照常解引用。`holds` 今天写在宿主里一个函数里 —— 两个指针不能比较，
 * 但**指针能变整数**（只有这一个方向）：base <= u64(p) && u64(p) < base + u64(len)。 */
if holds(p, i64(8)) { let v = i64(*p) }
```

**这一版与草稿的三处差别**（都是"写下去才发现"的，记在这里免得下次重推）：

1. **`ctx` 是可空的 `?ref void`**：句柄类的值本来就可能是空（宿主有时候没有"哪一只板"可说）；
   `ref void` 非空会让每个调用点都要先编一个值出来。
2. **槽上的 `effects` 不是装饰**：没有它，经表回调宿主只能按"它可能留住一切"算 ⇒ 传帧内地址
   就被拒（与"没签字的 `extern!`"同档）。签名**在槽上、不在类型上**：把槽里的指针拷进局部
   就丢了签名，所以要从槽里直接调。
3. **`plate.holds(p)` 与 `p as ref i64` 还不存在**：前者今天写成宿主里的一个普通函数就够
   （`u64(p)` 那条路已经落地）；后者是**整数 → 引用**，故意不开 —— 那是"把数字当指针用"，
   是另一个决定（不放开它，指针能被验证、不能被伪造）。

> **这段表原样抄进编译器编过、也跑过**（2026-09-29：表能建、槽能调、`alloc` 经槽拿到板内指针）；
> 端到端那一条（C 模块 + 回调 + 区间检查）在 `tests/cabi/heapmain.extc`。

**"假嵌入"的含义**：模块不是独立程序，它必须靠宿主发内存，所以它的"空间"就是这只 Heap；它自己的
arena / pool 仍然是它自己的（**每个模块一份运行期实例**），跨界只走这张表。

## 3. 寿命：显式 close + Arena 兜底（close 即 munmap）

> **板的寿命由宿主决定：显式 `close`（就像 pool 可以显式 `reset`），忘了关就由 open 它的那只 Arena 兜底；
> `close` = `munmap`，于是板内指针在关板之后再用就是硬缺页。**

这条必须定死，否则"少检验"就会退化成"不知道什么时候没的"。有了它，板内的槽**不需要世代**，模块也
**不需要配合**关板 —— 关不关是宿主自己的事。这也是它与 pool 唯一的结构差别：pool 靠世代把
use-after-free 变成一次检查，板靠 `munmap` 把它变成一次缺页。

**能留住，但只在板还开着的时候。** §4 那条不对称规则是这套设计里最要紧的一半：模块可以持有**板内**
指针（宿主的内存比模块代码活得久），宿主**不可以**持有模块的指针（数据或函数都不行）。

## 4. `dlclose` 为什么能安全

C 里 `dlclose` 危险，是四件事叠出来的：宿主攥着**模块代码/数据的指针**、模块注册的回调还挂在宿主表里、
卸载时**还有线程在模块里跑**、模块的静态/TLS 与析构。这套设计把前两件消掉了，第三件用协议挡，第四件
随代码一起消失。

**不对称规则（关键）**：宿主内存的寿命 ≥ 模块代码的寿命，所以

* **模块可以持有宿主指针**（宿主借出去的内存在模块卸载后依旧有效）；
* **宿主不可以持有模块指针**，数据或函数都不行 —— 破了就是跳进未映射页。

**注册一律给世代句柄。** 模块在宿主表里注册的任何东西都不给裸指针，给 `{slot, gen}`：`dlclose` 时把
属于该模块的槽**世代加一**，之后谁拿旧句柄来用就是当场 trap，而不是跳进没了的代码。这就是 pool 那招
"把 use-after-free 变成一次检查"，只不过这里保护的是**代码**，不只是数据。

**卸载协议（四步，宿主记账）**：

| # | 做什么 | 不做会怎样 |
|---|---|---|
| 1 | 停发新活（或推到安全点） | 卸载期间还有调用进来 ⇒ 跑到一半的代码消失 |
| 2 | 调模块的 `deinit`（如果有） | 模块自己的收尾没做 |
| 3 | 作废该模块的所有世代句柄 | 旧句柄仍可用 ⇒ 跳进未映射页 |
| 4 | `dlclose` | —— |

**"还有没有线程在模块里跑"由宿主记账**：每次调用进出一个计数，归零才允许卸载；不归零就拒绝卸载并
报清楚（这与并发那条线的"线程要静默"是同一件事）。别指望 glibc 不真卸 —— 按最坏情况设计，真卸掉也安全
才算安全。

## 4.5 本期落地状况（2026-09-28）

**已落地**（提交 `0a53001`，判据 P16 进 `tools/attack.py` 的 par 组）：

* **区域共享 arena**：`extc_par_region` 里给每个 worker 一只 `extc_arena`，区域由 `extc_par_run`
  `calloc`，`extc_par_close` 把每只 worker arena 的块链还回去再 `free`。worker 里的 `new` 落进
  `region->arenas[id]`（`extc_tls_arena` 指过去），**worker 退出时不销毁** —— 于是父线程 join
  之后直接读，不拷贝。
* **没有原子 bump，也不需要**：每个 worker 一只**自己的** arena，bump 路径里没有任何原子操作，
  竞争在"谁拥有哪只"这一层就消掉了（比原子 bump 更省）。区域本身是每个线程一只、按运行刷新，
  所以"每线程领整块、本地 bump"那条也自然满足。
* **只在需要时开**：调用点按 worker 是否会 `new`（`usesHome`）传 `withRegion`；不开时退回线程本地
  arena 并由 worker 自己销毁，既有行为一字不改。
* **判据**：worker 各自 `new` 一段、把那段视图写进自己分段的第一格（分段互不重叠 ⇒ 不冲突），
  父线程 join 后扫出来读，校验 0..n-1 每个恰好出现一次 —— 既是"发布"的证据，也是"分区不重叠"的
  证据。t = 1/2/4/8 全部 `bad=0`。
* **性能不回归（交错 A/B，改动前 `0a53001^` 建基线编译器，同一份源码）**：矩阵乘法 n=768 f32，
  1 线程 新 308.5 ms / 旧 312.2 ms（−1.2%），8 线程 新 45.7 ms / 旧 45.2 ms（+1.0%），加速比
  新 6.76x / 旧 6.90x，两边波动区间重叠。**顺带记一条教训**：本轮先量到过 5.91x，交错 A/B 之后
  判定那是噪声，不是回归 —— 前后两次测量的差别只有交错才能分辨。

**未落地**（下一期）：邮箱与 `sched::recvAny`（流式读取）、`sendable` 规则、dlopen 的接口表与
世代句柄（§2、§4）。

**原型（2026-09-29）**：`prototype-heap/` —— 纯 C，不动编译器一行。量了四件事：保留 + 按需 commit
的代价、分配那道门相对于 `malloc` 的开销、`close` 即 `munmap` ⇒ 旧指针硬缺页、以及大输入的三种借出
法（拷进板 / `mprotect` 只读借出 / 直接给）。数字与"这些数字不能说明什么"都在它的 README 里；
**参数是调参，会再测再调**。

**已知取舍**：

* 区域的寿命 = **本线程下一次并行运行**（那一刻关闭）⇒ 数据有效到那时为止；下一步可以考虑收紧到
  块、或放宽到显式 `release`。
* 用了 `parallel::run` 的程序，运行期块里**有**区域那半套的文本，但整段被 `#ifdef
  EXTC_PAR_REGION` 包着：只有"有 worker 会 `new`"的程序才在块前发射 `#define`，其余程序里那段
  **不参与编译**（不是死代码，也不进二进制）。语料里没有用 `parallel::run` 的程序 ⇒ golden
  414/414 逐字节不变。
* **不维护两份运行期文本，是有意的可维护性取舍**（作者 2026-09-28 定）：逐字节不变不是目标，
  可维护、性能与安全不损失才是。一份文本 + 一个 `#ifdef` 意味着改一处只有一处。
* 附带一条实测限制：那段运行期是一整条拼接字面量，C99 上限 4095 字节。上一轮为腾空间把几句注释
  压短了（措辞改动，属无意夹带），**目前仍保持压短的状态**。
* **那条拼接链已拆开，注释措辞已还原**（第四次尝试成的）。量过：那段是**一个** `bufPuts(out, …)`，
  106 段字面量、共 4031 字节，离 C99 上限只剩 64 B ⇒ 想腾空间必须先拆分，没有别的路。
* **前三次失败是同一个原因，而且很浅**：那个 `if (g.needPar || getenv("EXTC_DBG_PAR"))` 后面是
  **一条不带花括号的语句**。拆开以后 `if` 只护住了第一段，第二段变成**无条件执行** ⇒ 所有产物（包括
  不用并行的）都被塞进并行运行期的尾巴，414 个 golden 产物全变、且非法 C。两种并行配置看起来都正常，
  所以只有语料（golden）能抓到它。
* 修法两步：给那个 `if` 体加花括号；再按**括号深度**找安全点（先把字符串字面量剥掉再数，取"深度回到 1
  且该行剥完只剩逗号或空"的位置）拆成两次 `bufPuts`。文本顺序不变 ⇒ par 程序的产物也不变；不使用区域
  的程序里那半套仍由 `#ifdef EXTC_PAR_REGION` **排除在编译之外**。
* **教训（记下来免得再犯）**：在一段**不带花括号**的 `if` 体内插入第二条语句，会**静默改变控制流**——
  编译器不报错、两种配置都"看起来正常"，只有全量产物比对（golden）能抓到。

## 5. 与并发设计共用的一层

消息线（worker 当协程 + `send` 出去父线程再 resume）需要一只**共享 arena**：worker 在它里面分配产出，
父线程直接读，不拷贝。这与 Heap 的分配器**是同一个东西**，所以只做一次：

* **原子 bump**（一次 `atomic_fetch_add` 换一块，或每个线程先从公共段领一整块再本地 bump）；
* **按区域释放**（回收粒度是块，所以寿命 = 那次并行区域 / 那次调用）；
* **"堆视图"标记位**（跨界视图必须指向它）；
* 只读共享的**可见性**由消息本身给：邮箱写入 release、父线程读取 acquire，此外不需要锁。

消息线的其余决定（按 worker_id 规范化合并、浮点固定合并树、"不用 send 的程序产物逐字节不变且仍是
6.81x"）记在 §6。

### 5.1 队列不是原语（2026-09-28 定）

**单线程没有队列。** 协作式调度下"发送"与"接收"之间没有别的东西能跑，那个缓冲区在任何一个可观察
点上要么空、要么空得没有理由，语言还得替它回答一串本来不存在的问题：没人接的时候值放哪、放多久、
谁拥有它、多个待收值按什么顺序出。在 extC 里这些就是 arena 层号问题 —— 正是逃逸规则要拦的形状。
会合（`k = yield e`）没有这些：值在两次恢复之间就活在那帧里，帧布局本来就在管那个槽。

**跨线程里队列是真需求**（两边真的各自在跑，就绪与唤醒是真问题），但它**不该作为原语出现**：池子
已经具备该有的一切 ——

| 队列需要的 | 池子已有的 |
|---|---|
| 容量（背压） | 池子大小：占不到槽的生产者就得等 |
| 所有权转移 | `take` / `give` |
| 误用要响 | 世代校验：用旧的、重复消费都是当场 trap |

缺的只有两样 O(1) 的东西：一个**单调序号**（谁下一条）与每槽一个**就绪标志**（release 写、acquire
读 —— 这一次同步就是全部的可见性）。于是"队列" = 一池消息槽 + 一个计数器，没有新结构、没有新的
寿命概念、也没有独立的满/空策略。

**载荷不进区域 arena。** 定长消息内联在槽里；大块走池子句柄（池子是箱子、消息只是钥匙），用完
`give` 回去。放进区域 arena 会踩 §3.2 那条已知的"累积"：arena 的回收粒度是块，长寿命区域里反复
分配只增不减，RSS 会随"产生过多少消息"线性上涨，而不是随"在飞多少条"。

**现在不做。** 本期只做"worker 产出、父线程 join 后读"（§4.5）；流式要等真实用户来定容量与"满了
是等还是报"。前置工作是池子的线程安全（空闲链与世代号目前是单线程写法）。

**验收（无论将来怎么实现）**：长跑用例 —— 生产者/消费者发 10^6 条消息，断言 RSS 稳定在一个小上界
而不是随时间线性上涨；再把载荷换成"大块 + 池子句柄"跑一遍。

## 6. 消息线与它的两条验收

* **保留两条路，别互相替代**：规则形状的结果（每个输出恰好写一次）继续用现在的分段借用
  （`parallel::run`，实测 8 线程 6.81x，不需要任何消息）；不规则/流式的结果走消息。
* **合并顺序按 worker_id 规范化**：父线程不必等全部到齐，最小的未合并 id 到了就合，然后推进指针。
  于是既不乱序，也不牺牲流式性；"1 个线程和 8 个线程结果一样"由这条保证（浮点再固定合并树）。
* **验收一**：不用 send/recv 的程序，生成物与现在**逐字节相同**（是静态不存在，不是"存在但不用"，
  照 `needPar` 那套可达性标记做），矩阵乘法仍是 6.81x。
* **验收二**：用了 send 的程序，父线程读到的数据与串行结果逐元素相同，且**与线程数无关**。
* **前置**：`coroutine<A,B>`（分离的请求/应答类型）尚未实现 —— 见 `LAMBDA.md` §8 的状态说明。

## 7. 明确不做的（今天不定）

* Heap 内部**不做**世代校验（少检验是设计，不是欠账）；要稳定身份就用 pool。
* **不做**符号 interposition / 全局钩子；只走 §2 那张表。
* **不做**页级 CoW、不做模块间共享可变状态（只传值）。
* **不做**多进程沙箱（2026-09-29 定：开销太大；要的是"安全的单进程管理模式"）。
* **不做**相对地址/搬移（理由见 §1.6，与性能无关）。
* **不做**板之间的共享：**一只板属于一个模块**。共享等于两个外来方互相别名，插件之间也会打架。
* 不可信模块的**沙箱**不在本文范围：本文只保证"模块的 bug 碰不到宿主内部"，不保证它不谎报自己堆里的
  内容（那属于另一条线）。
