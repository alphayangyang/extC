# 边界层（Heap）

> **一句话**：宿主与外来代码（`dlopen` 的模块、C ABI 的另一侧）之间**只传值**，宿主指针一个都不过去；
> 跨界的数据一律住在宿主拥有的一只 **Heap** 里，外来代码拿到的是**整数下标**。数据比代码活得久，
> 所以 `dlclose` 也能做得干净。

## 0. 为什么要有这一层

宿主与外来代码的麻烦从来不是"怎么调用"，而是四件事同时成立：

1. 谁**拥有**跨界的那些字节；
2. 谁可能**别名**谁（外来代码能不能拿到宿主变量的地址）；
3. 它们各自**活多久**（宿主的作用域 arena 可能比模块早结束，模块代码可能比数据早消失）；
4. 出错的**后果**（C 里是踩内存，最坏是跳到已经卸载的代码里）。

三层的分工就是按"谁用"切的：

| 层 | 给谁用 | 结构 | 寿命 | 检验 |
|---|---|---|---|---|
| arena | 自己人（同一线程、同一作用域） | bump | 词法作用域 | 逃逸/深度分析（编译期） |
| pool | 自己人（需要稳定身份、异构） | 槽 + 世代 | 显式 drop | 每次访问查世代 ⇒ 用旧的必 trap |
| **Heap** | **外来代码（模块 / C ABI）** | **槽里全是指针** | **一次调用** | **进门只查下标范围，没有世代** |

Heap 少检验是**故意的**：它面向的是"隔着一层协议说话"的另一侧，世代与别名那套在边界上本来就用不上
——因为**跨界的东西只有值**，详见 §1。

## 1. 核心不变量：只传值，宿主指针不过去

> **宿主的地址永远不出界；模块能碰的内存，全是它自己申请、由宿主发出去的。**

这条一立，§0 里第 1、2 两条的麻烦就消失了：不存在"谁拥有"，因为所有权一直在宿主手上（Heap 里）；
不存在"别名"，因为给出的是副本（或一块专供它的新内存）。

由此推出两条**操作规则**：

* **返回值一律是整数下标**（`u64`），不是指针。宿主拿着下标去自己的 Heap 里取。
  ⇒ 一个指针形状的东西都不过界，宿主那边一次范围检查就够。
* **跨界视图必须指向 Heap 内部**。extC 的视图就是 `{ptr, len}`，一个指向宿主 arena 的视图跨界，
  等于把宿主的地址递出去了 —— 破掉整条不变量。做法可以很轻：给视图加一个"在 Heap 里"的标记位
  （与 `Thread=` 一个路数），边界处查这个位。

**CoW 先做对象级，页级以后再说。** 视图本来就是 `{ptr, len}` 一个整体，整块拷进 Heap 就是"传值"，
多数时候这就够了；页级（`mmap` 只读 + 缺页时拷）是给"大缓冲区且基本只读"的优化，等测出来需要再说
——别一上来就引入信号处理。

## 2. 假嵌入：接口形态

不要靠符号 interposition（那套要 `--allow-shlib-undefined` 之类的东西，且行为随链接器漂）。明说：

```extc
/* 宿主提供，模块只用这一张表。头一个字段是大小/版本，老模块配新宿主 ⇒ 干净拒绝，不是默默错读。 */
struct extc_heap_api {
    size: u64                    /* 表的大小；宿主按它决定哪些字段存在 */
    alloc: fn(...) -> u64        /* 申请，返回下标 */
    free:  fn(...) -> i32
    copyIn: fn(...) -> u64       /* 宿主把一块内存拷进来（模块申请、宿主填） */
    copyOut: fn(...) -> i32      /* 模块要的结果拷回宿主 arena */
    len: fn(...) -> i64
}
```

```extc
/* 宿主侧：dlopen ⇒ 取 init ⇒ 把表交出去 ⇒ 之后只通过整数下标说话 */
let h = dl::open("plugin.so")
h.init(ref api)                  /* 模块记住这张表；它自己不再找宿主符号 */
let idx = h.run(i64(7))          /* 模块把结果放 Heap，返回下标 */
let v = heap.take<i64>(idx)      /* 宿主从堆里领出来 */
```

**"假嵌入"的含义**：模块不是独立程序，它必须靠宿主发内存，所以它的"空间"就是这只 Heap；它自己的
arena / pool 仍然是它自己的（**每个模块一份运行期实例**），跨界只走这张表。

## 3. 寿命：一次调用一只 Heap

> **Heap 的所有者是这次调用；调用返回时整只撤掉。宿主想留下的结果，从堆里领出来拷进自己的 arena。**

这条必须定死，否则"少检验"就会退化成"不知道什么时候没的"。有了它，Heap 内部的槽**不需要世代**：
没有哪个下标在调用返回后还有意义，而调用返回这件事是宿主自己做的，不需要外来代码配合。

## 4. `dlclose` 为什么能安全

C 里 `dlclose` 危险，是四件事叠出来的：宿主攥着**模块代码/数据的指针**、模块注册的回调还挂在宿主表里、
卸载时**还有线程在模块里跑**、模块的静态/TLS 与析构。这套设计把前两件消掉了，第三件用协议挡，第四件
随代码一起消失。

**不对称规则（关键）**：宿主内存的寿命 ≥ 模块代码的寿命，所以

* **模块可以持有宿主指针**（宿主借出去的内存在模块卸载后依旧有效）；
* **宿主不可以持有模块指针**，数据或函数都不行 —— 破了就是跳进未映射页。

**注册一律给世代句柄。** 模块在宿主表里注册的任何东西都不给裸指针，给 `{slot, gen}`：`dlclose` 时把
属于该模块的槽**世代加一**，之后谁拿旧句柄来用就是当场 trap，而不是跳进没了的代码。这就是 pool 那招
"把 use-after-free 变成一次检查"，只不过这里保护的是**代码**，不只是数据。

**卸载协议（四步，宿主记账）**：

| # | 做什么 | 不做会怎样 |
|---|---|---|
| 1 | 停发新活（或推到安全点） | 卸载期间还有调用进来 ⇒ 跑到一半的代码消失 |
| 2 | 调模块的 `deinit`（如果有） | 模块自己的收尾没做 |
| 3 | 作废该模块的所有世代句柄 | 旧句柄仍可用 ⇒ 跳进未映射页 |
| 4 | `dlclose` | —— |

**"还有没有线程在模块里跑"由宿主记账**：每次调用进出一个计数，归零才允许卸载；不归零就拒绝卸载并
报清楚（这与并发那条线的"线程要静默"是同一件事）。别指望 glibc 不真卸 —— 按最坏情况设计，真卸掉也安全
才算安全。

## 4.5 本期落地状况（2026-09-28）

**已落地**（提交 `0a53001`，判据 P16 进 `tools/attack.py` 的 par 组）：

* **区域共享 arena**：`extc_par_region` 里给每个 worker 一只 `extc_arena`，区域由 `extc_par_run`
  `calloc`，`extc_par_close` 把每只 worker arena 的块链还回去再 `free`。worker 里的 `new` 落进
  `region->arenas[id]`（`extc_tls_arena` 指过去），**worker 退出时不销毁** —— 于是父线程 join
  之后直接读，不拷贝。
* **没有原子 bump，也不需要**：每个 worker 一只**自己的** arena，bump 路径里没有任何原子操作，
  竞争在"谁拥有哪只"这一层就消掉了（比原子 bump 更省）。区域本身是每个线程一只、按运行刷新，
  所以"每线程领整块、本地 bump"那条也自然满足。
* **只在需要时开**：调用点按 worker 是否会 `new`（`usesHome`）传 `withRegion`；不开时退回线程本地
  arena 并由 worker 自己销毁，既有行为一字不改。
* **判据**：worker 各自 `new` 一段、把那段视图写进自己分段的第一格（分段互不重叠 ⇒ 不冲突），
  父线程 join 后扫出来读，校验 0..n-1 每个恰好出现一次 —— 既是"发布"的证据，也是"分区不重叠"的
  证据。t = 1/2/4/8 全部 `bad=0`。
* **性能不回归（交错 A/B，改动前 `0a53001^` 建基线编译器，同一份源码）**：矩阵乘法 n=768 f32，
  1 线程 新 308.5 ms / 旧 312.2 ms（−1.2%），8 线程 新 45.7 ms / 旧 45.2 ms（+1.0%），加速比
  新 6.76x / 旧 6.90x，两边波动区间重叠。**顺带记一条教训**：本轮先量到过 5.91x，交错 A/B 之后
  判定那是噪声，不是回归 —— 前后两次测量的差别只有交错才能分辨。

**未落地**（下一期）：邮箱与 `sched::recvAny`（流式读取）、`sendable` 规则、dlopen 的接口表与
世代句柄（§2、§4）。

**已知取舍**：

* 区域的寿命 = **本线程下一次并行运行**（那一刻关闭）⇒ 数据有效到那时为止；下一步可以考虑收紧到
  块、或放宽到显式 `release`。
* 用了 `parallel::run` 的程序，运行期块的**文本**变了：区域那两个助手函数目前无条件发射（没用它
  时是死代码，不产生告警）。语料里没有用 `parallel::run` 的程序 ⇒ golden 414/414 逐字节不变；
  要做到"连 par 程序的产物也逐字节不变"，得把区域那半套拆成单独一段按可达性发射。

## 5. 与并发设计共用的一层

消息线（worker 当协程 + `send` 出去父线程再 resume）需要一只**共享 arena**：worker 在它里面分配产出，
父线程直接读，不拷贝。这与 Heap 的分配器**是同一个东西**，所以只做一次：

* **原子 bump**（一次 `atomic_fetch_add` 换一块，或每个线程先从公共段领一整块再本地 bump）；
* **按区域释放**（回收粒度是块，所以寿命 = 那次并行区域 / 那次调用）；
* **"堆视图"标记位**（跨界视图必须指向它）；
* 只读共享的**可见性**由消息本身给：邮箱写入 release、父线程读取 acquire，此外不需要锁。

消息线的其余决定（按 worker_id 规范化合并、浮点固定合并树、"不用 send 的程序产物逐字节不变且仍是
6.81x"）记在 §6。

## 6. 消息线与它的两条验收

* **保留两条路，别互相替代**：规则形状的结果（每个输出恰好写一次）继续用现在的分段借用
  （`parallel::run`，实测 8 线程 6.81x，不需要任何消息）；不规则/流式的结果走消息。
* **合并顺序按 worker_id 规范化**：父线程不必等全部到齐，最小的未合并 id 到了就合，然后推进指针。
  于是既不乱序，也不牺牲流式性；"1 个线程和 8 个线程结果一样"由这条保证（浮点再固定合并树）。
* **验收一**：不用 send/recv 的程序，生成物与现在**逐字节相同**（是静态不存在，不是"存在但不用"，
  照 `needPar` 那套可达性标记做），矩阵乘法仍是 6.81x。
* **验收二**：用了 send 的程序，父线程读到的数据与串行结果逐元素相同，且**与线程数无关**。
* **前置**：`coroutine<A,B>`（分离的请求/应答类型）尚未实现 —— 见 `LAMBDA.md` §8 的状态说明。

## 7. 明确不做的（今天不定）

* Heap 内部**不做**世代校验（少检验是设计，不是欠账）；要稳定身份就用 pool。
* **不做**符号 interposition / 全局钩子；只走 §2 那张表。
* **不做**页级 CoW、不做模块间共享可变状态（只传值）。
* 不可信模块的**沙箱**不在本文范围：本文只保证"模块的 bug 碰不到宿主内部"，不保证它不谎报自己堆里的
  内容（那属于另一条线）。

## 8. 留下来的问题（要作者拍）

2. `deinit` 是**强制**还是可选？（建议强制，理由是线程静默需要它。）
3. C ABI 那一侧是否也强制"返回值只能是整数下标"？（建议是；要返回字符串就返回堆内视图的下标。）
4. Heap 与 arena 的**转换**在哪一侧做：宿主 `copyOut` 时直接落到调用者的 arena 层号上？（建议是，接现有深度规则。）
