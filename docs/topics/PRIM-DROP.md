# 运行时块的"按需发射"：诊断与方案（研究材料）

> **状态：研究完成，方案待批。** 2026-10-04。**代码未动**（`__attribute__((unused))` 仍是兜底）。
> 结论一句话：**规则本来就对，那个符号只是"没被那条 pass 看见"。**

## 一、现象

一个**不打印结构化类型**的程序，生成物里照样有 `extc_print`（且只有它自己函数体里的递归调用
提到它 ⇒ 没有外部使用者）⇒ `-Werror=unused-function` 直接毙掉（实测：往 `stdlib/std/io.extc`
加几个 helper 就让 `tests/coro` 六个夹具全灭）。当时的兜底是给它加 `__attribute__((unused))`。

## 二、诊断（三块拼图，全部在 `src/back/codegen.c`）

**① "没人用就删"的规则本来就有，而且是行级的**（`dropRuntimeDefs`，5904 起）：

```c
size_t total  = countMentions(text, name);                 /* 整篇里这个名字出现几次 */
size_t inside = countMentionsIn(g, ln, span, name);         /* 它自己那段片段里出现几次 */
if (total == inside) { ...删掉... }                          /* 除了它自己，没人提到 ⇒ 删 ✓ */
```

`span` 用**大括号配对**量出（不是"第一个列 0 的 `}`" —— 注释说明那样会在文本已被删过的情况下
走到别人身上）。**自递归的调用就在 `span` 之内 ⇒ 天然不算"外部使用"** ✓ 规则是好的。

**② 但它只扫一个缓冲区**：`dropRuntimeDefs` 的入口是 `if (!g->primText) return;` —— 只看 `primText`。

**③ `extc_print` 根本不在那个缓冲区里**：

| 事实 | 位置 |
|---|---|
| `Buf rtPrint; /* `extc_print` - only if a structured type is printed */` | 264 |
| `bufPuts(&g.rtPrint, ...)` 写它的定义 | 7705 |
| **`if (g.needRuntime) bufPuts(out, bufCstr(&g.rtPrint));`** ← **整块发出** | **8665** |

⇒ 所以：`needRuntime` 是个**很粗**的条件（任何需要运行时块的程序都会置上它，比如我加的几个
`io` helper），块一发出就是**整块**，而块里的符号**享受不到**那条"没人用就删"的 pass ✓✓
**这就是根因**，而且它是"**整块发射** × **文本级删除**"这个组合的通用毛病，不是 `extc_print` 独有。

**顺带一条已修的旧账**：描述符表的注释里曾写着 `extc_print` 这个名字，而那条判定是**文本计数**
⇒ 注释里提一次 = 一次"外部使用" ⇒ 即使它进了那条 pass 也删不掉。**已修**（注释不再写这个名字）。

## 三、方案

### 原则

**不要修"什么时候发射"那个粗条件**（它的注释里写着真出过 bug：漏发 = 生成物坏掉 ✗），
而是**把块纳入那条已经在跑的删除 pass** —— 让"没人用就删"这条规则**覆盖到它**。

### 做法（二选一，倾向前者）

| 方案 | 内容 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）** | `dropRuntimeDefs` 的扫描文本**改为参数**（现在硬读 `g->primText`），然后对 `primText` 与 `rtPrint` **各扫一遍** | ~20 行 | 低。规则不动，只是多喂一个缓冲区 |
| B | 把 `rtPrint` **无条件**追加，完全交给 pass 裁 | 更少行 | 中：要求 pass 在"拿不准"时一律保留 ✓（它本来就是保守方向），但会改变所有产物的文本 ⇒ 快照差异更大 |

两条都不动 `needRuntime` ✓。

### 先写判据（这是上一轮失败买来的教训）

这件事**没有任何夹具覆盖** ⇒ "删错了"只能靠全语料撞见，"删不掉"则完全看不见 ✗。所以**先加判据**：

1. **J1**：不打印结构化类型的程序 ⇒ 生成物里**没有** `extc_print`（`grep -c` 为 0）；
2. **J2**：打印结构化类型的程序（`print(p)`）⇒ **有**它，且**程序输出不变**（防止"删过头"）；
3. **J3**（守规则本身）：一个**自递归、没人调用**的普通函数 ⇒ 生成物里没有它。
   （J3 走的是**函数删除**那一路，和本方案不是同一条 pass —— 它现在是**坏的**，见下。）

### 验证顺序

1. J1/J2 先加进 `tests/`（跑在**改动之前**：J1 必红 ✓ 记录"红"的样子）；
2. 落方案 A；
3. `tests/coro` + `tests/pool`（**哨兵**："只导入、不打印结构化类型"）+ 全语料（414 份必须仍是合法 C）；
4. 快照差异会**变大**（那些产物丢掉了一个未使用的函数 ✓ **预期内、可解释**，不是漂移）；
5. 最后**删掉 `__attribute__((unused))`** —— 它存在的唯一理由就是这件事。

## 四、明确不在本方案内（避免混做）

* **J3（函数那一路的自递归）**：`countGet(&counts, name) != 2` 那条规则同样被自递归喂坏 ✗。
  我试过换成"现场扫文本"，**把活函数也删了**（`tests/coro` 14/21），已自动回退 ✓ ——
  那条路要**先钉不变量**（`counts` 里的 "2" 是"原型 + 定义"，`countSpan(-1)` 在删除时怎么维护它），
  再动。**单独立项**。
* `needRuntime` 本身的粒度 ✗ 不动（理由见上）。
