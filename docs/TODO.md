# 待做（唯一清单）

**规则**：条目做完就搬进 [`usage/`](usage/)（或者舍弃）；砍掉就**直接删掉**，不留"已取消"。

写条目时讲清**要什么行为**，不要写"改哪个文件"——文件名会变。

## 已排定顺序

- **`view<T>` 改名**：把 `slice<T>` 改名成 `view<T>`，"slice" 留给切片操作。纯机械改动，单独一次做完。
- **checked 原语 + trap 统计**：先给切片索引、整数窄化、除法、移位补上"可检查"的版本（纯标准库新增，
  不动语言），再把"有多少 trap 是输入相关、本来可以恢复的"变成一个数字 —— 那个数字决定隐式传播要覆盖什么。
- **`mut` 权限挂根的判据**：方向已定（权限挂在根上，就地写 `mut`，由编译器查根是否可变），
  但**先要判据**：造一批"把只读根洗白成可写视图"的攻击形状（经过字段、局部拷贝、结构体字面量、
  deref 拷贝、函数返回、容器、协程），能红才实现。**没有红判据不实现。**
- **堆的逐对象回收**：`std::heap` 的板现在只能整体归还。原型里已经验过"一次保留、按需提交、按尺寸类回收"
  的形态，把那部分搬进来（或做成第三种容器基座）。
- **账本收缩**：清掉活文档里残留的状态句；把"禁止历史词"接进验收。
- **push 未同步的 commit**。

## 语言设计：还没定

- **大对象的值 / 句柄语义**（搁置中）：`string` 要不要改成不可变值语义加显式 `StringBuilder`；

## 缺陷与已知洞

- **`!` 出现在赋值目标里时会求值两次**：`(*f()!).field = v`（`f` 返回 `?mut ref T`）会调用 `f` 两次
  —— 解包生成的那段非空断言把操作数写了两遍。同一个写法去掉 `*`（`f()!.field = v`）会被拒（不是一个 place）；
  普通解引用 `(*f()).field = v` 不受影响，是单次求值。
  修法：赋值目标里遇到"不是 place 的指针表达式"时，先用一个指针临时量接住再写它指的东西；
  修好之后 `f()!.field = v` 也可以重新开放，而且是单次求值。
- **两个标准库/模块的编译期缺口**（都已实测复现）：
  ① 同时 `use stl::linmap`、`use stl::string` 并实例化以 `slice<u8>` 为值的映射时，
  生成的 C 里出现重复的 `option_slice_u8` 定义 ⇒ 编译失败；
  ② 非入口模块里的 `@export` 函数被同程序另一个模块调用时，定义发成 `f`、调用点写 `mod$f` ⇒ C 编译失败。
- **`<<` 链的实参从右往左求值**：`io::cout << "x" << a() << b()` 里 `b()` 先于 `a()`。
  后果是 `<< dl::close(h)` 这类"释放"写在同一个表达式里会**先释放再使用**（实测段错误）。
  要么给 `<<` 定一个从左到右的求值顺序，要么在文档里把"释放必须另起一句"写成硬规矩。
- **逃逸健全性闸门还剩一条**：`yield ref <帧内局部>` 被前端接受，生成物是畸形的 C。
- **AST 冻结施工单还剩几十条**：解析器之外的代码仍在写 AST。
- **产物指纹基线已失效**：它当前与主线大量不一致，不能再用作"我改了没有"的预言机。要么重取，要么放弃它。

## 语言功能（已定案、未实现）

- `f"…"` 的格式说明符（对齐、补零、定点小数）。
- `if let` 部分匹配。
- `owned`：让 `extern!` 能声明"返回的内存归调用者"。
- `@main` 注解（不再硬编码 `main`）。
- 线程：保守的 fork-join 加归约，引用不过线程。
- 字面量切片的深度放宽（静态存储里的字面量本来就是深度 0，现在偏保守）。
- 失败处理的后续：`if let` → `?` 允许错误转换 → 隐式传播。错误载体是纯值（码、文件、行），
  能不能失败由编译器推断；现在 `?` 只在少数语句位置合法，要能覆盖任意表达式位置。
- 模块：特权模块名单未封闭；类型名跨模块"必须限定"没挡严。
- 协程：请求只能表达"等可读"，没有"等可写"。
- 域 `ext`：域内写 `ext` 仍是编译错误。
- 范围类型（让索引可证明，从而免掉检查）。

  被 `tests/http/*` 直接引用（即它们事实上是**被测试的使用面**）。要么把它们写进文档，
  要么把测试改成只走公开入口 —— 在此之前不要标私有。
- `docs/usage/` 的**公开面欠账 35 个**（覆盖率棘轮基线）：其中大半是**内部助手与状态字段**——
