## 缺陷与已知洞

- **打开计数比清扫贵一个数量级（计数路线的真正门槛）**：同形状同规模比总指令，清扫侧只占
  **0–22%**，而打开计数的代价是 **+100%~+455%** —— 钱花在"地址→槽查表 + 旁路元数据读改写"
  （`ownSlab` 约 33 条指令/次、`holdUpdSlab` 同量级，每次计数两次查表），而原型的计数是
  "对象里的一个字段直接改"（约 1 条指令）。**发射层特化（每站点内联缓存/守卫）救不了**：
  把查找整段减掉后，计数价仍是清扫侧的 2.5–17 倍（清扫本来不跑的形状是无穷倍）。
  ⇒ 计数路线要成立，前提是**槽布局改动（计数进对象头）**，让单价降到约 3 条指令；即便到了那一步，
  也只有"清扫真的在跑"的形状会赢（实测估计 `spectrum_p4` 赢 9.7×、`spectrum_p5` 赢 2.7×，
  其余输）。证据、上界与逐形状数字见
  [`tests/reclaim-perf/TAXMAP.md`](../tests/reclaim-perf/TAXMAP.md) 第 9 节。
- **事件档的计数不完备：局部引用绑定只加不减**（**已冻结为诊断档**，见下）。事件档（计数开、清扫关）下，
  `var p = new node` 这样的局部绑定被算成一个持有者，而**作用域退出、每轮 arena 归还、函数返回都不销账**
  ⇒ 每个对象带一个幽灵持有者，计数永不归零 ⇒ 垃圾随规模线性涨（覆盖/淘汰/窗口三类形状 4N/N 峰值
  3.3–3.7×）。**决定不修**：实测事件档在语料里没有一个能赢的形状（有环形状上不成立 —— 强制用在
  `ring_per_round` 上 N=8000 涨到 8 369 MB；无环形状上会漏；就算不漏计数也比清扫贵 +100%~+455%），
  所以它降级为默认关的诊断开关，判据摘出电池（`gate-acyclic` 自报 manual、原 `gate-event-bounded` 删除）。
  **若将来要复活**：先给离开作用域的引用绑定补销账 + 立"inc/dec 配对"判据（配不平的区域不许关清扫），
  并先解决计数单价（见上一条）。现象、根因与量法教训见
  [`tests/reclaim-perf/TAXMAP.md`](../tests/reclaim-perf/TAXMAP.md) 第 7 节。
- **`!` 出现在赋值目标里时会求值两次**：`(*f()!).field = v`（`f` 返回 `?mut ref T`）会调用 `f` 两次
  —— 解包生成的那段非空断言把操作数写了两遍。同一个写法去掉 `*`（`f()!.field = v`）会被拒（不是一个 place）；
  普通解引用 `(*f()).field = v` 不受影响，是单次求值。
  修法：赋值目标里遇到"不是 place 的指针表达式"时，先用一个指针临时量接住再写它指的东西；
  修好之后 `f()!.field = v` 也可以重新开放，而且是单次求值。
- **两个标准库/模块的编译期缺口**（都已实测复现）：
  ① 同时 `use stl::linmap`、`use stl::string` 并实例化以 `slice<u8>` 为值的映射时，
  生成的 C 里出现重复的 `option_slice_u8` 定义 ⇒ 编译失败；
  ② 非入口模块里的 `@export` 函数被同程序另一个模块调用时，定义发成 `f`、调用点写 `mod$f` ⇒ C 编译失败。
- **`<<` 链的实参从右往左求值**：`io::cout << "x" << a() << b()` 里 `b()` 先于 `a()`。
  后果是 `<< dl::close(h)` 这类"释放"写在同一个表达式里会**先释放再使用**（实测段错误）。
  要么给 `<<` 定一个从左到右的求值顺序，要么在文档里把"释放必须另起一句"写成硬规矩。
- **逃逸健全性闸门还剩一条**：`yield ref <帧内局部>` 被前端接受，生成物是畸形的 C。
- **AST 冻结施工单还剩几十条**：解析器之外的代码仍在写 AST。

## 回收的量具与访存局部性（口径只写在 RECLAMATION「四.一」）

口径的**单一真源**是 [`RECLAMATION.md`](RECLAMATION.md) 的「四.一」：`[step]` 桶的实际阈值、
`EXTC_RC_SLOWSTEP` 的可用区间、"p99"指哪一种。本节只留"要做什么"，不复制口径。

- **`[step]` 的桶打不出细粒度**：1 / 4 / 16 µs 三档只计数、**不打印**，打印出来的
  `over16/over64/over256/over1ms` 从 16 µs 起步 ⇒ 单看 `[step]` 行**读不出 p99 ≤ 10 µs**。
  要做的：把细桶打出来，并/或补 4 µs、10 µs 两个**纯计数**桶；同时把桶标签写成阈值明确的形式
  —— 现在的计数器按**上界**命名，`over16` 的求和里出现 `B64us` 是设计如此，按字面读会得出错的
  阈值。纯计数、不扰动。
- **`EXTC_RC_SLOWSTEP` 低阈值不可用**：阈值单位 µs，且只在 `EXTC_RC_PAUSE` 打开时才解析生效；
  阈值压到几 µs 时大部分步都打印，整轮被 stderr 拖慢、外层计时作废。口径在 RECLAMATION「四.一」；
  这里要决定的是**要不要让它自己防呆**（低阈值限速/聚合，或直接拒绝小阈值）。
- **新 open：标记遍历的访存局部性（locality）**。证据（结论）：callgrind 缓存模拟下 `markStep`
  的**指令占比很小，却占 L1 数据读缺失的将近一半**；同一个步预算下**每对象成本随堆增大数倍**
  （DRAM 延迟量级）。出处：Lead 实测，已入库 [`archive/2026-10-15-locality.md`](archive/2026-10-15-locality.md)
  （callgrind 缓存模拟与"两个 p99 口径"的原始表都在那里）。候选方向：`ownSlab` 热缓存
  （单路/多路已有）；按 slab 局部性排序遍历；预取下一个对象；把每个对象要碰的几样（slab 头 /
  `occ` 位图 / 对象头 / 子字段）靠近或合并；**清扫预算按槽而不是按字**（字粒度下 1 字最多 64 槽
  ⇒ 最小清扫步仍可能远大于目标量级）。判据口径见 RECLAMATION「四.一」（"p99"要区分每步时长与
  每 run 最大步）。

### P5 超线性：诊断路线（自修用）

对应上面第 1 条。**先量后改**；每步只给"怎么取"，预期数字自己量。口径提醒：`[pause]` 只圈武装
窗口、是**下界**（成批推进 `markAdvance` 在武装之前、收尾不武装）⇒ 量"回收总时间"看 `[step]` 总量。

1. **数轮数 vs 规模（现在没有 `cycN`）**。两个现成量：`[pause] collects=`（= `extc_rc_pauseN`，
   在 `extc_rc_maybeCollect`/`extc_rc_checkOwed` 里自增）与 `[step] n`（子步数）。注意 `collects`
   数的是**武装窗口里真正进了 `extc_rc_step` 的次数**（起轮 + 在飞轮的每一次推进），**不是纯轮数**。
   在 **6M / 20M 两点**分别记两个数（同口径、同 `taskset -c 6`、best-of-N）⇒ 看谁随规模涨。
   要**纯轮数**就临时在"起轮那一点"加一个计数器（`!r->marking` 且触发通过处，即起轮调用点），
   一次性插桩、别提交。
2. **每轮标记量**。`[work] n`（有界热路径步数）+ `[worst]`（最坏步的 `pops`/`marked`）+ `[ubwork]`
   （无界步，正常应为 0）⇒ 估每轮弹了多少对象；与活集比（`r->live`；走访问器会 `settle`，
   只在非热路径或临时打印里取）。若"每轮量 ≈ 当前活集"且活集随 N 增长，第 1 步又显示轮数不降
   ⇒ 就是**轮数 × 活集**。
3. **阈值 / 触发账（锚点）**。函数名是稳定锚点；行号是当前树 `src/back/reclaim.c`
   （md5 `3361ee46…`），改代码后会漂：
   - 触发条件：`extc_rc_shouldSweep` 末句 `r->bytes > r->thr && extc_rc_roundOk(r)`（~1693–1702）；
   - 阈值重算 `extc_rc_thrUpd`：`thr = max(live×2, floor) × scale`（`scale` 溢出 ⇒ `thr = 0`）（~1681–1686）；
   - 起轮信用 `extc_rc_roundOk`：`allocBytes - roundVisitedBytes ≥ max(live, floor)`（~1689–1692）；
     **它与定点释放的 `visitedBytes` 是两本账**；
   - 窗口加力：`allocBytes - markStartAlloc > EXTC_RC_MARK_WINDOW ⇒ 该步预算 ×8`（~642；常量 ~535）；
   - 记账字段（结构体 `ExtcRcRegion`，~158–162）：`bytes`/`allocBytes`/`visitedBytes`/
     `roundVisitedBytes`/`live`/`floor`/`thr`；分配侧 `allocBytes += ss`（~695），释放侧
     `bytes -= ss`（`extc_rc_freeSlot`，~820），起轮/结轮消费信用（~1558、~1784–1796）。
   ⇒ 随规模记 `live`/`bytes`/`thr` 三点（临时打印最省事）。
4. **两条判定实验（先分辨"轮数"还是"单轮成本"）**。动手前先算**残差**（墙钟 − Σ`[step]`）：
   §10 已给出"超线性的大头在 `[step]` 之外"，所以**第一步是把那部分拆开**，而不是只盯 `[step]` 的桶。
   - **(a) 把阈值抬到极高**（临时让 `shouldSweep` 只在 `bytes` 超过一个大常数时成立）⇒ 若**轮数降到 1
     且总时间回到线性** ⇒ 根因是**轮数 × 活集**；改法方向 = 触发策略/自适应阈值（上面那本账），
     或把标记做成增量/分代。
   - **(b) 若轮数 = 1 仍超线性** ⇒ 根因在**单轮成本**：先查残差里那几类路径（槽管理 `extc_rc_alloc`、
     引用计数/写屏障 `storeRef*`、起轮种子压栈、cache/TLB），再查 glue 与遍历本体。glue 怎么取 = 在
     生成物里 `grep` 三个调用点各几处（`extc_rc_regionOf`/`extc_rc_shouldSweep`/`extc_rc_maybeCollect`；
     复核时是 **8 / 6 / 4** 处，会随发射点改动漂，以现场为准），发射点在 `src/back/codegen.c` 的
     `rcEmitTrigger`/`rcEmitOwe`/`rcEmitOwedCheck`/`rcAllocCore`；单轮成本超线性也可能是**访存局部性**
     （见「回收的量具与访存局部性」一节与 [`archive/2026-10-15-locality.md`](archive/2026-10-15-locality.md)）
     ⇒ 改法方向 = 把 glue 提出循环/减少每元素查表，或按 locality 的候选方向（清扫按槽、热缓存、预取…）。
5. **改完怎么验**：6M / 20M 两点 on/off 比值（目标：`on` 收到 `off` 的 ~1.2× 以内，且**保住 RSS 收益**
   ——`off` 档 RSS 明显更高）、重估幂次、记 `[step]` 总量占墙钟比；语义 **8/8**（五形状 + P2/P4/P6 与
   `EXTC_RECLAIM=0` 逐字相同）+ `digraph` **7984/1772** 逐字；reclaim 那组闸门（`count-unit`/`switch`/
   `count`/`gaps` 等）+ `gate-reclaim-work` + `gate-shard-cycles` + `nobench`/`docs`/`smoke`
   （`gate-shard-cycles` 仍挂 `bench`，`nobench` 盖不到，别忘单独跑）；指纹**同提交重冻**。
   记 on/off 比值时**必须带上那条硬警告**：`off` 臂连分配器一起换（纯 bump arena）⇒ 比值不是纯 GC 税。

## 语言功能（已定案、未实现）

- `f"…"` 的格式说明符（对齐、补零、定点小数）。
- `if let` 部分匹配。
- `owned`：让 `extern!` 能声明"返回的内存归调用者"。
- `@main` 注解（不再硬编码 `main`）。
- 线程：保守的 fork-join 加归约，引用不过线程。
- 字面量切片的深度放宽（静态存储里的字面量本来就是深度 0，现在偏保守）。
- 失败处理的后续：`if let` → `?` 允许错误转换 → 隐式传播。错误载体是纯值（码、文件、行），
  能不能失败由编译器推断；现在 `?` 只在少数语句位置合法，要能覆盖任意表达式位置。
- 模块：特权模块名单未封闭；类型名跨模块"必须限定"没挡严。
- 范围类型（让索引可证明，从而免掉检查）。

## 标准库

- 补齐字符串与序列操作：切分、连接、去空白、替换、带下标遍历、拉链。
- 容器缺的成员：动态数组的**中间插入与删除**（`pop` 已有：去尾不成问题）。
- 一次读满整块（读满给定缓冲的语义）；格式化输入（现在只有 `nextInt` 这类逐项读）。
- HTTP 客户端：分块编码、头部折叠、TLS、代理、cookie。

## 编译器内部（可整体搁置）

- 多文件输出 / 运行时独立 TU（收益未测）。
- 协程协议换成枚举（要先修协程类型两个槽位的精度）。
- 清理活函数内部未用的局部。
- 调度器"一个 fd 一个等待者"。

## 文档工程

- `docs/usage/` 的**公开面欠账 35 个**（覆盖率棘轮基线）：其中大半是**内部助手与状态字段** ——
  标准库的约定是"成员缺省公开，`@private` 才是内部"，所以 `inSync` / `depth` / `isSpace` 这类
  也算进了公开面。两条路：真对外的补进 `stdlib.md`；其余**标 `@private`** 收口，让清单反映真实 API。
- **这批欠账里有一部分不能靠标 `@private` 解决**：`std::http` 的 `findSub` / `putBytes` / `lower`
  被 `tests/http/*` 直接引用（它们事实上是**被测试的使用面**）。要么写进文档，
  要么把测试改成只走公开入口 —— 在此之前不要标私有。
- **`typeContainsProto` 的三个调用点都写成 `if (0 && …)`**（都在 `check_expr.c`），即恒不执行，
  函数本身还在。要么启用，要么连调用点一起删。
- **给公开 API 继续补 `@code` 使用例**（现有 10 段：`b64` · `hashMap` · `string` · `varArray` ·
  `pool` · `map` · `sha256` · `vector` · `fs` · `json`）。`std::io` 的重载细节、`hmac`、
  `std::net` / `ws` 等还没有。
- 语言页还缺最小例子：协程（`coroutine<A,B>` / `yield`）与域（`ext`），
  以及 `--dump-effects` / `--dump-tokens` 的输出格式说明。
