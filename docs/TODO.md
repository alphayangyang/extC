## 已排定顺序

- **`view<T>` 改名**：把 `slice<T>` 改名成 `view<T>`，"slice" 留给切片操作。纯机械改动，单独一次做完。
- **checked 原语 + trap 统计**：先给切片索引、整数窄化、除法、移位补上"可检查"的版本（纯标准库新增，
  不动语言），再把"有多少 trap 是输入相关、本来可以恢复的"变成一个数字 —— 那个数字决定隐式传播要覆盖什么。
- **`mut` 权限挂根的判据**：方向已定（权限挂在根上，就地写 `mut`，由编译器查根是否可变），
  但**先要判据**：造一批"把只读根洗白成可写视图"的攻击形状（经过字段、局部拷贝、结构体字面量、
  deref 拷贝、函数返回、容器、协程），能红才实现。**没有红判据不实现。**
- **堆的逐对象回收**：`std::heap` 的板现在只能整体归还。原型里已经验过"一次保留、按需提交、按尺寸类回收"
  的形态，把那部分搬进来（或做成第三种容器基座）。
- **区域回收**（机制见 [`RECLAMATION.md`](RECLAMATION.md)，数值见 `prototype-reclaim/`）。
  目标：不可达但仍占着存储的对象要有界，且**界与循环轮数无关**；停顿只与被扫区域有关、与整个堆无关。
  四层机制（本地整片释放、提权、计数归零、区域清扫）在默认路径上。清扫的覆盖还有缺口：八类形状的
  界仍随规模增长（其中七类比关掉回收还差）；它们是同一个动作的后果 —— **编译器在「列不全」的
  时候选择「不扫」**。要做的：
  1. **把「根」收敛成一个来源、一条链**：活引用槽的位置现在按词法作用域分函数拼；改由逃逸分析那一份
     「引用槽在哪、指向什么、活到哪一层」的事实统一产出，运行期只维护一条任何触发点都走得通的根链
     （帧节点 + 槽表 + 线程本地链）。这一步顺带覆盖"拥有者只调一次"与"被调者自己长循环"两类。
  2. **把「宿主」收敛成一条规则**：写引用时把目的地**求值一次**再逐叶落账，消掉"证不出宿主就整区域
     不扫"。现在同一条规则在检查器与代码生成里各有一份拷贝、粒度还不一致，要合成一份。
  3. **把「别收」的出口合成一个**：现在有四种互不相干的表达（编译期的区域级与函数级、运行期的
     一次性与永久），各自在不同地方查。
  5. **「这个区域不需要回收」的证明（按区域不发射 rc 运行期）** —— 目标口径最大的一块：现在
     只要程序里有一个受治理的分配点就**整程序**发射 rc；而 `bt` 这类"建好一棵树、遍历一遍、
     块退出整块丢弃"的形状根本不需要清扫，却在 in-small 上付 **12.0%**、全输入上 **1.4%** 的税。

     **判据（要精确，不能退化成"没有 ref 赋值"这种 trivial 规则）**：一个区域（= 一个 arena 层）
     满足以下三条 ⇒ 不需要回收：
       (a) 该区域内堆对象的每个 **ref 字段**在**每个对象上最多被写一次**（初始化，不是覆盖）——
           可判形状：该字段全程序只有一个 store 站点，宿主是**本帧新局部量**，且该站点每对象只执行
           一次（不在重访同一对象的循环里）；
       (b) **ref 类型的局部量/参数不被重新赋值**（声明初始化不算）—— 这是"最后一个根被丢掉"的唯一
           静态可见形式；
       (c) **没有丢引用的操作**：容器删除/替换、`@overwrite` 复用同一格子、free 类内建，以及任何
           **（传递地）违反 (a)/(b)/(c) 的被调函数**。
     ⇒ 三条成立时，区域内的对象只会随区域整体释放而消失，清扫无事可做 ⇒ 不发射 rc。

     **为什么不 trivial**：判据 (a)(b) 都需要**类型信息**才能问"这个位置是不是 ref" —— 否则
     `i = i + 1`、`d = d + 1` 都会被当成丢引用，规则立刻退化（`bt` 自己就有这些循环变量）。
     它覆盖的是一整个**真实类别**：解析器、变换器、测试里"建起来—读一遍—整块丢"的结构。

     **失败方向是安全的**（这一点决定了判据该往哪边保守）：rc 只释放**标记不到**的对象，关掉它
     只会释放得更少 ⇒ 错了是**内存涨**，不是悬垂。所以：
       · 反例判据 = **内存有界**（同一形状开/关 rc 的峰值 RSS 之比必须在界内）；
       · 红证明 = 把判定强制为真施加于**会丢引用**的形状（`cyclic_pressure`/`churn`）⇒ RSS 必须
         爆掉（第四十X刀的 no-trigger 消融就是这个形态：5 MB → 778 MB）。
     先有这两条判据，再动发射。

     判据 (a)/(b) 要的类型信息在检查器里（`planXxx` 只读访问器 + 冻结字段清单那套）；实现分两步：
     先在**所有被用函数**上算这三条（全函数都算 ⇒ 传递性自动覆盖，不需要不动点），再让
     `scanUnitReclaim` 在"分配点存在"之外追加"回收可能有事可做"。
     预期收益：`bt` in-small **12.0% → ~0**、全输入 **1.4% → ~0**；`rebuild`（每轮整块丢弃）也可能
     命中，那就是 3.7% 的因果税一起拿掉。

     * **复用现成的 arena 层事实 —— 不通**：`planArenaLevel` 只记在**分配站点**上，值表达式
       （局部量、字段读）拿不到它 —— 连"两个显然同区的局部量"打出来也是未记录（0）。
     * **"值是本帧新局部量" —— 通，但全语料只命中 1 个赋值点**（零新分析，codegen 自己就知道）。
     * **"值是被调者返回本帧 home 区新对象" —— 命中热点但覆盖面窄**：98 个赋值点里 8 个可证，
       其中 `bt` 2/2（目标口径那一档，约 1.4 个点）；其余 90 个的值是局部量与字段读，要的是
       **值级数据流**（分析现在只算"要求"并改写分配层，不留"某个局部量住在哪个 arena"），
       那是另一个量级的工程，收益还集中在少数形状。

     结论：**先做第二条**（便宜、零分析）；第三条要新建一份函数摘要（走 `an`/`plan` 访问器 +
     冻结字段清单），做之前先确认值不值。
     **先有判据再实现**：跨区登记判据（`gate-reclaim-switch` 的 `cross-region` 形状）必须能
     抓住"证错 ⇒ 漏登记 ⇒ 悬垂"的后果。

## 缺陷与已知洞

- **`!` 出现在赋值目标里时会求值两次**：`(*f()!).field = v`（`f` 返回 `?mut ref T`）会调用 `f` 两次
  —— 解包生成的那段非空断言把操作数写了两遍。同一个写法去掉 `*`（`f()!.field = v`）会被拒（不是一个 place）；
  普通解引用 `(*f()).field = v` 不受影响，是单次求值。
  修法：赋值目标里遇到"不是 place 的指针表达式"时，先用一个指针临时量接住再写它指的东西；
  修好之后 `f()!.field = v` 也可以重新开放，而且是单次求值。
- **两个标准库/模块的编译期缺口**（都已实测复现）：
  ① 同时 `use stl::linmap`、`use stl::string` 并实例化以 `slice<u8>` 为值的映射时，
  生成的 C 里出现重复的 `option_slice_u8` 定义 ⇒ 编译失败；
  ② 非入口模块里的 `@export` 函数被同程序另一个模块调用时，定义发成 `f`、调用点写 `mod$f` ⇒ C 编译失败。
- **`<<` 链的实参从右往左求值**：`io::cout << "x" << a() << b()` 里 `b()` 先于 `a()`。
  后果是 `<< dl::close(h)` 这类"释放"写在同一个表达式里会**先释放再使用**（实测段错误）。
  要么给 `<<` 定一个从左到右的求值顺序，要么在文档里把"释放必须另起一句"写成硬规矩。
- **逃逸健全性闸门还剩一条**：`yield ref <帧内局部>` 被前端接受，生成物是畸形的 C。
- **AST 冻结施工单还剩几十条**：解析器之外的代码仍在写 AST。

## 语言功能（已定案、未实现）

- `f"…"` 的格式说明符（对齐、补零、定点小数）。
- `if let` 部分匹配。
- `owned`：让 `extern!` 能声明"返回的内存归调用者"。
- `@main` 注解（不再硬编码 `main`）。
- 线程：保守的 fork-join 加归约，引用不过线程。
- 字面量切片的深度放宽（静态存储里的字面量本来就是深度 0，现在偏保守）。
- 失败处理的后续：`if let` → `?` 允许错误转换 → 隐式传播。错误载体是纯值（码、文件、行），
  能不能失败由编译器推断；现在 `?` 只在少数语句位置合法，要能覆盖任意表达式位置。
- 模块：特权模块名单未封闭；类型名跨模块"必须限定"没挡严。
- 范围类型（让索引可证明，从而免掉检查）。

## 文档工程

- `docs/usage/` 的**公开面欠账 35 个**（覆盖率棘轮基线）：其中大半是**内部助手与状态字段** ——
  标准库的约定是"成员缺省公开，`@private` 才是内部"，所以 `inSync` / `depth` / `isSpace` 这类
  也算进了公开面。两条路：真对外的补进 `stdlib.md`；其余**标 `@private`** 收口，让清单反映真实 API。
- **这批欠账里有一部分不能靠标 `@private` 解决**：`std::http` 的 `findSub` / `putBytes` / `lower`
  被 `tests/http/*` 直接引用（它们事实上是**被测试的使用面**）。要么写进文档，
  要么把测试改成只走公开入口 —— 在此之前不要标私有。
- **`typeContainsProto` 的三个调用点都写成 `if (0 && …)`**（都在 `check_expr.c`），即恒不执行，
  函数本身还在。要么启用，要么连调用点一起删。
- **给公开 API 继续补 `@code` 使用例**（现有 10 段：`b64` · `hashMap` · `string` · `varArray` ·
  `pool` · `map` · `sha256` · `vector` · `fs` · `json`）。`std::io` 的重载细节、`hmac`、
  `std::net` / `ws` 等还没有。
- 语言页还缺最小例子：协程（`coroutine<A,B>` / `yield`）与域（`ext`），
  以及 `--dump-effects` / `--dump-tokens` 的输出格式说明。
