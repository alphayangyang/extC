## 已排定顺序

- **语法糖**（用户指定先做，并行往后放）：候选取自下面「语言功能」——`f"…"` 的格式说明符、
  `if let` 部分匹配、`?` 覆盖任意表达式位置。先定做哪一个再动手。
- **`view<T>` 改名**：把 `slice<T>` 改名成 `view<T>`，"slice" 留给切片操作。纯机械改动，单独一次做完。
- **checked 原语 + trap 统计**：先给切片索引、整数窄化、除法、移位补上"可检查"的版本（纯标准库新增，
  不动语言），再把"有多少 trap 是输入相关、本来可以恢复的"变成一个数字 —— 那个数字决定隐式传播要覆盖什么。
- **`mut` 权限挂根的判据**：方向已定（权限挂在根上，就地写 `mut`，由编译器查根是否可变），
  但**先要判据**：造一批"把只读根洗白成可写视图"的攻击形状（经过字段、局部拷贝、结构体字面量、
  deref 拷贝、函数返回、容器、协程），能红才实现。**没有红判据不实现。**
- **堆的逐对象回收**：`std::heap` 的板现在只能整体归还。原型里已经验过"一次保留、按需提交、按尺寸类回收"
  的形态，把那部分搬进来（或做成第三种容器基座）。
- **区域回收**（机制见 [`RECLAMATION.md`](RECLAMATION.md)）。
  目标：不可达但仍占着存储的对象要有界，且**界与循环轮数无关**；停顿只与被扫区域有关、与整个堆无关。
  四层机制（本地整片释放、提权、计数归零、区域清扫）在默认路径上。
  机制层的待做项、优先级与出处只在 [`RECLAMATION.md`](RECLAMATION.md) 的「五、要做的」一节；
  真实业务形状（会话表、路由表、日志缓冲）的现状与复现见 [`bench/app/STALL.md`](../bench/app/STALL.md)。
  本条目**只留行为目标**，不复制那份清单，免得两处各自漂。
- **真实业务形状上的单位成本**：`bench/app/` 的三个场景（会话表、路由表、日志缓冲）的现状见
  [`bench/app/STALL.md`](../bench/app/STALL.md)。这三个形状**不执行任何回收指令**，但 extC 在路由表上慢于 Go、
  在日志缓冲上明显慢于 C++ 与 Go ⇒ 差距在分配、容器与代码生成层。要做的：定位这两个差距，并判断其中有没有回归。
- **重出 `bench/app` 的结果文件**：它的数值与当前构建对不上 —— 同一条命令、输出校验和相同，成本却差数倍。
  先确认是回归还是口径差，再用当前构建重出。

## 缺陷与已知洞

- **打开计数比清扫贵一个数量级（计数路线的真正门槛）**：清扫侧只占总指令的 0–22%，而打开计数的代价是
  +100%~+455% —— 钱花在"地址→槽查表 + 旁路元数据读改写"。发射层特化救不了：把查找整段减掉后，
  计数价仍是清扫侧的 2.5–17 倍。⇒ 计数路线要成立，前提是**槽布局改动（计数进对象头）**，让单价降到
  个位条指令；即便到了那一步，也只有"清扫真的在跑"的形状会赢。先决定是否继续；证据、上界与逐形状数字见
  [`tests/reclaim-perf/TAXMAP.md`](../tests/reclaim-perf/TAXMAP.md) 第 9 节。
- **AST 冻结施工单还剩几十条**：解析器之外的代码仍在写 AST。

## 回收：量具与停顿

口径的**单一真源**是 [`RECLAMATION.md`](RECLAMATION.md) 的「四.一」：`[step]` 桶的实际阈值、
低阈值诊断开关的可用区间、"p99"指哪一种。本节只留"要做什么"，不复制口径。

- **`[step]` 的桶打不出细粒度**：1 / 4 / 16 µs 三档只计数、**不打印**，打印出来的桶从 16 µs 起步
  ⇒ 单看 `[step]` 行**读不出 p99 ≤ 10 µs**。要做的：把细桶打出来，并/或补 4 µs、10 µs 两个**纯计数**桶；
  同时把桶标签写成阈值明确的形式 —— 现在的计数器按**上界**命名，按字面读会得出错的阈值。纯计数、不扰动。
- **停顿诊断的低阈值不可用**：阈值单位 µs，阈值压到几 µs 时大部分步都打印，整轮被 stderr 拖慢、外层计时作废。
  要决定的是**要不要让它自己防呆**（低阈值限速/聚合，或直接拒绝小阈值）。
- **标记遍历的访存局部性**：`markStep` 的**指令占比很小，却占 L1 数据读缺失的将近一半**；同一个步预算下
  **每对象成本随堆增大数倍**。出处：[`archive/2026-10-15-locality.md`](archive/2026-10-15-locality.md)。
  候选方向：按 slab 局部性排序遍历；预取下一个对象；把每个对象要碰的几样（slab 头 / `occ` 位图 / 对象头 /
  子字段）靠近或合并；**清扫预算按槽而不是按字**。判据口径见 `RECLAMATION.md`「四.一」。
- **切片延迟的尾部：搁置中。** 要的行为只有一句：`max_us` 的毛刺更少更紧（读法见上，不看 `max`）。
  做法是把**预算单位从工作量换成时间** —— 在标记弹出循环与清扫字循环里周期性查墙钟，超 deadline 就退出。
  **搁置的原因**：起轮信用、窗口加力与阈值重算都按 `allocBytes` 记账，换时间预算会把 pacing 一起牵动，
  账没一起改对之前先不做。真要捡起来，第一步是加纯诊断：把 `wall − CLOCK_THREAD_CPUTIME_ID` 与
  `getrusage(RUSAGE_THREAD).ru_nivcsw` 打出来，分清"不在 CPU 上"与"在 CPU 上撞上贵单元"。

## 语言功能（已定案、未实现）

- `f"…"` 的格式说明符（对齐、补零、定点小数）。
- `if let` 部分匹配。
- `owned`：让 `extern!` 能声明"返回的内存归调用者"。
- `@main` 注解（不再硬编码 `main`）。
- 并行：用户模型只有一句话 —— **可变数据有唯一主人，能共享的只有只读**。引用不过线程。
  第一版只给两个形状，都在并行块里，作用域结束一定 join：
  · 切块算：`parallel::for i in 0..n { … }` 只写自己那一段；`parallel::sum` / `count` / `max` / `min`
    做归约（每线程私有累加、join 合并），覆盖多数形状；
  · 传所有权：有界通道，`send` 是移动而不是共享，带本帧引用的值送不出去。
  只读视图本来就能共享，零复制。捕获规则：并行块只许捕获只读视图、标量和自己的输出段。
  死锁：线程之间没有「等对方」的边，唯一的等待是父等子 join，等待图是树，无环。
  第一版不做锁、原子、共享可变、内存序；用户写并发时不该出现「线程 / 锁 / 共享 / 原子」这些词。
  顺序：切块 + 归约（现有 `parallel::run` 作为逃生舱保留）→ 通道 → 只读快照（只在读多写少时给，
  发布单元由「多久写一次、写多大一坨」决定，不给透明整对象复制）。
- 字面量切片的深度放宽（静态存储里的字面量本来就是深度 0，现在偏保守）。
- 失败处理的后续：`if let` → `?` 允许错误转换 → 隐式传播。错误载体是纯值（码、文件、行），
  能不能失败由编译器推断；现在 `?` 只在少数语句位置合法，要能覆盖任意表达式位置。
- 模块：特权模块名单未封闭；类型名跨模块"必须限定"没挡严。
- 范围类型（让索引可证明，从而免掉检查）。

## 文档工程

- `docs/usage/` 的**公开面欠账 35 个**（覆盖率棘轮基线）：其中大半是**内部助手与状态字段** ——
  标准库的约定是"成员缺省公开，`@private` 才是内部"，所以 `inSync` / `depth` / `isSpace` 这类
  也算进了公开面。两条路：真对外的补进 `stdlib.md`；其余**标 `@private`** 收口，让清单反映真实 API。

  被 `tests/http/*` 直接引用（它们事实上是**被测试的使用面**）。要么写进文档，
  要么把测试改成只走公开入口 —— 在此之前不要标私有。
- **有一处恒不执行的判断**（条件写成 `0 && …`）挂在类型元信息查询上：要么启用，要么连那段判断一起删掉。
- **给公开 API 继续补 `@code` 使用例**（现有 10 段：`b64` · `hashMap` · `string` · `varArray` ·
  `pool` · `map` · `sha256` · `vector` · `fs` · `json`）。`std::io` 的重载细节、`hmac`、
  `std::net` / `ws` 等还没有。
- 语言页还缺最小例子：协程（`coroutine<A,B>` / `yield`）与域（`ext`），
  以及 `--dump-effects` / `--dump-tokens` 的输出格式说明。
