# 待做（唯一清单）

**规则**：条目做完就搬进 [`usage/`](usage/)（或者舍弃）；砍掉就**直接删掉**，不留"已取消"。

写条目时讲清**要什么行为**，不要写"改哪个文件"——文件名会变。

## 已排定顺序

- **`view<T>` 改名**：把 `slice<T>` 改名成 `view<T>`，"slice" 留给切片操作。纯机械改动，单独一次做完。
- **checked 原语 + trap 统计**：先给切片索引、整数窄化、除法、移位补上"可检查"的版本（纯标准库新增，
  不动语言），再把"有多少 trap 是输入相关、本来可以恢复的"变成一个数字 —— 那个数字决定隐式传播要覆盖什么。
- **`mut` 权限挂根的判据**：方向已定（权限挂在根上，就地写 `mut`，由编译器查根是否可变），
  但**先要判据**：造一批"把只读根洗白成可写视图"的攻击形状（经过字段、局部拷贝、结构体字面量、
  deref 拷贝、函数返回、容器、协程），能红才实现。**没有红判据不实现。**
- **堆的逐对象回收**：`std::heap` 的板现在只能整体归还。原型里已经验过"一次保留、按需提交、按尺寸类回收"
  的形态，把那部分搬进来（或做成第三种容器基座）。
- **区域回收**（机制见 [`RECLAMATION.md`](RECLAMATION.md)，数值见 `prototype-reclaim/`）。
  目标：不可达但仍占着存储的对象要有界，且**界与循环轮数无关**；停顿只与被扫区域有关、与整个堆无关。
  四层机制（本地整片释放、提权、计数归零、区域清扫）在默认路径上。清扫的覆盖还有缺口：八类形状的
  界仍随规模增长（其中七类比关掉回收还差）—— 它们都是同一个动作的后果：**编译器在「列不全」的时候
  选择「不扫」**。三个真实业务形状（会话表、路由表、日志缓冲）在默认档下已经**不发射回收运行期**，
  判据与复现见 [`bench/app/STALL.md`](../bench/app/STALL.md)。

  **机制层的待做项、优先级与出处只在 [`RECLAMATION.md`](RECLAMATION.md) 的「要做的」一节**（含
  "按区域不发射运行期"的判定卡点、跨过程 must 分析、取消式收尾与无界源）。本条目**只留行为目标，
  不复制那份清单**，免得两处各自漂；行为目标就是上面那句：不可达但仍占着存储的对象有界，
  且界与循环轮数无关；停顿只与被扫区域有关、与整个堆无关。

- **真实业务形状上的单位成本**：`bench/app/` 的三个场景（会话表、路由表、日志缓冲）已有三语言的用户视角停顿数据，
  取自 [`bench/app/STALL.md`](../bench/app/STALL.md)。这三个形状**不执行任何回收指令**，
  但 extC 在路由表上慢于 Go、在日志缓冲上明显慢于 C++ 与 Go ⇒ 差距在分配、容器与代码生成层。
  要做的：定位这两个差距，并判断其中有没有回归。
- **重出 `bench/app` 的结果文件**：它的数值与当前构建对不上 —— 同一条命令、输出校验和相同，成本却差数倍。
  先确认是回归还是口径差，再用当前构建重出。

## 缺陷与已知洞

- **打开计数比清扫贵一个数量级（计数路线的真正门槛）**：同形状同规模比总指令，清扫侧只占
  **0–22%**，而打开计数的代价是 **+100%~+455%** —— 钱花在"地址→槽查表 + 旁路元数据读改写"
  （`ownSlab` 约 33 条指令/次、`holdUpdSlab` 同量级，每次计数两次查表），而原型的计数是
  "对象里的一个字段直接改"（约 1 条指令）。**发射层特化（每站点内联缓存/守卫）救不了**：
  把查找整段减掉后，计数价仍是清扫侧的 2.5–17 倍（清扫本来不跑的形状是无穷倍）。
  ⇒ 计数路线要成立，前提是**槽布局改动（计数进对象头）**，让单价降到约 3 条指令；即便到了那一步，
  也只有"清扫真的在跑"的形状会赢（实测估计 `spectrum_p4` 赢 9.7×、`spectrum_p5` 赢 2.7×，
  其余输）。证据、上界与逐形状数字见
  [`tests/reclaim-perf/TAXMAP.md`](../tests/reclaim-perf/TAXMAP.md) 第 9 节。
- **事件档的计数不完备：局部引用绑定只加不减**（**已冻结为诊断档**，见下）。事件档（计数开、清扫关）下，
  `var p = new node` 这样的局部绑定被算成一个持有者，而**作用域退出、每轮 arena 归还、函数返回都不销账**
  ⇒ 每个对象带一个幽灵持有者，计数永不归零 ⇒ 垃圾随规模线性涨（覆盖/淘汰/窗口三类形状 4N/N 峰值
  3.3–3.7×）。**决定不修**：实测事件档在语料里没有一个能赢的形状（有环形状上不成立 —— 强制用在
  `ring_per_round` 上 N=8000 涨到 8 369 MB；无环形状上会漏；就算不漏计数也比清扫贵 +100%~+455%），
  所以它降级为默认关的诊断开关，判据摘出电池（`gate-acyclic` 自报 manual、原 `gate-event-bounded` 删除）。
  **若将来要复活**：先给离开作用域的引用绑定补销账 + 立"inc/dec 配对"判据（配不平的区域不许关清扫），
  并先解决计数单价（见上一条）。现象、根因与量法教训见
  [`tests/reclaim-perf/TAXMAP.md`](../tests/reclaim-perf/TAXMAP.md) 第 7 节。
- **`!` 出现在赋值目标里时会求值两次**：`(*f()!).field = v`（`f` 返回 `?mut ref T`）会调用 `f` 两次
  —— 解包生成的那段非空断言把操作数写了两遍。同一个写法去掉 `*`（`f()!.field = v`）会被拒（不是一个 place）；
  普通解引用 `(*f()).field = v` 不受影响，是单次求值。
  修法：赋值目标里遇到"不是 place 的指针表达式"时，先用一个指针临时量接住再写它指的东西；
  修好之后 `f()!.field = v` 也可以重新开放，而且是单次求值。
- **两个标准库/模块的编译期缺口**（都已实测复现）：
  ① 同时 `use stl::linmap`、`use stl::string` 并实例化以 `slice<u8>` 为值的映射时，
  生成的 C 里出现重复的 `option_slice_u8` 定义 ⇒ 编译失败；
  ② 非入口模块里的 `@export` 函数被同程序另一个模块调用时，定义发成 `f`、调用点写 `mod$f` ⇒ C 编译失败。
- **`<<` 链的实参从右往左求值**：`io::cout << "x" << a() << b()` 里 `b()` 先于 `a()`。
  后果是 `<< dl::close(h)` 这类"释放"写在同一个表达式里会**先释放再使用**（实测段错误）。
  要么给 `<<` 定一个从左到右的求值顺序，要么在文档里把"释放必须另起一句"写成硬规矩。
- **逃逸健全性闸门还剩一条**：`yield ref <帧内局部>` 被前端接受，生成物是畸形的 C。
- **AST 冻结施工单还剩几十条**：解析器之外的代码仍在写 AST。

## 语言功能（已定案、未实现）

- `f"…"` 的格式说明符（对齐、补零、定点小数）。
- `if let` 部分匹配。
- `owned`：让 `extern!` 能声明"返回的内存归调用者"。
- `@main` 注解（不再硬编码 `main`）。
- 线程：保守的 fork-join 加归约，引用不过线程。
- 字面量切片的深度放宽（静态存储里的字面量本来就是深度 0，现在偏保守）。
- 失败处理的后续：`if let` → `?` 允许错误转换 → 隐式传播。错误载体是纯值（码、文件、行），
  能不能失败由编译器推断；现在 `?` 只在少数语句位置合法，要能覆盖任意表达式位置。
- 模块：特权模块名单未封闭；类型名跨模块"必须限定"没挡严。
- 范围类型（让索引可证明，从而免掉检查）。

## 标准库

- 补齐字符串与序列操作：切分、连接、去空白、替换、带下标遍历、拉链。
- 容器缺的成员：动态数组的**中间插入与删除**（`pop` 已有：去尾不成问题）。
- 一次读满整块（读满给定缓冲的语义）；格式化输入（现在只有 `nextInt` 这类逐项读）。
- HTTP 客户端：分块编码、头部折叠、TLS、代理、cookie。

## 编译器内部（可整体搁置）

- 多文件输出 / 运行时独立 TU（收益未测）。
- 协程协议换成枚举（要先修协程类型两个槽位的精度）。
- 清理活函数内部未用的局部。
- 调度器"一个 fd 一个等待者"。

## 文档工程

- `docs/usage/` 的**公开面欠账 35 个**（覆盖率棘轮基线）：其中大半是**内部助手与状态字段** ——
  标准库的约定是"成员缺省公开，`@private` 才是内部"，所以 `inSync` / `depth` / `isSpace` 这类
  也算进了公开面。两条路：真对外的补进 `stdlib.md`；其余**标 `@private`** 收口，让清单反映真实 API。
- **这批欠账里有一部分不能靠标 `@private` 解决**：`std::http` 的 `findSub` / `putBytes` / `lower`
  被 `tests/http/*` 直接引用（它们事实上是**被测试的使用面**）。要么写进文档，
  要么把测试改成只走公开入口 —— 在此之前不要标私有。
- **`typeContainsProto` 的三个调用点都写成 `if (0 && …)`**（都在 `check_expr.c`），即恒不执行，
  函数本身还在。要么启用，要么连调用点一起删。
- **给公开 API 继续补 `@code` 使用例**（现有 10 段：`b64` · `hashMap` · `string` · `varArray` ·
  `pool` · `map` · `sha256` · `vector` · `fs` · `json`）。`std::io` 的重载细节、`hmac`、
  `std::net` / `ws` 等还没有。
- 语言页还缺最小例子：协程（`coroutine<A,B>` / `yield`）与域（`ext`），
  以及 `--dump-effects` / `--dump-tokens` 的输出格式说明。
