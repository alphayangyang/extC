## 二、这一轮做完的事（DEVLOG 第十一段续六有全版）

1. **撤回一个错误方向**：`#84` 的「孩子是句柄」实测 **8.6× 慢**（0.73 → 6.30 ns/op，同负载同校验和）——
   句柄寻址是 `handle → pLive 校验 → slots[dense] → vals[dense]`，下标就是一次访存。
   ⇒ 手搓 `freeHead`/`shrink` **不是性能欠账**，只是可选的代码统一。
2. **落地「零初始化收窄」**：容器里**每个槽都先写后读**的列不需要清零（清它是纯多做：写一遍
   马上被覆盖的字节 + 把用不到的页提交掉）。加了内建 `poolResizeRaw<T>`，把 `map` 四列 +
   `shrink` 新块、`vector`/`string` 缓冲、`hashMap` 的 `keys`/`slot`/`bucketOfDense`、`linMap`
   两列换掉；**保留清零**：`hashMap.tag`（空桶就是 0）、`pool` 的 `ent`（`pFree` 把 0 读作空闲）、
   `map` 的 `path`/`side`。
3. **收益（交错 A/B，校验和逐字节一致）**：`map` RSS **−17.5%**（40.9 → 33.7 MB）/ 时间 −0.4% ·
   `string` **−10.8%** / −7.9% · `hashmap` **−8.0%** / −1.9% · `vector` 0% / −10.1%；
   `bench/app` 场景 B（`map`）**40.8 → 32.7 MB / 90.0 → 62.0 MB（−31%）**，场景 A 78.8 → 72.5 MB。
   容量有余量时最多时间 −40% / RSS −46%。**没有一个变慢。**
4. **挖出两处被清零掩盖的真 bug**：`map::shrink` 无条件拷满 17/17/18 槽，而 **kids 只有内部节点、
   vals 只有叶子**才有 —— 另一侧那些槽从没写过，清零时读到 0（**而 0 恰好是个合法节点号** ⇒
   「看着没事」），raw 后拿垃圾去 `old2new[kid]` 索引 ⇒ 越界 trap。已修。
5. **判据**：`tests/map` 的增长判据从「纯 RSS 不等式」换成**精确字节账**（每节点字节必须相同）——
   旧不等式成立的原因之一是**预留那版被清零撑大**，收窄后它被"基线变好"翻转（**判据红 ≠ 代码差**）；
   `tests/pool` 加**两层金丝雀**：毒化（判据是**输出逐字节一致**，不是只看退出码）+ memcheck（上限基线）。

## 二′、本轮第二部分：边界检查的账（DEVLOG 第十一段续七）

**量法**：消融 —— 同一份生成 C **只删掉** `slice_T_index` 里那句检查，其余一字不动，校验和逐字节相同。

- **微基准**：可证循环 `for i in 0..xs.len { xs[i] }` GCC **本来就消除**；不可证下标 **+3 条指令/访问
  （Ir +25%）但时间只 +0.18%**。⇒ 那 3 条指令本身几乎免费。
- **真实容器**（去全部检查）：`vector` 0.45%（噪声）· `string` −7.1% · `hashmap` −12~15.8% ·
  **`map` −18.7~21.6%（指令 −61%）**。
- **map 拆开**：基线 1060.4 ms → 只加 `@inline` **948.8 ms（−8.6%）** → +`childSlot`/`lowerIn`
  **928.9 ms（−10.5%）** → 去全部检查 844.2 ms（−18.7%）。⇒ **~10% 是"检查挡住内联"，~8% 才是检查自己。**
- **分支预测没有空间**：检查占全部**分支的 57%**，但去掉 3.15 亿条分支只少 1250 万误判（这类分支≈从不跳）
  ⇒ `__builtin_expect` **0 收益**；真正误判的是**剩下**的数据相关分支（10.2% → 18.4%，43.9M 次）。
- **已落地**：`map` 的 15 个函数加 `@inline`。`bench/stl` 的 map **1.12s → 0.88s**（对 C++ `std::map`
  0.58× → **0.45×**）；`bench/app` 场景 B **−8.8%**（对 Go 3.94× → 3.48×）。**别乱加**：hashMap 那 6 个
  小访问器只值 ~1%。

## 二″、SIMD 的下一步（已量清，未开工）

- **纯 ISO C 的无分支写法就够**（`s += (ks[i] < k)`，`-std=c11 -pedantic-errors` **实测通过**），
  让编译器向量化：**默认 `-O2` 无 `-march` 时 i32 键已经拿到 SSE2**（`pcmpgtd`/`psubd`/`paddd`），
  **i64 键不行**（GCC：`no vectype for int64_t compare`，SSE2 没有 64 位比较）⇒ 要 `-march=native`
  （项目已有的可选开关）才出 `pcmpgtq`+`paddq`。
- **不需要** GNU `vector_size`（虽然 `-pedantic-errors` 也收）或 `<immintrin.h>`（SSE4.1 以上的 intrinsics
  还得 `-msse4`/`-march`，且把生成物绑死在 x86）。
- 微基准（16 键，L1 常驻）：无分支比分支二分 **快 57~64%**（纯 ISO C），`-march=native` 向量化后 **快 87%**。
  **但 map 的键在指针追逐里，cache miss 会吃掉大部分 ⇒ 收益必须端到端重测。**
- **落点**：泛型 `map<K,V>` 上不了这条路（要整数比较）⇒ 正是 PLAN #84 里作者写下的 **`mapI64` 专用表**。

## 二‴、为什么 Go 快（DEVLOG 第十一段续八，**反证实验**）

**把 Go 的结构用 extC 重写一遍，输出逐字节相同，再交错计时**：

| 场景 | extC 现状 | 同结构重写 | Go |
|---|---|---|---|
| A 会话表（哈希） | 0.99× | — | 1.00× |
| B 路由表 | B+ 树 **3.278 s（3.55×）** | **0.869 s（0.94×，比 Go 快）** | 0.922 s |
| C 日志缓冲 | 逐字节+完整 push **59.7 ms（1.83×）** | memmove+最小 push **34.0 ms（1.04×）** | 32.4 ms |

- **B**：树的名次要靠 `kidsCnt` 逐孩子累加（callgrind 18.9%），而 Go 的名次就是**数组下标**；
  扣掉各自一次性排序后 extC 0.324 s vs Go 0.330 s = **0.98×**。
- **C**：① `dropFront` 逐字节 —— **extC 没有整块搬移原语**（−21%）；② `push` 每字节做
  `pStale()` + **两次 `extc_arena_release`** + 两项检查（−27%）。
- ⇒ **差距在库的成熟度，不在语言内核。**

## 四、工具坑（省得再踩）

- `edit` 工具会**重置 `tests/*/run.sh` 的执行位** ⇒ `check.sh` 报 `Permission denied`。改完 `chmod +x`。
- **前台等长任务会被卡住**：一律 **后台 + `timeout`**，跑完再收。跑 `check.sh` 必须 `</dev/null`。
- extC 语法：`<<` 不能跨行续写；`||` 也不能跨行；类型名必须小写开头；`option` 不能与 `none` 直接比；
  给 `ref` 参数传局部变量要写 `ref x`；**`i64`→`i32` 要显式 `i32(x)`**（只允许隐式加宽）。
- 生成的 C 的**既定编译契约**是 `-O2 -std=c11 -fwrapv`（`MANUAL.md` §8 / `src/main.c`）。
- 量性能：同一个二进制在两次测量之间能差 25%（WSL2 宿主负载）⇒ **A/B 一律交错跑、看比值**。
  **单批顺序测量会骗人**：本轮我先用"改生成的 C"预演过一次，数字比真改动漂亮，原因是我自己的
  二分步骤把 `growStores` 改回了清零、又把"清零版"存成了备份 —— 交错 A/B 才抓出来。
- 定位"读未初始化"：**memcheck 指行** + **`newNode` 把 kid 槽填 `-1` 的哨兵探针**。毒化填 0xAA
  （负数）对 `if kid >= 0` 那类判据**是隐形的**，别只靠它。
