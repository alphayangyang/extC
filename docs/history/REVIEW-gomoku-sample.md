## 4. 它暴露的四个真问题

### 4.1 格式串：其实**可以不违反 P** —— 但要分清两件事

`println("无效落子：{}", e)` 有两层问题：

**第一层（好解）**：格式串违反 P，是因为「**运行时**解析格式」。但如果**编译器在编译期解析并展开成一串 printf**，运行时就没有解析了 —— **P 不禁止**。

> 结论：**格式串可以留，但必须是编译期展开的语法糖，不是运行时解释器。** 代价是它不能是动态字符串（`println(fmt, x)` 里 `fmt` 是变量就不行），这个限制要写进错误信息。

**第二层（真问题）**：`e` 是一个 `GameError` 枚举值 —— **怎么把枚举变成文本？** 语言现在完全没有这个机制。这是 `Display` / `trait` / `interface` 的雏形，是语言里第一个「用户可扩展的多态」。见 §5 的问题 5。

### 4.2 arena 归属：这段代码正好证明「arena 必须是词法的」

`alphabeta` 在每个节点都调 `candidates()`，每次都分配一个 `VarArray<Point>`。而 `region search { }` 只包住 `find_best_move` 的函数体。

于是问题来了：**`alphabeta` 里分配的数组属于谁？**

| 如果 arena 是… | 后果 |
|---|---|
| **动态的**（`region search` 覆盖整棵调用子树） | 每次递归的候选表都活着 → **O(节点数) 内存，直接爆** |
| **词法的**（每个函数帧一个 arena） | 子节点返回就释放 → **O(深度 × 分支)** ✓ |

**我们的 §2 已经投票给词法了，这份代码正好说明为什么必须如此。**

> ⚠️ 这条要在 DESIGN.md 里写死，并且要写清：**`region` 不是「整棵子树的 arena」，它只是「给一个词法作用域起名字」**。这段代码里 `region search` 其实是可以省的（函数帧本来就是 arena），它的唯一作用是把名字给出来。

### 4.3 发散臂

```extc
let p = match parse_move(ref line) {
    Ok(p) => p,
    Err(_) => {
        println("格式错误，用 x,y")
        continue          // ← 这个臂不产生值
    }
}
```

`match` 是表达式，但有一个臂是 `continue` —— **类型检查器必须有「发散 / never 类型」的概念**，否则这个臂推不出 `Point`。Rust 有 `!`，TypeScript 有 `never`。extC 得有等价物。

### 4.4 「零初始化」和「值拷贝」跟 P 有张力 —— 但 P 需要一句澄清

`var b: Board` 默认清零（900 字节 memset），递归里 `var child = b` 拷贝 900 字节 —— **这些在 P 的字面意思下都是「运行时开销」**。

答案是 P 需要澄清一句：

> **P 禁止的是「隐藏的机制」（GC、异常、运行时元数据、隐藏分配），不是「数据拷贝」。**
> 否则连 `x + y` 都该禁止。

**零初始化其实是 P 的胜利**：C 里最大的 UB 来源之一就是「读到未初始化内存」，它是**运行时才能发现的**；默认清零把它变成**编译期就能保证的**。代价是 memset —— 可以接受，而且编译器还能在能证明「马上会被完全覆盖」时把 memset 消掉（这正是 P 说的「能证明的不留痕迹」）。
