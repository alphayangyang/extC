# 回收（机制与待做）

这份文档解释 extC 的内存回收要长成什么样，以及为此要做的几件事。
它属于"有什么待做"那一类，和 [`TODO.md`](TODO.md) 同源 —— `TODO.md` 是清单，这里是它背后的机制。

## 一、回收的基本盘

extC 的存储按**词法区域**划分：函数体是一层，每个块再往里一层，循环体是它自己的一层。
每层是一串块，一层的对象在离开这一层时**整片**还给系统。

于是最常见的形状是零成本的：

<!-- fragment -->
```extc
while i < n {
    var p = new node      // 分配在循环体那一层
    p.v = i
    i = i + 1
}                          // 这一轮结束，整片释放
```

一个值要活得更久，就必须把它的存储**提到更外层的区域**去（下称**提权**）。
提权是安全的，但它是单向的：存储一旦落到外层区域，就只能等那一层结束才回收。

## 二、要解决的问题

提权把一个对象放进长命区域之后，如果那个对象**在循环里被反复覆盖**，它的存储就会攒起来，
数量随循环轮数增长。典型的形状是"条件保存"：

<!-- fragment -->
```extc
var saved: ?ref node = null
while i < n {
    var p = new node
    if keep { saved = p }     // 存进去 ⇒ p 要活到函数结束
    i = i + 1
}
```

每一轮的 `p` 都可能进 `saved`，所以每一份都得活到函数结束。而运行期真正被 `saved` 持有的
永远只有一份，前面那些已经被覆盖掉了。

**要达到的行为**：不可达但还占着存储的对象，其总量**有界**，且这个界**与循环轮数无关**。

## 三、回收分四层

| 层 | 什么时候回收 | 回收多少 | 代价 |
|---|---|---|---|
| 本地 | 离开作用域（含每轮循环体）| 整片 | 零 |
| 提权 | 真实的逃逸动作发生的那一刻 | 把那一份存储挪到外层 | 一次指针操作 |
| 事件回收 | 覆盖、清空、摘除、离开作用域 | 当场释放那**一个**对象 | 一次指针操作 |
| 区域清扫 | 某个区域的垃圾超过它的存活量 | 该区域内的不可达对象 | 扫一个区域，微秒级 |

前两层和事件回收处理掉绝大多数对象；区域清扫只负责"确定不了"的那一小部分。

## 四、事件回收

思路很直接：**很多"最后一根线断掉"的时刻，是程序自己刚刚做的一个动作造成的。**

<!-- fragment -->
```extc
var p = new node
var q: ?ref node = p     // 两根线
outer = p
outer = null             // outer 这根断了 —— 但 q 还在，所以这个对象还不能放
```

所以"一个动作发生了"只说明**一根线断了**，不说明**这是最后一根线**。三种应对：

| 应对 | 怎么判断 | 代价 |
|---|---|---|
| 静态证明唯一 | 编译器证明这个对象只有这一个持有者 | 编译期；证不出时用不了 |
| 计数 | 给每个对象记"有几根线指着它"，归零才放 | 每次引用复制都要动一次；环形结构永远不归零 |
| 交给兜底 | 不确定就不放，留给区域清扫 | 那部分对象要多活一会儿 |

extC 走的是第一条加第三条：**能证明的当场放，证不出的交给清扫**。计数不引入 ——
它的代价落在每一次引用复制上，而且环形结构处理不了。

## 五、区域清扫

清扫的基本盘是"从根出发标记，放掉没标上的"。它对 extC 有两处特殊：

* **根表由编译器给。** 清扫的触发点在分配点，是编译器选的位置；在每个这样的位置，
  哪些引用槽是活的，编译器是知道的。于是根表可以静态发射，不需要写屏障、不需要影子栈、
  也不需要保守扫描。
* **触发量跟着存活量走。** 触发量取"上次清扫后的存活量"，再留一个下限。触发量若是个固定的小常数，
  存活集一大，开销就会失控。

**能达到的行为**：任何一个区域的驻留垃圾不超过"它的存活量 + 触发量"；
停顿只与该区域有关，与整个堆的大小无关。

触发量是**用户旋钮**：它直接换挡内存与 CPU，不影响正确性。下限越小，内存越紧、清扫越勤。

## 六、为什么停顿能切分

全局扫描每次都要从根遍历**全部**存活对象，包括那些很久不动、根本不产垃圾的结构。
区域清扫可以只扫有垃圾的那一个区域，把不动的结构留在一旁。

代价是**纪律**：一起生一起死的东西要放在同一层区域里，一个长期结构最好自成一层。
这样"扫谁"才是件可以选择的事。

## 七、要做的

* **事件回收**：在覆盖、清空、摘除、离开作用域这些位置，当编译期能确定那个对象没有别的持有者时，
  当场把它的存储释放。释放是一次指针操作。证不出时什么都不做。
* **运行期提权**：分配先落在当前区域，在**真实的**逃逸动作发生时才把那一份存储转移到外层区域。
  转移不改对象地址（所以别名和指针同一性都保住），也不搬动数据。
* **区域局部清扫**：按需触发；触发量取"上次清扫后的存活量"与用户下限的较大者；
  根表在触发点静态发射；只扫该区域内的块。
* **触发量的接口**：给用户一个可调的每区域垃圾预算，默认值取一个够小的常数。
* **唯一性判据**：把"这个对象只有这一个持有者"变成一个能静态回答的问题。
  这是事件回收的命中率来源，也是唯一能让事件回收覆盖更多形状的办法。
  没有判据时，事件回收照样安全，只是命中率低、更多垃圾落到清扫。
