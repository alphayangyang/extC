# 回收（机制与待做）

这份文档说明 extC 的内存回收长成什么样，以及为此要做的几件事。
它属于"有什么待做"那一类，和 [`TODO.md`](TODO.md) 同源：`TODO.md` 是清单，这里是它背后的机制。

## 模型总览

**前提**：编译到 C11；**允许别名**；存储按词法作用域分层、作用域编译期已知；
不开写屏障、不做原子操作、不搬对象、无 STW。

**要解决的问题**：提权把一个对象放进长命区域之后，如果它**在循环里被反复覆盖**，存储就攒起来，
数量随循环轮数增长。典型形状是"条件保存"：

<!-- fragment -->
```extc
var saved: ?ref node = null
while i < n {
    var p = new node
    if keep { saved = p }     // 存进去 ⇒ p 要活到函数结束
    i = i + 1
}
```

每一轮的 `p` 都可能进 `saved`，而运行期真正被 `saved` 持有的永远只有一份。

**目标**：不可达但仍占存储的对象，其总量有界，且这个界**与循环轮数无关**。

**四层**

| 层 | 触发时刻 | 回收量 | 代价 |
|---|---|---|---|
| 本地 | 离开作用域（含每轮循环体）| 整片 | 零（指针拨回）|
| 提权 | 真实逃逸动作发生的时刻 | 把那一份存储挪到外层区域 | 一次指针操作，**地址不变** |
| 计数归零 | 覆盖/清空/摘除/离开作用域，使持有者数归零 | 当场释放**那一个**对象 | 每次**指针赋值**动一次计数 |
| 区域清扫 | 某区域内存压力超限 | 该区域内的不可达对象 | 扫一个区域 |

前三层处理掉绝大多数；区域清扫只负责**环**和计数饱和掉的那一小部分。

**保证**：允许别名；环也能收回；任一区域的驻留垃圾不超过"存活量 + 阈值"；
停顿只与被扫区域有关、与堆大小无关；无写屏障、无 STW。

**代价**：分配是 bump；计数挂在**指针赋值**上（数据写不记）；回收算法本身只占很小一部分指令。
相对开销取决于形状：**分配密集时这套机制赚，大量改链而极少分配时它赔**（省法见"要做的"）。

**旋钮**：触发量换"内存 ↔ 吞吐"；分片数换"**停顿 ↔ 吞吐**"；计数的省略程度换"写密集时的税 ↔ 分析工作量"。
三个都不涉及正确性。

## 一、存储：区域

每个词法层（函数体、每个块、每轮循环体）是一个区域，区域是一串块，离开该层整片归还。
区域里的每个对象占一个**槽**：载荷按尺寸档放进块里，**超过一块的载荷单独分配，但仍然只是一个槽**
—— 计数、跨区登记、标记、清扫对大小对象走同一条路径，不因为载荷大就另开一条。

槽的**布局与每槽元数据**同样是这套机制的一部分：载荷按 **16 字节**向上取整（不是 2 的幂 ——
80 字节的对象就占 80 字节的槽，省掉取整碎片），在 slab 里连续排布；每槽的元数据是三张位图
（占用 / 标记 / 跨区登记，≈3 bit/槽）+ 跨区入边计数（2 B）+ **16 位类型号**（2 B；号 → 描述符
的映射是**每块 slab 的小类型表**，按指针相等去重，1 号固定是兜底描述符）。槽步长既然不是 2 的幂，
"由对象指针找槽号"就不是一次移位，而是一次**乘倒数右移**（精确性论证在实现里，判据见
[`tests/reclaim-perf/README.md`](../tests/reclaim-perf/README.md) §11）。
所以下面的形状是零成本的：

<!-- fragment -->
```extc
while i < n {
    var p = new node      // 分配在循环体那一层
    p.v = i
    i = i + 1
}                          // 这一轮结束，整片释放
```

要活得更久就得把存储**提到更外层的区域**（下称**提权**），而提权是单向的：
存储一旦落到外层区域，就只能等那一层结束才回收。判据只有一条（深度：参数 0、函数体 1、
每进一个块加一）：

<!-- fragment -->
```extc
depth(引用) >= depth(存放位置)      // 满足才允许存
```

提权是"这片存储要活得久"的声明，它不知道运行期到底有几份会被真正持有 —— 这就是要解决的问题。

## 二、计数归零（**默认关闭**；`EXTC_RC_NOCOUNT=0` 打开）

> **默认口径**：编译器默认**不做持有者计数**，回收只靠第三节的区域清扫 ——
> 清扫的种子/遍历不依赖计数（从根槽与已登记的跨区种子出发、靠每槽的类型描述符下钻），
> 所以区域仍然有界；少掉的只是"最后一个持有者死 ⇒ 当场回收"这条快路。
> 翻转的依据与全套证据（31 条形状棘轮、ASan 语料、gaps 集合、停顿探针、绝对峰值）
> 见 `CHANGELOG.md` 第十一刀。下面这一节描述的是**打开计数时**的口径。

**最后一根线断掉的时刻，就是持有者数归零的时刻。** 每次指针赋值加减一次，归零当场释放。

<!-- fragment -->
```extc
var p = new node
var q: ?ref node = p     // 计数 2
outer = p                // 计数 3
outer = null             // 计数 2 —— 还有 q，不放
q = null                 // 计数 1 —— 还有 p，不放
p = null                 // 计数 0 —— 放
```

* **只挂在"指向关系改变"上。** 数据字段赋值不记；引用赋值记两次（目标加一、旧值减一）；
  同值赋值可以不记。
* **到顶粘性锁住、此后不再减。** 宁可交给清扫，也不能提前释放。
* **环永不归零**，交给区域清扫 —— 这是引入计数换来的：不需要程序自己标识环。

## 三、区域清扫

从根出发标记，放掉没标上的。四处特殊：

* **根表由编译器给。** 触发点在分配点、是编译器选的位置；那里哪些引用槽是活的编译器知道，
  于是根表静态发射，不需要写屏障、影子栈或保守扫描。
* **根表只覆盖本帧，所以清扫只在「本帧拥有」的区域上进行；不属于本帧的，记一笔账留给拥有者。**
  根表按词法作用域拼：本帧活着的局部量、形参、全局量。它看不见调用栈上其他帧的活引用，因此往
  **调用者传下来的区域**（被调者的分配落进调用者的那一层）分配时，触发点不物化根表，只在那个区域上
  留一个「欠一次清扫」的标志；**拥有它的那一帧在自己下一次把同一层 arena 交给被调者之前**销账 ——
  那一刻上一批被调者已经返回、这一批还没进入，它的静态根表就是完整的种子；拥有者没有下一处调用点时，
  整片要等到帧销毁才还。**整条调用链共用的线程本地区域只在 worker 帧里清扫**，归属按调用链算。
  种子不完整时宁可不清扫，也不能把活对象当垃圾放掉。
* **跨区引用只登记一个 bit。** 引用被存进别的区域时，在**目标对象所在位置**的位图里置一位，
  播种时顺序扫这张位图；位置释放时那一位跟着清掉，所以没有陈旧表项。
* **触发按内存压力，并会自行退场。** 计数已收掉所有非环垃圾，于是区域占用≈存活，清扫只在
  占用明显超过上一轮存活量时才有意义；再加一条自适应：一次清扫一无所获就把该区域阈值翻倍
  （学到"这里没有环"），真收到东西则复位。**无环的程序永不进入清扫。**

清扫本身是**顺序扫位图字**：不追指针、不逐个释放。

## 三点五、覆盖点的定点释放（环在覆盖点就没了）

环永不归零，所以计数那一层收不了它；但"**覆盖一个槽**"这个动作本身能判死一棵树 —— 只要那
条槽是这棵树**唯一**的外部入边。编译器只在能说出这句话的形状上发射（`src/back/codegen.c` 的
`rcEmitStoreRelease`，四条判据同时成立）：

* ① 赋值在某个循环体里；
* ② 目标槽是本帧的引用槽（在静态根表里）、且声明在**所有**在册循环之外 —— 每一轮被同一个
  长命槽覆盖；循环内的游标（`cur = t`）不满足；
* ③ 写进去的值是本帧 `new` 出来、**从不被重新赋值**的局部对象，并且**它所在的区域本帧拥有**
  —— 只有那种区域，本帧的根表才是完整的种子（与分配点的触发同一条判据）；
* ④ 这个对象已经被写进过某个堆对象的引用字段（`(*cur).next = head`）：刚分配就链进堆对象的
  局部，才可能是一棵树/一条环的头。

发射的是 `extc_rc_storeRefOwnedRelease(&槽, 新值, 宿主, 那只区域, 根表, n)`，其中**根表里剔除了
被覆盖的那一格**（它此刻还装着旧值；把它算进种子就等于自己证明旧结构是活的 ⇒ 一个槽都放不掉）。
运行期先按**其它根 + 本区域跨区种子**标记（与第三节整区清扫**同一套种子**），再从旧值出发沿
类型描述符走，只 `freeSlot` 那些"可达**且**未被标记"的槽，最后把标记位清干净（`extc_rc_sweep`
是唯一会清它的地方，不清就会把标记留给下一次 `collect`）。

**安全论证**：释放集是"**同一点、同一套种子**下整区清扫会释放的集合"的**子集** ⇒ 四种静态
判据就算全判错，被别的活根/种子指着的对象也不会被放（trial deletion 的轻量形态）。于是这个
机制的失效方向是**少收**，不是提前释放。前提与整区清扫逐条相同，所以回落也逐条照抄。

**保守回落**（任何一条不成立就一个字节都不发，产物与今天逐字相同）：根表不可靠
（`rcRootsUnreliable`）/ 协程帧 / **分片 `EXTC_RC_SHARDS > 1`**（标记只覆盖**这一只片**，
"只被别的片里的活对象指着"的单元标不到 ⇒ 会放掉活对象，所以分片下一律不发）/ 目标区域
`noSweep` / 目标区域有欠账 `owe`（`checkOwed` 同一条理由）/ 旧值经 `ownSlab` 不在静态给出的
那只区域里。

**信用（`extc_rc_budgetOk`）**：一次 O(活集) 遍历必须由"**自上次遍历以来的新分配**"偿付 ——
要求 `allocBytes - visitedBytes ≥ max(live, floor)`（`floor` 是区域下限；区域从没扫过时 `live = 0`）。
清扫本来就满足这条（触发线 `max(2·live, floor)·scale ≥ need`）；**释放是唯一的破口**：它由赋值
触发，没有分配垫着，于是"赋值 N 次"会变成 N 次全活集标记（实测 `rg_grow_tail`：40k 次追加
5.08 s、关档 2.4 ms）。加上这条之后，总遍历量 ≤ Σ信用 ≤ 总分配量 = **线性**；代价是信用不够
时这次释放不做（垃圾晚一步收，峰值有常数上界），失效方向仍是**少收**。

**判据**：`tests/reclaim-gaps/gate-release.sh`（挂 `nobench`）：`ring_per_round` 默认档
**清扫次数 ≤ 1**、N vs 4N 峰值 **< 1.5×**、语义与关档逐字相同、**释放槽数 > 0**（防空转）。
实测（本机，N=20/80）：清扫 **55 → 1**、峰值 **10.61 → 6.48 MB**、释放槽数 **4883 / 20303**。
剩下的那 1 次是**第 2 轮循环头的启动空扫**：`keep` 的旧 head 要到第 2 轮的 `keep = head` 才被
判死，而第 2 轮循环体开头的分配触发点先到压力线（那一次 `freed=0`，自学习还把 `scale` 翻倍，
是触发策略自己的事）。红证明：注入 `release-off`（关掉发射 ⇒ 判据红）。

## 三点七、整段不发射 rc 运行期（区域"不需要回收"的证明）

前面几层都是**运行期**的机制：计数、清扫、定点释放。这一层是**编译期**的：一个区域被证明
"清扫无事可做"时，它**整段不发射 rc 运行期**——不是"清扫不触发"，是生成物里一个 rc 调用都没有，
连运行期文本都不进。今天只要程序里有一个受治理的分配点就**整程序**发射 rc；这一层把那个
判据收窄到"**回收可能有事可做**"。

**判据（(a)(b)(c)，一具函数一具地算，整单元合取）**：

* **(a) 每个 ref 字段每对象最多被写一次**（初始化，不是覆盖）。判的形状：写站点的宿主是本帧
  `var x = new T` 出来的局部量、这个绑定在整具函数体里**从不被重新赋值**，且同一个（宿主声明,
  字段）在这具函数里只有**一处**站点。前两条把"宿主对象"钉死在那条 `new` 上（递归的每层调用
  各有自己的 `x` ⇒ 各有自己的动态对象），后两条保证那处站点每对象只执行一次。**按宿主声明计，
  不按站点个数计**。
  **细化 (a′)：站点在循环里也可以** —— 真正的要求是"每对象最多写一次"，所以只要宿主的分配点
  **不比站点浅**（分配循环深度 ≥ 站点循环深度）就够了：那种宿主是**本迭代新建**的，循环里那个
  字段仍然是每对象写一次。宿主在循环**外**（分配深度更浅）⇒ 同一个对象被反复改写 ⇒ 仍判否。
  再加一层收窄：宿主那条 `new` 的存储**最后被放**的 arena 层也得 ≥ 站点循环深度（逃逸提权把它
  提到更长寿的层时判否）。"站点不在任何循环里"因此只是 (a′) 在站点深度为 0 时的特例。
* **(b) ref 类型的局部量/参数不被重新赋值**（声明初始化不算）。写进栈上槽（标识符、局部聚合的
  字段）的引用赋值都是丢引用。**嵌套块里声明**一个 ref 局部量**不算**：它的对象随块 arena
  整片释放（`bt` 的 `let t = bottomUp(d)` 正是这一档）。
  **细化 (b′)：ref 局部量的槽可以覆盖**，只要写进这个槽的**全部**值都随本迭代的 arena 一起死
  —— 即每个值的存储层 ≥ 这次写入所在的最内层循环体的作用域层（`null` 不丢对象，天然合格）。
  于是"覆盖"只是少一个根，丢的是本来就会随这次迭代释放的存储，不会攒下界随轮数涨的垃圾；
  值**逃到更长寿的 arena**（函数层）⇒ 判否。局部聚合的字段、以及任何证不出层的值仍旧判否。
  **层从哪来**：`new` 的层用 `arenaDepthOf(planArenaLevel)`（与 (a′) 同一把尺），沿写入在
  同一趟走查里传播（`h = c`）、字段读沿字段名取最浅（`p = p.next`），整条链用一个**最小不动点**
  求解（`idleSolveLvls`；写入可以依赖后面才写的绑定，顺序解不出来）。**禁止**用 `anRefDepth`、
  字段表的深度、词法嵌套计数或 `lookup()->depth` —— 实测它们互不一致（同一个 `h = c` 上分别
  给出 1 / 3 / 6 / 4，arena 层是 3），混用会把逃逸形状判成 idle（`cross_scope_cycle` 的界 2.57×）。
* **(c) 没有丢引用的操作**：容器删除/替换、`@overwrite` 复用同一格、free 类内建、`domain` 块、
  `ext`/`dyn`（看不清的并发与派发）、**带引用的值聚合被产生成临时量**（结构体/数组/枚举载荷/
  按值返回的调用结果：它一死，里面的引用在那个时刻失去这个根，而临时量的存储属于哪一层 arena
  由逃逸分析定，可能的形态是"本帧的家房间"⇒ 界随轮数涨）、以及**看不清的被调者**带着引用。
  看得清的被调者不逐层追 —— 传递性由**整单元合取**覆盖：被调者自己也是被发射的一具函数，会再
  被判一遍；**一处不满足 ⇒ 整单元判否**。一条**声明的初始化式**不按临时量判：值落进具名槽，
  槽的 arena 层由它的块深度给出（循环体内声明 ⇒ 每轮整片释放）⇒ 有界；它的子表达式照常判
  （`wrap { n: mk(i) }` 里的 `mk(i)` 仍是一颗会被丢掉的临时量）。
   **细化 F（task-36）**：站点**不在任何循环里**（`minLoopScope == 0`）时放行 —— 循环外的临时量
   每次调用只产生/丢一次，它的存储最坏落在**调用方当前块**（`arenaArg` 默认就是调用点的块）：
   调用方在循环里时那块每轮归还，调用方不在循环里时也就丢一次；把它变成"家房间垃圾"的唯一路子
   （把聚合体存进比迭代长的槽）由 (a)/(b) 那两条挡着。**边界是实测的**：
   `struct_copy_ret_home`（站点在 `mk` 里、循环外）判 idle 后 N vs 4N = **1.00×**；
   `byval_temp`（站点在**循环里**：`take(mk(i))`）**必须仍判否** —— 整条放宽它峰值 **2.12×**，
   它是 `gate-idle-bounded.sh` 的常驻对照。
 * **细化 A/B/E（task-38）**：同一个（宿主, 叶路径）被写两处时，若**被覆盖的旧值另有根**
   （值是某个**形参**的投影、且本帧不写那个宿主的字段）⇒ 覆盖没丢根，放行（`idleValueOtherRoot`）；
   写目的地的**逐叶路径**（`(*root)[i]`、`s.kids[0]`）也落账，**非字面量下标**收进同一个键
   `base[]`（`idleDestPath`）；最外一层是**元素槽**且下标是"**在本循环体内被赋值**"的标识符时，
   不再要求"宿主本迭代新建"（元素槽序列 —— 每轮写的是不同叶槽）。三条一起让
   `persist_nodes`（2343.7 µs，命中集合最大）与它的真实语料来源 `bench/oi/persist/p3834_nodes.extc`
   判 idle：停顿 2699/2465 µs → **0**（探针拒绝插桩 ⇒ 无清扫调用点），真实语料墙钟 4.33 s → 3.18 s、
   峰值 766 MB → 508 MB、stdout 逐字不变。**边界**（`gate-idle-bounded.sh` 的两个新对照，
   实测抓出来的：原来六条对照对这三条窄化一条都不红 ⇒ 判据本来没牙）：
   `field_overwrite_lost_root`（A 若打回"整条放开"⇒ 1.52×）与 `fixed_slot_overwrite`
   （E 若打回"任意元素目的地"⇒ 1.56×）都必须留在回收档。

**它不等价于"无环"**：两条判据互不蕴含。②允许回边（`a.next = b` 与 `b.next = a` 两处站点
各自满足 (a)），而无环判据允许"每对象写一次"以外的丢引用（计数能兜住）。两条判据服务两个
不同的机制：无环 ⇒ 事件档（计数代替清扫）；② ⇒ 干脆不发射 rc。②的安全论证因此不是"没有环"，
而是"**没有丢引用**"：区域内的对象只会随区域整体释放而消失。

**E2 型（"这个区域永远不需要回收"）：判定现状与卡点（未落地）**

本节的判据是**整单元**的；另有一条更窄的用法：对**单个区域** R 证明"它永远不需要回收"，
于是 R 上的触发/销账整段不发射（消减的是那个区域的运行期，不是整单元）。要证三件事，
健全性条件各不相同：

* **(a) 没有释放路径能碰到 R 的槽**、**(b) R 没有出边**（宿主在 R 的引用赋值，其值也在 R 或 null）。
  (b) 是**屏障半场**的硬条件：跨区登记写在**值**所在的区域上，所以一条 R→S 的边就是 S 的**永久根**；
  只掐宿主在 R 的那个屏障而 R 还有出边 ⇒ S 的清扫看不见这条根 ⇒ **悬垂**。反向（宿主在 S、值在 R）
  不需要掐：登记留在 S 的站点上，而 R 的指针仍是合法的 rc 槽。(a)(b) 可判 —— (b) 直接复用生成物里
  已有的"同区"证明（`rcFreshHostRegion` / `extc_rc_storeRefSameRegion` 那条路）。
* **(c) R 里没有对象会变成垃圾**（内存界）—— 这正是本节 (a)(b)(c) 判据族要干的事；E2 只是把它的
  作用域收到**一个区域**，另外加上本节没有的 (b) 那条屏障条件。

**卡点：P2 型形状被本节判据的一条保守条款挡住。** 尾插形状里 `x.tail = b` 的宿主 `x` 是形参
（`t` 是形参投影），而判据要求写站点的宿主必须是**本帧 `new` 出来的局部量**，于是整单元判否
（`src/check/check_top.c` 的 `idleWriteOk`；拒绝理由的特征串是 "the host object is not a local
created by new in this frame"；诊断口径 `EXTC_DBG_RCIDLE=1` 逐函数打印判定与理由）。P2 此时**只被
这一条挡住**，生成物的其余部分全过。

**放宽这一条不健全。** 把"宿主非本帧新建"改成"只要值是本帧新建就放行"，反例是
`fn f(keep: mut ref T) { keep.f = new T }` 被循环调用：站点在 `f` 里、不在循环里（躲开循环条款），
宿主是形参，单元合取也看不见丢引用 ⇒ 每轮丢一个对象、**无界涨**，却被判成"永远不需要回收"。
P2 与这个反例的差别**只有"旧值是否另有根"这一维**（P2 的旧值先被链进了头指针），而那条证明是
**跨过程/别名**级的，本帧的语法扫描给不了；两条候选红判据（有没有 `freeSlot` 能碰到 R / 有没有跨区
登记）**都抓不到**这个反例：它既不释放也不登记。三条便宜的替代也不够：复用分配站点上的 arena 层
事实（值表达式拿不到它）、只放宽"值是本帧新建"（零新分析，但能命中的站点极少）、或认"值是被调者
返回本帧 home 区的新对象"（命中热点但覆盖面窄，要的是值级数据流，是另一个量级的工程）。

⇒ 要落 E2/E1，必须先造一条**跨过程 must 分析**（"链先接上、尾指针再前进"这类跨语句、跨调用的
不变量，证据形态是 `planFn*` 加不动点）。消减机制（掐触发/销账、同区改发裸存）的锚点已经就绪，
但判定恒假：落地必须做到"生成物逐字不变、判据空转"，红演示用注入把判定强制为真。两条判据
（静态清单 + 运行期守卫）**只给规格、不落空壳** —— 判定缺席时不许把"绿"当成证据。规格与锚点见
会话归档 [`archive/2026-10-15-gc-pause.md`](archive/2026-10-15-gc-pause.md) 报告索引里的 `E2_LANDING.md`。
**口径**：掐掉运行期后能不能压到线内，取决于按 `-O1` 还是 `-O2` 验收（见"四.一"）。

**开关语义**：`EXTC_RECLAIM=1` 是"**允许**回收 / 不强制关闭"，不是"强制发射"——证明成立时
发射运行期只是空转，所以②在**任何档**下都跳过。`EXTC_RECLAIM=0` 仍然是从不发射、对照组。

**失效方向**：少收 ⇒ **内存涨**，不是悬垂（rc 只释放标记不到的对象）。安全网是两条动态判据
加一条红证明：

* **税趋近 1**：`tests/reclaim-perf/gate-tax.sh` 的 `bt` 从 **1.133×（11.8%）降到 1.000×**
  （开/关档产物**逐字节相同**），中输入的 `bt-mid` 从 1.031× 降到 1.000×。
* **峰值有界**：**被判 idle 的形状**（默认档产物与关档逐字节相同）N vs 4N 的峰值 RSS 必须
  **< 1.5×** 且 4N 的绝对峰值有上界 —— `tests/reclaim-perf/gate-idle-bounded.sh`
  （`gate-reclaim-idle`），另带一个**必须仍在回收档**的对照形状（防判据一律放行）与反空跑
  （②真的生效：rc 记号 → 0）。`rebuild_per_round`（"循环里建、每轮丢"的最小形状）与
  `closure_chain` 是 (a′)+(b′) 那一类的安全网，**必须有界**。第二条防线是
  `tests/reclaim-acyclic/` 的 ⑦ 安全格：`cyclic_pressure`、`scale_growth` 这些有跨轮回边的

  `tests/reclaim-gaps/shapes/cross_scope_cycle.extc`、`scale_growth`、`live_churn`——都是
  "循环里建、每轮丢"的**同族**形状，只是对象逃逸到了函数层 arena：它们必须**仍留在回收档**
  （实测产物与细化前**逐字节相同**，N vs 4N 与细化前的基线一致：1.04× / 1.88× / 1.60×）。
* **能力棘轮**：`tests/reclaim-perf/gate-rc-idle-corpus.sh`（`gate-rc-idle-corpus`）数
  **固定语料清单**里"产物不含任何 `extc_rc_`"的形状数（清单与下限都只许往上；基线 **8**，

* **红证明**：注入 `reclaim-idle-always`（把判定强制为真）施加到会丢引用的形状 ⇒ 垃圾只等区域

## 四、停顿与分片

**停顿 ∝ 被扫区域的可达集**，所以最直接的手段是**分片**：把一个逻辑结构切进多个区域、每次只收一片。
分片数就是"停顿 ↔ 吞吐"的旋钮，不影响正确性。

两条纪律：**跨区登记要连分片一起分**，否则各片的清扫会都被同一批入口拖住；
**片边界必须与结构边界对齐** —— 只有"每个结构一个分配点"的形状才拿得到停顿收益：
同一处分配出来的东西（一条链、一个环、一代结点）始终留在同一片里，片内链条与环保持完整。
把一条链或一个环强行切开，跨片登记位就会成为环垃圾的种子 —— 不可达的环被这些登记位撑着，
界随轮数增长。

> **分片同理，编译器也守**：片号是**按分配站点**给的（`片号 = 站点序号 % 片数`），所以"结构边界
> = 片边界"只在**可能成环的结构各自落在单个分配站点**里时自动成立。单元里一旦存在**跨站点**的
> 可能环（`applyCycleMerges` 的站点并查集给出、分量含 ≥2 个分配站点），`EXTC_RC_SHARDS > 1`
> 在该单元就**退化成单片**（`src/back/codegen.c` 的 `scanUnitReclaim`）：只把"同环组的站点"钉进
> 同一片不够 —— 环组之外的站点（容器、索引）仍在别的片，跨片引用照样把整条环钉住。
> 代价写在明处：这种单元里分片旋钮**不再有停顿收益**（保守方向：界优先）。
> 单站点自环（`shard_bands` 的"每条链一个分配点"）不触发这条，分片照旧 ⇒ 旋钮在它该有用的
> 形状上仍然有用。判据：`tests/reclaim-perf/gate-shard-cycles.sh`（`digraph` 上默认档的峰值
> ≤ 0.5× **同 N 的关档基准**、默认档的 4N/N < 关档的 4N/N、且 `SHARDS=4` 的 4N ≤ 2× 默认档；
> `shard_bands` 上 `SHARDS=4` 的停顿仍 < 0.75× `SHARDS=1`）。与同 N 的关档比：绝对峰值里混着
> 每槽元数据那样的常数项，跨规模比会被常数项掩盖 —— 关档基准把常数项消掉，留下的才是回收
> 真正压住的增量。

> **编译器现在自己守这条纪律（「可能的环」的候选区域合并）**：一个 *可能闭环* 的引用写
> （`(*cur).f = v`，值既不是空、也不是新分配、也不是严格更年轻的层 —— 判据就是 `fnAcyclic`
> 那条现成的 `SR_BAD`）如果宿主 `cur` 可能指向**不止一只区域**里的分配站点，编译器就把这些
> 候选站点连同值**并到最浅的那一只**（`src/check/check_escape.c` 的 `applyCycleMerges`，
> 在全局电平求解之后、placement 之前跑）。只往更长寿的一侧挪，所以最多多留一会儿；
> 候选里出现家区域时不并（家区域的决定已经关死），`EXTC_RECLAIM=0` 时也不并 —— 没有回收
> 运行期就没有区域划分，关档产物逐字不变。
> 判据：`tests/reclaim-gaps/shapes/ring_per_round.extc`（N vs 4N 峰值 < 1.5×），修前 3.90×、
> 修后 1.00×，见该目录 README 的 §G8。

取舍同样清楚：**分片让停顿变好，代价是峰值内存与吞吐变差** —— 每片都有自己的存储底噪
（片多，底噪就多），也都有自己的标记栈。

分片的代价是**纪律**：一起生一起死的东西放在同一层区域里，一个长期结构自成一层或自己分片。

### 四.一、窗口怎么量、判据用哪个数（`EXTC_RC_PAUSE=1`）

**量具**：`EXTC_RC_PAUSE=1` 时进程退出打三行到 stderr ——
`[pause]`（契约入口 `collect`/`checkOwed` 进→出）· `[step]`（**每个切片**：`markStep`/`sweepStep`
每次调用的墙钟 n/max/total + 阈值桶 `over16/over64/over256/over1ms`）·
`[work]`（同一批切片的**确定性工作量**：`walk_max/scan_max/push_max` + `>16/>64/>256` 桶）。
`tools/rc-pause-probe.py` 也能插桩 `extc_rc_collect` 与热路径 `extc_rc_step`（`PROBE … step_*`），
并在插桩失败时 **rc=1**（不许伪装成 `sweeps=0`）。

**`[work]` 的盲区（2026-10-15 抓到，已补量具）**：`[work]` 只统计 `budget ≤ EXTC_RC_MARK_BATCH_MAX`
的**有界热路径步**；契约排空/结算收尾（`budget=∞`）连量具都躲过去 —— `[step] n` 与 `[work] n`
的差就是它们。于是「一次无界排空」在 `[work]` 里表现为**零工作量**（看起来像"这一步没工作"）。
补的三行：

* `[ubwork]`：无界步单列 —— `mark_n/walk_max/scan_max/push_max` + `sweep_n/sw_words_max/sw_freed_max`
  + 按入口分 `settle_n/collect_n/release_n/other_n`。判据：正常程序 `mark_n == 0 && sweep_n == 0`
  （无界排空只允许出现在显式契约入口，且必须被点名）。
* `[worst]`：**耗时最大那一步**的分项归因（`kind=mark|sweep`、`why=` 入口标签、预算与各项计数），
  用来区分「多项叠加」与「单一项顶到预算」。
* `[guard]`：屏障参与者计数 `r4_wb_open`（**信息量** —— 程序可以不 `regionDrop`，那时 >0 合法）。
  **真正的判据是 `finish`/`abort` 里的配对自检**：`r->marking` 为真 ⇒ 该区域贡献过 `wb+1`，
  减完必须恰好少 1，漏减/下溢都会 `extc_rc_oops`（`trap: reclaim: R4:` + rc≠0）。**不要**写成
  "退出时 `wb==0`"。

`EXTC_RC_TRACE_UB=1` 再把每一次无界排空连**当时的步号**打出来（`[ubtrace] step_n=…`）⇒
「热循环里每轮一次」与「进程退出时一次」由步号直接区分，不靠推理。

**判据用哪两个数**：
1. **确定性工作量界**（`[work]`）：热路径每步 `walk ≤ EXTC_RC_MARK_BATCH_MAX`、
   `scan ≤ EXTC_RC_SEED_WORDS`、`push ≤ EXTC_RC_SEED_PUSHES + 63`（压栈按**字**收口：一个字最多
   64 位，所以最后一个字可能超出名义预算 ≤63；这是粒度，不是失控）。超界就是**真的**要做整形。
   **这条已由 `gate-reclaim-work` 自动强制**（挂 `nobench`，约 3 秒）：五形状现场生成+运行，
   `[work]` 必须存在且 `n>0`（否则文案是"插桩失败/工具不兼容"，不许当绿）、每形状 3 次逐字相同、
   三条界全部**蕴含式**成立；三个预算与 `rsbit` 字宽都从**产物** `#define` grep（读不到 ⇒ 红，
   不许硬编码）。红演示见 `docs/CHANGELOG.md` 顶部：把种子扫描的字预算拿掉 ⇒
   `scan_max=5120 > SEED_WORDS=512` 直接红（就是那个历史洞）；把 `[work]` 改名 ⇒ 五形状全红在"插桩失败"。
2. **超阈切片计数**（`[step]` 的 `overK`）：`over1ms` 必须恒 0；`over64/over256` 用于比值。
   判据是"计数在中位数/最小值口径下不上升"，不是单次最大值。

**统一工作量预算 `EXTC_RC_WORK_BUDGET=W`（C 编译期 `-D`，默认 0 = 关）**：默认形态下
`walk`（`MARK_BATCH_MAX`）、`scan`（`SEED_WORDS`）、`push`（`SEED_PUSHES`）是**三个独立预算**且
**叠在同一步**里 ⇒ 一步最坏 = W_walk + W_scan + W_push 个单位。`W > 0` 时三者与 `wbDebt` 加力
**共用一个总额**（walk 1 对象 = scan 1 字 = push 1 槽 = 1 个单位），由 `markStep` 里的
`wleft` 扣减；种子字**压不完就把剩余位留在 `seedBits`、游标停在同一字**，所以一个字绝不半途
丢弃（丢位 = 种子不完整 = 不安全），也**不靠 `+63` 超发**换完整性。观测口径是 `[wbudget]`：
`tot_max`（单步 walk+scan+push 最大值）必须 `≤ W`，`assist_max` 是其中 `wbDebt` 加力的份额。

**两个非预算停顿源（已定位并封掉）**：
* **`settle` 的无界排空**：`regionFree` 原来调 `settle` 把在飞一轮**做完**。P5@2.4M 实测一次排空
  **268,785 个对象 / 25.2 ms**（`[worst] why=settle budget=4294967295`，`over1ms=2`）。区域马上整片
  `free` ⇒ 收尾没有可观测意义 ⇒ 改成 `extc_rc_abort`（取消在飞轮 + 屏障参与者 -1），
  25.2 ms → **200–570 µs**、`over1ms` → **0**（`[ubwork] mark_n=0 sweep_n=0`）。
* **分片触发的 `extc_rc_bytes/live`**：这两个访问器的契约是"先 `settle` 再读数" ⇒ 落在 mutator 触发
  路径上时**每次触发**付一次 O(在飞轮) 停顿（实测 8 片 2.4M：`step_n=19101` 处**在环内**排空
  65,569 个对象 ≈1.1 ms，`[pause]` 看不见它）。触发只需要一个**序** ⇒ 换 `extc_rc_garbageHint`
  （`bytes - live`，不 settle）。分片 2.4M 的 `[step] max` 1.1–1.4 ms → **12.8–178.3 µs**。
* **慢步量具** `EXTC_RC_SLOWSTEP=<µs>`（默认关）：超阈值的每一步都打 `kind/why/分项/mscap/msp`
  ⇒ 判"长尾是外部抢占还是真的重对象"（前者工作量恰好等于预算、`mscap` 不变）。

**不要用单次 `smax` 当判据**（实测）：同一份产物、同一确定性工作量（`[work]` 逐字相同），
p5 的 `smax` 在 40 次里能从 17.2 µs 跳到 362.2 µs（**21×**）、shard 16.6↔249.2（15×），
而这些run 的 **involuntary context switch ≈ 0**（最高 20% 组均值 0.0–0.4）⇒ 不是进程被抢占；
`taskset -c <核>` 钉核（本机无 `chrt` 权限）**不能**系统性削掉它（钉/不钉的 p90 与 `over64`
在 ±30% 内来回、方向不一致）。残余的是**外部干扰**：中断、频率、以及同机其它进程的
cache/内存带宽争用 —— µs 级切片上这就是测量噪声。**结论：单次最坏片不可作判据；要压就压
"工作量界"与"超阈计数"。**

**口径：引用任何数字前先钉这一条。** 同一份 Ir 在 `-O1` 与 `-O2` 下的墙钟差可以相当大
（`-O1` 会把调用/`memset` 这类开销放大）⇒ **跨口径引用无效**：写数字必须连它出自哪一档一起写。
reclaim 形状闸门（`gate-shapes`/`gate-work`/`gate-shard-cycles`/`gate-idle-projection`）用 `-O2`；
`bench/run.sh`、`gate-idle-bounded`、`ablate-tax`（cyc）用 `-O1`（**以各脚本自己的编译命令行为准**）。
**本文档默认引用 `-O2`**，`-O1` 的数字单独标。判定"某条优化能不能压到线内"的结论完全取决于钉哪
一档 —— 验收线必须先钉死，再谈达标。

**无界步必须单列。** `[work]` 只统计**有界热路径步**（`budget ≤ EXTC_RC_MARK_BATCH_MAX`）⇒
`regionFree`→`settle`、`collect`、定点释放的 `mark` 这些 `budget=∞` 的排空**整段不进 `[work]`**；
而 `[pause]` 的包裹（`pauseArm`）只挂在 `maybeCollect`/`checkOwed` 上，**不包 `settle`** ⇒ 一次无界
收尾只在 `[step]` 的 max 里露头，两个"日常看"的行都看不见它。**量具与判据见本节上面的
`[ubwork]`/`[worst]` 段**（本节只有一份规格，不重复）：正常程序各入口计数必须为 0，`over1ms` 恒 0。
`gate-reclaim-work` 现在强制这两条；在那之前它全绿**不等于**没有无界步。

**工作量守恒不是时间守恒。** 若把标记侧那几条独立预算并成一个统一工作量预算 W，记住它的单位是
"1 对象 = 1 字 = 1 槽 = 1 个单位"：`tot_max == W` 是**工作量**守恒，**不是时间界**。单位价格
**不是一个常数**（同一份工作的冷/暖态能差两个数量级），所以"最坏停顿 = W × 常数"这种推法会错；
把"最坏步耗时 ÷ 预算"当作单位价格也是错的（那是尾部，不是价格）。清扫另有**独立预算**
（按字计，1 字最多 64 槽 ⇒ 一步的释放数 ≈ 字预算 × 64），标记侧的天花板压不到它；要压最坏步
必须两边一起看。W 的观测口径与推荐值见会话归档报告索引里的 `PAUSE_10US.md`。

## 五、要做的

现在还有若干形状**清扫覆盖不到**：那些形状的界仍随规模增长，有的比关掉回收还差。它们是同一个
动作的后果 —— **编译器在「列不全」的时候选择「不扫」**。要做的是两块。

* **把「根」与「宿主」各自收敛成一个来源、一个出口。**
  - **根**：活引用槽的位置现在按词法作用域分函数拼。应当由逃逸分析那一份「引用槽在哪、指向什么、
    活到哪一层」的事实统一产出，运行期只维护**一条任何触发点都走得通的根链**（帧节点 + 槽表 +
    线程本地链）：进帧登记一次、出帧撤销，标记时遍历整条链。
  - **宿主**：写引用时要能说出"这条槽装在哪个对象里"。现在下标槽、基表达式带调用或视图的槽证不出
    宿主，于是整个区域不扫；应当把目的地求值一次，再逐叶落账。
  - **出口**：「别收」现在有四种互不相干的表达（编译期的区域级与函数级、运行期的一次性与永久），
    各自在不同地方查。应当合成一个。
* **把登记点铺全**：协程帧、`ext` 派生的帧、整条 worker 调用链共用的线程本地区域，以及被当作
  「枚举不出引用」处理的几类载荷（`match` 绑定、`dyn` 载荷、池容器元素、视图元素），都要能把引用
  登记进那条链。

**语义边界**（是决定，不是缺口）：板、池、C 栈、`dyn` 池这类**不受回收管辖**的内存里放着的引用，
它的入边无法被登记-撤销追踪，只能把**目标钉住** —— 那块内存活着，目标就不放；界由容器的生命周期给。

* **计数按编译期收窄**：计数加不加由编译期决定，而不是一律加。**能省的只有 `inc` 那一侧**
  （省 `dec` 永远安全，代价只是晚收），判据是**对象级**的：该对象的账本在它活着期间只增不减 ——
  也就是"它的**每一条**入边都不会有 `dec` 落下来"。注意这是**对象**的性质，不是边的性质：
  任一条边留了 `dec` 而别的边省了 `inc`，这个 `dec` 就可能把它打到 0（`hold` 归零当场放）。
  三个可用的充分来源：
  ① 该对象的**全部**入边统一决定（要么全发、要么全省）；全省时死期由所在区域的释放/清扫兜底 ——
     注意**块退出只 release arena，rc 区域活到帧销毁**，"块里建的链随块整片释放"不是今天的实现；
  ② 赋的是本函数 `new` 出来的对象，别名集合封闭，且各入边槽此后再不被写；
  ③ 有一条持有边**在被省的边活着期间不会被销账** —— 不是"存在别的持有者"：持有边自己可能先死
     （反例 `keep_other_holder_dies.extc`：省掉这条边的 `inc` ⇒ 读到 `v=2`，基线 `v=7`）。
  实现落点：`inc` 侧要能单独省（`holdUpd +1` 与跨区登记 `rs` 分开），并加"账本只增"的分析事实；
  **已落地的一档（跨过程"本帧不会销账"）**：`rcNoDec(F) = ¬写引用槽(F) ∧ ¬未知/extern 调用(F)
  ∧ ¬并发(F) ∧ ∀g∈callees(F): rcNoDec(g)` 的调用图最小不动点成立时，F 里局部引用绑定的 `inc`
  改发 `extc_rc_initRefNoHold`（只写槽）。自环（递归）不构成保守理由 —— 环上没人写槽就没有 `dec`。
  实测 `bt` 的税 4.637× → 2.040×（in-small）／4.124× → 1.075×（全输入）。
  判据：`tests/reclaim-elide/` 的 `elide_readonly_recursion`（该省）+ `keep_callee_writes` /
  `keep_indirect_callee`（两条语义敏感的健全性反例）。实现见
  `src/check/check_top.c` 的 `computeRcNoDec`、计划侧 `planRcNoDec`、`src/back/codegen.c` 的 `stVar`。
  收益在"大量指针赋值、极少分配"的代码里最大，而**当前最大的一笔是局部引用拷贝**
  （`var p = t`，见 [`tests/reclaim-perf/README.md`](../tests/reclaim-perf/README.md) §10）——
  那一笔要跨过程效果（"被调者不会释放它"），比上面三类都难。
* **环的可观测性**：让"这个区域里有环"能被统计到，自学习退场才有更准的判据，
  而不必靠"扫了才知道没有"。

### 五.一、按优先级的开放项（机制与出处）

上面两块是"清扫覆盖不到"的机制缺口；下面这份是**开放项清单**，按优先级排，每条只写"要什么行为"
与出处。实测数字只在归档与 `CHANGELOG.md` 里，本节不复制它们 —— 出处见会话归档
[`archive/2026-10-15-gc-pause.md`](archive/2026-10-15-gc-pause.md) 的报告索引。

1. **取消式收尾 —— 已落地**（`extc_rc_abort`：`regionFree` 不再排空在飞的一轮，取消并配对减
   `wb`；`finish`/`abort` 带运行期配对自检）。P5@2.4M 的 25.2 ms 排空消失（`over1ms` 0，
   `[ubwork]` 各入口全 0）；**残留**：多区域同时标记（`wb>1`）下的取消路径没测。
2. **记账访问器不要再收尾**：`bytes`/`live`/`scale`/`sweeps`/`freedSlots` 现在每次观测都 `settle`
   ⇒ 程序在循环里查账就付 O(在飞轮)。**分片触发的片选择已改走 `garbageHint`**（不 settle）；
   对外的"观测即终值"契约要单独决定（`PAUSE_10US.md`）。
3. **`collect` 契约入口的无界是设计决定，不是缺口**：它承诺"调用内收完一轮"，codegen 不发它；
   要它有界就得改契约语义（`PAUSE_10US.md`）。
4. **定点释放的无界标记**：`releaseOld` 里的 `mark` 仍是 `budget=∞` 的 O(活集) 遍历，靠信用摊销、
   单次仍无界；现有形状没有一个触发过它，所以只有量具、没有形状（`PAUSE_10US.md`）。
5. **R4 没有守卫**：关屏障到清扫结束之间"把白对象写进黑对象"的边写入无守卫；应收尾条件里常驻一条
   可检验的量（`REVIEW.md`/`M1P_SPEC.md`）。
6. **M2 只有诊断**："灰已置黑却还没被扫"的断言只在诊断脚本里，没收进收尾条件（同上）。
7. **多区域同时标记（`wb>1`）下的取消路径没测**：取消式收尾只在单区域的销毁路径上验过（`PAUSE_10US.md`）。
8. **统一预算 W 自身的覆盖**：W>0 的 sanitizer 抽样与 N vs 4N 都没测（`PAUSE_10US.md`）。
9. **`gate-shard-cycles` 仍挂在 `bench` 档** ⇒ `nobench` 盖不到它；要么降规模进 `nobench`，
   要么接受它只在含基准的档里跑（`GATE_FIX.md`/`WORK_GATE.md`）。
10. **已黑值缓存**：指令数收益大，但缺"守卫 + 红演示 + 尺寸标定"才能谈落地（`C3_DIRTY.md`）。
11. **两笔归因还没做**：`alloc` 每调用的指令数、P4 的清扫分步成本（`REDUNDANCY_AUDIT.md`/`PAUSE_10US.md`）。
12. **E1/E2 悬置**：E2 卡在跨过程 must 分析（见"三点七"），E1 是它的直接后果；不立这条大项，
   表示耦合的那两个形状只能靠小刀压到接近 1 的比值（`E2_LANDING.md`/`ARENA_CRITERION.md`）。
13. **语料覆盖**：`-O1` 全谱交叉验证被并发污染作废、待补；真实应用与 `bench/` 其它形状未覆盖
   （报告索引里的 `ARCHIVE_2026-10-15.md`）。
14. **判据自身的粗粒度**：超阈桶是粗分位；小预算下"标记栈高水位 + `markStep` 内的 `realloc`"
   这条耦合没定量（`PAUSE_10US.md`）。

  [`tests/reclaim-gaps/`](../tests/reclaim-gaps/README.md) 给出。

  [`tests/reclaim-unified/RECON.md`](../tests/reclaim-unified/RECON.md) 给出。
* **两条新闸门**（都挂 `nobench`，运行期零改动）：
  - `gate-reclaim-work` 强制**工作量界** —— `[work]` 必须存在且 `n>0`（否则文案是"插桩失败/
    工具不兼容"，不许当绿）、每形状多次运行逐字相同、三条界全部从**产物**里读出（读不到即红，
    不许硬编码）；红演示见 `CHANGELOG.md`：拿掉种子扫描的字预算 ⇒ `scan_max` 越界直接红，
    把 `[work]` 改名 ⇒ 五形状全红在"插桩失败"。
  - `gate-foreign-skip` 守**"跳过旧值登记查表"的前提** —— 每个撤销点被"这只区域出现过跨区值"
    把门、每个登记点同行置位，再编一个带守卫的构建跑一次，要求守卫被检查过且零违例（拿不到守卫
    计数行即红，按"插桩失败"处理）。失效方向是**不安全**（漏撤一条跨区入边），语义与输出类判据
    看不出来，所以它必须是结构门禁。
  - 分片那条 `gate-shard-cycles` 的判别口径是**平均切片**与**超阈计数**（`over1ms` 恒 0、
    长切片受控），不是单次最大值；它仍挂 `bench` 档（`nobench` 盖不到，见"五.一"）。
* **两条通用规则**（比任何单条判据都重要）：
  - **判据必须能红。** 每条不变量都要有一个注入或结构门禁，红点写进表里（见下面两张表）；
    "没测到"不等于"已证否"。
  - **插桩/判定失败不许伪装成绿。** 量具读不到目标时必须报"工具不兼容/插桩失败"并让判据红，
    而不是报一个 0：`[work]` 缺失、以及探针认不出增量形态（`owed-home` 这类形状），都属于这一类。
    同一条规则也管"按区域判定"：判定缺席时不许落"空壳绿"的判据（见"三点七"）。

## 快路径与"跳过"：前提、失效方向、判据

运行期里有若干**为了省事/省时**直接返回的地方。它们每一条都依赖一个前提；前提被破坏时，
失效方向可能是"多留"（保守）也可能是"少算"（不安全）。义务表管"必须成立什么"，这里管
"**跳过的那一刀为什么安全**"。

**这些地方在代码里都带 `/* skip:<id> */` 标记，标记与下表由 `tools/check_skip_table.py`
（`gate-skip-table`）双向对齐**：代码里出现而表里没有 ⇒ 红；表里有而代码里没有 ⇒ 红；
出现**没标记**的单行早退 ⇒ 红（棘轮，只许往下拧）。表里不带标记的行是"非早退形态"的
快路径/边界，由人读（例如 `partN` 闸门本身不是早退）。

| 标记 | 跳过 | 前提 | 破坏后的方向 | 判据 |
|---|---|---|---|---|
| `skip:chain-bad` | 帧根链上有一帧**枚举不全**（协程帧/`ext` 帧/池元素/视图元素/`match` 绑定那几档）⇒ 整条链拒绝清扫（种子不完整）| 该帧的槽枚举不全 ⇒ 标记走不到它持有的引用 | 多留（保守）| 与 `skip:nosweep` 同一个出口：义务 7 单测 + 注入 `noSweep-drop` | 
| `skip:sweepfree` | `EXTC_RC_SWEEPFREE=1`（事件档）⇒ 该区域永不触发清扫，只靠计数归零当场回收 | 整程序被证明无环、且**所有能丢引用的位置都是被计数的 rc 槽**（否则记数不完备）| 少算（内存涨，不是悬垂）| **诊断档**：实测它在语料里没有一个能赢的形状，判据已摘出电池（`gate-acyclic` 自报 manual，见 [`tests/reclaim-perf/TAXMAP.md`](../tests/reclaim-perf/TAXMAP.md) 第 7 节）；手工红证明仍用注入 `acyclic-always`（有环形状 RSS 爆）|

| `skip:rscnt-have` | `rscnt`（每槽跨区入边计数表）已经建过 ⇒ `extc_rc_rsAlloc` 直接返回 | 表一旦建好就跟着 slab 活到 `slabFree`（懒分配只发生在第一次 `rsInc`）| 无（幂等；若重复分配就会泄漏旧表 ⇒ 这条必须保持）| 跨区形状语义逐字（`cross_region`）+ `gate-reclaim-work` |
| `skip:rscnt-none` | `rscnt` 表不存在 ⇒ 只读访问器返回 0、`rsDec`/`freeSlot` 跳过写 | 表不存在 ⇔ 这块 slab 一次登记都没有过（`rsAlloc` 只在 `rsInc`/`rsIncSlab` 里调）⇒ 没有入边可减/可读 | 少算（把「有入边」读成 0）| 跨区形状 `EXTC_RC_STATS=1` 的 `rs_live` 不随轮数涨 + `gate-reclaim-switch` / `gate-reclaim-gaps` |
| `skip:same-region` | 值与宿主**在同一个区域**（编译期证得）⇒ 赋值时不登记、不查表 | 两项都是**本帧新局部量**且 arena 层相同 ⇒ 这条边不可能跨区 | 少算（不安全）| `gate-reclaim-switch` 的 `cross-region：登记量判据`；注入 `same-region-always`（把判定强制为真）⇒ 红在那条上 | 
| `skip:occ-free` | 按槽计数/登记/持有的入口：槽没占用就返回 | 只有**占用**的槽才有计数、登记位、类型 | 多留（保守）| 注入 `occ-guard-drop` ⇒ 红在 `bump 跨区：bump 槽在按槽登记之外` |
| `skip:sat-inc` / `skip:sat-dec` / `skip:hold-zero` | 计数到顶粘住 / 降到零以下不再减 | 饱和值粘住 | 少算（不安全）| `count-nosat` / `rsinc-nosat` ⇒ 各自红在饱和判据上 |
| `skip:not-own` / `skip:no-pointer` | 指针查不到自己的 slab（或指针为空）⇒ 当作"不是本运行期的槽" | 只有本运行期的 slab 才会被查 | 少算（不安全）| 反向表 `ownTab`/`bigTab` **无上限**（`realloc` 翻倍）⇒ 查不到只可能是外来指针；ASan 语料 + 跨语言对拍 |
| `skip:lookup-probe` | 反向表二分查找的越界/不等判断 | 表按载荷地址有序 | 少算（不安全）| `gate-checkc` 两模式全语料编过 + ASan 语料；**没有专门注入** |
| `skip:reg-dup` | `extc_rc_register` 已置位就不再置 | 登记位是幂等标记 | 少算（不安全）| 单测 `登记：目标槽登记位置位` + `register-noop` |
| `skip:no-desc` | 槽没有类型描述符（数据对象）⇒ 不追字段 | 数据对象没有引用字段 | 少算（不安全）| 单测 `类型：描述符字段数正确` + `mark-nodesc` |
| `skip:no-region` | 宿主区域证不出来 ⇒ 跳过登记 | —— | 少算（不安全）| 由调用方改走"目标区域退出清扫"（义务 7）|
| `skip:no-trigger` | 压力没到阈值（或起轮信用未到）⇒ 不起新轮 | 阈值由 `live`/`scale` 推出；起轮信用由起轮/结轮消费的 `roundVisitedBytes` 计（与定点释放的 `visitedBytes` **分开**）| 内存（界）| `thr-stale` ⇒ `阈值缓存③`；`sweep-never` ⇒ churn 界红；`gate-reclaim-gaps` 的 `cross_scope_cycle`/`own_room_cycle`（把起轮信用去掉会让这两个形状饿死）|
| `skip:mark-tick` | `markAdvance` 的节拍计数没到（每 `EXTC_RC_MARK_EVERY` 次分配推进一步）| 节拍只是**摊销**：少推一步 ⇒ 本轮标记晚一点完成，下个分配点还会推 | 无（只影响时点）| 五形状语义逐字 + `gate-reclaim-switch`；单测 `无环有界负载：清扫次数不随规模增长` |
| `skip:finish-early` | 标记还没做完（`!marking` / `!seedsDone` / `msp != 0`）⇒ `finish` 不做，留给后续步进 | 只有种子与标记栈都空，才允许关屏障、起清扫 | 无（幂等：步进早晚会做完）| `gate-reclaim-count-unit` 的环/饱和断言 + `gate-reclaim-switch` 语义 |
| `skip:marking-resume` | 本轮标记还在飞 ⇒ 热路径（`maybeCollect`/`checkOwed`）只做一次**成批推进**，不另记停顿 | 在飞一轮由分配路径的 `markAdvance` + `finish` 摊销；`settle` 在查询/销毁处兜底收完 | 无（把一次长停顿摊成多步）| `gate-reclaim-switch` 语义 + `EXTC_RC_PAUSE` 的 `[step]`；窗口判据（cross ≈ 6–20 µs）|
| `skip:owe-credit` | 销账点的**第一轮**无条件兑现（`roundVisitedBytes == 0`）；之后起轮信用未到 ⇒ 欠账挂着 | 起轮信用由新分配偿付；一个从没起过轮的区域没有"已消费"的账 | 多留（保守：垃圾晚一步收）| `gate-reclaim-switch` 的 `owed-home`（探针清扫次数 > 0）+ `gate-reclaim-count-unit` 的"义务 7"|
| `skip:shade-off` | 没有在飞标记（`extc_rc_wb == 0`）或新值为空 ⇒ 屏障不动作 | 没有标记就没有白对象需要着色 | 无（幂等；热路径常态）| 语料指纹 + `gate-reclaim-switch` 语义；`gate-skip-table` 自检 |
| `skip:shade-outside` | 新值不在本运行期的 slab 里，或它所在区域没在标记 ⇒ 不动作 | 只有本运行期的 slab、且该区域正在标记时才需要着色 | 少算（不安全）| `owns` 守卫单测 + 跨区登记判据 + ASan 语料 |
| `skip:shade-free` | 槽空闲（`occ` 位为 0）⇒ 不是对象，不动作 | 空闲槽没有引用字段可追 | 少算（不安全）| 单测 `守卫：空闲槽不是活对象`；`gate-skip-table` |
| `skip:shade-black` | 槽已标黑 ⇒ 不重复着色 | 黑对象不需要再入灰集 | 无（幂等）| `gate-reclaim-switch` 语义 + 单测 `槽唯一` |
| `skip:nosweep` | 种子不完整的区域 ⇒ 一个字节都不扫 | 该区域有追不到宿主的入边 | 少算（不安全）| 义务 7 单测 + `noSweep-drop` |
| `skip:release-budget` | 自上次 O(活集) 遍历以来的新分配 < `max(live, floor)` ⇒ 这次定点释放不做 | 一次 O(活集) 遍历必须由分配量摊销；否则赋值路径上出现 O(N²)（40k 次追加 5.08 s vs 关档 2.4 ms）| 多留（保守：垃圾晚一步收）| `gate-release`（`ring_per_round` 释放槽数仍 >0）+ `gate-reclaim-switch` + `gate-idle-bounded` |
| `skip:not-sweeping` | 没有正在进行的分步清扫 ⇒ `sweepStep` 直接返回 0 | 分步清扫是显式状态（`sweeping`）| 无（幂等）| `gate-reclaim-switch` 的形状语义 + `EXTC_RC_PAUSE` 的 `[step]` 行 |
| `skip:sweeping-resume` | 上一轮分步清扫没扫完 ⇒ 触发点只**续扫一步**，不起新的 mark | mark 依赖"标记位图已清零"，位图由清扫逐字清零 | 无（把一次长停顿摊成多步）| `gate-reclaim-switch` / 语料指纹（语义逐字节）|
| `skip:sweep-continue` | 这一步没扫到底 ⇒ `sweepStep` 返回 0，下一轮（分配点）继续 | 游标留在区域里 | 无（同上）| `gate-skip-table` + `gate-reclaim-switch` |
| `skip:nosweep-abandon` | 义务 7 区域（`noSweep`）**弃扫**：在飞的一轮就地作废，之后一个字节都不扫 | 种子不完整 ⇒ 该区域只靠计数回收 | 无（少收 ⇒ 内存涨，不是悬垂）| `gate-reclaim-count-unit` / `reclaim-unit` 的"义务 7"断言 |
| `skip:no-owe` | 没有欠账 ⇒ 不销账 | `owe` 由触发点置位 | 多留（保守）| `gate-reclaim-switch` 的形状语义判据 |
| `skip:no-bumpslab` | 还没 bump 过 ⇒ `bumpReset` 直接返回 | 没有 slab 就没有可复位的指针 | 无（幂等）| 单测 `bump：载荷连续排布` / `bump reset：不新增 slab` |
| `skip:armed` | 统计只装一次 | 幂等 | 无（诊断）| 无（诊断路径，不影响回收语义）|
| （无标记）`if (extc_rc_rsIncN) unlinkChildren(...)` | 一次登记都没发生过 ⇒ 不必撤边 | `rsIncN == 0` ⇒ 没有 `rsInc` 类边 | 多留（保守）| `unlink-nop` 证明"撤边"有牙；这个**守卫**没有专门注入 |
| （无标记）`if (partN > 1) { 登记 }` | 只有一个区域参与 rc ⇒ 免登记 | 单区域不可能有跨区边 | 少算（不安全）| `gate-note-part` + `cross-region` 登记量判据 |
| （无标记）`#if EXTC_RC_NOCOUNT` 整段 | 关掉计数时计数入口变空操作 | 没有读者 | 少算（不安全）| 单测**两档都跑**（默认 61 / 计数 103）|
| （无标记）`ownTab`/`bigTab`/`mstk` 增长 | `realloc` 翻倍；失败即 `oops` | 不静默截断 | 不会静默失效 | `gate-checkc` + ASan 语料 |
| （无标记）区域注册表上限 `EXTC_RC_REG_MAX = 512` | 满了仍新建区域但**不登记** | 活跃区域数不超过 512 | **仅泄漏**（该区域不会被 `regionDrop` 回收）| **无判据**（需要 >512 个活跃块区域 ≈ 512 MiB slab，成本不成比例）|
| （无标记）递归深度上限 `EXTC_RC_REC_LIMIT = 100000` | —— | —— | 明确 trap（不静默）| `extc_rec_enter` 主动报错 |

**结论**：唯一"有上限且静默"的是区域注册表那条，方向是泄漏（保守）；其余要么无上限（增长），
要么前提被判据钉住。

## 不变量与它们的"牙"

回收的健全性靠一串**义务**（代码注释里编号的那几条）。下表把每条义务、它坏掉时的方向、
在哪强制、以及**哪条判据证明它有牙**列在一起 —— 只写"有判据"不算，能红的才算，
证明方式写清楚（注入名 / 单测名 / 形态）。**没有牙的当场标出来**，不留"看着像有"。

| 不变量 | 坏掉的方向 | 在哪强制 | 怎么证明它有牙 |
|---|---|---|---|
| 义务 1：`initRef` 新槽只写、加一，**不读旧值** | 不安全 | `extc_rc_initRef*` | 注入 `count-noinc` ⇒ 计数档红在 `initRef：目标计数 +1` |
| 义务 2/5：登记位不留陈旧入口（撤销出边、释放清位）| 泄漏（保守）| `freeSlot` 清 `rsbit`、`unlinkChildren` 撤出边 | 注入 `rsinc-drop` ⇒ `cross-region：登记量判据破了`；撤销侧：单测 `撤销：…` + 注入 `rsdec-nop` ⇒ 红在 `撤销：撤掉一条边后计数减一、登记位仍在` |
| 义务 3：计数到顶**粘住**（`hold` 与 `rscnt` 都一样）| 不安全 | `rsInc`/`rsIncSlab`/`holdUpd*` 的 `SAT` 守卫 | 注入 `count-nosat` ⇒ `饱和：计数到顶粘住`；注入 `rsinc-nosat` ⇒ `跨区计数：到顶粘住`；注入 `realpath-noreg`（只破坏**真实赋值路径**的登记）⇒ 红在 `跨区计数（真实路径）：到顶粘住`，证明真实路径那一组断言有独立的牙 |
| 义务 4：按**对象自己的**描述符走指针字段 | 不安全（走漏 ⇒ 少标）| `extc_rc_mark` 用 `s->type[i]` | 单测 `类型：描述符字段数正确` + 注入 `mark-nodesc` ⇒ 红在 `跨区：B 从入边位图播种` |
| 义务 7：种子不完整 ⇒ 目标区域**退出清扫** | **不安全** | `storeRefUnknown` / `storeStructCons` 的保守分支 | 单测 `义务 7：…退出清扫` + 注入 `noSweep-drop` ⇒ 红在那条上 |
| 参与区域数（单区域免登记快路径的前提）| **不安全** | 槽的**诞生点**记 `partN`：`extc_rc_alloc` 无条件记、`storeStructCons` 的保守分支也记；**赋值侧不再记**（冗余：槽的区域在诞生时已记过，见 CHANGELOG 2026-10-15）；`extc_rc_regionFree` 开头有 **R3 运行期守卫**复查"有占用槽 ⇒ `part == 1`" | `gate-note-part`：静态 R2「会交出槽 ⇒ 必须记参与」（**在真实缺陷 `storeStructCons` 上红过**）+ 运行期 R3。R3 的红演示：注入"删掉 `alloc` 的 `notePart`" ⇒ 静态 `FAIL [R2] extc_rc_alloc`（rc=1）**且** `trap: reclaim: R3: occupied slot in a region with part == 0`（rc=1），撤回后绿。另有 `cross-region` 登记量判据 |
| 触发语义：压力阈值随 `live`/`scale` 更新 | 性能/内存 | `collect`/`regionFloor`/`regionNew` 末的 `thrUpd` | 注入 `thr-stale` ⇒ `阈值缓存③：倍数翻倍后阈值 ×2` |
| 本地/形参槽的只写入口（`EXTC_RC_LOCALSTORE`，默认关）**只允许用在 `owner == 0` 的槽上** | **不安全**（对象宿主走它 ⇒ 跨区登记整段丢失）| `codegen.c` 的 `rcLocalStore && rcNoCount && hostBase == NULL`；`storeRefLocal` 只写 | 注入 `localstore-on-objhost`（把 `hreg != NULL` 的对象宿主存储也改发该入口）⇒ `cross_region` 的 `rs_inc/rs_dec/rs_live/rs_hwm` 从 `200000/196611/3389/65537` **塌成 0/0/0/0**，`gate-reclaim-switch` **红（通过 1 失败 1，exit 1）** —— 实测；等价性（无计数档下 `storeRefOwned(slot,v,0)` 的 gated 块因 `so == 0` 无副作用）见 `tests/reclaim-perf/LOCALSTORE-IMPL.md` |
| 回收税判据线自身有牙（税不许涨）| 性能 | 赋值/分配路径的实现（区域指针复用、登记快路径…）| 注入 `perf-lookup`（让 `rcRegionRef` 恒返回 NULL）⇒ `gate-reclaim-tax` 红在 `税 1.679× > 上限 1.620×` |
| 界不随轮数涨（churn / 峰值）| 内存 | 触发 + 清扫 + 区域轮转 | 注入 `sweep-never` ⇒ `bounded-churn N→4N 2.71×`；注入 `overregister` ⇒ `cyclic-pressure 3.64×` |
| 计数模式：计数归零**当场回收** | 性能/内存 | `holdUpd*` | 注入 `count-nodec` ⇒ `storeRef：归零当场释放` |
| bump 槽在**按槽登记之外** | 保守（设计事实）| `bump` 不置占用位 | 单测 `bump 跨区：…`（钉住事实，不是判"好坏"）|
| `extc_rc_register` 置的**种子位**与它的清理配对 | 不安全 | `register` 置位、`freeSlot` 清位 | 单测 `登记：目标槽登记位置位` + 注入 `register-noop` ⇒ 红在那条上 |
| 分配器：一个槽不重复发出（活对象地址两两不同）| 不安全 | `freelist`/`bump` 不变量 | 单测 `槽唯一：…` + 注入 `freelist-stuck` ⇒ 红在 `复用之后新拿到的这批也两两不同`（**ASan 抓不到这种别名**：内存是合法的）|
| 覆盖点定点释放：只放"**仅**从旧值可达"的槽（其它活根/种子一律标活）| 不安全（会放掉还被别的根指着的对象）| `extc_rc_releaseOld`：先 `extc_rc_mark`（其它根 + 跨区种子），只 `freeSlot` 未标记的 | 注入 `release-off` ⇒ `gate-release` 红在"清扫次数 ≤1 / 峰值比 / 释放槽数 >0"三条上（实测关掉发射 55 次扫、10.61 MB）|

**13 条全部有牙**（每条都给了注入或结构门禁，且红点写在表里）。单测现在**两档都跑**：
默认（无计数）**59 条**、计数档 **101 条** —— 后者是计数专属断言，用 `#if !EXTC_RC_NOCOUNT`
显式标注（driver 不显式标注就只会覆盖计数档，默认档的编译分支不会被单测碰到）。
