# 回收（机制与待做）

这份文档解释 extC 的内存回收要长成什么样，以及为此要做的几件事。
它属于"有什么待做"那一类，和 [`TODO.md`](TODO.md) 同源 —— `TODO.md` 是清单，这里是它背后的机制。

## 一、回收的基本盘

extC 的存储按**词法区域**划分：函数体是一层，每个块再往里一层，循环体是它自己的一层。
每层是一串块，一层的对象在离开这一层时**整片**还给系统。

于是最常见的形状是零成本的：

<!-- fragment -->
```extc
while i < n {
    var p = new node      // 分配在循环体那一层
    p.v = i
    i = i + 1
}                          // 这一轮结束，整片释放
```

一个值要活得更久，就必须把它的存储**提到更外层的区域**去（下称**提权**）。
提权是安全的，但它是单向的：存储一旦落到外层区域，就只能等那一层结束才回收。

## 二、要解决的问题

提权把一个对象放进长命区域之后，如果那个对象**在循环里被反复覆盖**，它的存储就会攒起来，
数量随循环轮数增长。典型的形状是"条件保存"：

<!-- fragment -->
```extc
var saved: ?ref node = null
while i < n {
    var p = new node
    if keep { saved = p }     // 存进去 ⇒ p 要活到函数结束
    i = i + 1
}
```

每一轮的 `p` 都可能进 `saved`，所以每一份都得活到函数结束。而运行期真正被 `saved` 持有的
永远只有一份，前面那些已经被覆盖掉了。

**要达到的行为**：不可达但还占着存储的对象，其总量**有界**，且这个界**与循环轮数无关**。

## 三、回收分四层

| 层 | 什么时候回收 | 回收多少 | 代价 |
|---|---|---|---|
| 本地 | 离开作用域（含每轮循环体）| 整片 | 零 |
| 提权 | 真实的逃逸动作发生的那一刻 | 把那一份存储挪到外层 | 一次指针操作 |
| 计数归零 | 最后一次引用被覆盖/清空/摘除的那一刻 | 当场释放那**一个**对象 | 每次**指针赋值**动一次计数 |
| 区域清扫 | 某个区域的内存压力超限 | 该区域内的不可达对象 | 扫一个区域 |

前三层处理掉绝大多数对象；区域清扫只负责**环形结构**和计数饱和掉的那一小部分。

## 四、怎么知道"最后一根线断了"

**最后一根线断掉的时刻，就是引用计数归零的时刻。** 于是给每个对象记一个持有者数，
每次引用赋值加减一次，归零当场释放：

<!-- fragment -->
```extc
var p = new node
var q: ?ref node = p     // 两根线：计数 2
outer = p                // 三根线：计数 3
outer = null             // 计数 2 —— 还有 q，不放
q = null                 // 计数 1 —— 还有 p，不放
p = null                 // 计数 0 —— 放
```

一条容易误解的地方，先说清：**计数只挂在"指向关系"改变的地方，与数据写无关。**

<!-- fragment -->
```extc
p.val = x          // 数据字段：不记
p.next = q         // 指向关系变了：q 加一、原来的那个减一
p.next = p.next    // 同值：可以不记
```

所以成本是按**指针赋值**计的，不是按"写"计的。读多写少、或者写大多落在数据字段上的代码，
这套计数的相对成本很低；反过来，**大量改链、极少分配**的代码是它最吃亏的形状。

三条必须说清的地方：

* **计数要精确，不能饱和后回落。** 计数用有限宽度，一个对象被极多引用时会上溢。
  上溢处的处理是**粘性**的：一旦到顶就锁住，此后不再减小。
  这样它永远不会被误判成归零 —— 宁可把这个对象交给清扫，也不能提前释放。
* **环由第四层兜底。** 环里的对象互相持有，计数永远不归零。它们不会漏掉，
  只是要等区域清扫。**这正是引入计数换来的东西**：不需要程序自己标识环。
* **计数只在赋值点动一次。** 编译器知道每个引用赋值的位置，加减都是静态发射的；
  不需要写屏障、不需要原子操作（单线程）。

## 五、区域清扫

清扫的基本盘是"从根出发标记，放掉没标上的"。它对 extC 有三处特殊：

* **根表由编译器给。** 清扫的触发点在分配点，是编译器选的位置；在每个这样的位置，
  哪些引用槽是活的，编译器是知道的。于是根表可以静态发射，不需要写屏障、不需要影子栈、
  也不需要保守扫描。
* **跨区引用用位图登记，不用指针表。** 一个引用被存进别的区域时，在**目标对象所属位置**
  的位图里登记一个 bit。清扫时顺序扫这张位图就能拿到全部外部入口 —— 没有指针表要增长，
  也没有陈旧的表项：位置一旦被释放，那一位跟着清掉。
* **触发量按内存压力，并会自行退场。** 计数已经收掉了所有非环垃圾，于是区域的占用≈存活；
  清扫只在占用明显超过上一轮存活量时才有意义。再加一条自适应：一次清扫一无所获就把该区域的
  阈值翻几倍（学到"这里没有环"），真收到东西则复位。**无环的程序永不进入清扫，停顿为零。**

**能达到的行为**：任何一个区域的驻留垃圾不超过"它的存活量 + 阈值"；
停顿只与该区域有关，与整个堆的大小无关。

## 六、停顿怎么切分

全局扫描每次都要从根遍历**全部**存活对象，包括那些很久不动、根本不产垃圾的结构。
区域清扫可以只扫有垃圾的那一个区域，把不动的结构留在一旁。

**停顿 ∝ 被扫区域的可达集**，所以最直接的手段是**分片**：把一个逻辑结构切进多个区域，
每次只收其中一片。分片数就是停顿与吞吐之间的旋钮，不影响正确性。

代价是**纪律**：一起生一起死的东西应放在同一层区域里，一个长期结构最好自成一层或者自己分片。
这样"扫谁"才是件可以选择的事。**跨区引用要连登记位一起分**，否则各片的清扫会都被同一批入口拖住。

## 七、要做的

* **提权**：分配先落在当前区域，在**真实的**逃逸动作发生时才把那一份存储转移到外层区域。
  转移不改对象地址（所以别名和指针同一性都保住），也不搬动数据。
* **计数归零释放**：在覆盖、清空、摘除、离开作用域这些位置静态发射计数的加减；
  归零当场释放。宽度取足够大，到顶后粘性锁住。
* **跨区登记位**：引用被存进别的区域时，在目标位置登记一个 bit；
  位置释放时清掉。清扫的入口由这张位图顺序扫出来。
* **区域清扫**：按需触发，触发量取"上一轮存活量的倍数"与用户下限的较大者，
  并带自学习退场；根表在触发点静态发射；只扫该区域内的块。
* **分片接口**：给用户一个可调的分片数，默认取一个够小的常数。它是停顿旋钮。
* **计数按编译期收窄**：同一份代码，计数加不加应当由编译期决定，而不是一律加。能省的情形有：
  对象所在区域反正要被清扫（清扫会兜底）、赋的是全新分配的对象（计数从零起、不可能归零）、
  编译器能证明该对象还有别的持有者。省掉的是**不发射代码**，不是加一层间接。
  这一条的收益在"大量指针赋值、极少分配"的代码里最大。
* **环的可观测性**：让"这个区域里有环"这件事能被计数或统计到，
  自学习退场才有更准的判据，而不必靠"扫了才知道没有"。
