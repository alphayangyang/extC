# extC 语言设计

> extC 是一门**编译到 C11** 的高级程序设计语言，建立在**全自动推导的 Arena + Zone + Pool 多形态内存管理**之上，
> 目标是同时具备：**安全** · **性能** · **资源友好（省内存）** · **互操作（与 C 等）** · **开放** · **易上手**。
>
> 本文只讲设计本身。标注约定：**【已实现】** / **【计划中】**。

## 一、为什么编译到 C11

extC 不做自己的后端、运行时与 GC，而是把程序翻译成一份**可读的 C11 文件**，再交给成熟 C 工具链。

这带来四件事：

1. **性能天花板就是 C 的天花板** —— 没有 VM、没有解释器、没有 GC 停顿，抽象在生成物里被摊平成循环与指针运算；
2. **互操作不是"桥"，而是同一层** —— 生成物本身就是 C，任何 C 库直接可用；
3. **可读、可调试、可嵌入** —— 生成物带 `#line` 指回 extC 源码；任何接受 C 的构建系统都能接住它；
4. **语言的可信面小** —— 需要相信的只有那个编译器与一份很小的运行期（分区/池的簿记），不是一整套运行时语义。

生成物契约固定：C11、`-O2` 默认、整数回绕有定义（`-fwrapv`）。**【已实现】**

## 二、多形态内存管理：Arena + Zone + Pool

extC 的核心主张是：**内存的"该活多久"不该由使用者逐处标注，而应被推导出来**；
而推导不出来的部分，退到一套**运行期可校验的池**，而不是退到"随便"。

| 形态 | 生命周期由谁负责 | 手段 | 典型用途 | 失效方式 |
|---|---|---|---|---|
| **Arena（地方 / 分区）** | 编译期证明 | 深度账：值的深度不得超过它所在地方的深度 | 一次性构造的数据、语法树、请求级对象 | 地方退出 ⇒ 整块回收 |
| **Zone（分区层级）** | 编译期 + 层级 | 分区可嵌套；出口即回收整棵子树 | 分层任务、分阶段构造、临时工作区 | 同上（外层退出带走全部内层） |
| **Pool（池）** | 运行期校验 | 句柄 `{slot, gen, ep}` + 世代比较 | 需要"身份"与"复用"的对象、容器存储 | 陈旧句柄**当场 trap**，不指向别人的对象 |

三条规则把三档缝在一起：

- **能证明的证明**：`new` 在当前位置分配；视图（`ref` / `slice`）带深度，逃逸分析拒绝"活得比存储久"的引用；
- **不能证明的运行期查**：池里的东西以句柄寻址，`{slot, gen, ep}` 三元组让"这个句柄还是当年那个对象吗"成为一个可判定的问题；
- **不能查的让你签字**：与外部世界相邻的地方（`extern!`、`!`、零拷贝视图）必须显式声明意图。

### 2.1 全自动推导：不需要写"这块内存归谁"

- **引用的种类自动决定**：`ref` / `mut ref` 由"该位置是否可写"推出，调用点无需书写所有权标记；
- **新东西生在哪里由调用者决定**（home 机制）：被调函数内部的分配落在**调用者**选择的那个地方 ⇒
  `fn make() -> varArray<T>` 可以放心返回，缓冲区本来就比这次调用活得久；
- **泛型单态化**：每个实例各自生成代码，元素类型的方法与运算符在**实例期**检查；
- **不做借用检查器的全套仪式**：没有生命周期参数、没有显式的 `&mut` 别名规则，深度账只回答"够不够久"。

**【已实现】**（`?ref T` 可空引用、`slice<T>` 视图协议、逃逸分析、home 机制均在）

### 2.2 池：同一种基底，两种被检查的模式

- **容器板模式**：块可以替换与归还 ⇒ 容器增长时用 `realloc` 原地长大，**RSS 峰值最优**；
- **对象表模式**：只追加，`give` / `resize` **直接 trap** ⇒ 句柄永远指向同一格同一代；
- **重置即换代**：`reset` 之后旧句柄再也校验不过（否则它指向的是后来占用该槽位的那个对象）。

模式、世代与陷阱共同保证：**池里的东西永远不会被静默地用错**。**【已实现】**

## 三、安全：不靠 GC，也不靠"小心"

extC 的安全不是"编译期拒绝一切"，而是**每条路径都有明确归属**：

- **视图不外借**：池底容器交出内容要么**拷贝**（`toSlice` / `sub`），要么**签名**（`subView`：零拷贝、增长即失效）；
- **可空是类型**：`?ref T` 不是"可能为空的指针"，想用就得先证明；`p!` 是显式断言，**零成本**；
- **失败是值**：`option` / `result` / `?` 向上返回；没有异常、没有隐藏控制流；
- **越界与陈旧句柄 trap**，且带位置；`trap` 不是未定义行为；
- **契约只有三种签字方式**：`!`（断言）、`extern!` + `effects`（外部函数影响声明）、`subView`（零拷贝视图）。

一句话：**能证明的证明，不能证明的当场停，剩下的签字负责**。**【已实现】**

## 四、性能：抽象在生成物里被摊平

- **零成本的一等公民**：`p!` 在 C 里就是那个指针；`@inline` 直达 `always_inline`；运算符与方法是普通函数调用；
- **单态化泛型**：`vector<i32>` 与 `vector<string>` 是两份代码，没有装箱、没有间接跳转（这是 `dyn` 之前的分发方式）；
- **连续布局**：池底容器（`string` / `vector`）内容连续，可整体取出交给 C；`map` 是 `ORDER = 16` 的 B 树，名次查询 `lowerBound` / `rankAt` 为 **O(log n)**（借子树规模，不做遍历）；
- **缓冲与批量**：`reader` 一次 `read(2)` 填一整块；`append` 是整段移动；`copyInto<T>` 提供切片级批量拷贝；
- **生成物可再优化**：交出的 C 可以继续被 `-O3` / LTO / PGO 加工，语言不挡路。

**【已实现】**（`dyn` 的实现会引入受控的间接调用，属**【计划中】**）

## 五、资源友好：省的是常驻内存与峰值

- **没有 GC 元数据**：对象没有头、没有标记位、没有分代表；
- **整块回收**：地方退出时按块归还，不逐对象释放；
- **不预留、按需、可收缩**：容器按 1.5 倍增长，`shrink` 把水位降回去；
- **槽位复用**：池的重置把槽位放回空洞链，下一轮直接复用，**不向系统要新页**；
- **峰值可控**：容器板模式允许原地换块，避免"新块+旧块同时在线"的双份占用。

设计取向是**把内存的账交给结构与位置，而不是交给一个后台线程**。**【已实现】**

## 六、互操作：与 C 同层，而不是隔着桥

- **C ABI 直通**：`extern!` 声明外部函数，`effects Addr=0 Cont=0` 说明它对地址与继续执行的影响；
- **生成物可读**：调试 C 与调试 extC 是同一件事；`--no-line-map` 可选；
- **系统级能力就在标准库里**：块缓冲读写、文件流、标准流重定向、终端 raw 模式、进程退出；
- **两个方向都通**：extC 调用 C（`extern!`），C 也可以调用生成的函数（生成物是普通 C）。

**【已实现】**；`owned`（由外部获得的内存归本模块负责）**【计划中】**

## 七、开放：能力按需装配

- **语义导入**：`use a::b` 是模块解析，不是文本包含；模块可以来自 `-I` 目录或标准库；
- **`impl` 可挂在类型体之外**，且可以**跨模块**、可以写**限定名**目标、**内建标量**也能挂方法；
  由此得到一种"扩展方法"式的开放：`impl string { fn parseJSON … }` 写在 `json` 模块里，
  **引入 json 才有这个方法**；
- **运算符可重载**，按**右操作数类型**精确匹配：`>>` 可以同时为 `i64`、`slice<u8>`、`string` 各写一个；
- **一个类型一份方法集**：`impl` 是追加不是替换，重名报错并指出先前那一处；
- 跨模块名字必须限定（`mod::name`），诊断直接给出该写什么。

更远的一层开放**【计划中】**：`trait` 声明与 `dyn Trait`（运行期多态）、开放注册与动态链接
（前置是接口文件与 ABI 冻结）。

## 八、易上手：C 家族的形状，加上两个符号

- **语法是 C 家族**：`fn` / `let` / `var` / `struct` / `enum` / `match` / `while` / `for`，一看就懂；
- **没有需要背的所有权标注**：不写生命周期、不写借用标记，深度账由编译器算；
- **错误处理只要两个符号**：`?` 向上返回、`!` 断言取值；
- **一条命令跑起来**：`extc --run file.extc` 生成 C、编译、执行；`--dump-tokens` / `--dump-effects` 帮你看编译器看到了什么；
- **标准设施自己吃自己的狗粮**：prelude 与标准库都是 extC 写的 —— 语言好不好用，先由它自己的库回答；
- **诊断教人**：缺方法会指出该 `use` 哪个模块，重名会指出先前那一处，跨模块名字漏了限定会给出该写的写法。

**【已实现】**

## 九、不做什么（同样是设计）

- **不做宏**：能力扩展走 `impl` 与模块，而不是文本替换；
- **不做异常**：失败是值，控制流不隐藏；
- **不做 GC，也不做引用计数**：生命周期由位置与池负责；
- **不做隐式所有权与隐式转换**：运算符只按右操作数类型精确匹配；
- **不做全套生命周期标注**：借用只回答"够不够久"这一个问题；
- **标准库不强制私有**：语言**能**强制（成员级 `@private` 已实现），但库选择把内部成员**列清楚**而不是锁上 —— 透明优先。

## 一句话收束

extC 想做的事，是把"**这块内存该活多久**"从人的记性里拿出来 —— 能推导的推导，推导不出的运行期校验，
校验不了的显式签字；在此之上，交出 C 的性能、C 的互操作、以及一门不用先学会内存管理才能开始写的语言。
