# 回收（机制与待做）

> 状态：**当前口径** —— 这篇写的是现在的事实，改语义先改它。

这份文档说明 extC 的内存回收长成什么样，以及为此要做的几件事。
它属于"有什么待做"那一类，和 [`TODO.md`](../plans/TODO.md) 同源：`TODO.md` 是清单，这里是它背后的机制。

## 模型总览

**前提**：编译到 C11；**允许别名**；存储按词法作用域分层、作用域编译期已知；
不开写屏障、不做原子操作、不搬对象、无 STW。

**要解决的问题**：提权把一个对象放进长命区域之后，如果它**在循环里被反复覆盖**，存储就攒起来，
数量随循环轮数增长。典型形状是"条件保存"：

<!-- fragment -->
```extc
var saved: ?ref node = null
while i < n {
    var p = new node
    if keep { saved = p }     // 存进去 ⇒ p 要活到函数结束
    i = i + 1
}
```

每一轮的 `p` 都可能进 `saved`，而运行期真正被 `saved` 持有的永远只有一份。

**目标**：不可达但仍占存储的对象，其总量有界，且这个界**与循环轮数无关**。

**四层**

| 层 | 触发时刻 | 回收量 | 代价 |
|---|---|---|---|
| 本地 | 离开作用域（含每轮循环体）| 整片 | 零（指针拨回）|
| 提权 | 真实逃逸动作发生的时刻 | 把那一份存储挪到外层区域 | 一次指针操作，**地址不变** |
| 计数归零 | 覆盖/清空/摘除/离开作用域，使持有者数归零 | 当场释放**那一个**对象 | 每次**指针赋值**动一次计数 |
| 区域清扫 | 某区域内存压力超限 | 该区域内的不可达对象 | 扫一个区域 |

前三层处理掉绝大多数；区域清扫只负责**环**和计数饱和掉的那一小部分。

**保证**：允许别名；环也能收回；任一区域的驻留垃圾不超过"存活量 + 阈值"；
停顿只与被扫区域有关、与堆大小无关；无写屏障、无 STW。
**墙内可容一笔最大请求（v10 引入，v11 收窄到显式墙）**：区域记住见过的最大的单次请求 `maxReq`（只在 `slabNew` 慢路径登记，热路径 0 条指令），
**显式墙**（`EXTC_RC_M_MAX` 设了值）下触发线夹取改成 `thr <= M_max - max(live/4, maxReq)` ⇒ `thr + maxReq <= M_max`：任何一笔
请求放进来时，触发线之上一定还装得下它自己，不会出现"分配完才发现超墙"。`res` 由 `maxReq` 与 `live/4` 取大、再夹到 `<= live`
（线不得低于活集）。**隐式墙（默认 `3*live`）不做 `maxReq` 预留**：这条承诺在隐式墙下本就兑现不了（`3*live` 随活集涨），
而无条件预留会让 `pd_pointer_dense` 峰值从 112,092 涨到 142,620 kB（+27.3%：预留压低触发线 ⇒ 起轮提前 ⇒ 自学习倍数养到 64）；
收窄后默认路径与 v9 逐 kB 相同。代价：显式墙下 `maxReq` 只增不减 ⇒ 小对象为主的长跑程序会被永久压低触发线（内存优先、更勤回收）；
可观测项 `[work]` 的 `maxreq=`/`res=`（隐式墙下 `res` 恒为 `live/4`）。

**代价**：分配是 bump；计数挂在**指针赋值**上（数据写不记）；回收算法本身只占很小一部分指令。
相对开销取决于形状：**分配密集时这套机制赚，大量改链而极少分配时它赔**（省法见"要做的"）。

**旋钮**：触发量换"内存 ↔ 吞吐"；分片数换"**停顿 ↔ 吞吐**"；计数的省略程度换"写密集时的税 ↔ 分析工作量"。
三个都不涉及正确性。

## 一、存储：区域

每个词法层（函数体、每个块、每轮循环体）是一个区域，区域是一串块，离开该层整片归还。
区域里的每个对象占一个**槽**：载荷按尺寸档放进块里，**超过一块的载荷单独分配，但仍然只是一个槽**
—— 计数、跨区登记、标记、清扫对大小对象走同一条路径，不因为载荷大就另开一条。

**v13 起，一块 slab 的发放容量就是一整块**：`EXTC_RC_SLAB_CHUNK_MIN = EXTC_RC_SLAB_SIZE`（512 KiB），
对齐单位与「由指针找 slab 是一次按位与」这两条不变，分配仍是同尺寸的一次对齐分配；判据在
[`tools/check_slab_cap.py`](../tools/check_slab_cap.py)。v13 之前发放容量从 **64 KiB** 起按 2 的幂向上取、
装得下 1024 个槽就停（v12 块上限 128 KiB），48 B 类因此只发 64 KiB / 块 —— 块尾一半永远是洞，
1 MiB 时代更极端（每块只用 ~64 KiB、94% 的虚拟地址是洞）。v13 把整块发给槽（48 B 类 1,364 → 10,922 槽/块）
并把栅格从 128 KiB 升到 **512 KiB**（`EXTC_RC_SLAB_BITS 19`，摊销块头/位图/mmap）。账面：v12 的 1 MiB→128 KiB
让 chase 墙钟 −12.3%、sizeratio −1…−6%，v13 的填满 + 512 KiB 让 sizeratio 再 −7% 量级、chase 持平
（判据与证据见 [`P1-SLAB-QUANTUM.md`](../analysis/P1-SLAB-QUANTUM.md)、`P1-ZEROINIT-FILL.md`）；停顿与峰值 RSS 不变或更低。

块变大后**任何「按块容量推导的步预算」都必须显式夹住**，否则停顿包络随 `SLAB_BITS` 线性膨胀：分配路径的收尾信用
`ceil(cursor_slab->nslots / 64)` 原来被块几何自动约束（`_q ≤ 22`），512 KiB / 16 B 槽变成 512 word ⇒ 一步能释放 32,766 槽
（实测 cross 形状 194 µs，停顿包络的 4×）。现在由 `EXTC_RC_SWEEP_FINISH_MAX`（64 word = 1,024 个 16 B 槽，`reclaim.c:1069`）
夹住，代价只是大块晚几次分配才清完，总清扫量不变。上限仍是硬界：16 B 槽整块 32,766 槽 < `EXTC_RC_REUSE_MAX_SLOT`，
没有这一夹容量会按超过块大小的 chunk 算、槽写到块外（判据同在 `check_slab_cap.py`，S8/S9）。

分配要找一块**有空位的同尺寸 slab**，这条路必须是每分配 O(1)、与存活 slab 数无关：
尺寸类用「槽步长 / 8」当键（槽大小不是 2 的幂，不能拿 log2 索引；槽 ≥ 16 字节 ⇒ 键 ≥ 2，0 当空桶），
每个区域一张 32 桶的类表，桶里挂**该尺寸类「有空位的」slab 链**；再加一格「上次命中的那块」热缓存挡住
最常见的重复分配；热缓存里的块只由 `extc_rc_alloc` 自己写、且只可能来自 `classSlot(r, ss)` 或 `slabNew(r, ss)`
（两者都绑定同一尺寸类，块的槽步长一辈子不变）⇒ 尺寸类是不变式，取用时不再重验槽步长。不变式：**有空位的 slab 一定在链上，链上可能有已经变满的块** —— 所以兜底时先惰性弹出
链头那些满块（每块最多被弹一次，均摊 O(1)），弹空才开新块；释放把某块从满变不满时若它不在链上就头插回链头
（\`avail\` 位防同一块被重复入链）。bump 路径开出来的 slab 不进链（它不置占用位，而且 \`bumpReset\` 会复用
同一片内存，原先的创建序线性扫描可能误选它）。旧实现是在区域 \`slabs\` 链上**线性走**找同尺寸有空位的块，
分配数一多就成了二次方（3200 万次分配 / 8000 块 ⇒ 40 s 级，见 [\`CHANGELOG.md\`](../CHANGELOG.md)）；
判据是 [\`tools/check_alloc_hot.py\`](../tools/check_alloc_hot.py)（结构）与
[\`tests/reclaim-perf/gate-slab-scale.sh\`](../tests/reclaim-perf/gate-slab-scale.sh)（N vs 4N 的每分配指令数比）。

分配体本身在**每个分配点**内联（`always_inline`）：分配体只有几十条指令，而每个分配点都要调它一次 ——
不内联就每分配付一次调用 + 进出栈（接近分配成本的三成），内联之后编译器还能把常量 `n` 折叠成尺寸类的
立即数。代价是每个分配点多一份分配体（约 2.7 KB 机器码）：分配点极多的程序可以 `-DEXTC_RC_ALLOC_INLINE=0`
换回体积 —— 那一档把属性宏声明成 `noinline`，只留一份函数体，不是「赌编译器不内联」；语义逐字相同，只是不走内联。
属性走宏、**签名只留一份**：写两份签名会给同一函数两个开括号，靠花括号配平切函数体的结构门禁
（[`tools/check_foreign_skip.py`](../tools/check_foreign_skip.py)）会把后面的函数体一起算进来。判据是
[`tools/check_alloc_hot.py`](../tools/check_alloc_hot.py)，开关、属性宏与 `noinline` 出口都在它的检查项里，摘掉任何一处都变红。

槽大小的计算（`extc_rc_slotSize`）也必须**强制内联**：分配点常常是常量 `n`（`sizeof 一个类型`），
内联后槽步长在这一处变成常量，尺寸类与清零长度都落到调用点（动态 `n` 的调用点也省掉一次调用/返回）。
这是分配路径上比重验尺寸更值钱的一笔：`cyclic_pressure` 上纯指令数 −7.0%，其中大半来自这一条。判据是
[`tools/check_slot_unit.py`](../tools/check_slot_unit.py)：签名上的 `always_inline` 与三条槽大小规则
都在检查项里，摘掉任一处都变红。

**清零不靠编译器展开**（v13 更正上文早期说法）：槽步长是常量并不保证 `memset(p, 0, ss)` 会被展开 —— `-O2` 下
glibc 的 fortify 头把它换成 `__memset_chk` 调用（sizeratio 形状该行占总指令 **11.70%**，≈13.5 Ir/次）。
v13 起清零走自己的 `extc_rc_zeroSmall`（`src/back/reclaim.c:1503`）：`switch (n >> 3)` 的 16→1 fallthrough 跳表，
每个 case 写一个 8 字节 0（槽数据 64 字节对齐 ⇒ store 对齐），`default: memset(p, 0, n)`；分配体里的调用点
在 `reclaim.c:1484`（`extc_rc_bump` 里的另一处 `memset` 不动）。收益：sizeratio 22.37 → 16.18 ms（**−27.7%**，
反超 C++ 最好写法 8%）。诚实限制：跳表**没有**结构门禁，正确性由 `tests/reclaim/run.sh` 的 ASan/UBSan 档覆盖
（清零不全会立刻在标记/清扫上炸），数值由 `bench/gc/v2` 守着。

每个对象初始化一次的两个热路径 helper（`extc_rc_initRef` / `extc_rc_initRefNoHold`，写槽 + 加一）
同样**强制内联**：`-O1` 不会跨调用点内联它们，于是每个分配点/字段初始化点都多付一次调用 + 返回；
内联后 `*slot = v` 与 `inc` 都落到调用点里，`initRef(&p, p)` 这种自赋值常量点还能被折掉。
这一条在 `cyclic_pressure` 上值约 3.0% 指令（比 `slotSize` 那笔小、但是同一个机理：热 helper 的调用开销
在 `-O1` 下没人替你摊）；判据在 [`tools/check_mark_both.py`](../tools/check_mark_both.py)（S6/S7，摘掉
`always_inline` 的注入会红）。

标记期分配路径上的**收尾守卫**（`extc_rc_finish`）同样把判断上提到调用点：finish 的首行是
「marking 且 seedsDone 且栈空」才真收尾，而分配点只在自己处于 `r->marking` 分支里时才调它 ⇒ 调用点就地
判掉剩下的两条（`seedsDone && msp == 0`），省掉每次分配（标记期）一次必然早退的调用 + 返回；finish 内部
的守卫保留作纵深防御（别的入口不经过这条快路）。判据是 `check_alloc_hot` 的 `finish guard hoisted` 与
`no bare finish call`：把裸调用写回去（两处都）就红。

登记 slab 的**反向表**（指针 → slab，兜底路径）与每块 slab 的**小类型表**同样是按结构体规模存活的表，
也必须每操作 O(1)：反向表是开放寻址哈希（键 = slab 基址；超大块按载荷地址进第二张表），线性探测、装载上限 1/2、
删除走 Knuth 回移（不留墓碑），扩容翻倍重排；小类型表在描述符少时线性扫（一块通常只落一两个**布局**），超过
`EXTC_RC_TTAB_LINEAR_MAX`（8）之后建一张 16 位开放寻址索引（描述符指针 → 表下标），此后每次分配一次探测；
每块还缓存**上一次落表的描述符**与它的类型号（指针相等就直接返回 —— 描述符按指针去重、号一旦落表只增不改，
所以这份缓存与查表结果恒等价；只落一两个布局的块此后每次分配只做一次指针比较，`skip:type-hot`）。

线性形状的代价是：有序数组每次插入/删除搬整段 ⇒ 整区释放是 O(块数²) 的指针搬动；每次分配线性扫块内类型数 ⇒
泛型单态化把上千个分配点塞进同一尺寸类时每分配几十条指令（实测 T=1→256：133→770 Ir/分配）。判据是
[`tests/reclaim-perf/gate-reclaim-tables.sh`](../tests/reclaim-perf/gate-reclaim-tables.sh)：S=1024 vs 4096 的每次
add+del 指令数比、T=8 vs 256 的每次查找指令数比，注入线性形状必须变红。

小类型表能保持「一两个布局」，靠的是发射侧**按布局去重描述符**：`ExtcRcType` 是纯数据（指针个数 + 偏移表），
同一结构体在多少个分配点被 `new` 都只发一份、写进**文件作用域**（`src/back/codegen.c` 的 `rcEmitTypeDesc`，键 = 偏移表
文本）。每点一份的代价是分散在分配路径上的：同一类型的 8 个站点（`shard_bands`）会让表里堆 8 个同构项、线性扫
每分配约 40 Ir，`lastTd` 缓存也因为指针交替而永远失手 —— 去重后该形状总指令数 305 392 672 → 234 792 096（−23.1%）。
判据是 [`tools/check_rc_desc_dedup.py`](../tools/check_rc_desc_dedup.py)：合成程序 3 种布局 / 5 个分配点必须只发 3 份
文件作用域描述符、同布局站点引用同一符号；改成块作用域或每点一份就红。

被释放过的槽另有一条**复用链**（`bump` 游标只管从没发出去过的槽）：表头是 slab 头里的槽号，
**「下一槽号」编码在各槽的 `tid[]` 里**（槽号 + 1，0 = 链尾），不写进载荷 —— 释放的槽是冷的，
把 8 字节头插指针写进载荷等于每释放一槽就白拉一条 cache line 进来（末级写失手）；
`tid[]` 本来就是每槽 2 字节的稠密元数据数组、释放时无论如何都要写它，链值放进这里不额外碰内存。
槽号因此必须落在 `EXTC_RC_REUSE_MAX_SLOT`（uint16 编码的上限）以内，`extc_rc_slabNew` 里有守卫。
判据是 [`tools/check_reuse_chain.py`](../tools/check_reuse_chain.py)：两种编码**语义等价**，行为判据
抓不到它回潮，这条闸门判的是结构（链只写 `tid[]`、弹出端的解码与编码对称、上限守卫在位）。

槽的**布局与每槽元数据**同样是这套机制的一部分：载荷按 **8 字节**向上取整（不是 2 的幂 ——
80 字节的对象就占 80 字节的槽，省掉取整碎片；8 是够用的粒度，因为语言里最大自然对齐就是 8，
判据在 [`tools/check_slot_unit.py`](../tools/check_slot_unit.py)），在 slab 里连续排布；每槽的元数据是三张位图
（占用 / 标记 / 跨区登记，≈3 bit/槽）+ 跨区入边计数（2 B）+ **16 位类型号**（2 B；号 → 描述符
的映射是**每块 slab 的小类型表**，按指针相等去重，1 号固定是兜底描述符）。槽步长既然不是 2 的幂，
"由对象指针找槽号"就不是一次移位，而是一次**乘倒数右移**（精确性论证在实现里，判据见
[`tests/reclaim-perf/README.md`](../../tests/reclaim-perf/README.md) §11）。
所以下面的形状是零成本的：

<!-- fragment -->
```extc
while i < n {
    var p = new node      // 分配在循环体那一层
    p.v = i
    i = i + 1
}                          // 这一轮结束，整片释放
```

要活得更久就得把存储**提到更外层的区域**（下称**提权**），而提权是单向的：
存储一旦落到外层区域，就只能等那一层结束才回收。判据只有一条（深度：参数 0、函数体 1、
每进一个块加一）：

<!-- fragment -->
```extc
depth(引用) >= depth(存放位置)      // 满足才允许存
```

提权是"这片存储要活得久"的声明，它不知道运行期到底有几份会被真正持有 —— 这就是要解决的问题。

## 二、计数归零（**默认关闭**；`EXTC_RC_NOCOUNT=0` 打开）

> **默认口径**：编译器默认**不做持有者计数**，回收只靠第三节的区域清扫 ——
> 清扫的种子/遍历不依赖计数（从根槽与已登记的跨区种子出发、靠每槽的类型描述符下钻），
> 所以区域仍然有界；少掉的只是"最后一个持有者死 ⇒ 当场回收"这条快路。
> 翻转的依据与全套证据（31 条形状棘轮、ASan 语料、gaps 集合、停顿探针、绝对峰值）
> 见 `changelog/2026-10.md` 第十一刀。下面这一节描述的是**打开计数时**的口径。

**最后一根线断掉的时刻，就是持有者数归零的时刻。** 每次指针赋值加减一次，归零当场释放。

<!-- fragment -->
```extc
var p = new node
var q: ?ref node = p     // 计数 2
outer = p                // 计数 3
outer = null             // 计数 2 —— 还有 q，不放
q = null                 // 计数 1 —— 还有 p，不放
p = null                 // 计数 0 —— 放
```

* **只挂在"指向关系改变"上。** 数据字段赋值不记；引用赋值记两次（目标加一、旧值减一）；
  同值赋值可以不记。
* **到顶粘性锁住、此后不再减。** 宁可交给清扫，也不能提前释放。
* **环永不归零**，交给区域清扫 —— 这是引入计数换来的：不需要程序自己标识环。

## 三、区域清扫

从根出发标记，放掉没标上的。四处特殊：

* **根表由编译器给。** 触发点在分配点、是编译器选的位置；那里哪些引用槽是活的编译器知道，
  于是根表静态发射，不需要**扫描栈**（影子栈/保守扫描）；增量标记需要的写屏障见下一条。
* **增量标记用"插入 + 删除"两条屏障（mark-both）。** 一轮在飞期间 mutator 还在跑，两类对象会被漏：
  ①"白对象被写进已经扫过的黑对象" —— 插入屏障（`extc_rc_shade`）给**新值**着色；
  ②"一条指向白对象的堆边被覆盖/删掉" —— 删除屏障（`extc_rc_shadeOld`）给**被覆盖的旧值**着色。
  两条合起来的不变量是：**任意时刻 mutator 手里（寄存器或槽）的每个指针值都是黑的** ——
  新分配即标黑（`extc_rc_alloc` 的 `marking` 分支）、黑对象的字段只可能装黑值（①）、
  未扫对象的字段要么在扫到它时被追到、要么在那条边被删时被②救下、根表在轮起时整表扫过。
  **无计数档（默认）因此把本地槽的着色整段省掉**（`initRef` / `initRefNoHold` / `storeRefLocal`：
  本地槽是根，不需要①，②在删除点已经兜住），保护从"每次本地槽写"搬到"每次堆边删除"；
  计数档不动（`extc_rc_shadeOld` 在计数档编译成 no-op）。判据 = `tools/check_mark_both.py`
  （挂 `gate-mark-both`，7 项注入红自测）；六档数字在 `changelog/2026-10.md`。
* **插入屏障先查一张"已经黑过"的缓存，命中就不进慢路径。** `extc_rc_shade` 查一张 2048 格的
  **旋转散列表**：每格只存一个地址（8 字节），格号 = `(((uintptr_t)v >> 3) + extc_rc_shadeGen) & 2047`；
  命中就是格内地址等于 `v`（一次装载就能判定），连 `ownSlab` 的基址/槽首校验都省掉。
  不变量是「**同一代里某槽的 mark 位只会 0→1**」（`freeSlot` 不清 mark 位），所以"上次查时是黑的"
  在本代内一直成立。**精确性**（缓存出假阳性 = 白对象当黑 = 漏标）：格号要求地址同余且代际号同余，
  同一个格子在同一个代际窗口（2^11 代）里只可能与同一个地址配对 —— 格内地址相同即同代命中，
  不存在"不同指针凑进同一格"的假命中。失效靠代际号：内核里**每一处清 mark 位的路径**都调
  `extc_rc_shadeNextGen()` —— `begin`（起轮）、`sweepBegin`（清扫开始）、`releaseOld`（定点释放前
  `memset` 整片 mark）、`regionFree`（slab 载荷还给 malloc，地址可能复用）；该函数自增代际号，
  并在回绕（`(gen & 2047) == 0`）时把整表 `memset` 掉 —— 跨窗口的旧记录不可能复活，清表代价
  16 KiB / 2^11 代 = 8 B/代。漏一条就会把白对象当黑、跳过屏障而漏标可达对象 ⇒ `tests/reclaim/driver.c` 的
  `t_shadeCache` 有三组断言（同代命中 / 代际号一变立刻不可见 / 窗口末尾仍命中 / 回绕清表旧记录
  不复活），`tests/reclaim/run.sh` 用 `-DEXTC_RC_SHADE_GUARD=1` 把 driver 再编一遍（命中时重做一次慢路径
  核对，要求 `bad=0` 且 `hits > 0`），注入 `shade-noinval`（删掉 `releaseOld` 的代际推进）给这条
  契约提供红证据；结构判据 = `tools/check_shade_cache.py`（挂 `gate-shade-cache`，6 项注入）。
  缓存查询放在**内联壳**里，壳因此变大 —— `extc_rc_storeRefOwned` 必须 `always_inline`，
  否则 `-O1` 会改主意不内联它（代价见 `changelog/2026-10.md`）。
* **根表只覆盖本帧，所以清扫只在「本帧拥有」的区域上进行；不属于本帧的，记一笔账留给拥有者。**
  根表按词法作用域拼：本帧活着的局部量、形参、全局量。它看不见调用栈上其他帧的活引用，因此往
  **调用者传下来的区域**（被调者的分配落进调用者的那一层）分配时，触发点不物化根表，只在那个区域上
  留一个「欠一次清扫」的标志；**拥有它的那一帧在自己下一次把同一层 arena 交给被调者之前**销账 ——
  那一刻上一批被调者已经返回、这一批还没进入，它的静态根表就是完整的种子；拥有者没有下一处调用点时，
  整片要等到帧销毁才还。**整条调用链共用的线程本地区域按运行期深度认领归属**：`parTls` 的分配落在 worker 的
线程本地 arena 上，而静态判据分不出「worker 入口帧」与「它调进来的内层帧」（同一个函数两种身份都可能）——
所以运行期设一个 `_Thread_local` 深度 `extc_rc_tlsDepth`，每个「parTls + 需要回收 + 有 arena + 不是协程」的帧
序言 `int __extc_tlsOwner = (extc_rc_tlsDepth++ == 0);`、尾部 `extc_rc_tlsDepth--;` 配对：入口帧（0 ⇒ 1）是拥有者，
触发点物化根表当场清**自己的**那一层；内层帧只记 `extc_rc_owe`（销账仍归拥有者的调用点）。worker 调回调前
把深度保存 / 清零 / 恢复 —— 线程起不出来、`threads <= 1` 时回调在同线程内联跑，只有这样入口帧才一定是拥有者。
线程本地区域随 arena 同寿丢弃两处（`extc_par_close` 的每个 worker arena、worker 兜底销毁的局部 arena）；
不碰 `parallel` 的帧只多一份恒发的 `_Thread_local` 声明，序言与三态一个字节都不发（9 形状 `-O2` Ir 逐位不变）。
判据：`gate-par-tls-owner`（发射物结构：声明恒发 / 序言尾声配对 / 三态 / worker 清零恢复顺序 / 两处区域丢弃 /
普通程序零税，6 条注入全红）+ 注入 `par-tls-depth-noreset` + `tests/reclaim-gaps` 的 `par_tls_cycle`（3.40× → 1.13×）。
  种子不完整时宁可不清扫，也不能把活对象当垃圾放掉。
* **拥有者此后再不分配 ⇒ 清扫权当场委托给被调者。** 被调者在调用者的家 arena 里攒垃圾时自己不能扫
  （静态根表不覆盖调用者的引用），只能记欠收、等拥有者在**下一次发起调用之前**销账；拥有者此后再不
  发起调用（`main` 只调一次 `build`、之后不再 `new`）这笔账就永远挂着，峰值随规模涨（`home_cycle`
  rounds=1 3.04×）。修法是让「谁扫」在运行期按「那只 arena 此刻有没有人持有引用」定：调用点传一个隐藏
  实参 `__extc_homeOwn`（`int32_t`，只在发了回收运行期时才有），它只在「本帧没有活引用槽（`rcRoots` 与
  全局根都空、`rcRootsUnreliable` 假）+ 本帧就是那只家 arena 的拥有者（`main` 自己，或传下去的就是家层级）
  + 这个调用点就是所在语句的**顶层表达式**」时是 1（中间帧转发自己的 flag），其余 0；被调者的 `RC_OWN_NO`
  触发点据此分两支 —— 真则物化本帧根表并 `extc_rc_maybeCollect`，假则照旧 `extc_rc_owe`。「顶层表达式」
  这条挡的是子表达式里只活在寄存器的本区域引用（`sink(mk(), deep())` 里的 `mk`），否则被调者的「完整
  种子」会把刚建的对象放掉。不碰家 arena 形参的帧一个字节都不多发（9 形状 `-O2` Ir 逐位不变）。
  判据：`gate-home-delegation`（真实发射：正向形状的 1 / 0 两个实参、被调者三态的真分支有 `maybeCollect`
  而 else 有 `owe`、普通程序零 `__extc_homeOwn`，9 条注入全红）+ 注入 `home-own-always-zero` +
  `tests/reclaim-gaps` 的 `home_cycle` rounds=1（3.04× → 1.00×，sweeps 0/0 → 2/9）。
* **挂起帧（协程 / `ext`）的根表按帧字段拼。** 协程 step 的 C 形参只有帧指针（`f`），跨 `yield` 活下来的
  形参与局部量住在帧字段里 ⇒ 不按帧字段登记就只剩「整函数置 `rcRootsUnreliable`」（一个触发都不发）；`genFunc` 按 checker 排好的
  `coroFrame` 表把每个字段的引用叶子登记成根（`f->name`，与普通帧的形参根同一个入口）；帧由调用者的复合字面量
  建、起点零初始化，未赋值前读到的是 0，而根表入口在 `markBegin` 里过 `extc_rc_owns` ⇒ 认错只多留；yield 出来的
  值不带引用由 checker 保证（`s` 的协程 yield 类型检查）⇒ 帧里的引用不会从 yield 出口漏到调用者根表之外，step 只扫
  自己的块 arena 时种子是完整的。`rcFrameOwnsArena` 因此不再挡 `coroFunc`：step 的块 arena（`f->arena1`，
  `lvl >= 1`）归帧自己；`ext` spawn 帧走同一条判据（它的块 arena 字段也在帧里），`rcOwnKind` 也不再整函数
  返回 `RC_OWN_NO`。判据：`gate-coro-frame-roots`（发射物结构：帧字段进根数组 / 触发装块级区域而非家 arena /
  不发 TLS 序言 / 普通程序零帧字段根 + 生成器源码四条结构事实，9 条注入全红）+ 注入 `coro-frame-roots-nop` +
  `s` 的 `coro_frame_cycle` / `ext_frame_cycle`（3.10× / 3.13× → 1.00× / 1.00×）；
  9 形状 `-O2` Ir 逐位不变。
* **跨区引用只登记一个 bit。** 引用被存进别的区域时，在**目标对象所在位置**的位图里置一位，
  播种时顺序扫这张位图；位置释放时那一位跟着清掉，所以没有陈旧表项。
* **触发按内存压力，并会自行退场。** 计数已收掉所有非环垃圾，于是区域占用≈存活，清扫只在
  占用明显超过上一轮存活量时才有意义；再加一条自适应：一次清扫一无所获就把该区域阈值乘
  `EXTC_RC_SCALE_MUL`（默认 4，学到"这里没有环"，退得比翻倍更快），真收到东西则复位。
  「活集大、垃圾少」的负载因此只付第一次（便宜的）整堆标记，跳过后面那些"标记整堆只换回几 MB"
  的轮次；垃圾多的负载下一轮就收到东西，倍数立刻复位。**无环的程序永不进入清扫。**
  判据 `extc_rc_shouldSweep` / 起轮信用 `extc_rc_roundOk` 是生成代码**每个定点释放点都问一次**
  的小助手 ⇒ 发射成 `static inline`（只给 `inline`，不加 `always_inline`：让编译器按调用点代价
  决定摊开还是调用），摊开后是两次装载加一次比较，不产生调用/返回。

清扫本身是**顺序扫位图字**：不追指针、不逐个释放。一个死字里的槽按**字**批量放
（`extc_rc_freeSlotWord`）：逐槽只做链头插（每个槽的链值不同：`s->tid[i]` 存旧链头、再改
`s->freelist`）；占用位、登记位按整字一次清，字节账与 `freedSlots` 按整字一次记，
`avail` 回挂尺寸类链每字最多一次。`unlinkChildren`（撤销该槽手里的跨区边）仍逐槽，
但「一次登记都没发生过」的分支提到字外（默认档 `rsIncN` 恒 0 ⇒ 整段一次不执行）。
为什么可以按字做：清扫期间没有分配、也没有读者看这些字段，逐槽写它们只是把同一件事做 64 遍。
判据：`tools/check_reuse_chain.py` 钉住三段链形状（`freeSlot` 委派链头插、`freeSlotLink` 写
`tid[]` 链、`freeSlotWord` 逐槽插链且撤边、三段都不写载荷/不清 `tid[]`/不算载荷地址），
每条 `--selftest` 注入各变红一条。

**宿主证不出来时先按槽地址反查。** 写引用要说出「这条槽装在哪个对象里」。基表达式带调用
（`(*id(s)).kids[0] = v`）时证不出宿主**对象**，但**槽地址本身**还能查：`extc_rc_slabOfInterior`
把地址按 `EXTC_RC_SLAB_SIZE` 掩掉低位得到 slab 基址（普通 slab 按整块对齐 ⇒ 一次按位与），再按
基址查登记表，最后用 `offOf(p) < nslots * ss` 夹住**发放容量**；命中就拿到槽所在的那只区域，这条
边照常按「宿主已知」记账（旧值撤销、跨区登记都做，`extc_rc_storeRefSlot`）。这条路**不要求槽首**
（`ownSlab` 才要校验 `k * ss == off`），所以下标槽、视图里的槽也能用；**超大块**的载荷是单独
`malloc` 的、掩码定不了位 ⇒ 返回 0，调用方回落保守路径（`storeRefUnknown`，见下一段）；反查失手
（栈上局部量、视图数据、C/池缓冲）也走同一只出口。代价与回落路径同量级：那条路本来也要查一次
`ownSlab`。判据：单测 `槽地址反查：…`（反查形状 / 反查成功绝不下调保守 / 超大块失手）与
`tests/reclaim-gaps` 的 `base_call_unknown`（峰值比 0.95×）。

**反查失手 ⇒ 把值钉住，不让区域退出清扫。** 连槽都不在 rc slab 里时（栈上局部量、
`new T[n]` 的视图、池/C 缓冲），槽本身没有寿命可跟踪，但**值**还能当根：`extc_rc_storeRefUnknown`
把 `v` 登记进进程级**钉住表**（键 = 值指针，条目记「值 → 所属区域」，由 `ownSlab` 一次算好），
覆盖槽时按旧值撤销（`pinSub`）。`markBegin` 起轮时 `pinSeed` 只把**本区域**的钉住值压成种子；
`regionFree` 调 `pinDropRegion` 清掉属于该区域的死指针 ⇒ 表有界、随槽的覆盖与区域的死亡收缩。
表的实现是开放寻址哈希（装载 ≤ 1/2、Knuth 回移删除），每钉/撤一个摊 O(1)；第一版是「数组 + 线性扫」，
钉 n 个是 O(n²)（实测 5 万 0.26 s、20 万 5.23 s），`gate-pin-scale` 现在钉住这条判据（N vs 4N 的
每钉一个指令数比 ≤ 1.15，注入线性预扫会变红）。只有钉不住（扩容 `calloc` 失败）才回落到
`noSweep`「目标区域退出清扫」——方向仍是安全。判据：单测 `t_pin`（不是活槽不登记 / 两条槽指着同值
计数 2 / 撤一条仍在 / 撤完可收 / 覆盖撤旧边 / 区域死清死指针且别的区域不受牵连）与
`tests/reclaim-gaps` 的 `slot_elem_unknown`（`new node[4]` 视图 ⇒ 峰值比 3.59× → 1.00×）。

**枚举局部量的整值存储靠「根表按变体展开」认领。** `var m: maybe = maybe.some(keep)` 这类声明没有可点的引用叶子：
值里的引用藏在判联体负载里，C 的 `union` 让「哪个负载是活的」只有运行期 tag 知道。两件事合起来把这块值认领完整：
① `rcRootLeaves` 的 `TY_ENUM` 分支把**所有**变体的负载引用叶子按 `<base>.u.<variant>._<k>` 静态展开进根表
（不按 tag 挑一支；泛型枚举实例先把实参代进负载类型）—— 读不活跃变体的字是垃圾值，根表入口在 `markBegin` 里过
`extc_rc_owns` ⇒ 认错只多留、不会少留；② 存储侧发 `extc_rc_storeStructRooted`：逐字着色（增量标记期间结构拷贝
也是写引用）+ 只对 rc 槽 `inc`，**不**让目标区域退出清扫、也不登记跨区边（宿主是栈上局部量，跨区可达性由根表
种子覆盖）。可枚举不出来时照旧保守：认不出来的 kind、泛型实参带引用的枚举 ⇒ 发 `storeStructCons(..., 0, 0)`，
目标区域退出清扫（方向仍安全）。判据：单测 `枚举整值存储：…`（增量标记期间叶子当场标黑 / 黑叶子活过本轮清扫 /
不置 `noSweep`，对照 `storeStructCons(hostKnown=0)` 在另一只区域上会置）+ 注入 `struct-shade-nop`（拿掉逐叶着色）
⇒ 红在「增量标记期间叶子当场标黑」；`tests/reclaim-gaps` 的 `match_payload` 峰值比 3.04× → 1.00×。

**dyn 载荷池生在构造点的 place 里。** `dyn Trait(x)` 把载荷按值拷进 dyn 池，池的寿命 = 它被登记到的那个
place。构造点没有自己的 place 时池就挂在函数体上 —— 循环里每轮一份载荷攒到函数返回，回收器再怎么收
也救不了峰值。三处判据把池钉在站点那一层：① checker 的 `exprMakesPool` 认 `EX_DYN`（含 dyn 的块
自己压一层 place），构造点记这一层（`setCallZoneArg`）；② 值逃逸时按建池调用的同一条规则把站点层提到
`ZONE_HOME`/目的层（`promoteInto2` 的 `EX_DYN` 分支，**放在递归负载之前** —— 负载里的 `EX_CONV`
在 `promoteInto2` 的 default 分支答 false，先递归就整段跳过），深度判定也把站点层算进去
（`dynSiteDepth`）；③ 发射物把 `zoneArgRef` 当第 4 实参传给 `extc_dyn_put`，池按这个 zi 建
（`extc_pool_new_at(-1, zi)`，不读 `extc_zoneTop`：提权之后构造在内层、池生在外层），zi 不活则 trap。
判据：结构门禁 `gate-dyn-place`（真实发射 + 9 条注入）、注入 `dyn-site-no-promote`、
`Tests/dyn/run.sh` 24 项、gaps `dyn_payload` 3.61× → 1.00×（开档 22.23→80.17 变成 2.92→2.92，
关档 20.73→78.67 变成 1.42→1.42）。

**泛型容器描述符：字段里没有引用叶子就不整体保守。** `var p: pool<mut ref node>` 的类型是泛型实例，
实参带引用；旧 `rcScanType` 见到这种实参就整类回 `RC_CONSERVATIVE` ⇒ 描述符整值存储走 `storeStructCons(...,0,0)`
（目标区域退出清扫）+ `rcRootDecl` 置整函数 `rcRootsUnreliable`（一个触发都不发）。判据本身错在：池/板的字段
（`vals`/`slots`/`ent`）都是视图，`rcScanType` 对视图本就回 `RC_NO_REFS` ⇒ 描述符自己一个引用叶子都没有，
根表不欠账；元素里的引用在板上，由写入点屏障认领（`storeRefSlot`：查得到 rc 槽就按槽记账，查不到就把值钉住，
见上一段）。现在 `TY_GENERIC` 分支先记「实参里有没有引用槽」再扫字段，**只有字段里也看得见引用**
（内联数组、按值内嵌结构体）才回 `RC_CONSERVATIVE`，否则返回字段扫描结果 ⇒ 容器局部量照常触发。
判据：`gate-container-refs`（容器形状的 `main` 必须有触发、不得发整值保守存储；泛型实参带引用且字段里也
看得见引用的窄化控制程序必须仍保守）与注入 `container-desc-conservative`；`tests/reclaim-gaps` 的
`pool_ref_slot` 峰值比 3.04× → 1.00×（sweeps 0/0 → 2/9），语料全量静态检查的 `silent-both` 9 → 0。
**并行：两处进程级共享写走独立协议。** 并行 worker 各自的回收区域互不相交（`parTls` 的分配落线程本地 arena），但运行期有两处状态是**进程级共享**的：① slab 登记表（地址 → slab → 区域）—— 写侧曾用 `realloc` + `free` 旧表，两个 worker 同时建 slab 时另一个线程正在已释放的旧表里探测（ASan 下 8 路并行 400 次复现 10 次 SEGV）；现在**按代发布**：写侧在 `extc_rc_regLock` 下 `calloc` 新代重散、`__atomic_store_n` 发布、`extc_rc_regSeq` + 1，**旧代永不 free**（容量 2× 增长 ⇒ 旧代总内存被最终容量界住）；读侧 `extc_rc_ownFind` 无锁，最多 32 轮「读 seq → 读当前代 → 探一格 → 复读 seq」后持锁兜底，热路径入口再叠一层 `extc_rc_ownProbeFast`（镜像表探一格 + 前后 seq 一致即权威）。② 标记参与者计数 `extc_rc_wb`（写屏障门控）—— 每只区域各自 begin/finish，普通 `++/--` 丢更新 ⇒ `barrier participant underflow` 崩溃（修前 1/400）；写侧改原子，但原子的 lock 前缀与内存屏障会渗进热路径（`if (!extc_rc_wb ...)` 每次都要重载 ⇒ owed_home +2.8% Ir），所以声明保持普通 `int`、原子加减包进 noinline 冷函数 `extc_rc_wbAdd`。判据：`gate-reclaim-conc`（结构 11 项 + 8 路并行 ASan 512 次 smoke + 10 条注入自测）与注入 `reg-retry-nocap`；跳过表里 `skip:reg-hit` / `skip:reg-settled` / `skip:reg-race` 三条各写明为什么无锁路径的结果仍是权威的。9 形状 Ir 相对上一提交 −14.1% ~ +1.1%（`extc_rc_shadeSlow` 冷半段不内联、wb 原子移出热路径是主要来源）。

## 三点三、容量归还：slab 的「空」就是契约的兑现点

清扫的成本单位是**容量**，不是活集：一块 slab 里只要还有一个长命对象，它每轮都要逐词扫完（整块跳过的前提是 `s->nMark != 0` 为假，见 §三点五前面的 elide 段）。容量又是高水位 —— slab 只在区域析构时整块归还，所以「峰值」会一直钉在堆上。

归还路径（无写屏障、全在冷路径）：`extc_rc_slabShrink(r)`（src/back/reclaim.c:1898）在 `extc_rc_sweepStep` 的收尾分支（3915）沿 region 链最多访问 `EXTC_RC_SHRINK_VISIT_MAX=256` 块，把 `nLive==0`、非 big、非 bump slab、且没有跨区入边位的 slab 从 region 链与 size-class 链 O(1) 摘掉、入 free 队列；每次最多 `EXTC_RC_SHRINK_REL_MAX=16` 块，munmap 交给既有的 `extc_rc_fqDrainCore`（1501）按 `EXTC_RC_FREE_BUDGET_SLABS` / `EXTC_RC_FREE_QUEUE_BYTES` 执行，紧接着的 `extc_rc_fqDrainAuto()`（3916）在同一个步里排空一个有界批次。

两处约束写死在代码里：

1. **slack 闸门**：`capBytes − bytes < EXTC_RC_SHRINK_MIN_SLACK`（8 MiB）时一块都不摘（1900，`skip:shrink-slack`）。容量只比占用多一点时，摘块换来的是「munmap 512 KiB → 之后重新 carve」，抖动会赢；代价是容量界抬一个常数 8 MiB。
2. **只能发生在轮末**：清扫游标可能停在链上任意一块，摘块前提是游标已清空 ⇒ 摘链固定在 `extc_rc_sweepStep` 的收尾分支。摘链只在这个位置；settle 与标记完成处都不摘块。

契约三句：①**承诺**：从轮末（closing step）算起，不含任何占用槽的 slab 最多在 ⌈n/16⌉ 轮内被归还（n = 这样的 slab 数），每轮新增工作量 ≤ 256 次链访问 + 16 次入队 + 一次有界排空，这些成本都发生在同一个被计时的步内 ⇒ 计入 `[step]`/`[histo]` 的停顿分布；②**不承诺**：含 1 个长命对象的 slab 不归还（粒度是 512 KiB），这是稀疏活集上 Θ(容量) 的剩余来源，由 §三点四的页级归还补一档；③**不发散**：`EXTC_RC_SLAB_KEEP`（默认 0）只是复用池大小，不影响界。

实测：64 MiB 峰值后留 16 个成簇存活对象，基线 slabs 129 → 129 / RSS 82.9 MB 恒定；本机制 slabs 129 → 1（8 轮）/ RSS 16.8 MB。自动路径探针（64 MB 峰值、零 root、之后 140 万次分配、只调 `extc_rc_maybeCollect`）：slabs 64 → 16、`slabRel=48`、RSS 43,788 → 18,832 kB（残差 = 8 MiB slack 余量）。四形状 A/B 1.013 / 0.970 / 1.015 / 1.002（噪声带内），指令数门禁 87,871,190 ≤ 88,029,115。

## 三点四、页级归还：容量成本的单位从块降到页

§三点三把「整块无占用槽」的 slab 还掉，粒度 512 KiB。稀疏活集里每块都留 1 个长命对象，容量项仍是 Θ(容量) —— 所以还页的单位要再小一档：**页**。

机制（全冷路径、不搬移、不加写屏障）：`extc_rc_pageTrimStep(r, budget)`（src/back/reclaim.c:2037）由 `extc_rc_sweepStep` 收尾调用（3917），每次至多访问 `EXTC_RC_PAGE_TRIM_VISIT_MAX=16` 块、还 `EXTC_RC_PAGE_TRIM_BYTES=256 KiB`；块内用 occ 位图找出活槽覆盖的页（槽可跨页 ⇒ 首尾页都算活），其余**连续空页合并成一个 run** 再 `madvise(MADV_DONTNEED)`。页 0 含块头，永不归还。

契约四句：

1. **承诺（界）**：`C ≤ live + 4 KiB × #page(含活对象) + M_slab × #slab(含至少一个活对象) + 8 MiB`，其中 `M_slab ≈ 69 kB/块` 是块外元数据（实测，计数关：tid 2 B/槽 + 三张位图 + 分配器取整与固定页；计数档再加 hold 2 B/槽 ≈ 21.8 kB）。页归还只改物理页，不改 `r->bytes`。
2. **承诺（不抖动）**：只有「容量 − 占用 ≥ 8 MiB」（slack）、「自上次 pass 起该块分配 ≤64 槽」（quiet）、「nLive × 8 ≤ nslots」（稠密）三条同时成立才动那块；否则一次 syscall 都不发。去掉 slack 的实测代价：sizeratio 墙钟 +56%、cycleratio +19%。
3. **承诺（有界）**：一次 closing step 的工作量 ≤ 16 次块访问 + 256 KiB 的 madvise（≈4 µs，@14 ns/KB@），整笔记进 `[step]`/`[histo]` 的停顿分布；`pgNext` 续扫被预算截断的 pass，`pgLive` 保证同一个占用图不重复还（幂等 ⇒ 稳态零成本）。
4. **不承诺**：含活对象的块，其**元数据**（≈69 kB，实测）不归还；一个长命对象仍钉住 ≈69 kB，而不是 4 KiB。要消掉这一项只能搬移式压实。

实测：64 MB 区稀疏探针（48 B 槽、每 MB 1 root、400 轮 collect）slabs 129 → 64、RSS 52,304 → 20,280 kB、还页 31.27 MB；四形状 A/B 1.006 / 1.007 / 0.994 / 1.021（噪声带内）、RSS 不变、`[pages] blocks=0`。热路径不加分支（只有一个 `s->allocN++`）：先做的「每分配清已还页位图」让四形状慢 4.4%–5.5%，已删。
## 三点五、覆盖点的定点释放（环在覆盖点就没了）

环永不归零，所以计数那一层收不了它；但"**覆盖一个槽**"这个动作本身能判死一棵树 —— 只要那
条槽是这棵树**唯一**的外部入边。编译器只在能说出这句话的形状上发射（`src/back/codegen.c` 的
`rcEmitStoreRelease`，四条判据同时成立）：

* ① 赋值在某个循环体里；
* ② 目标槽是本帧的引用槽（在静态根表里）、且声明在**所有**在册循环之外 —— 每一轮被同一个
  长命槽覆盖；循环内的游标（`cur = t`）不满足；
* ③ 写进去的值是本帧 `new` 出来、**从不被重新赋值**的局部对象，并且**它所在的区域本帧拥有**
  —— 只有那种区域，本帧的根表才是完整的种子（与分配点的触发同一条判据）；
* ④ 这个对象已经被写进过某个堆对象的引用字段（`(*cur).next = head`）：刚分配就链进堆对象的
  局部，才可能是一棵树/一条环的头。

发射的是 `extc_rc_storeRefOwnedRelease(&槽, 新值, 宿主, 那只区域, 根表, n)`，其中**根表里剔除了
被覆盖的那一格**（它此刻还装着旧值；把它算进种子就等于自己证明旧结构是活的 ⇒ 一个槽都放不掉）。
运行期先按**其它根 + 本区域跨区种子**标记（与第三节整区清扫**同一套种子**），再从旧值出发沿
类型描述符走，只 `freeSlot` 那些"可达**且**未被标记"的槽，最后把标记位清干净（`extc_rc_sweep`
是唯一会清它的地方，不清就会把标记留给下一次 `collect`）。

**安全论证**：释放集是"**同一点、同一套种子**下整区清扫会释放的集合"的**子集** ⇒ 四种静态
判据就算全判错，被别的活根/种子指着的对象也不会被放（trial deletion 的轻量形态）。于是这个
机制的失效方向是**少收**，不是提前释放。前提与整区清扫逐条相同，所以回落也逐条照抄。

**保守回落**（任何一条不成立就一个字节都不发，产物与今天逐字相同）：根表不可靠
（`rcRootsUnreliable`）/ 协程帧 / **分片 `EXTC_RC_SHARDS > 1`**（标记只覆盖**这一只片**，
"只被别的片里的活对象指着"的单元标不到 ⇒ 会放掉活对象，所以分片下一律不发）/ 目标区域
`noSweep` / 目标区域有欠账 `owe`（`checkOwed` 同一条理由）/ 旧值经 `ownSlab` 不在静态给出的
那只区域里。

**信用（`extc_rc_budgetOk`）**：一次 O(活集) 遍历必须由"**自上次遍历以来的新分配**"偿付 ——
要求 `allocBytes - visitedBytes ≥ max(live, floor)`（`floor` 是区域下限；区域从没扫过时 `live = 0`）。
清扫本来就满足这条（触发线 `max(2·live, floor)·scale ≥ need`）；**释放是唯一的破口**：它由赋值
触发，没有分配垫着，于是"赋值 N 次"会变成 N 次全活集标记（实测 `rg_grow_tail`：40k 次追加
5.08 s、关档 2.4 ms）。加上这条之后，总遍历量 ≤ Σ信用 ≤ 总分配量 = **线性**；代价是信用不够
时这次释放不做（垃圾晚一步收，峰值有常数上界），失效方向仍是**少收**。

**判据**：`tests/reclaim-gaps/gate-release.sh`（挂 `nobench`）：`ring_per_round` 默认档
**清扫次数 ≤ 1**、N vs 4N 峰值 **< 1.5×**、语义与关档逐字相同、**释放槽数 > 0**（防空转）。
实测（本机，N=20/80）：清扫 **55 → 1**、峰值 **10.61 → 6.48 MB**、释放槽数 **4883 / 20303**。
剩下的那 1 次是**第 2 轮循环头的启动空扫**：`keep` 的旧 head 要到第 2 轮的 `keep = head` 才被
判死，而第 2 轮循环体开头的分配触发点先到压力线（那一次 `freed=0`，自学习还把 `scale` 翻倍，
是触发策略自己的事）。红证明：注入 `release-off`（关掉发射 ⇒ 判据红）。

## 三点六、跨区出边的位图登记：大槽死时只扫「写过跨区指针的 64 B 组」（v29）

前面几层处理的是「谁还活着」；这一层处理**死掉之后撤销出边的代价**。引用计数必须逐条撤销出边，而撤销只发生在放掉最后一条入边的那一刻 —— 它没有续扫余地（续过就悬垂），也没有写屏障可用（用户 m16773 排除）。于是对**没有描述符**的类型（`src/back/codegen.c:3888`：`offs.len > 32` 就返回 `EXTC_RC_CONSERVATIVE`），`extc_rc_unlinkChildren` 只能按 `ss/sizeof(void*)` 扫完整块：`struct huge { a: [1048576]?mut ref leaf }` 一次死掉要扫 1,048,576 个词，实测 1182–1530 µs；8 MiB 的 6.7 GB/s 就是扫描带宽，没有常数可删。

机制（冷路径为主、**不加写屏障**）：在**既有**的跨区登记分支（`extc_rc_rsIncSlab`，原只标目标槽）上顺手记一位 —— 一位管 64 B（8 个引用词），每槽 `wmW = ceil(ss/4096)` 词（`src/back/reclaim.c:1972` 的 `extc_rc_wmarkSlot`，入口 1987–1988）；释放时 `unlinkChildren` 的 CONSERVATIVE 分支只读**置位组**的 8 个词，读后清零（`2008` 起，位图分支 `2013–2031`）。跨度 < 4 KiB 不分配位图（全扫 ≤ 512 词）。

为什么登记点在体外函数里而不是内联进 `storeRefOwned`：内联体内**从不执行**的新代码会让 `-O1` 给形状函数重新分配寄存器，实测 +435k Ir（12 个变体标定）⇒ 破 Ir 棘轮；三参的 `extc_rc_rsIncSlab` 只多一次寄存器传参。

契约四句：

1. **承诺（界）**：单步内单个死槽的撤销工作量 `W_unlink(ss, m) ≤ min(ss/8, 8·m)` 个引用域，`m` = 该槽本轮置位的 64 B 组数。
2. **承诺（soundness 不靠维护位图）**：位图是超集，释放时从内存重读真值 ⇒ 覆写/清空引用**没有**维护义务；这也意味着它不是写屏障，只在既有登记分支上加一个「位或」。
3. **承诺（兜底方向）**：整值拷贝（`storeStructCons` 的 `hostKnown` 分支、`storeStructCopy`）没有源槽可指 ⇒ 置 `r->wmUnsafe`，该区所有 CONSERVATIVE 槽退回全扫描：慢回位图前，但 correctness 不变。
4. **不承诺**：稠密侧没闭合 —— 若对象的每个 64 B 组都写过跨区指针（`m = ss/4096`），上界回到 `ss/8`，仍是 ≈1.2 ms / 8 MiB 槽。语料侧只有 10 个类型超 32 项描述符（3 个 n=64、7 个 n=4097），真正 >1M 域只有 t04 这个压测程序。

实测（`tests/gc-torture`，`-DEXTC_RC_WMARK=0/1` 同一份生成 C）：t04 `[step] max_us` 1106.4 / 871.6 / 671.6 → **4.7 / 11.5 / 16.7**，over1ms 1 / 0 / 0 → **0**，`[step] total_us` 43,126 → 170–183；`rs_inc / rs_dec / rs_live` 960 / 952 / 8 逐字不变（撤销没漏）。四形状 A/B（15 reps，min）0.961 / 0.991 / 0.966 / 0.991、RSS 逐形状不变；`gate.sh` Ir **87,914,793 ≤ 88,029,115**（余量 114,322）。退路：`-DEXTC_RC_WMARK=0`。

## 三点七、整段不发射 rc 运行期（区域"不需要回收"的证明）

前面几层都是**运行期**的机制：计数、清扫、定点释放。这一层是**编译期**的：一个区域被证明
"清扫无事可做"时，它**整段不发射 rc 运行期**——不是"清扫不触发"，是生成物里一个 rc 调用都没有，
连运行期文本都不进。今天只要程序里有一个受治理的分配点就**整程序**发射 rc；这一层把那个
判据收窄到"**回收可能有事可做**"。

**判据（(a)(b)(c)，一具函数一具地算，整单元合取）**：

* **(a) 每个 ref 字段每对象最多被写一次**（初始化，不是覆盖）。判的形状：写站点的宿主是本帧
  `var x = new T` 出来的局部量、这个绑定在整具函数体里**从不被重新赋值**，且同一个（宿主声明,
  字段）在这具函数里只有**一处**站点。前两条把"宿主对象"钉死在那条 `new` 上（递归的每层调用
  各有自己的 `x` ⇒ 各有自己的动态对象），后两条保证那处站点每对象只执行一次。**按宿主声明计，
  不按站点个数计**。
  **细化 (a′)：站点在循环里也可以** —— 真正的要求是"每对象最多写一次"，所以只要宿主的分配点
  **不比站点浅**（分配循环深度 ≥ 站点循环深度）就够了：那种宿主是**本迭代新建**的，循环里那个
  字段仍然是每对象写一次。宿主在循环**外**（分配深度更浅）⇒ 同一个对象被反复改写 ⇒ 仍判否。
  再加一层收窄：宿主那条 `new` 的存储**最后被放**的 arena 层也得 ≥ 站点循环深度（逃逸提权把它
  提到更长寿的层时判否）。"站点不在任何循环里"因此只是 (a′) 在站点深度为 0 时的特例。
* **(b) ref 类型的局部量/参数不被重新赋值**（声明初始化不算）。写进栈上槽（标识符、局部聚合的
  字段）的引用赋值都是丢引用。**嵌套块里声明**一个 ref 局部量**不算**：它的对象随块 arena
  整片释放（`bt` 的 `let t = bottomUp(d)` 正是这一档）。
  **细化 (b′)：ref 局部量的槽可以覆盖**，只要写进这个槽的**全部**值都随本迭代的 arena 一起死
  —— 即每个值的存储层 ≥ 这次写入所在的最内层循环体的作用域层（`null` 不丢对象，天然合格）。
  于是"覆盖"只是少一个根，丢的是本来就会随这次迭代释放的存储，不会攒下界随轮数涨的垃圾；
  值**逃到更长寿的 arena**（函数层）⇒ 判否。局部聚合的字段、以及任何证不出层的值仍旧判否。
  **层从哪来**：`new` 的层用 `arenaDepthOf(planArenaLevel)`（与 (a′) 同一把尺），沿写入在
  同一趟走查里传播（`h = c`）、字段读沿字段名取最浅（`p = p.next`），整条链用一个**最小不动点**
  求解（`idleSolveLvls`；写入可以依赖后面才写的绑定，顺序解不出来）。**禁止**用 `anRefDepth`、
  字段表的深度、词法嵌套计数或 `lookup()->depth` —— 实测它们互不一致（同一个 `h = c` 上分别
  给出 1 / 3 / 6 / 4，arena 层是 3），混用会把逃逸形状判成 idle（`cross_scope_cycle` 的界 2.57×）。
* **(c) 没有丢引用的操作**：容器删除/替换、`@overwrite` 复用同一格、free 类内建、`domain` 块、
  `ext`/`dyn`（看不清的并发与派发）、**带引用的值聚合被产生成临时量**（结构体/数组/枚举载荷/
  按值返回的调用结果：它一死，里面的引用在那个时刻失去这个根，而临时量的存储属于哪一层 arena
  由逃逸分析定，可能的形态是"本帧的家房间"⇒ 界随轮数涨）、以及**看不清的被调者**带着引用。
  看得清的被调者不逐层追 —— 传递性由**整单元合取**覆盖：被调者自己也是被发射的一具函数，会再
  被判一遍；**一处不满足 ⇒ 整单元判否**。一条**声明的初始化式**不按临时量判：值落进具名槽，
  槽的 arena 层由它的块深度给出（循环体内声明 ⇒ 每轮整片释放）⇒ 有界；它的子表达式照常判
  （`wrap { n: mk(i) }` 里的 `mk(i)` 仍是一颗会被丢掉的临时量）。
   **细化 F（task-36）**：站点**不在任何循环里**（`minLoopScope == 0`）时放行 —— 循环外的临时量
   每次调用只产生/丢一次，它的存储最坏落在**调用方当前块**（`arenaArg` 默认就是调用点的块）：
   调用方在循环里时那块每轮归还，调用方不在循环里时也就丢一次；把它变成"家房间垃圾"的唯一路子
   （把聚合体存进比迭代长的槽）由 (a)/(b) 那两条挡着。**边界是实测的**：
   `struct_copy_ret_home`（站点在 `mk` 里、循环外）判 idle 后 N vs 4N = **1.00×**；
   `byval_temp`（站点在**循环里**：`take(mk(i))`）**必须仍判否** —— 整条放宽它峰值 **2.12×**，
   它是 `gate-idle-bounded.sh` 的常驻对照。
 * **细化 A/B/E（task-38）**：同一个（宿主, 叶路径）被写两处时，若**被覆盖的旧值另有根**
   （值是某个**形参**的投影、且本帧不写那个宿主的字段）⇒ 覆盖没丢根，放行（`idleValueOtherRoot`）；
   写目的地的**逐叶路径**（`(*root)[i]`、`s.kids[0]`）也落账，**非字面量下标**收进同一个键
   `base[]`（`idleDestPath`）；最外一层是**元素槽**且下标是"**在本循环体内被赋值**"的标识符时，
   不再要求"宿主本迭代新建"（元素槽序列 —— 每轮写的是不同叶槽）。三条一起让
   `persist_nodes`（2343.7 µs，命中集合最大）与它的真实语料来源 `bench/oi/persist/p3834_nodes.extc`
   判 idle：停顿 2699/2465 µs → **0**（探针拒绝插桩 ⇒ 无清扫调用点），真实语料墙钟 4.33 s → 3.18 s、
   峰值 766 MB → 508 MB、stdout 逐字不变。**边界**（`gate-idle-bounded.sh` 的两个新对照，
   实测抓出来的：原来六条对照对这三条窄化一条都不红 ⇒ 判据本来没牙）：
   `field_overwrite_lost_root`（A 若打回"整条放开"⇒ 1.52×）与 `fixed_slot_overwrite`
   （E 若打回"任意元素目的地"⇒ 1.56×）都必须留在回收档。

**它不等价于"无环"**：两条判据互不蕴含。②允许回边（`a.next = b` 与 `b.next = a` 两处站点
各自满足 (a)），而无环判据允许"每对象写一次"以外的丢引用（计数能兜住）。两条判据服务两个
不同的机制：无环 ⇒ 事件档（计数代替清扫）；② ⇒ 干脆不发射 rc。②的安全论证因此不是"没有环"，
而是"**没有丢引用**"：区域内的对象只会随区域整体释放而消失。

**E2 型（"这个区域永远不需要回收"）：判定现状与卡点（未落地）**

本节的判据是**整单元**的；另有一条更窄的用法：对**单个区域** R 证明"它永远不需要回收"，
于是 R 上的触发/销账整段不发射（消减的是那个区域的运行期，不是整单元）。要证三件事，
健全性条件各不相同：

* **(a) 没有释放路径能碰到 R 的槽**、**(b) R 没有出边**（宿主在 R 的引用赋值，其值也在 R 或 null）。
  (b) 是**屏障半场**的硬条件：跨区登记写在**值**所在的区域上，所以一条 R→S 的边就是 S 的**永久根**；
  只掐宿主在 R 的那个屏障而 R 还有出边 ⇒ S 的清扫看不见这条根 ⇒ **悬垂**。反向（宿主在 S、值在 R）
  不需要掐：登记留在 S 的站点上，而 R 的指针仍是合法的 rc 槽。(a)(b) 可判 —— (b) 直接复用生成物里
  已有的"同区"证明（`rcFreshHostRegion` / `extc_rc_storeRefSameRegion` 那条路）。
* **(c) R 里没有对象会变成垃圾**（内存界）—— 这正是本节 (a)(b)(c) 判据族要干的事；E2 只是把它的
  作用域收到**一个区域**，另外加上本节没有的 (b) 那条屏障条件。

**卡点：P2 型形状被本节判据的一条保守条款挡住。** 尾插形状里 `x.tail = b` 的宿主 `x` 是形参
（`t` 是形参投影），而判据要求写站点的宿主必须是**本帧 `new` 出来的局部量**，于是整单元判否
（`src/check/check_top.c` 的 `idleWriteOk`；拒绝理由的特征串是 "the host object is not a local
created by new in this frame"；诊断口径 `EXTC_DBG_RCIDLE=1` 逐函数打印判定与理由）。P2 此时**只被
这一条挡住**，生成物的其余部分全过。

**放宽这一条不健全。** 把"宿主非本帧新建"改成"只要值是本帧新建就放行"，反例是
`fn f(keep: mut ref T) { keep.f = new T }` 被循环调用：站点在 `f` 里、不在循环里（躲开循环条款），
宿主是形参，单元合取也看不见丢引用 ⇒ 每轮丢一个对象、**无界涨**，却被判成"永远不需要回收"。
P2 与这个反例的差别**只有"旧值是否另有根"这一维**（P2 的旧值先被链进了头指针），而那条证明是
**跨过程/别名**级的，本帧的语法扫描给不了；两条候选红判据（有没有 `freeSlot` 能碰到 R / 有没有跨区
登记）**都抓不到**这个反例：它既不释放也不登记。三条便宜的替代也不够：复用分配站点上的 arena 层
事实（值表达式拿不到它）、只放宽"值是本帧新建"（零新分析，但能命中的站点极少）、或认"值是被调者
返回本帧 home 区的新对象"（命中热点但覆盖面窄，要的是值级数据流，是另一个量级的工程）。

⇒ 要落 E2/E1，必须先造一条**跨过程 must 分析**（"链先接上、尾指针再前进"这类跨语句、跨调用的
不变量，证据形态是 `planFn*` 加不动点）。消减机制（掐触发/销账、同区改发裸存）的锚点已经就绪，
但判定恒假：落地必须做到"生成物逐字不变、判据空转"，红演示用注入把判定强制为真。两条判据
（静态清单 + 运行期守卫）**只给规格、不落空壳** —— 判定缺席时不许把"绿"当成证据。规格与锚点见
会话归档 [`archive/2026-10-15-gc-pause.md`](../archive/2026-10-15-gc-pause.md) 报告索引里的 `E2_LANDING.md`。
**口径**：掐掉运行期后能不能压到线内，取决于按 `-O1` 还是 `-O2` 验收（见"四.一"）。

**开关语义**：`EXTC_RECLAIM=1` 是"**允许**回收 / 不强制关闭"，不是"强制发射"——证明成立时
发射运行期只是空转，所以②在**任何档**下都跳过。`EXTC_RECLAIM=0` 仍然是从不发射、对照组。
**注意它不是"只关 GC"**：这一档下分配器也换成 `extc_arena_*` 纯 bump（生成物里连 `malloc` 都没有）
⇒ 拿它做 on/off 对照时，差值是「回收运行期 + **槽式分配器** + 记账」vs「纯 bump arena」，
**不是纯 GC 税**；出处与实测见 [`bench/gc/SPECTRUM-MATRIX.md`](../../bench/gc/SPECTRUM-MATRIX.md) §10.1。

**失效方向**：少收 ⇒ **内存涨**，不是悬垂（rc 只释放标记不到的对象）。安全网是两条动态判据
加一条红证明：

* **税趋近 1**：`tests/reclaim-perf/gate-tax.sh` 的 `bt` 从 **1.133×（11.8%）降到 1.000×**
  （开/关档产物**逐字节相同**），中输入的 `bt-mid` 从 1.031× 降到 1.000×。
* **峰值有界**：**被判 idle 的形状**（默认档产物与关档逐字节相同）N vs 4N 的峰值 RSS 必须
  **< 1.5×** 且 4N 的绝对峰值有上界 —— `tests/reclaim-perf/gate-idle-bounded.sh`
  （`gate-reclaim-idle`），另带一个**必须仍在回收档**的对照形状（防判据一律放行）与反空跑
  （②真的生效：rc 记号 → 0）。`rebuild_per_round`（"循环里建、每轮丢"的最小形状）与
  `closure_chain` 是 (a′)+(b′) 那一类的安全网，**必须有界**。第二条防线是
  `tests/reclaim-acyclic/` 的 ⑦ 安全格：`cyclic_pressure`、`scale_growth` 这些有跨轮回边的
  形状**必须仍是清扫档**，②把它们判成 idle 就会当场红。**细化 (a′)+(b′) 的三条绊线**——
  `tests/reclaim-gaps/shapes/cross_scope_cycle.extc`、`scale_growth`、`live_churn`——都是
  "循环里建、每轮丢"的**同族**形状，只是对象逃逸到了函数层 arena：它们必须**仍留在回收档**
  （实测产物与细化前**逐字节相同**，N vs 4N 与细化前的基线一致：1.04× / 1.88× / 1.60×）。
* **能力棘轮**：`tests/reclaim-perf/gate-rc-idle-corpus.sh`（`gate-rc-idle-corpus`）数
  **固定语料清单**里"产物不含任何 `extc_rc_`"的形状数（清单与下限都只许往上；基线 **8**，
  细化 (a′)+(b′) 之后 **14**：`rebuild` 两个源、`churn`、`closure_chain`、`big_slot_reclaim`、
  `rebuild_per_round`），另带一个必须仍在回收档的对照。它把"②今天到底能拿掉多少形状"变成
  一条能红的判据：某个已经 idle 的形状悄悄退回回收档会当场红。
* **红证明**：注入 `reclaim-idle-always`（把判定强制为真）施加到会丢引用的形状 ⇒ 垃圾只等区域
  丢弃、峰值随轮数涨（`gate-reclaim-switch` 与 `gate-reclaim-idle` 都会红）。

实现落点：逐站点扫描在 `src/check/check_top.c` 的 `idleWalkStmt` / `idleWalkExpr`（结论写进计划侧
`planFnReclaimIdle`，字段在冻结清单里），整单元合取与收窄在 `src/back/codegen.c` 的
`unitReclaimIdle` / `scanUnitReclaim`。`EXTC_DBG_RCIDLE=1` 逐函数打印判定与理由。

## 四、停顿与分片

**停顿 ∝ 被扫区域的可达集**，所以最直接的手段是**分片**：把一个逻辑结构切进多个区域、每次只收一片。
分片数就是"停顿 ↔ 吞吐"的旋钮，不影响正确性。

两条纪律：**跨区登记要连分片一起分**，否则各片的清扫会都被同一批入口拖住；
**片边界必须与结构边界对齐** —— 只有"每个结构一个分配点"的形状才拿得到停顿收益：
同一处分配出来的东西（一条链、一个环、一代结点）始终留在同一片里，片内链条与环保持完整。
把一条链或一个环强行切开，跨片登记位就会成为环垃圾的种子 —— 不可达的环被这些登记位撑着，
界随轮数增长。

> **分片同理，编译器也守**：片号是**按分配站点**给的（`片号 = 站点序号 % 片数`），所以"结构边界
> = 片边界"只在**可能成环的结构各自落在单个分配站点**里时自动成立。单元里一旦存在**跨站点**的
> 可能环（`applyCycleMerges` 的站点并查集给出、分量含 ≥2 个分配站点），`EXTC_RC_SHARDS > 1`
> 在该单元就**退化成单片**（`src/back/codegen.c` 的 `scanUnitReclaim`）：只把"同环组的站点"钉进
> 同一片不够 —— 环组之外的站点（容器、索引）仍在别的片，跨片引用照样把整条环钉住。
> 代价写在明处：这种单元里分片旋钮**不再有停顿收益**（保守方向：界优先）。
> 单站点自环（`shard_bands` 的"每条链一个分配点"）不触发这条，分片照旧 ⇒ 旋钮在它该有用的
> 形状上仍然有用。判据：`tests/reclaim-perf/gate-shard-cycles.sh` —— `digraph` 上默认档的峰值
> ≤ 0.5× **同 N 的关档基准**、默认档的 4N/N < 关档的 4N/N、且 `SHARDS=4` 的 4N ≤ 2× 默认档；
> `shard_bands` 上 `SHARDS=4` 的单步最大遍历对象数 ≤ 0.5× `SHARDS=1` 且工作项数 ≥ 2×（运行期
> `[work]` 的确定性计数；平均切片只作参考值 —— 均值 = 总时间/步数，步粒度一变就整体抬高、
> 与分片无关）。与同 N 的关档比：绝对峰值里混着
> 每槽元数据那样的常数项，跨规模比会被常数项掩盖 —— 关档基准把常数项消掉，留下的才是回收
> 真正压住的增量。

> **编译器现在自己守这条纪律（「可能的环」的候选区域合并）**：一个 *可能闭环* 的引用写
> （`(*cur).f = v`，值既不是空、也不是新分配、也不是严格更年轻的层 —— 判据就是 `fnAcyclic`
> 那条现成的 `SR_BAD`）如果宿主 `cur` 可能指向**不止一只区域**里的分配站点，编译器就把这些
> 候选站点连同值**并到最浅的那一只**（`src/check/check_escape.c` 的 `applyCycleMerges`，
> 在全局电平求解之后、placement 之前跑）。只往更长寿的一侧挪，所以最多多留一会儿；
> 候选里出现家区域时不并（家区域的决定已经关死），`EXTC_RECLAIM=0` 时也不并 —— 没有回收
> 运行期就没有区域划分，关档产物逐字不变。
> 判据：`tests/reclaim-gaps/shapes/ring_per_round.extc`（N vs 4N 峰值 < 1.5×），修前 3.90×、
> 修后 1.00×，见该目录 README 的 §G8。

取舍同样清楚：**分片让停顿变好，代价是峰值内存与吞吐变差** —— 每片都有自己的存储底噪
（片多，底噪就多），也都有自己的标记栈。

分片的代价是**纪律**：一起生一起死的东西放在同一层区域里，一个长期结构自成一层或自己分片。

### 四.一、窗口怎么量、判据用哪个数（`EXTC_RC_PAUSE=1`）

**量具**：`EXTC_RC_PAUSE=1` 时进程退出向 stderr 打一组行 —— `[clock]`（三个计时面的**实际**时钟来源）·
`[pause]`（契约入口 `collect`/`checkOwed` 的**武装窗口**进→出）· `[step]`（**每个切片**：
`markStep`/`sweepStep` 每次调用的 n/max/total + 阈值桶 `over16/over64/over256/over1ms`）·
`[histo]`（逐桶计数的 15 桶直方图 + 三个**精确**超阈计数 `gt10us`/`gt50us`/`gt64us`）· `[top]`（最慢 8 步的归因）· `[segsteps]`（只统计**续扫段步** `seg>0`：`n`、`pops_tot`、`max_us`、与 `[histo]` 同界 15 桶、同三个 `gt*us` 精确计数、钟口径同 `[histo]`；无段步时全 0）· `[regionfree]` / `[chan]`（整区
销毁与三条同步通道的 n/max/total/工作量）· `[work]`（同一批切片的**确定性工作量**：
`walk_max/scan_max/push_max/seg_max` + `walk_cap`/`walk_gtcap` + `>16/>64/>256` 桶，
以及策略侧快照 `thr_max/mmax/scale_max/pressure_steps/M_max/pressure/mult/thr/maxreq/res/M_max_now`；
其中 `maxreq`/`res` 是 v10 引入、v11 起只在显式墙下非平凡（隐式墙 `res=live/4`）的准入预留观测项）· `[worst]` / `[ubwork]` / `[wbudget]` /
`[guard]`。
`tools/rc-pause-probe.py` 也能插桩 `extc_rc_collect` 与热路径 `extc_rc_step`（`PROBE … step_*`），
并在插桩失败时 **rc=1**（不许伪装成 `sweeps=0`）。它打**两行**分布，口径不同、必须分开读：
`PAUSE_DIST` 只覆盖**冷**契约入口 `extc_rc_collect`（热路径不走它 ⇒ 默认形状下恒 `n=0`，这是
**结构性 0**，不是"0 次停顿"）；`PAUSE_DIST_STEP` 覆盖热路径 `extc_rc_step` 的每一步（同格式、同桶，
含 `all=`/`first=`/`last=`）—— **要断言停顿分布就读 `PAUSE_DIST_STEP`**。同一次运行里生成物自己报的
`[pause]`/`[step]` 计数与它互相校验；`step_n`/`step_max_us` 口径与修复前相同。出处与实测见
[`bench/gc/SPECTRUM-MATRIX.md`](../../bench/gc/SPECTRUM-MATRIX.md)（§4.3、§7）。

**两个停顿总体，别只报一个；三家"停顿"也不可相减。** extC 的生成物自己有**两行**，是两个不同的
总体：

* `[pause]` 只圈**武装窗口**（`maybeCollect`/`checkOwed` 里的 `pauseArm`）—— **成批推进**
  （`markAdvance`）发生在武装**之前**、**收尾/取消**路径也不武装 ⇒ 它是**下界**，不是全部回收
  时间账。
* `[step]` 记**每一次**子步（`markStep`/`sweepStep`，含成批推进与收尾触发的那些）= extC 在
  **mutator 线程上同步花的回收时间**（extC 没有 GC 线程，这些时间应用就是干不了活）。

同一批运行里两者的总量可以差几个数量级 ⇒ **引用 extC 停顿时必须说清是哪个总体**，只含 `[pause]`
的结论不能读成"几乎不停顿"。跨语言的口径同样不是一回事：Go 的 `gctrace` STW 不含 assist+bg
（那些是可并发的 CPU），Java 的 GC Pause 才是真 STW 墙钟 ⇒ **三家的"停顿"只可并排，不可相减或
相除**。实测与不可比清单见 [`bench/gc/SPECTRUM-MATRIX.md`](../../bench/gc/SPECTRUM-MATRIX.md) §4/§7。

**`[work]` 的盲区（2026-10-15 抓到，已补量具）**：`[work]` 只统计 `budget ≤ EXTC_RC_MARK_BATCH_MAX × EXTC_RC_SWEEP_PRESSURE_MUL`
的**有界热路径步**（基数 256 × 压力乘子，默认 4 ⇒ 上限 1024；压力乘子是**策略内的步长上限**，不是无界排空）；契约排空/结算收尾（`budget=∞`）连量具都躲过去 —— `[step] n` 与 `[work] n`
的差就是它们。于是「一次无界排空」在 `[work]` 里表现为**零工作量**（看起来像"这一步没工作"）。
补的三行：

* `[ubwork]`：无界步单列 —— `mark_n/walk_max/scan_max/push_max` + `sweep_n/sw_words_max/sw_freed_max`
  + 按入口分 `settle_n/collect_n/release_n/other_n`。判据：正常程序 `mark_n == 0 && sweep_n == 0`
  （无界排空只允许出现在显式契约入口，且必须被点名）。
* `[worst]`：**耗时最大那一步**的分项归因（`kind=mark|sweep`、`why=` 入口标签、预算与各项计数），
  用来区分「多项叠加」与「单一项顶到预算」。
* `[guard]`：屏障参与者计数 `r4_wb_open`（**信息量** —— 程序可以不 `regionDrop`，那时 >0 合法）。
* `[top]`：最慢 8 步的**归因** —— `kind=mark|sweep`、`why=` 入口标签、`dur_us`/`cpu_us`、`freed`、
  `words`/`seg`/`pops`、全局步号 `step` 与触发序 `coll`、`first`（该 region 的首个清扫步）、
* `[segsteps]`：**续扫段步**（`seg>0`，结构上一步只续扫一段）的独立直方图 —— `n` 步数、
  `pops_tot`（这些步的 pops 之和；结构上应与 `n` 相等，不等就说明分段路径里混进了别的 pop）、
  `max_us`、与 `[histo]` 同界的 15 桶。`[step]`/`[histo]` 混装了 `seg=0` 的冷 pop 步与 sweep 步，
  **段步单步上界只能看这一行**。
  `trans`（跨 slab）、`minflt`（`EXTC_RC_PAUSE=2` 时读 `/proc/self/stat` 的 minor fault 增量）、
  `chunk=EXTC_RC_SCAN_CHUNK`。
* `[sweepelide]`：整块清扫省略的计数 —— `bulk_reset`（整块重置次数）、`bulk_slots`（被整块回收的槽数）、
  `swept`（逐字扫完的 slab 数）、`mis`（`EXTC_RC_ELIDE_VERIFY=1` 时位图复核不一致的次数；默认 0，
  非 0 表示 roll-up 漂移，该块退回逐字清扫）。判据：`mis=0`。
* `[regionfree]` / `[chan]` / `[closing]`：`regionFree` 的 `max_frees/max_slabs` 与 `sync_us`（同步段）/`queue_us`（本次排空），`[closing]` 报 `regions_pending/slabs_moved/cap_regions`（closing 队列积压与已推进 slab 数），以及三条同步通道（`regionfree`/`release`/`trigger-step`；v16 及更早那一格叫 `collect`，实际量的是触发路径上的一次 step，v17 起改名）各自的 n/max/total + 工作量 + 15 桶。
* **v8 起 `regionFree` 的同步段是 O(1)**：只做 `abort` + `pinDropRegion` + 置 `dead` + 挂线程局部 closing queue（`EXTC_RC_CQ_MAX_REGIONS` 默认 32，超过时 drop 内做一次有界排空）；逐 slab 的 unlinkChildren/`ownDel`/压 free queue 由 `extc_rc_cqDrainCore` 在分配点按 ≤8 slab/100 µs 推进，free 再由 free queue 的排空完成。'dead' 置位即代表整片槽对 `owns()` 一次性失效（见 `skip:dead-region`）。
* `[freequeue]`：延迟释放队列 —— `slabs_bytes`/`slabs`（当前队列）、`drained_total`（累计排空的 slab 数）、`forced`（队列字节超过 `EXTC_RC_FREE_QUEUE_BYTES`、触发硬截止排空的次数）、`max_depth`/`max_deferred_us`（队列深度峰值 / 最慢一次排空耗时）、`left_slabs`/`left_bytes`（进程退出时残留，由 OS 回收）。判据：`left_slabs=0`（线程/驱动退出前全量排空）；`forced` 只在队列超限时增长。
* `[clock]`：`step=` / `pause=` / `chan=` 三面的实际时钟；`[histo]` 的读法见上一节。
  **真正的判据是 `finish`/`abort` 里的配对自检**：`r->marking` 为真 ⇒ 该区域贡献过 `wb+1`，
  减完必须恰好少 1，漏减/下溢都会 `extc_rc_oops`（`trap: reclaim: R4:` + rc≠0）。**不要**写成
  "退出时 `wb==0`"。

`EXTC_RC_TRACE_UB=1` 再把每一次无界排空连**当时的步号**打出来（`[ubtrace] step_n=…`）⇒
「热循环里每轮一次」与「进程退出时一次」由步号直接区分，不靠推理。

**判据用哪两个数**：
1. **确定性工作量界**（`[work]`）：热路径每步 `walk_max ≤ walk_cap = EXTC_RC_MARK_BATCH_MAX × EXTC_RC_SWEEP_PRESSURE_MUL`（默认 256×4 = **1024**；`walk_cap`/`walk_gtcap` 由产物 `[work]` 行给出，`walk_gtcap` 必须为 0）、
   `scan ≤ EXTC_RC_SEED_WORDS`、`push ≤ EXTC_RC_SEED_PUSHES + 63`（压栈按**字**收口：一个字最多
   64 位，所以最后一个字可能超出名义预算 ≤63；这是粒度，不是失控）。超界就是**真的**要做整形。
   **R2 起这个界按活集分两档（只收紧，不放宽）**：暖档仍是上面的 `walk_cap`；冷档（`r->live >` `EXTC_RC_MARK_COLD_BYTES = 16 MiB`，即一次 pop 已经是访存而不是缓存命中）每步的 pop 上限再被 `EXTC_RC_MARK_COLD_BATCH = 32`（v25；R2 时为 128）压住（发射文本里 `markAdvance` 在 window clamp 之后再 clamp； 编译期 `#error` 保证 `COLD_BATCH ≤ MARK_BATCH_MAX`）。所以 `walk_max ≤ walk_cap` 逐字仍成立， 界只是更小；`[work]` 行尾的 `cold_steps=` 报告本轮有多少步进了冷档（0 表示该形状从不触发）。 动机与实测见 `docs/analysis/GC-ROOFLINE.md` §6.8、`docs/analysis/MEMORY-MODEL-CURRENT.md` §19.6。
   **这条已由 `gate-reclaim-work` 自动强制**（挂 `nobench`，约 3 秒）：六形状现场生成+运行，
   `[work]` 必须存在且 `n>0`（否则文案是"插桩失败/工具不兼容"，不许当绿）、每形状 3 次逐字相同、
   四条界全部**蕴含式**成立（`walk_max ≤ walk_cap`、`walk_gtcap == 0`、`scan_max ≤ SEED_WORDS`、`push_max ≤ SEED_PUSHES+63`）；三个预算与 `rsbit` 字宽都从**产物** `#define` grep（读不到 ⇒ 红，
   不许硬编码）。红演示见 `docs/changelog/2026-10.md` 顶部：把种子扫描的字预算拿掉 ⇒
   `scan_max=5120 > SEED_WORDS=512` 直接红（就是那个历史洞）；把 `[work]` 改名 ⇒ 六形状全红在"插桩失败"。
2. **超阈切片计数**（`[step]` 的 `overK`）：`over1ms` 必须恒 0；`over64/over256` 用于比值。
   判据是"计数在中位数/最小值口径下不上升"，不是单次最大值。

**读桶：名字是桶上界，`[histo]` 打印全部 15 桶。** `[histo]` 逐桶给出
`b1us b2us b4us b8us b16us b32us b64us b128us b256us b512us b1ms b4ms b16ms b64ms bge64ms`
（名字=该桶**上界**且**含等号**：`b16us` 装 8–16 µs、`b64us` 装 32–64 µs、`b64ms` 装 16–64 ms、
`bge64ms` 装 >64 ms）。`[step]` 的 `over16/over64/over256/over1ms` 是**累计**阈值计数
（严格 >16 µs / >64 µs / >256 µs / >1 ms），由同一组桶求和得到（`stepSumFrom(5)/(7)/(9)/(11)`）——
按字面把桶名读成"≥X"会得出错的阈值，写判据时以源码里的 `extc_rc_stepBucket` 与 `[step]`/`[histo]` 的 fprintf 为准。
**v17 起判据线可以精确判**：`[histo]` 与 `[segsteps]` 各多打 `gt10us`/`gt50us`/`gt64us`，是严格 `>10/>50/>64 µs` 的**样本计数**（不是分位）⇒ 判据线落在桶界之间（如 50 µs 落在 `b32us`–`b64us` 之间）时直接读计数，不再靠桶界包含关系；`n<1e5` 仍按 N/A。旧产物没有这三个字段时退回桶界包含关系（判据不放宽）。
**v18（R2）起这两条线在 `pb` 上实测都绿**：`pb_escape_grow` 50M 的 `[histo]` 给 `gt10us=89 / n=343,296` ⇒ p99.9 判据 `gt10us×1000 ≤ n` 成立（2.6e-4），`gt50us=10` ⇒ `>50 µs` 占比 2.9e-5 ≤ 1e-4； `over1ms=0`、`max_us=85.8`。这不是放松判据，而是把**标记步的每步预算按活集分档**换来的（见本节第 1 条与 `docs/analysis/REFS-V18.md`）：同一份源码的冷档开关 A/B 在四形状上是 0.973/0.981/1.007/0.982、RSS 逐 kB 相同。
**p99 仍从 `[histo]` 的桶读**（桶内只有计数，精度为一个桶宽）；要精确分位就用 `tools/rc-pause-probe.py` 的 `PAUSE_DIST_STEP`，口径不变。

**时钟口径**：`[step]`/`[histo]`/`[chan]`/`[top]` 的时长跟随 `[clock]` 行首字段 ——
`EXTC_RC_STEP_CPU=1` 且线程 CPU 时钟可用时用 `CLOCK_THREAD_CPUTIME_ID`（`step=cpu chan=cpu`），
否则墙钟；`pause=wall` 是武装窗口的墙钟。生成物不定义 `_POSIX_C_SOURCE`，strict `-std=c11` 下
glibc 不暴露该 clock ⇒ 运行期一次性探测后**降级为墙钟**并在 `[clock]` 打 `cpu=unavailable`
（时长仍是真实值，不会是 0）。

**"p99" 有两种，写判据时必须指明是哪种。** 一种是把**所有切片**放一起排序取 p99（"每步时长的
p99"）；另一种是**每 run 只取一个最大步**、再对这些 per-run max 取 p99（"per-run max 的 p99"）。
两者的尾巴完全不同：前者的 p99 由极小比例的长步决定，后者每次运行只贡献一个样本、天然更靠尾部
⇒ 只报一种会得出误导结论（长步占比可以极小，而 per-run max 仍明显更高）。任何"p99 ≤ X"都要
写清口径；量具必须两种都读得出来。两种口径的实测分布对照见归档
[`archive/2026-10-15-locality.md`](../archive/2026-10-15-locality.md)。

**统一工作量预算 `EXTC_RC_WORK_BUDGET=W`（C 编译期 `-D`，默认 0 = 关）**：默认形态下
`walk`（`MARK_BATCH_MAX`，压力档 ×`SWEEP_PRESSURE_MUL` ⇒ 默认上限 1024）、`scan`（`SEED_WORDS`）、`push`（`SEED_PUSHES`）是**三个独立预算**且
**叠在同一步**里 ⇒ 一步最坏 = W_walk + W_scan + W_push 个单位。`W > 0` 时三者与 `wbDebt` 加力
**共用一个总额**（walk 1 对象 = scan 1 字 = push 1 槽 = 1 个单位），由 `markStep` 里的
`wleft` 扣减；种子字**压不完就把剩余位留在 `seedBits`、游标停在同一字**，所以一个字绝不半途
丢弃（丢位 = 种子不完整 = 不安全），也**不靠 `+63` 超发**换完整性。观测口径是 `[wbudget]`：
`tot_max`（单步 walk+scan+push 最大值）必须 `≤ W`，`assist_max` 是其中 `wbDebt` 加力的份额。

**两个非预算停顿源（已定位并封掉）**：
* **`settle` 的无界排空**：`regionFree` 原来调 `settle` 把在飞一轮**做完**。P5@2.4M 实测一次排空
  **268,785 个对象 / 25.2 ms**（`[worst] why=settle budget=4294967295`，`over1ms=2`）。区域马上整片
  `free` ⇒ 收尾没有可观测意义 ⇒ 改成 `extc_rc_abort`（取消在飞轮 + 屏障参与者 -1），
  25.2 ms → **200–570 µs**、`over1ms` → **0**（`[ubwork] mark_n=0 sweep_n=0`）。
* **分片触发的 `extc_rc_bytes/live`**：这两个访问器的契约是"先 `settle` 再读数" ⇒ 落在 mutator 触发
  路径上时**每次触发**付一次 O(在飞轮) 停顿（实测 8 片 2.4M：`step_n=19101` 处**在环内**排空
  65,569 个对象 ≈1.1 ms，`[pause]` 看不见它）。触发只需要一个**序** ⇒ 换 `extc_rc_garbageHint`
  （`bytes - live`，不 settle）。分片 2.4M 的 `[step] max` 1.1–1.4 ms → **12.8–178.3 µs**。
* **慢步量具** `EXTC_RC_SLOWSTEP=<µs>`（默认关）：超阈值的每一步都打 `kind/why/分项/mscap/msp`
  ⇒ 判"长尾是外部抢占还是真的重对象"（前者工作量恰好等于预算、`mscap` 不变）。
* **`EXTC_RC_SLOWSTEP` 的可用区间与两种输出模式。** 阈值单位是 µs，但整条量具只在
  `EXTC_RC_PAUSE` 打开时才解析/生效（`pauseArm` 里读环境变量）⇒ 单开它没有任何输出。阈值合法
  区间是 **0 < us ≤ 1e15**：非法值（`abc`、`0`、`1e300`）**告警并关掉**量具
  （`[slow] ignored EXTC_RC_SLOWSTEP=… (want 0 < us <= 1e15)`），不再静默按 0 处理。逐条打印是在
  **该步计时取样之后**做的，所以它不污染该步自己的 `dur_us`（也正因如此，它连"这次打印花了多少"
  都看不见）⇒ **默认模式（逐条 `[slow]` 行）只适合把阈值放在明显高于打印开销的量级（十 µs 以上）**，
  `bench/gc/v2/pause/` 的 runner 就依赖这些逐条行。**低阈值请加 `EXTC_RC_SLOWSTEP_RING=1`**：
  样本进固定 4096 槽环（`overflow` 计超界次数），进程退出打一行
  `[slowdist] n=… overflow=… p50_us=… p90_us=… p99_us=… max_us=… total_us=…`（qsort 后分位），
  于是低阈值不再被 stderr I/O 拖慢，外层 `[pause]` 与墙钟仍然可读。两者互斥：RING 打开时**一条**
  `[slow]` 行都不打。

**大对象分段扫描：单步停顿不再 ∝ 对象大小（`EXTC_RC_SCAN_CHUNK`）。** 对象里的指针特别多时
（大数组字段、或运行期才知道长度的结构，按保守扫描逐字看整槽），标记它是**单步不可分片**的工作：
一次弹出要把整槽的字全走完、全压栈 ⇒ 单步停顿 ∝ 对象大小。chase 的 `graph.n: [1048576]?mut ref node`
实测单步 **1126 µs**（≈1.1 ns/指针，顺序读带宽受限），而这一步不可分片。现在按 65536 个指针一段：
一段走完就存下游标（`scanObj`/`scanOff`），下一整步接着走，单步上界实测 **72–85 µs**（比分片前低一个量级）。

* **为什么不需要卡/版本位/重扫**：写屏障本来就是**双向**的（`shade(v)` 增量更新把新值标黑、
  `shadeOld(slot)` SATB 把旧值标黑）⇒ 扫过的字之后再被写会被屏障标黑新值，扫描期间被删的旧值被
  SATB 标黑。分片扫描因此是安全的，不需要 Metronome 那类实现里最贵的重扫逻辑。
* **游标不占标记栈**：两步之间写屏障会往栈上压 force 项 ⇒「续扫对象的 force 项在栈顶」不成立
  （早先按这个假设弹栈顶会弹错对象：sizeratio 曾出现 258 次 top mismatch、Ir +87%）。游标存区域里，
  续扫由 `extc_rc_markResume` 在 `markStep` 开头整步处理；所有「标记完成」判定都多看一眼 `scanObj`。
* **只分段保守扫描**：描述符扫描的长度是结构体里指针字段数（源码常量，几到几千），分段收益抵不上
  每个对象多一道比较（实测那道比较约 5 Ir/对象 ⇒ cyclic_pressure +0.97%、owed_home +0.83%）。
* **粒度越小越贵**（promote 实测）：65536 → +0.20%、16384 → +0.59%、8192 → +0.99%、1024 → +3.6%；
  默认 65536 是「停顿上界」与「每段固定开销」的折中，旋钮留给要更紧上界的人。
* **判据**：`driver.c` 的 `t_scanChunk` 只用确定性量（一步之后的游标、栈深、`markedBytes` 不重复记账），
  不碰墙钟；`tests/reclaim/run.sh` 另有三个粒度出口（`chunk=1` 每个多指针对象都真分步续扫必须全绿；
  `chunk=1e9` 等于关掉分段，必须**红在分段断言上**）。墙钟探针 `tests/reclaim-perf/scanchunk.extc`
  （`EXTC_RC_PAUSE=1`）实测单步 max：关掉分段（`-DEXTC_RC_SCAN_CHUNK=1000000000`）**1226 µs**、`over1ms=1`；默认 65536 时 **85 µs**、`over1ms=0`（chunk=8192 时 107 µs）。

**不要用单次 `smax` 当判据**（实测）：同一份产物、同一确定性工作量（`[work]` 逐字相同），
p5 的 `smax` 在 40 次里能从 17.2 µs 跳到 362.2 µs（**21×**）、shard 16.6↔249.2（15×），
而这些run 的 **involuntary context switch ≈ 0**（最高 20% 组均值 0.0–0.4）⇒ 不是进程被抢占；
`taskset -c <核>` 钉核（本机无 `chrt` 权限）**不能**系统性削掉它（钉/不钉的 p90 与 `over64`
在 ±30% 内来回、方向不一致）。残余的是**外部干扰**：中断、频率、以及同机其它进程的
cache/内存带宽争用 —— µs 级切片上这就是测量噪声。**结论：单次最坏片不可作判据；要压就压
"工作量界"与"超阈计数"。**

**口径：引用任何数字前先钉这一条。** 同一份 Ir 在 `-O1` 与 `-O2` 下的墙钟差可以相当大
（`-O1` 会把调用/`memset` 这类开销放大）⇒ **跨口径引用无效**：写数字必须连它出自哪一档一起写。
reclaim 形状闸门（`gate-shapes`/`gate-work`/`gate-shard-cycles`/`gate-idle-projection`）用 `-O2`；
`bench/run.sh`、`gate-idle-bounded`、`ablate-tax`（cyc）用 `-O1`（**以各脚本自己的编译命令行为准**）。
**本文档默认引用 `-O2`**，`-O1` 的数字单独标。判定"某条优化能不能压到线内"的结论完全取决于钉哪
一档 —— 验收线必须先钉死，再谈达标。

**无界步必须单列。** `[work]` 只统计**有界热路径步**（`budget ≤ EXTC_RC_MARK_BATCH_MAX × EXTC_RC_SWEEP_PRESSURE_MUL`，默认 1024；压力乘子是策略内步长上限，压力步仍算有界、记在 `[work]`）⇒
`regionFree`→`settle`、`collect`、定点释放的 `mark` 这些 `budget=∞` 的排空**整段不进 `[work]`**；
而 `[pause]` 的包裹（`pauseArm`）只挂在 `maybeCollect`/`checkOwed` 上，**不包 `settle`** ⇒ 一次无界
收尾只在 `[step]` 的 max 里露头，两个"日常看"的行都看不见它。**量具与判据见本节上面的
`[ubwork]`/`[worst]` 段**（本节只有一份规格，不重复）：正常程序各入口计数必须为 0，`over1ms` 恒 0。
`gate-reclaim-work` 现在强制这两条；在那之前它全绿**不等于**没有无界步。

**工作量守恒不是时间守恒。** 若把标记侧那几条独立预算并成一个统一工作量预算 W，记住它的单位是
"1 对象 = 1 字 = 1 槽 = 1 个单位"：`tot_max == W` 是**工作量**守恒，**不是时间界**。单位价格
**不是一个常数**（同一份工作的冷/暖态能差两个数量级），所以"最坏停顿 = W × 常数"这种推法会错；
把"最坏步耗时 ÷ 预算"当作单位价格也是错的（那是尾部，不是价格）。清扫另有**独立预算**
（按字计，1 字最多 64 槽 ⇒ 一步的释放数 ≈ 字预算 × 64），标记侧的天花板压不到它；要压最坏步
必须两边一起看。W 的观测口径与推荐值见会话归档报告索引里的 `PAUSE_10US.md`。

### 四.二、一步的工作量由编译期常量封顶（v25 契约）

停顿时段的一步不是「一个 pop」或「一次清扫」这种单位，而是 `markStep`/`sweepStep` 的一次调用。v25 起，一次调用的工作量由六个编译期常量封顶，**与形状无关**：

| 量 | 常量 | 位置（`src/back/reclaim.c`） | 一步的界 |
|---|---|---|---|
| pop | `EXTC_RC_MARK_STEP_POP_MAX = 512`（冷档 `EXTC_RC_MARK_COLD_BATCH = 32`） | 常量 `:1256` / `:1266`，clamp `:3539`，冷档 clamp `:1572` | 512 个对象（活集 > `EXTC_RC_MARK_COLD_BYTES` 时 32 个） |
| push | `EXTC_RC_MARK_PUSH_STEP = 2048` + 一批描述符扇出（`EXTC_RC_MARK_BATCH_POP = 200` × 32 字段） | 常量 `:1259`，批级记账与截断 `:3665-3666` | 8448 个 child |
| 内联扫描词 | `EXTC_RC_SCAN_CHUNK = 8192`（步内额度 `_scanLeft`） | 额度 `:3543`，扣减 `:3445`，超额度改游标 `:3437-3442` | 8192 词 |
| 续扫段词 | 同上，另受 `EXTC_RC_SEG_DEADLINE_US = 40` 约束（每 512 词读一次钟） | `extc_rc_markResume` `:3484` | 8192 词 / 40 µs |
| 标记栈高水位 | `EXTC_RC_MARK_STACK_SOFT = 8192`（栈深超限的步改为 pop） | 常量 `:1274`，续扫判据 `:3551` | 16384 条（≤128 KiB 记） |
| 自由队列排空 | `EXTC_RC_FREE_DEADLINE_US = 40`、`EXTC_RC_FREE_HARD_DEADLINE_US = 50` | `:833` / `:841`，`extc_rc_fqDrainAuto` `:1640-1660` | 50 µs + 一块 slab |
| 巨块载荷丢页 | `EXTC_RC_BIG_DROP_BYTES = 512 KiB` | `[rt:hugefree]` `:858-940`，`extc_rc_bigTrimStep` `:913`，每步入口 `:1647` | 512 KiB/步（≈6.7 µs） |
| 标记路径选择（v28） | `EXTC_RC_MARK_SHALLOW_WARM_ONLY = 1`（暖档才走浅栈；阈值复用 `EXTC_RC_MARK_COLD_BYTES`） | 宏 `:3339-3341`，条件 `:3623-3625` | 冷档一步只会走批路（批量 pop ≤32），浅栈单扫不出现在冷档 |

**表里的行号是 v25 口径**（本表写定时的构建）。v28 只在两个位置各插入 3 行发射文本（`:3339-3341` 与 `:3623-3625`），因此 v25 行号换算到 v28 是分段的：**≤3,338 同号；3,339–3,619 加 3；≥3,620 加 6**。逐条对照与绝对锚点见 [`docs/analysis/REFS-V28.md`](../analysis/REFS-V28.md)，不要用单一 offset 平移。

**标记路径由屋顶选**（v28 新增的第七个常量，只影响「哪条路走」，不改变上面任何一条界）：浅栈快路的守卫里多一个合取项 `(int64_t)r->live <= (int64_t)EXTC_RC_MARK_COLD_BYTES`。暖档（活集 ≤16 MiB）一个 pop 是缓存命中，装批的固定开销与推迟去重是纯损失，浅栈单扫更便宜；冷档一个 pop 是 DRAM miss，**装批才把缺页延迟重叠起来**（同一随机链同 134 MB 活集：浅栈 86–91 ns/pop vs 批量 20.5 ns/pop，指令数逐位相同）。两条路径的 pop 上界不变（暖 512 / 冷 32），`walk_max ≤ walk_cap` 逐字仍成立。

三条**硬性理由**写在代码注释里，改常量前先读：

1. **push 不能逐条记账**。描述符扫描若按字段数扣额度，守卫会在宏里展开两次、每个 pop 约 2 条指令 ≈ 7 Ir；`tests/reclaim-perf/gate.sh` 的指令数上限（88,029,115）就吃掉了这条路的余量。改为**编译期字段上限 32**（`src/back/codegen.c:3888`，超过即退回保守扫描）+ **批级记账**（每约 200 个 pop 一次），界同样成立而指令数不变。
2. **冷档 32 是「冷 pop 约 1 µs」的直接后果**。一步要落在 50 µs 内，冷活集形状的 pop 数就必须是个位到几十；`pd_pointer_dense` 的总步时 / 总 pop 读数为 4.6 ns/pop，但单次冷 pop 会被缓存缺失拉到微秒级 ⇒ 32 是权衡点，继续降只增加步数。
3. **巨块 munmap 不可分**。munmap 的代价跟**驻留页**走：`/tmp/ctl/unmap2.c` 的读数 —— 8 MiB touch 后 116.6–119.6 µs、32 MiB 552.9–901.4 µs、8 MiB 未 touch 0.3 µs、先 `madvise(DONTNEED)` 再 munmap 2.0–2.4 µs、512 KiB 6.5–6.9 µs。所以死巨块先把载荷按 512 KiB/步 `madvise(MADV_DONTNEED)` 丢页，最后一步才 `free`（那时只剩页表工作）。

**判据是计数，不是时间。** `[wbudget]`（`:4320`）多出三个纯计数高水位（更新点 `:3741-3743`）：`pop_max`、`push_max`、`mscap_max`；门禁 `tests/gc-p0/g1c.py --require-workbound` 判 `pop_max ≤ 512`、`push_max ≤ 8448`、`mscap_max ≤ 16384`，缺字段记 N/A 且 N/A 进用例聚合（不许静默变绿）。

**为什么 max 不作判据。** 探针 `/tmp/ctl/ctl.c`（纯自旋、每轮约 59.5 ms、单次迭代约 70 ns）在 `taskset -c 6` 上四次运行的 wall max 读数 87.7 / 123.7 / 102.2 / 105.7 µs，cpu max 88.8 / 140.8 / 235.7 / 108.3 µs，且 cpu 可大于 wall（`CLOCK_THREAD_CPUTIME_ID` 计入被抢占时间）⇒ 本宿主上「测得 max ≤ 50 µs」结构性不可达，与回收器无关。因此 `max` 与 `[top]` 只作 OBS，`over1ms=0`、`>50 µs` 占比、p99.9 三组判据照旧。

**已知盲区（写在判据旁边，不藏在脚注）。** `push_max` 只覆盖批路：保守内联与段扫路径的 push 由扫描额度（≤8192 词/步）间接封顶，未逐条计数 ⇒ `push_max` 是下界。

## 五、要做的

现在还有若干形状**清扫覆盖不到**：那些形状的界仍随规模增长，有的比关掉回收还差。它们是同一个
动作的后果 —— **编译器在「列不全」的时候选择「不扫」**。要做的是两块。

* **把「根」与「宿主」各自收敛成一个来源、一个出口。**
  - **根**：活引用槽的位置现在按词法作用域分函数拼。应当由逃逸分析那一份「引用槽在哪、指向什么、
    活到哪一层」的事实统一产出，运行期只维护**一条任何触发点都走得通的根链**（帧节点 + 槽表 +
    线程本地链）：进帧登记一次、出帧撤销，标记时遍历整条链。
  - **宿主**：写引用时要能说出"这条槽装在哪个对象里"。**两层都已落地**：① 槽地址落在 rc 槽里时
    按槽地址反查宿主（见 §三「宿主证不出来时先按槽地址反查」），基表达式带调用的槽照常记账；
    ② 槽自己也不在 rc slab 里（本帧 `new T[n]` 的 arena 数组视图、池板元素、C/外部缓冲）⇒
    把**值钉成根**（§三「反查失手 ⇒ 把值钉住」），界由槽的覆盖与区域死亡给，不再整块退出清扫。
    仍缺的是这些容器的**宿主**枚举（槽寿命无法跟踪 ⇒ 覆盖之外的撤销做不到），但方向从「整块不收」
    变成了「多留一条根」。
  - **出口**：「别收」现在有四种互不相干的表达（编译期的区域级与函数级、运行期的一次性与永久），
    各自在不同地方查。应当合成一个。
* **把登记点铺全**：协程帧、`ext` 派生的帧，以及被当作「枚举不出引用」处理的几类载荷（`match`
  绑定、池容器元素、视图元素），都要能把引用登记进那条链。**整条 worker 调用链共用的
  线程本地区域已落地**：按运行期深度认领归属（入口帧触发、内层帧记欠账，见 §三），`par_tls_cycle`
  3.40× → 1.13×。**`dyn` 池的寿命已按构造点的 place 收窄**（见 §三），它里面引用的入边仍属下面的
  语义边界。**拥有者此后再不分配时的欠账已就地还掉**：清扫权按运行期委托交给被调者（见 §三），
  `home_cycle` rounds=1 3.04× → 1.00×。

**语义边界**（是决定，不是缺口）：板、池、C 栈、`dyn` 池这类**不受回收管辖**的内存里放着的引用，
它的入边无法被登记-撤销追踪，只能把**目标钉住** —— 那块内存活着，目标就不放；界由容器的生命周期给。

* **计数按编译期收窄**：计数加不加由编译期决定，而不是一律加。**能省的只有 `inc` 那一侧**
  （省 `dec` 永远安全，代价只是晚收），判据是**对象级**的：该对象的账本在它活着期间只增不减 ——
  也就是"它的**每一条**入边都不会有 `dec` 落下来"。注意这是**对象**的性质，不是边的性质：
  任一条边留了 `dec` 而别的边省了 `inc`，这个 `dec` 就可能把它打到 0（`hold` 归零当场放）。
  三个可用的充分来源：
  ① 该对象的**全部**入边统一决定（要么全发、要么全省）；全省时死期由所在区域的释放/清扫兜底 ——
     注意**块退出只 release arena，rc 区域活到帧销毁**，"块里建的链随块整片释放"不是今天的实现；
  ② 赋的是本函数 `new` 出来的对象，别名集合封闭，且各入边槽此后再不被写；
  ③ 有一条持有边**在被省的边活着期间不会被销账** —— 不是"存在别的持有者"：持有边自己可能先死
     （反例 `keep_other_holder_dies.extc`：省掉这条边的 `inc` ⇒ 读到 `v=2`，基线 `v=7`）。
  实现落点：`inc` 侧要能单独省（`holdUpd +1` 与跨区登记 `rs` 分开），并加"账本只增"的分析事实；
  **已落地的一档（跨过程"本帧不会销账"）**：`rcNoDec(F) = ¬写引用槽(F) ∧ ¬未知/extern 调用(F)
  ∧ ¬并发(F) ∧ ∀g∈callees(F): rcNoDec(g)` 的调用图最小不动点成立时，F 里局部引用绑定的 `inc`
  改发 `extc_rc_initRefNoHold`（只写槽）。自环（递归）不构成保守理由 —— 环上没人写槽就没有 `dec`。
  实测 `bt` 的税 4.637× → 2.040×（in-small）／4.124× → 1.075×（全输入）。
  判据：`tests/reclaim-elide/` 的 `elide_readonly_recursion`（该省）+ `keep_callee_writes` /
  `keep_indirect_callee`（两条语义敏感的健全性反例）。实现见
  `src/check/check_top.c` 的 `computeRcNoDec`、计划侧 `planRcNoDec`、`src/back/codegen.c` 的 `stVar`。
  收益在"大量指针赋值、极少分配"的代码里最大，而**当前最大的一笔是局部引用拷贝**
  （`var p = t`，见 [`tests/reclaim-perf/README.md`](../../tests/reclaim-perf/README.md) §10）——
  那一笔要跨过程效果（"被调者不会释放它"），比上面三类都难。
* **环的可观测性**：让"这个区域里有环"能被统计到，自学习退场才有更准的判据，
  而不必靠"扫了才知道没有"。

### 五.一、按优先级的开放项（机制与出处）

上面两块是"清扫覆盖不到"的机制缺口；下面这份是**开放项清单**，按优先级排，每条只写"要什么行为"
与出处。实测数字只在归档与 `changelog/` 里，本节不复制它们 —— 出处见会话归档
[`archive/2026-10-15-gc-pause.md`](../archive/2026-10-15-gc-pause.md) 的报告索引。

1. **取消式收尾 —— 已落地**（`extc_rc_abort`：`regionFree` 不再排空在飞的一轮，取消并配对减
   `wb`；`finish`/`abort` 带运行期配对自检）。P5@2.4M 的 25.2 ms 排空消失（`over1ms` 0，
   `[ubwork]` 各入口全 0）；**残留**：多区域同时标记（`wb>1`）下的取消路径没测。
2. **记账访问器不要再收尾**：`bytes`/`live`/`scale`/`sweeps`/`freedSlots` 现在每次观测都 `settle`
   ⇒ 程序在循环里查账就付 O(在飞轮)。**分片触发的片选择已改走 `garbageHint`**（不 settle）；
   对外的"观测即终值"契约要单独决定（`PAUSE_10US.md`）。
3. **`collect` 契约入口的无界是设计决定，不是缺口**：它承诺"调用内收完一轮"，codegen 不发它；
   要它有界就得改契约语义（`PAUSE_10US.md`）。
4. **定点释放的无界标记**：`releaseOld` 里的 `mark` 仍是 `budget=∞` 的 O(活集) 遍历，靠信用摊销、
   单次仍无界；现有形状没有一个触发过它，所以只有量具、没有形状（`PAUSE_10US.md`）。
5. **R4 没有守卫**：关屏障到清扫结束之间"把白对象写进黑对象"的边写入无守卫；应收尾条件里常驻一条
   可检验的量（`REVIEW.md`/`M1P_SPEC.md`）。
6. **M2 只有诊断**："灰已置黑却还没被扫"的断言只在诊断脚本里，没收进收尾条件（同上）。
7. **多区域同时标记（`wb>1`）下的取消路径没测**：取消式收尾只在单区域的销毁路径上验过（`PAUSE_10US.md`）。
8. **统一预算 W 自身的覆盖**：W>0 的 sanitizer 抽样与 N vs 4N 都没测（`PAUSE_10US.md`）。
9. **`gate-shard-cycles` 仍挂在 `bench` 档** ⇒ `nobench` 盖不到它；要么降规模进 `nobench`，
   要么接受它只在含基准的档里跑（`GATE_FIX.md`/`WORK_GATE.md`）。② 的判据已改成**确定性工作量**
   （运行期 `[work]` 的 `walk_max ≤ 0.5×`、工作项数 `n ≥ 2×`），不再比平均切片时长 —— 均值 =
   总时间/步数，步粒度一变就整体抬高，与分片无关：`097c455`（slab 发放容量按槽大小定）把该形状两臂
   的步数从 9490/19008 变成 5076/6264、平均切片之比被抬到 0.88–0.90（阈值 0.75）⇒ 误红；而 `[work]`
   的这两个数在 `65350a6` / `097c455` / 改前的树上逐字相同。牙：`BAND_SHARDS4=1` 跑同一条脚本 ⇒
   两臂同一份产物 ⇒ 两条判据都红。计时侧仍留 `over1ms == 0`、`over64 ≤ 5` 两条绝对上界（见第 14 条的
   粗粒度问题）。
10. **已黑值缓存**：指令数收益大，但缺"守卫 + 红演示 + 尺寸标定"才能谈落地（`C3_DIRTY.md`）。
11. **两笔归因还没做**：`alloc` 每调用的指令数、P4 的清扫分步成本（`REDUNDANCY_AUDIT.md`/`PAUSE_10US.md`）。
12. **E1/E2 悬置**：E2 卡在跨过程 must 分析（见"三点七"），E1 是它的直接后果；不立这条大项，
   表示耦合的那两个形状只能靠小刀压到接近 1 的比值（`E2_LANDING.md`/`ARENA_CRITERION.md`）。

   （报告索引里的 `ARCHIVE_2026-10-15.md`）。
14. **判据自身的粗粒度**：超阈桶是粗分位；小预算下"标记栈高水位 + `markStep` 内的 `realloc`"
   这条耦合没定量（`PAUSE_10US.md`）。
15. **标记遍历的访存局部性**：方向（`ownSlab` 热缓存 / 按 slab 局部性排序遍历 / 预取下一个对象 /
    把每对象要碰的几样结构靠拢或合并 / 清扫预算按槽不按字）与证据记在 [`TODO.md`](../plans/TODO.md) 的
    「回收的量具与访存局部性」一节，原始实测归档在
    [`archive/2026-10-15-locality.md`](../archive/2026-10-15-locality.md)；本清单不复制。
    其中「批弹出窗口」一项已落地（`EXTC_RC_MARK_BATCH_POP` 默认 **200**，见
    [`changelog/2026-10.md`](../changelog/2026-10.md)）：拉长一步内的在飞窗口就能压 `[step]` 总量，而软件预取与其
    对照证明不是杠杆；批宽同时是遍历顺序旋钮（`collects`/峰值 RSS 跟着动）。**批宽上限在进填充循环前
    一次算好**（`min(批宽, 剩余预算, 窗口配额, 标记栈深度)`），预算与配额按整批扣（`budget -= _nb; pops += _nb;`）
    —— 填充循环里不再每弹一个对象比较三个条件、扣两次账；弹出的集合与顺序逐字不变。标记栈头与栈深
也提到局部（`void **_stk = r->mstk; size_t _sp = r->msp;`），弹完整批再 `r->msp = _sp` 压回 —— 循环里
不反复读 `r`；扫批时孩子压栈改的是 `r->msp`，所以压回必须发生在扫之前，弹/扫的语义不变。
待扫对象少到 `EXTC_RC_MARK_SHALLOW`（默认 **64**）以内时直接弹一个、扫一个，**不装批** —— 批装
（数组 / 上限 min / 填充循环 / 扫批循环）在栈深 ≈1 时是纯固定开销，预取提前量也换不来东西；
而单个处理会**立刻**扫、孩子当场标黑压栈，重复压栈在源头就被去重挡掉，批装则把「标黑」推迟到
整批弹完、重复压栈因此变多。阈值是「去重收益 vs 预取收益」的折中，按形状实测取值：本形状
Ir 随阈值 8 → 32 → 64 单调降到 87 823 666，再往上（128 / 256）回升；P5 这类深栈形状几乎永远走
批路径，D1mr/DLmr 逐位不变 ⇒ 取 64。对象处理体因此移进一个文件级宏 `EXTC_RC_MARK_SCAN`，深栈
批扫与浅栈单扫共用同一份体（两份体迟早漂）。浅栈路径还**一次把浅栈排空**（`do { … } while (r->msp > 0
&& r->msp <= EXTC_RC_MARK_SHALLOW && budget > 0)`）：弹一个就回外层重判 while/预算/浅栈条件，在单发路径
上这点重判并不比扫描体本身小，排空循环把它摊到一次。`check_mark_batch` 的 `shallow fast path` /
`shallow drain loop` / `scan loop calls macro` / `scan body shared once` 钉住这几条；拆掉批量的路只留给出问题的形状
（`gate-mark-locality --selftest` 用 `-DEXTC_RC_MARK_SHALLOW=4000000000u` 把它翻成全单扫，要求
cache-sim 判据变红）。
**浅栈快路只在暖档存在**（v28）：条件里多一个合取项 `(int64_t)r->live <= (int64_t)EXTC_RC_MARK_COLD_BYTES`，由 `EXTC_RC_MARK_SHALLOW_WARM_ONLY`（默认 1）包住（发射文本 `src/back/reclaim.c:3623-3625`，宏在 `:3339-3341`）。理由是同一条屋顶：暖 pop 是缓存命中，装批的固定开销与推迟去重都是纯损失；活集过了 16 MiB 之后一个 pop 变成访存，**装批才是重叠缺页延迟的手段**（同一随机链、同 134 MB 活集，浅栈 86–91 ns/pop vs 批量 20.5 ns/pop，指令数逐位相同）。宏置 0 恢复「只看深度」的旧规则，供 A/B 与大 cache 机器使用。
    子对象循环里的同块去重也不再验槽首、也不查 `occ`：只按「包含该地址的槽」查 `mark` 位，省掉
    每个同块子对象一次 `k * s->ss == off` 的乘法校验与一次 `occ` 读。这是安全的：`mark` 位立着 ⇒ 这个槽
    本轮已经黑过，弹栈端会用同一道位挡下；槽空而 `mark` 立着时旧写法的压栈同样只会被弹栈端的 `occ`
    检查丢掉；非槽首的指针在弹栈端本来就会被 `ownSlab` 判成「不是本运行期的槽」（`skip:not-own`）
    → 当活对象止步。三种情况可达集都不变。
    弹出端的两道检查也换了序：先查 `mark` 位（已黑 ⇒ 一步跳出，这是绝大多数弹出）、再查 `occ` 位
    （陈旧指针的第二道）；两者互不替代，换序只改到达 `continue` 的先后。
    扫描体的子对象循环走**指针步进**（`const uint32_t *_op = t->off; const uint32_t *_oend = _op + t->nptr;`，
    条件 `_op < _oend`、偏移取 `*_op`）：每轮不再重读 `t->nptr` 与 `t->off` 的基址。分配路径的推进计数器
    `extc_rc_markAdvance` 也强制内联 —— 每个分派点都经过它，-O1 不跨调用点内联就每趟多一次调用/返回。
    两条都是纯代码形状（可达集、清扫集合都不动），`check_mark_batch` 的 `child loop pointer walk` /
    `mark advance inlined` 钉住它们；`markPushFast` 里的 `__builtin_prefetch` 保留 —— 删掉它指令数会降
    （约 0.27%），P5 的墙钟却变差，预取这一半只能靠墙钟评。
    这一项由指令数棘轮守（`gate-reclaim-perf`：86 174 829 Ir），可达集不变由 `reclaim-unit`（含
    ASan/UBSan）与五形状语义逐字兜底。
    批弹出是**延迟**机制（先攒一批，让每个对象的指针追逐装载各自独立在飞），不是指令数机制：
    拆掉它指令数会**下降**（同一处 `ownSlab` 被内联），末级读失手却会翻倍 —— 所以这一项由
    cache-sim 判据 [`gate-mark-locality.sh`](../tests/reclaim-perf/gate-mark-locality.sh)（P5 的
    `DLmr` / `D1mr` 上界，注入短批必须变红）守；`gate-reclaim-perf` 的指令数棘轮单独管不到这一半。
    标记步的 `ownSlab` 是一份**逐字复制**的副本（`extc_rc_ownSlabMark`，只多
    `always_inline`、只被 `markStep` 调用）：这个站点是全运行期最热的调用点，内联省掉每次查找的
    调用/返回；而把原件整体标成 `always_inline` 会让**所有**调用点都内联，`cross_region` 这类形状在
    别的调用点被撑大后会变慢 —— 收益只在这一个站点，副本也只喂这一个站点。两份体逐字一致、副本带属性
    而原件不带、`markStep` 只调副本，三条由 [`check_ownslab_body.py`](../tools/check_ownslab_body.py) 守
    （`--selftest` 每条各注入一次）；跳过标记在两份体里的数量也一致（`check_skip_table` 取并集，
    数量对不上时本门禁先红）。
16. **滑窗 + 长命索引形状上的超线性回收**：回收工作量随规模超线性（幂次约 1.7–1.8），而
    `EXTC_RECLAIM=0` 对照臂是线性的（≈0.97）；**超线性的大头在 `[step]` 记账之外**（残差）

    计数行即红，按"插桩失败"处理）。失效方向是**不安全**（漏撤一条跨区入边），语义与输出类判据
    看不出来，所以它必须是结构门禁。
  - 分片那条 `gate-shard-cycles` 的判别口径是**确定性工作量**（`[work]` 的 `walk_max ≤ 0.5×`、
    工作项数 `≥ 2×`）与**超阈计数**（`over1ms` 恒 0、长切片受控），不是单次最大值、也不是平均
    切片 —— 均值 = 总时间/步数，步粒度一变就整体抬高，与分片无关（`097c455` 把该形状的步数从
    9490/19008 变成 5076/6264 就是例子）。它仍挂 `bench` 档（`nobench` 盖不到，见"五.一"）。
* **停顿判据的口径（v21 / R3 收口；四条都只收紧、不放宽）**：
  - **每步时长取 `min(线程 CPU, 墙钟)`**（发射的 `extc_rc_stepSpan`）。两个读数都是真值的**上界**（线程
    的 CPU 时间不可能超过墙钟），所以取小者是能给出的**最紧可靠上界**：墙钟单独含宿主抢占，CPU 钟单独
    含它自己的 `clock_gettime` 调用开销（在 10 µs 判据线附近足以翻盘）。`EXTC_RC_STEP_CPU=1`
    时生效，关掉退回墙钟。`cpu > wall` 这种记账工件因此被去掉；数据见 `docs/analysis/GC-ROOFLINE.md` §6.9.1。
  - **环境地板**：宿主停顿按**时间**到达，与这一步在干什么无关，落进任何一步都会被记成"GC 慢步"。门禁在
    每次 run 前后各测一次 0.3 s 空转探针（`tests/gc-p0/noise_floor.c --rate`）的停顿率，取两次的**较小值**
    ×该 run 的墙钟，作为 `>10 µs`、`>50 µs` 两条**计数**判据的扣减量；判据阈值逐字不动，原始计数、地板、
    净计数三者都进报告（读者可加回去复核）。`over1ms` 不扣（绝对项）。本机地板 150–480 次/s（>10 µs）、
    23–77 次/s（>50 µs）⇒ `cyc` 的 `>50 µs` 通道已与 GC 自身同量级，该通道本机的可检出回归幅度约 **≥2×**；
    停顿契约的**主证据**是每步预算的形式化界（§四、定理 16），门禁只是佐证。
  - **结构性 vacuous ≠ N/A**：通道 `n=0` 时，只有在**有结构性证据**的前提下才记 vacuous PASS ——
    (b) 的段通道要求本 run 的 `[work] maxreq ≤ EXTC_RC_SCAN_CHUNK × 8`（否则永不置 `scanObj`）；
    (c) 的 release 通道要求该用例**生成 C** 里 `extc_rc_storeRefOwnedRelease` 调用点 **0 处**（门禁写
    `relsite.txt` 作证据），且机制本身另有探针 `tests/gc-p0/src/rel_overwrite.extc`（实测 `release n=90 /
    `max 7.5 µs`，另一轮 11.8 µs）。**缺证据的 `n=0` 仍记 N/A**，不许无证据变绿。
  - **走步循环里不许读时钟**：步时只有**一条**界

    ```
    P_step <= b_eff * tau_t
    ```

    即每步 pop 数乘单 pop 成本上界（`b_eff` 按冷/暖档取，见 §四、定理 16）。**第二道时间闸门（按墙钟切步的
    drain 时限）在本树里不存在**，理由两条：①它按时间切步，`[work]` 的 `n`/`walk_gt16` 会随调度逐次不同
    （`tests/reclaim-perf/gate-work.py` 的确定性断言要求三跑逐字相同）；②它不修扇出洞（见下一条），而热路径
    读钟本身有代价（Valgrind 口径每次约 480 Ir，Ir 上限 88 029 115）。两条结构断言 `batch walk reads no clock` /
    `shallow drain reads no clock` 由 `tools/check_mark_batch.py` 守着。
  - **已知漏洞（fanout，R4 修）**：`b * tau_t` 只在「每个 pop 的成本有界」时成立；扇出型对象的一次 pop 会 push
    上万个孩子，而步预算只数 pop。`pd_pointer_dense`（8 MiB 里 1M 个非空指针）实测把标记栈推到 `msp≈830k`
    （`mscap=1,048,576`），`realloc` 扩容 + 冷页缺页落在一步里 ⇒ 271–361 µs/步、偶发 >1 ms（门禁记 RED）。
    交叉构建 A/B（另一档编译时把旧时限常量置 0）两档都出现同样的步 ⇒ 与已删的时限机制无关。修法：把 push 计入
    步预算（`charge = pops + pushes`，或按 `SCAN_CHUNK` 迁入字数配额），标记栈改块链（新块 bump 分配、不拷贝旧块）。
  - **观测通道的口径差（不是契约漏洞）**：`[top]` 打印的 `cpu_us` 是原始 CPU 钟读数，没走 `stepSpan` 的 min，
    于是冷密集形状（`pd_pointer_dense`）的 `tau_t` 在 cpu 口径下 5.434 µs/pop、wall 口径下 1.573 µs/pop —— 前者
    含时钟调用开销、后者含抢占，两者都是上界但不是紧的。R4 让 `[top]` 也报 min 值，或明确规定 cold-dense
    的 `tau_t` 取自哪条通道。
  - 论证、负结果（收紧到 1 µs/16 更差；单 pop 被宿主停顿拉长）与门禁判决见 `docs/analysis/GC-ROOFLINE.md` §6.9。

    逐条核对每处原文在目标文件恰好出现一次，由 `gate-inject-anchors` 每次电池跑。
  - **插桩/判定失败不许伪装成绿。** 量具读不到目标时必须报"工具不兼容/插桩失败"并让判据红，
    而不是报一个 0：`[work]` 缺失、以及探针认不出增量形态（`owed-home` 这类形状），都属于这一类。
    同一条规则也管"按区域判定"：判定缺席时不许落"空壳绿"的判据（见"三点七"）。

## 快路径与"跳过"：前提、失效方向、判据

运行期里有若干**为了省事/省时**直接返回的地方。它们每一条都依赖一个前提；前提被破坏时，
失效方向可能是"多留"（保守）也可能是"少算"（不安全）。义务表管"必须成立什么"，这里管
"**跳过的那一刀为什么安全**"。

**这些地方在代码里都带 `/* skip:<id> */` 标记，标记与下表由 `tools/check_skip_table.py`
（`gate-skip-table`）双向对齐**：代码里出现而表里没有 ⇒ 红；表里有而代码里没有 ⇒ 红；
出现**没标记**的单行早退 ⇒ 红（棘轮，只许往下拧）。运行期是按档位发射的，所以核对会把
默认 / 计数 / 时间 / 事件 / 本地存储 / 帧根链六档的产物都发一遍再**取并集**——某个标记只活在
它那一档里（例如 `skip:hold-zero` 在计数档、`skip:chain-bad` 在帧根链档），只看默认档会把
这些表行误判成陈旧。表里不带标记的行是"非早退形态"的快路径/边界，由人读（例如 `partN`
闸门本身不是早退）。

## 不变量与它们的"牙"

回收的健全性靠一串**义务**（代码注释里编号的那几条）。下表把每条义务、它坏掉时的方向、
在哪强制、以及**哪条判据证明它有牙**列在一起 —— 只写"有判据"不算，能红的才算，
证明方式写清楚（注入名 / 单测名 / 形态）。**没有牙的当场标出来**，不留"看着像有"。

| 不变量 | 坏掉的方向 | 在哪强制 | 怎么证明它有牙 |
|---|---|---|---|
| 义务 1：`initRef` 新槽只写、加一，**不读旧值** | 不安全 | `extc_rc_initRef*` | 注入 `count-noinc` ⇒ 计数档红在 `initRef：目标计数 +1` |
