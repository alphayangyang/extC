# 弱引用（设计稿 v3，已实现）

> 状态：**已实现** —— 运行期 `[rt:weak]` 块、编译器四个内建、`std::weak` 三块都已落地；
> 判据在 `tests/weak/`（4 个程序）与本节 §6。改语义先改本文。

弱引用是「指向一个由回收器管的对象的引用，但不让它活着」。本文回答四件事：用户怎么写、
语义有几条、运行时怎么用**纯读校验**判断失效、以及哪些判据锁住它。

## 1 为什么不是 `?ref`

对象上有三种「没有」可以同时出现，必须能分开说：

| 问题 | 类型形状 | 例 |
|---|---|---|
| 键在不在容器里 | 容器的 `at(k) -> ?V` | `map.at("x")` 返回 `?i64` |
| 值本身可空 | 值类型自己带 `?` | `?string` 的 `none` |
| 弱引用还活不活 | `weak<T>::upgrade() -> option<ref T>` | 对象被回收 ⇒ `none` |
| 从未绑定过 | 外层再加一层：`?weak<T>` | 结构体字段初始为 `none` |

`?ref T` 与 `option<T>` 是**两个族**：

```text
error: `?` needs an `option<...>` or `result<...>`, found `?ref node`
note: `?` works on the `option` / `result` from the prelude.
```

所以弱引用把「失效」放进 `option`（`upgrade` 的返回类型），而不是放进 `?ref`。这样它今天就能吃
`?` 传导、零语言改动；反过来，`?ref` 的可空值 `null` 与「对象已被回收」在类型上也区分得开。

**为什么不用 `result<ref T, PointError>`。** 失效是**预期事件**，不是错误：它是回收器正常工作的一部分。
放进 `result` 有三个代价：① 每个调用点被迫写失败分支；② `?` 会把正常回收变成 early return 的可恢复
失败，调用者容易把它当「操作失败」重试；③ 与主流同族 API 不一致（Java `WeakReference.get`、C++
`weak_ptr::lock`、Python `weakref`、Swift `weak`、Rust `Weak::upgrade` 全部是 option / null）。

## 2 API 与三条语义

<!-- fragment -->
```extc
use std::weak

var w: weak<node> = weak::of(ref n);            // 取一个句柄，O(1)，不登记
let got: option<ref node> = w.upgrade();        // 目标还在就是 some(REF)，否则 none
let alive: bool = w.isValid();                  // 不取引用，只问活不活
w = weak::of(ref other);                        // 覆盖：纯值，旧句柄自然失效
```

`weak<T>` 是 **24 字节的纯值**（`addr` / `tag` / `wgen` 三个 `i64`），可以按字节拷贝、可以当结构体字段 /
容器元素 / `option` 载荷，没有 `@drop`、没有引用计数、不需要提升。拷贝就是多一个独立句柄：两份各自失效。

三条用户可见语义：

1. **`upgrade()` 的结果在被持有期间是强引用。** 它就是普通 `ref` 局部：回收器扫到栈根就保活。
   所以「拿到引用之后对象突然消失」不存在；消失只会发生在 `upgrade()` 返回 `none` 的那些调用。
2. **它的逃逸级别 = 调用点当前的 zone。** 与 `new` / `alloc` 同一条规则：在帧里登记的结果活不到
   外层作用域，除非提升（`promote`）。不新增一套逃逸求解器。
3. **目标必须是回收器管辖的对象。** 目标是帧 arena / 池块 / 板上的对象时 `of()` 运行期 `trap`
   （这三类存储不归还到「槽」这个粒度，「失效」永远不会发生，弱引用没有意义）。

## 3 失效语义：句柄绑地址，标签绑槽的一生，序号绑 slab 的一生

| 事件 | 句柄之后 `upgrade()` |
|---|---|
| 目标还活着，且槽没被复用 | `some(同一个地址)` |
| 目标被回收、槽还没被复用 | `none`（占用位为 0）|
| 目标被回收、槽已复用给别的对象 | `none`（槽版本号变了）|
| 整个 region 关闭、slab 已归还给分配器 | `none`（slab 不在表里，或 slab 序号变了）|
| 巨块载荷超出预留被搬走 | `none`（旧地址的槽已释放）|
| 对象原地增长（在预留内） | `some(同一个地址)` —— 地址没变 |

「回收器把槽放回空闲链」与「版本号 +1」是同一个时刻，所以**槽被复用之后旧句柄永远不会指向新对象**：
新对象诞生时版本号已经与句柄里的标签不同。

## 4 运行时：`(addr, tag, wgen)` 的纯读校验

```c
/* weak<T> 的载荷就是这三个数（stdlib 侧一个 24 字节 `value）*/
uint64_t addr;   /* 目标对象地址：回收器按 slab 表反查宿主 slab */
uint64_t tag;    /* 槽版本号（每槽 4 字节，slab 侧惰性分配）*/
uint64_t wgen;   /* slab 序号（进程级、永不重用）*/
```

`upgrade(addr, tag, wgen)` 是**五次纯读**，任何一次不过都返回 `none`：

1. 用 `addr` 在 slab 表里找到宿主 slab（只做地址区间比较，不解引用 `addr`）；找不到 ⇒ `none`；
2. slab 序号与 `wgen` 不同 ⇒ `none`（这个地址现在是另一个 slab 的）；
3. 宿主 region 已关闭 ⇒ `none`；
4. 槽的占用位为 0 ⇒ `none`；
5. 槽版本号与 `tag` 不同 ⇒ `none`（槽被复用过了）。

五条都过才返回 `addr`。`of()` 做一次反查 + 一次读版本号 + 惰性分配版本表，**不写任何登记结构**。

### 4.1 版本号在哪些地方 +1

| 位置 | 动作 | 成本 |
|---|---|---|
| 释放单个槽（`extc_rc_freeSlotLink`）| `if (slab->ver) slab->ver[slot]++;` | 一次分支 + 一次自增；只在用到弱引用的单元里发射 |
| 整块 slab 重置（`extc_rc_sweepElide`）| 遍历该 slab 的槽批量 +1 | 与清位图同阶，都是 `O(nslots)` |
| 分配 | **不动** | 0（分配热路径指令数不变，`tests/reclaim-perf/gate.sh` 的预算线不受影响）|

### 4.2 为什么还要一个 slab 序号（ABA）

只有 `(addr, 版本号)` 时有一个洞：slab 被整块归还后，分配器会把**同一段地址**再给一个新 slab，
新 slab 的版本表全 0。若旧句柄的版本号当初正好是 0，而新 slab 的同号槽已占用，`upgrade` 就会
把一个陌生对象的地址交回去——这不是「活得久了点」，而是拿到别人的对象。

所以每块 slab 出生时领一个进程级序号 `wgen`，句柄把它一起记住；地址被复用 ⇒ 序号不同 ⇒ `none`。
`wgen` 只有 8 字节/块，并且在分配热路径上没有成本（slab 创建时一次性写入）。

### 4.3 为什么没有登记表

登记表（句柄池 + 目标侧链 + 所有者数组 + 待清队列）能工作，但它把两件本该零成本的事变成了代码：

1. **目标死亡时要遍历句柄链**（`O(k)`），k 大就要分批、就要队列、就要「队列里的槽不许复用」的规则，
   停顿与 ABA 都从这条链上来；
2. **句柄值本身的销毁要跑 `@drop`**。而 `new T` 里 `T` 含 `@drop` 字段时回收器**不跑钩子**
   （`ExtcRcType` 只有 `{nptr, off}`，没有 finalizer；探针：`struct node { b: buf<i64> }` 2000 轮之后
   `bufLive()` 停在 65,536,000 B）。句柄值一旦被放在那种对象里，登记表的条目就永远删不掉。

版本号方案把这两条都消掉：**目标死亡零工作**（版本号在释放时自然 +1），句柄值不需要析构（24 字节纯值），
也不依赖任何钩子。代价是 `upgrade()` 多一次 slab 表反查，以及句柄绑地址、对象搬家即失效。

### 4.4 代价

| 项 | 量 |
|---|---|
| `weak<T>` 值 | 24 B（`std::weak_ptr` 16 B、Java 的 `WeakReference` 是一个对象头）|
| 每槽版本号 | 4 B，惰性；只落在「有对象被登记过」的 slab 上 |
| 每块 slab 序号 | 8 B，slab 创建时写入 |
| `of()` | 一次反查 + 一次读，~10 ns 量级（首次还要 `calloc` 版本表）|
| `upgrade()` | 五次纯读，~10–20 ns 量级（slab 表是地址比较，不是哈希）|
| 目标死亡 | **0** |
| 分配 / 释放热路径 | 释放槽多一次分支（仅用到弱引用的单元），分配 0 |

## 5 与运行时的接线

| 位置 | 动作 |
|---|---|
| `[rt:weak]` 块（`src/back/rt/64-weak.inc`）| 与 `[rt:buf]` 同套路：发射在 `emitLateRuntime`、在回收运行期之后，因此能调 `extc_rc_*` 的 static 函数；由 `g->needWeak` 点亮 |
| 编译器内建 | `weakAddr<T>`（地址）、`weakTag<T>`（槽版本）、`weakGen<T>`（slab 序号）、`weakUpgrade<T>`（校验并给 `?ref T`）|
| `g->needWeak` 的来源 | `scanWeakUse` 走一遍函数体与各类型的成员体找这四个名字（它们没有声明、等不到 `FuncDef`，所以不能照 `@builtin` 的路子点亮）|
| `rcPlanDecide` | 单元里出现 weak 内建 ⇒ 不许判 idle |
| `EXTC_RECLAIM=0`（T0）| 用到 weak 就编译期报错：弱引用要回收器 |
| 探针 | `[weak] of=N hit=N miss=N`，随 `EXTC_RC_PAUSE=1` 的报告一起打印；只有用过弱引用的程序才有这一行 |

## 6 判据与实测

`tests/weak/` 4 个程序，`通过 4，失败 0`：

| 程序 | 判据 | 实测 |
|---|---|---|
| `basic.extc` | 活着的目标可升级、拷贝的句柄同样有效、可解引用 | `1 1 7` |
| `stale.extc` | 目标所在 region 关闭后升级为 `none`；同一句柄再问仍是 `none` | `0 0 1` |
| `many.extc` | `vector<weak<i64>>` 装 4 个句柄：3 个死、1 个活 | `3 1` |
| `trap.extc` | 对栈上局部取句柄 ⇒ 运行期 trap，文本指名「不在任何回收区域里」| trap 文本 + 退出码 1 |

其它锁：

- **指令预算**：`tests/reclaim-perf/gate.sh` 的 Ir 线不变（分配热路径不加代码）。
- **生成 C 逐字**：不用弱引用的程序不发射 `[rt:weak]`，`emitted_identity` 里只有用到弱引用的样例会变。
- **T0**：`EXTC_RECLAIM=0` + 弱引用 = 编译期错误（不是运行期惊喜）。
- **段选择**：`[rt:weak]` 只在 `g->needWeak` 时发射；节的识别与 `[rt:counters]` / `[rt:chain]` 同一条规则 —— 只有带 `----` 的节标题行才算边界（注释里提到节名不算）。

## 7 失效时机（实测结论，写文档的人容易猜错）

extC 的失效时机由**存储释放**给出，不是「下一次收集」：

- 函数体内 `new` 落在**块作用域的区域**里（循环体、内层块各自有区域），块退出即整块释放 ⇒ 目标槽
  在那一刻被放回空闲链、版本号 +1 ⇒ `upgrade()` 立刻 `none`。
- 同一区域里持续分配不会让槽失效：区域没关、槽没被回收，句柄就一直有效 —even 若那块内存早已无引用。
  这与追踪式回收器的「弱引用在下一次 GC 后失效」不同，是区域生命周期的直接结果。
- 因此判据写成「活着 = 同一未关闭区域内；失效 = 目标所在区域关闭（或槽被回收/复用）」，
  不写成「分配一堆垃圾之后失效」。

## 8 边界与未做

- **只对单线程。** `par` 的 worker 各自持有 region，跨线程登记需要定义「谁看到谁释放」；并发设计暂缓。
- **不做 ephemeron。** 「键弱、值跟着键一起死」需要回收器传播可见性，是另一种机制（Java `WeakHashMap` 语义）。
- **不做「弱引用当容器键」的接口糖。** 容器先把 `at(k) -> ?V` 定完，弱引用只做「值可失效」这一件事。
- **句柄绑地址。** 对象若被搬到新地址（超出预留的巨块增长），旧句柄失效；这是版本号方案的固有代价，
  语义上等价于「目标死了」，调用点本来就是 `option` 分支。
- **`new T` 里含 `@drop` 字段不跑钩子**是本设计暴露出来的既有缺口，与弱引用无关，单独记账；
  弱引用不依赖钩子，所以在它修好之前也能用。
- **已知编译器缺陷**：`dropUnreferenced` 的 scoped 分支用临时缓冲的偏移去 `g->body` 里定位，
  match 臂里未被使用的载荷绑定因此删不掉（`-Werror=unused-variable`）。`_` 丢弃绑定已经由生成器在
  声明处补 `(void)` 绕开；普通未使用绑定要等那个偏移问题修好。
- **stdlib 公开面**只有 `of` / `upgrade` / `isValid` 三个；模块放 `std::weak`（不进 `std::data`）。
