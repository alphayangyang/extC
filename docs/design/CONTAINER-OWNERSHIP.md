# 容器的所有权与拷贝语义（R4c 的规则）

> 状态：规则已定并落地 —— `vector` 与 `string` 的存储已经在缓冲区基质上（`buf<T>` 预留 /
> 密排槽），`hashMap` 的元素所有权（移动进、逐元素 drop）已接，`linMap` / `linSet` 的存储也已换成
> `block<T>`（`docs/design/BUF-INVARIANT.md` §17）；`hashMap` / `map` / `place` 的 **存储**仍在池板块上，
> 迁完它们才能删池。判据在 `bench/containers/`（四格 V + 三格 S）、
> `tests/stl/`、`tests/gc-p0/`（G15 / G21 / G22）。

## 1. 要解决的问题

池板块把容器的值语义做成**别名 + 世代号**：容器里的 `vals` 是 `mut slice<T>`，指向池按块发出的一段；
`var b = a` 是 O(1)，两块共享同一段存储，靠 `pid` / `pidGen` 判「这份容器值还指着那块存储吗」
（`pStale()` 比世代、`pPoison()` 把陈旧容器收空、`pins` 冻结）。共享拷贝不要钱，价目记在内存上：
**池只还世代号，不把板块还回 RSS**，所以峰值按「构造过的总量」算。

缓冲区基质不一样：**一个缓冲区值拥有自己的一片地址空间**（2 MiB 量子的预留；小载荷走 16 B..64 KiB
的密排槽，槽与邻居共页）。拥有就不能有两个所有者，所以值语义跟着改 —— 这份文档把改法定成四条不变量。

## 2. 证据：三种基质对拍

`bench/containers/` 三臂编译同一份 `.extc` 源（`old` = 池版本的编译器与标准库，`new` = 当前树，
`cpp` = libstdc++）。`--reps 11`、`taskset -c 6`、min-of-11、三臂输出逐字相同：

| 形状 | 考什么 | old | new | cpp | new/old | 峰值 RSS old → new |
|---|---|---|---|---|---|---|
| V1 增长到 8e6 个 `i64` | 增长 | 28 ms | 19 ms | 55 ms | 0.68× | 64,252 → 65,652 kB（+2.2%） |
| V2 2e6 元素克隆 5 次 | 拷贝 | 28 ms | 16 ms | 35 ms | 0.57× | 32,876 → 34,940 kB（+6.3%） |
| V3 clear 后复用容量 | 复用 | 52 ms | 29 ms | 68 ms | 0.56× | 64,252 → 65,660 kB（+2.2%） |
| V4 20 万个小容器生死循环 | 小对象周转 | 4 ms | 4 ms | 7 ms | 1.00× | 1,868 → 1,868 kB |
| S1 1000 万次 15 字节短串 | SSO 路径（不分配） | 34 ms | 34 ms | 33 ms | 1.00× | 1,868 → 1,868 kB |
| S2 16 条 4 MiB 长串逐块 append | 长串增长 + 峰值 | 26 ms | 9 ms | 41 ms | 0.35× | 67,328 → **12,100 kB** |
| S3 8 MiB 串 clone 20 次 | 深拷贝 | 19 ms | 12 ms | 24 ms | 0.63× | 18,136 → 24,396 kB（+6.1 MiB） |

V4 是刻意选的**反向形状**：池在小对象周转上最便宜（板块在池里复用，容器死掉只还世代号），
缓冲区基质每次都要从尺寸类链上摘一个槽、再还回去。这一格必须打平 —— 第一批做法是
「归还路径只有一把锁、一次查类」（`extc_buf_slotGiveLocked`）加 `freeStorage` 内联（1.25× → 1.00×，
池底 `vector` 时代）；槽制度落地之后同一条形状又回到 1.3×，这一轮的两处底盘修法（归还一趟扫描、
每个尺寸类留一个空量子暖着）再拉回 1.00×，机制与数字在 `docs/design/BUF-INVARIANT.md` §13.4。

S3 的 +6.1 MiB 是**尺寸类与 2 MiB 量子粒度**的代价：8 MiB 长串实际占到 10 MiB 的片，
拷贝期间新旧两片同时在场；S2 的 −54 MiB 是同一件事的收益 —— 峰值跟着活集走，
不跟着「构造过的总量」走。两条一起看才是这次换基质的价目。

## 3. 四条不变量

R1 **拥有存储的值不可拷贝，只能移动。** 这是 `@noCopy` 的语义：`var b = a` 是移动，之后 `a` 不可用；
要一份独立副本写 `var b = a.clone()`（或容器自己的等价成员）。`buf<T>`、`vector<T>` 是这条规则。

「取出来」不是移动：只有名字能转移，从元素或字段里取出拥有存储的值是**拷贝**，对 `@noCopy` 类型是编译错误
（`let d = s[0]` / `let d = box.b`）。这是 R1 的另一半 —— 否则同一个槽会同时被两份所有权持有，各还一次。
这条规则覆盖**所有**按值位置：普通实参、关联函数实参、方法实参、结构体字面量字段、枚举载荷、
`return`、以及**运算符的右操作数**（`==` / `<` / `+` / `<<` 都是脱糖成一次方法调用）。
判据是「目的地类型是 `@noCopy`，来源是元素 / 字段 / 解引用」；纯名字是转移（合法），临时量与
`new` 原地搬（合法），方法链读（`v.view()[i].m()`）不产生第二份所有权（合法）。泛型模板里目的地还是类型
参数，所以检查推迟到实例化，只在这个实例真的调用了那个方法时才是错。规则与判据的细节在
`docs/design/BUF-INVARIANT.md` §14。

R2 **元素进容器是移动，容器对元素负责。** 容器的 `clear` / `shrink` / `release` / `pop` / 覆盖写逐元素
跑 `@drop`（由 `elemDrop<T>` / `elemTake<T>` 两个库内原语驱动），因此「容器里装拥有存储的元素」是合法的。

R3 **没有预留的值按值语义照旧。** `i64`、`@value` 的小结构体、以及 **SSO 区内的 `string`**（≤16 字节）
本来就不持有预留，成员拷贝就是完整拷贝 —— 这条不变量保证短串的拷贝仍然廉价（S1 那一格 34 ms / 1000 万次）。

R4 **容器要留存外来值时，自己 clone 一份。** 所有权不共享：`put` / `push` / `set` 收 `ref` 或移动进来的值，
留在容器里的那份由容器自己建（`clone()`）。调用点不需要传「能被偷走的值」，容器也不需要世代号。

R5 **零值必须可 drop。** 声明 `var s: string` 得到的是**值**（内联空串），它照样在离开作用域时跑 `@drop`；
所以每个 `@drop` 钩子都要对零值安全（`reserved > 0` 才归还），而「没有初值的局部变量不跑 drop」是错的
—— 循环里每轮都声明一个空串、再把它写长，那一轮的存储就再也没人还。

## 4. 为什么不是「让容器深拷贝」

另一条路是把四种容器都做成 `@value` + `clone` 钩子（C++ 的 rule-of-5 路线）：`var b = a` 触发 O(n) 深拷贝。
否掉它，理由三条：

1. **静默 O(n) 拷贝与「内存有界、可预测」冲突。** 本项目要的是「一步的工作量由常量封顶、堆由活集定」；
   把 O(n) 藏在赋值号后面，等于把分配点从程序里可见的地方挪进编译器的隐式动作。
2. **它解决不了嵌套。** `vector<vector<i64>>` 的元素是拥有存储的值，`@value` 的副本各自拥有预留，
   元素入容器仍然要一次显式 clone（或者一次移动）；规则不减反增。
3. **与容器已有的规则不一致。** `buf<T>` 和 `vector<T>` 已经是 `@noCopy`（元素所有权那一轮定的），
   再把 `string` 做成可拷贝，语料里会出现两种「看起来一样、拷贝代价差 10⁶」的值。

代价写在明处：调用点要写 `clone()`。这是显式的，也是可以数的（`tests/stl/buf_own*.extc` 就是数它的）。

## 5. `string` 的落点：借基质，不持有 `buf` 字段

`string` 是 `@value`（值语义 + 深拷贝 `clone`），但它的长存储**不是** `buf<u8>` 字段，而是
直接调基质的四个入口：

| 需要 | 入口 | 说明 |
|---|---|---|
| 小载荷（≤ 64 KiB） | `bufmod::extc_buf_slotReserve(u64(cb))` | 从 13 个尺寸类（16 B..64 KiB）里拿一个槽 |
| 大载荷 | `bufmod::extc_buf_reserve` + `bufmod::extc_buf_span` | 2 MiB 量子的地址预留，`span` 报实际片长 |
| 归还 | `bufmod::extc_buf_release(m.data, u64(m.len))` | 槽回尺寸类链，预留回 buddy |

原因是**零值不变量**：`buf<T>` 的字段 `mem: mut slice<u8>` 是非空引用，而 `string` 的零值必须是
「内联空串」（全仓依赖 `var s: string` 就能用），含非空引用的结构体不能零初始化；`?buf<u8>` 是
`option<buf<u8>>`，不能与 `null` 比。所以策略留在 `string.extc`，基质只提供三个动作 + 一个释放。

两个数分得清：`cap` 是**答应给调用者的容量**（`capacity()` 返回它），`big.len` 是基质实际给的片长
（尺寸类或 2 MiB 量子的粒度，总是 ≥ `cap`）。归还按 `big.len` 整片还；抬容量时只要还装得下就
一个字节都不搬 —— 这是尺寸类白送的原地增长；`clone` 知道自己要多大，所以一次要到刚好装下的容量
（不经过 1.5 倍逐级扩容），拷贝只搬一份字节。

## 6. 迁移顺序与判据

1. ~~`vector<T>`~~：已完成 —— `@noCopy`，持有 `buf<T>`。
2. ~~`string`~~：已完成 —— SSO 16 字节保留，长存储走基质（§5），`@value` + `@drop`，深拷贝 `clone`。
3. **`hashMap<K,V>`**：元素所有权已接（移动进、逐元素 drop）；存储仍是池板块，下一步换成 `buf<K>` /
   `buf<V>`，扩容时把元素**移动**到新预留（不是拷贝），旧预留整块释放。
4. **`map<K,V>`**（有序 map）同上；`place.extc` 的池引用迁走。
5. **删池**：`stdlib/std/sys/pool.extc`（77 行）、`stdlib/std/data/pool.extc`（493 行）、运行期
   `src/back/pools.c` 与 `extc_pool_*`。到此存储基质从四种（帧 arena / 回收区 / 池 / plate）变成三种。

每一步的判据（缺一不可）：

- `bench/containers/` 对应形状 `new ≤ old × 1.10`，RSS `new ≤ old + 8 MiB`；
- `tests/gc-p0/run.sh g22` 的位移判据（`maxRSS(k=16 条 1 MiB 串) ≤ 1.5 × maxRSS(k=4)`）判 PASS ——
  它量的是「峰值只由活集决定」，与 S2 是同一件事的两个量具；
- S2 类形状的 RSS **不随迭代数增长**（≈ 2 × 单条活集，而不是 4 MiB × 串数）；
- `tests/stl`、`tests/pool`、`tests/pin` 全绿（世代语义的用例按新语义重写，不许直接删）；
- G15（池 pin 泄漏）与 G21（buf 引用元素）两条 RSS 判据仍 PASS；
- 全门禁（`check.sh nobench` / `docs`、`tests/reclaim` 两档、`gc-torture`、`gc-p0`、`Ir`）与
  `tools/emitted_identity.py --check` 的差异面逐程序核对。

## 7. 用户可见的变化

- **`string` 不再共享**：`var b = a` 是移动；要独立副本写 `a.clone()`。短串（≤16 字节）例外 —— 它本来就
  不持有预留，移动它就是搬 16 字节成员，代价与拷贝相同。
- **`capacity()` 是答应给的字节数**：`withCap(13)` ⇒ `capacity() == 13`，`shrink()` 之后等于
  `max(len, 16)`。`shrink()` 只有在片比需要的容量大一倍以上时才真搬家（否则只降 `cap`）——
  它换回内存，不该每调用一次就付一次拷贝。
- **世代号与 `pStale` / `pPoison` 退场**：`string` 没有「陈旧视图」这种运行期状态了，因为不再有第二个所有者
  能释放存储；剩下的失效只有一种：**增长搬家**，与 `buf` 的视图规则一致。名字暂时留着（恒 `false` / 收成零值）。
- **`io::cout << s` 收 `ref string`**：打印是读，不该每打一次就深拷贝一份（`@value` 的按值形参会拷贝）。
- **顺序**：`vector`、`string` 已在缓冲区基质上，`linMap` / `linSet` 的存储已换成 `block<T>`；`hashMap` / `map` / `place` 随后。
