# 容器的所有权与拷贝语义（R4c 的规则）

> 状态：规则已定，正在按此文迁移。判据在 `bench/containers/`（四格 V + 三格 S）与 `tests/stl/`、
> `tests/gc-p0/`（G15/G21）。

## 1. 要解决的问题

`vector` / `string` / `hashMap` / `map` 今天的存储来自**池板块**：容器里的 `vals` 是 `mut slice<T>`，
指向池按块发出来的一段；值拷贝是**别名 + 世代号**（`pid` / `pidGen`，`pStale()` 比世代、`pPoison()`
把陈旧容器收空、`pins` 冻结）。于是 `var b = a` 是 O(1) 且两块共享同一段存储。

`buf<T>` 基质不一样：**一个容器值拥有自己的预留**（一片懒建的地址空间，预留内增长零拷贝）。
拥有就不能有两个所有者，所以值语义必须跟着改。这份文档把改法定成四条不变量，后面的迁移照它做。

## 2. 证据：池的共享拷贝买到了什么

`bench/containers/` 三臂编译同一份 `.extc` 源（`old` = 池版本编译器，`new` = 当前树，`cpp` = libstdc++）。
`--reps 11`、`taskset -c 6`、min-of-11：

| 形状 | 考什么 | old | new | cpp | new/old | RSS 偏差 |
|---|---|---|---|---|---|---|
| V1 增长到 8e6 个 `i64` | 增长 | 34 ms | 22 ms | 64 ms | 0.65× | +1.9% |
| V2 2e6 元素克隆 5 次 | 拷贝 | 28 ms | 14 ms | 36 ms | 0.50× | +5.7% |
| V3 clear 后复用容量 | 复用 | 54 ms | 28 ms | 76 ms | 0.52× | +1.9% |
| V4 20 万个小容器生死循环 | 小对象周转（池的主场） | 4 ms | 3 ms | 7 ms | 0.75× | 0% |
| S1 1000 万次 15 字节短串 | SSO 路径（不分配） | 35 ms | 35 ms | 32 ms | 1.00× | 0% |
| S2 16 条 4 MiB 长串（64 字节 append 65536 次） | 长串增长 | 22 ms | 22 ms | 40 ms | 1.00× | 见下 |
| S3 8 MiB 串 clone 20 次 | 深拷贝 | 19 ms | 19 ms | 23 ms | 1.00× | +0.1% |

S 三格今天 old 与 new 逐字相同（`string` 还在池上），它们的用处是**把迁移前的基线钉住**：
迁移之后 `new` 臂对这三个数负责。

S2 的 RSS 是这几格里的关键证据。形状是「16 条 4 MiB 长串顺序构造、每条用完即弃」，活集恒为一条 4 MiB：

| 串数 k | 1 | 2 | 4 | 8 | 16 |
|---|---|---|---|---|---|
| 峰值 RSS | 5.8 MB | 9.9 MB | 18.2 MB | 34.5 MB | 67.3 MB |

**线性、斜率 ≈ 4 MiB/串，与活集无关**：池不把上一条串的板块还回 RSS，只还世代号。同一形状的 C++ 臂
是 11.7 MB（同时只有一条串活着）。这就是「共享拷贝」的价目：拷贝不要钱，内存按**构造过的总量**算。

## 3. 四条不变量

R1 **拥有存储的值不可拷贝，只能移动。** 这是 `@noCopy` 的语义：`var b = a` 是移动，之后 `a` 不可用；
要一份独立副本写 `var b = a.clone()`（或容器自己的等价成员）。`buf<T>`、`vector<T>` 今天已经是这条规则。

R2 **元素进容器是移动，容器对元素负责。** 容器的 `clear` / `shrink` / `release` / `pop` / 覆盖写逐元素
跑 `@drop`（由 `elemDrop<T>` / `elemTake<T>` 两个库内原语驱动），因此「容器里装拥有存储的元素」是合法的。

R3 **没有预留的值按值语义照旧。** `i64`、`@value` 的小结构体、以及 **SSO 区内的 `string`**（≤16 字节）
本来就不持有预留，成员拷贝就是完整拷贝 —— 这条不变量保证短串的拷贝仍然廉价（S1 那一格 35 ms / 1000 万次）。

R4 **容器要留存外来值时，自己 clone 一份。** 所有权不共享：`put` / `push` / `set` 收 `ref` 或移动进来的值，
留在容器里的那份由容器自己建（`clone()`）。调用点不需要传「能被偷走的值」，容器也不需要世代号。

## 4. 为什么不是「让容器深拷贝」

另一条路是把四种容器都做成 `@value` + `clone` 钩子（C++ 的 rule-of-5 路线）：`var b = a` 触发 O(n) 深拷贝。
先否掉它，理由三条：

1. **静默 O(n) 拷贝与「内存有界、可预测」冲突。** 本项目要的是「一步的工作量由常量封顶、堆由活集定」；
   把 O(n) 藏在赋值号后面，等于把分配点从程序里可见的地方挪进编译器的隐式动作。
2. **它解决不了嵌套。** `vector<vector<i64>>` 的元素是拥有存储的值，`@value` 的副本各自拥有预留，
   元素入容器仍然要一次显式 clone（或者一次移动）；规则不减反增。
3. **与已提交的规则不一致。** `buf<T>` 和 `vector<T>` 已经是 `@noCopy`（元素所有权那一轮定的），
   再把 `string` 做成可拷贝，语料里会出现两种「看起来一样、拷贝代价差 10⁶」的值。

代价写在明处：调用点要写 `clone()`。这是显式的，也是可以数的（`tests/stl/buf_own*.extc` 就是数它的）。

## 5. 迁移顺序

1. **`string`**：SSO 16 字节保留，`big` 那份存储从池换成 `buf<u8>`；`clone` 深拷贝；加 `@drop` 释放预留；
   删 `pid` / `pidGen` / `pins` / `pStale` / `pPoison` / `frozen` 这套世代机制（`subView` 的失效改由「增长即失效」
   的不变量说明，与 `buf` 的视图规则一致）。
2. **`hashMap<K,V>`**：`keys` / `vals` 从池板块换成 `buf<K>` / `buf<V>`；插入时对键 clone（R4）；
   扩容时把元素**移动**到新预留（不是拷贝），旧预留整块释放。
3. **`map<K,V>`**（有序 map）同上。
4. **`place.extc`** 的池引用迁走。
5. **删池**：`stdlib/std/sys/pool.extc`（77 行）、`stdlib/std/data/pool.extc`（493 行）、运行期 `src/back/pools.c`
   与 `extc_pool_*`。到此存储基质从四种（帧 arena / 回收区 / 池 / plate）变成三种。

每一步的判据（缺一不可）：

- `bench/containers/` 对应形状 `new ≤ old × 1.10`，RSS `new ≤ old + 8 MiB`；
- `tests/gc-p0/run.sh g22` 的位移判据（`maxRSS(k=16 条 1 MiB 串) ≤ 1.5 × maxRSS(k=4)`）从 XFAIL 转 PASS ——
  它量的是「峰值只由活集决定」，与 S2 的斜率表是同一件事的两个量具；
- S2 类形状的 RSS **不随迭代数增长**（迁移后应当 ≈ 2 × 单条活集，而不是 4 MiB × 串数）；
- `tests/stl`、`tests/pool`、`tests/pin` 全绿（世代语义的用例按新语义重写，不许直接删）；
- G15（池 pin 泄漏）与 G21（buf 引用元素）两条 RSS 判据仍 PASS；
- 全门禁（`check.sh nobench` / `docs`、`tests/reclaim` 两档、`gc-torture`、`gc-p0`、`Ir`）与
  `tools/emitted_identity.py --check` 的差异面逐程序核对。

## 6. 用户可见的变化

- **`string` 不再共享**：`var b = a` 是移动；要独立副本写 `a.clone()`。短串（≤16 字节）例外——它本来就不持有预留，
  移动它就是搬 16 字节成员，代价与今天的拷贝相同。
- **世代号与 `pStale` / `pPoison` 退场**：容器没有「陈旧视图」这种运行期状态了，因为不再有第二个所有者能释放存储；
  剩下的失效只有一种：**增长搬家**，与 `buf` 的视图规则一致。
- **顺序**：先 `string`，再 `hashMap` / `map`；`vector` 已经在新基质上。
