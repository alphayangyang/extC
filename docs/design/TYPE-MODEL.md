# 类型模型：值、引用、复合

> 状态：**当前口径** —— 这篇写的是现在的事实，改语义先改它。

Status: **design**（2026-11-04）。这是提案，尚未实施；实施顺序进[待做清单](../plans/TODO.md)。

一句话：**存储的所有权只有一种（place），类型的形态只有三类（值、引用、复合），运行期多态只有一种载体。**

本文只回答"一个值是什么形状、它能不能拥有存储、它失效时听谁的"。存储本身住哪儿（帧、板块、对象表）在[内存模型](MEMORY-MODEL.md)；区域的释放规则在[回收机制与待做](RECLAMATION.md)。

## 一、三类

| 类 | 例子 | 有字节吗 | 指向别处吗 | 能拥有存储吗 | 赋值时发生什么 |
|---|---|---|---|---|---|
| **值** | `i64`、`f64`、`bool`、`u8`、`fn(...)` 指针 | 是，几个字节 | 否 | 否 | 位拷贝 |
| **引用** | `ref T`、`mut ref T`、`?ref T`、`slice<T>`、`ndview<T>`、槽句柄 | 是一个"从哪儿开始"的坐标 | **是** | 否 | 复制坐标 |
| **复合** | `struct`、`enum`、`array<T, N>`（`[N]T` 是糖）、`buf<T>`、闭包、`any` | 是，若干字段 | 看字段 | 默认拥有（`@noCopy` 则不可拷） | 逐字段拷贝，或禁止 |

三条判据，以后分类只看它们：

- 它是不是"别人的东西的坐标"？是 → **引用**。
- 它是不是"一串有字段的数据"？是 → **复合**。
- 都不是 → **值**。

`impl` 挂在任何一类上都可以（标量可以有方法，视图可以有方法，复合当然可以）。方法归属不改变类型属于哪一类。

**为什么是三类而不是两类或四类。** 这三类是三个正交问题的答案：有没有自己的字节、是不是指着别处、有没有字段与方法。两类合成不了（把引用并进复合，就要给"没有字段的复合"单开特例）；四类没必要——"句柄"看着像第四类，其实是**引用 + 世代号**，"视图"是**引用 + 长度或形状**，都落在已有的引用规则里。

## 二、`slice` 就是"引用 + 长度"

这一条把半页规则消掉了：

| 看起来是新东西 | 实际是 |
|---|---|
| `slice<T>` | 引用 + 长度 |
| `ndview<T>` | 引用 + 形状与步长 |
| 槽句柄（`pool`/`dyn` 那种） | 引用 + 世代号 |

由此直接得到三条，不用再单独规定：

1. **视图不拥有存储**，所以"要不要一份自己的字节"只有一个判断：`view()` 是看，`snapshot()` 是拿一份自己的。二者不是一个类型的两种模式，是两种不同的东西。
2. **视图失效 = 引用失效**，只有一条寿命规则：引用不能比它指着的 place 活得久。提前归还（显式收缩、重置）不是编译期能完全证明的，所以由运行期的"冻结位"把它变成确定性错误，而不是静默读到旧字节。
3. **池不是第五种身份，是一类 place**。槽表 + 世代 + 板块只是"提供存储并按代作废"的地方；句柄只是引用它的一种坐标。所以"池应该是用户能写的库"在类型模型里是成立的：它不新增类型形态，只新增一个 place 供应商。

## 三、长度：两个世界（`array<T, N>` 与 `buf<T>`）

同一个"数组"只有一种概念，容量来源有两种，类型上差一个字段：

| | 存储在哪 | 长度 | 谁拥有 | 典型用途 |
|---|---|---|---|---|
| `array<T, N>` | 值里面（内联） | 类型的一部分，编译期常量 | 值本身 | 固定形状的数据：三维向量、矩阵、摘要、读缓冲、C 结构体镜像 |
| `buf<T>` | place（今天帧，将来可归板块） | 运行时数据，`len()` | 值本身，`@noCopy` | 运行时才知道多大：读文件、拼接、增长 |

四条规则：

1. **`[N]T` 是 `array<T, N>` 的糖**，同一个类型的两种写法。多维写成 `[I, J]T` 或 `[I][J]T`，
   两者是同一种嵌套数组类型：形状本来就在类型里，所以 `[2, 3]f64` 与 `[3, 2]f64` 是两个类型，
   而 `[2][3]f64` 与 `[2, 3]f64` 可以互相赋值。
2. **方法名一致**：`len()`、`view()`、`viewMut()`、`clone()`、`==`。`array.len()` 是编译期常量，`buf.len()` 是运行时值。
3. **转换只有两条显式通道**：`array[..]` 与 `buf.view()` 借出 `slice`；`slice.snapshot()` 拿回一个拥有者。没有隐式转换。
4. **"长度不符"分两种**：两个 `array` 长度不同是**不同类型**（编译期错误）；两个 `buf` 长度不同是**不同数据**（运行时比较、运行时拷贝）。

<!-- fragment -->
```extc
var m: [4][4]f64              // 内联 128 字节，零分配
var b: buf<u8> = new u8[n]    // 一次分配，长度是 n
dot(m[0][..], v[..])          // 两者都借出 slice，一个函数吃任意长度
```

由此 `slice<T>` 的语义只剩一条：**它永远只是借用**。"我造了一块 64 KB 缓冲"这件事写在 `buf` 上，不再藏在"这行 `new` 写在哪儿"里。

`new` 读哪个世界，由**注解**决定，不由名字决定：注解是标了 `@buffer` 的类型时，`new T[n]` 就是该类型的一参数构造函数（今天 `buf<T>::withCap(n)`）；注解是 `slice<T>` 时，它仍是一条视图。元素类型必须与类型参数一致，写错是编译错误而不是重解释。`@buffer` 是对外承诺的三件事：一个类型参数、一个"收下元素个数"的构造函数、离开作用域时把存储还回去。

## 四、const 泛型（最小范围）

只为一件事故：**让"长度是编译期常量"的泛型代码可写**。没有它，要么为每个长度手写一份，要么退回 `slice` 丢掉静态检查。

**已经能跑的那一半**（`<const N: i64>` + 签名里的 `[N]T`（含多维 `[N, M]T`）+ 体内把 `N` 当整数）：`N` 由调用点的数组长度推出，不同长度是不同实例（`dot_array_3_f64` / `dot_array_2_f64`），长度不符在调用点报 `argument expects `[3]f64`, found `[2]f64``。判据在 `tests/constgen`。**还没有的两半**：显式写成 `<3>`（今天只能靠推断，因为 `3` 不是类型）、以及 `N` 出现在 `struct` 字段或 `impl` 里。

| 做 | 不做 |
|---|---|
| `<const N: i64>`；`N` 可用于数组长度、也可在函数体里当编译期整数 | `buf<T, N>`（内联容量进类型系统） |
| `array<T, N>` 的元素类型可以是类型参数（单态化时布局自然具体） | 浮点/字符串/结构体常量参数，`where` 约束，默认值 |
| 判据：`dot(v3, v2)` 必须报错 `expects [3]f64, found [2]f64`；`[[N]M]f64` 能按实参替换 | `impl [N]T` 式的特殊规则（`impl` 一律挂在 `array<T, N>` 上） |

<!-- fragment -->
```extc
fn dot<const N: i64>(a: [N]f64, b: [N]f64) -> f64 {
    var s: f64 = 0.0
    for i in 0..N { s = s + a[i] * b[i] }
    return s
}
fn zeros<const N: i64>() -> [N]f64 { … }
```

## 五、载体：`any` 是复合，且 `dyn` 与它同一表示

`any` 是一个复合类型，字段是"一个描述符指针 + 一份载荷"：载荷 ≤ 8 字节时内联在值里，超过就放在区域的一块存储里。装箱即快照——**载体拥有它的载荷**，所以它从不参与寿命检查、不需要冻结位、也不会悬垂。

`dyn Trait` 是同一种表示，只是描述符换了一种视图：

| | 描述符里放什么 | 怎么调用 | 每次开销 |
|---|---|---|---|
| `dyn Trait`（名义） | 该 trait 的方法槽 | 一次间接：`描述符 → 槽 → 函数` | 原型 0.89 ns，语言实现约 1.5 ns |
| `any`（结构） | 全类型描述符：字段表 + 名字到槽的映射 | 具体类型已知时直接调用；按名字时才查表 | 候选 ≤8：0.69 ns（热循环常被内联）；12 / 40 个候选：2.0 / 4.0 ns |

于是"动态"只有一个入口、两种看法：**名义视图**保证"这个值一定实现了某组方法"，**结构视图**允许"调用任何同名方法，不存在就 trap"。给一个类型登记方法只发生在一处；`any` 不再是一种独立的生命周期，它只是"一个带描述符的复合值"。

成本预算（同一台机器，钉核、`-O2`、多轮取最小）：

| 操作 | 每次 |
|---|---|
| 装箱 + 拆箱（载荷 ≤ 8 字节，内联） | 0.59 ns |
| 装箱 16 字节结构体（走区域） | 5.4 ns |
| 动态派发（候选 ≤8） | 0.69–0.9 ns，被内联时更低 |
| 动态派发（12 / 40 个候选，排序表 + 二分） | 2.0 / 4.0 ns |
| 静态调用 | ≈ 0（内联） |

装箱那 5.4 ns 里大头是分配与缺页：一千万次装箱就是 160 MB，全部留在区域里直到块退出。所以**热循环里不要反复装箱**；要更进一步就得让箱子有死亡时间，那是引用计数的活，不在当前范围内。

### 已经能跑的那一半

`std::data::buf<T>` 是这套语义的库级原型：标了 `@noCopy`，所以值位置出现时转移；标了 `@drop`，
所以离开作用域、被覆盖、函数中途返回时自动把池板还回去。`varArray` 与它的同一形状实测：
8e6 个 `i64`，`buf` 峰值 **64 MB**、`varArray` **130 MB**（前者是一份，后者是历代之和）。

语言级的 `new T[n] -> buf<T>`、以及把 `slice<T>` 收成纯借用，还没做。

## 六、两条跨类规则

整套模型只有这两条规则，其余都是推论。

**规则一：引用不能比它指着的 place 活得久。** 编译期用深度检查证明大部分情况；证明不了的（提前把存储还回去）在运行期用冻结位变成确定性错误。**错的方向永远是"trap"，不是"静默读旧字节"。**

**规则二：复合默认按值拷贝；`@noCopy` 的复合不能被拷贝，只能借或移动。** 移动 = 位搬 + 源位置标死。**这一半已经落地**（`var b = a` 与 `var b: box = { c: a }` 都是转移，之后读 `a` 是编译错误，给它赋新值就重新可用）；还差的是临时量那一半——它要等 `buf<T>` 的拥有者信息，落地前 `s = s + t` 仍会留下旧存储。

由此得到每个语法位置发生什么：

| 写法 | 值 | 引用 | 复合（默认可拷） | `@noCopy` 复合 |
|---|---|---|---|---|
| `var x = e` | 位拷贝 | 复制坐标，受规则一约束 | 逐字段拷贝（或移动临时量） | 移动（源不再是 place） |
| 传参 | 位拷贝 | 复制坐标 | 逐字段拷贝，或按签名借出 | 只能借：`ref`/`mut ref` |
| 返回 | 位拷贝 | 只能返回比函数活的 | 逐字段拷贝 | 移动 |
| 字段赋值 | 位拷贝 | 复制坐标 | 逐字段拷贝，旧值不留痕迹 | 移动 |
| 放进载体（`any`/`dyn`） | 装箱 | 装箱（载荷是坐标时，深挖成快照） | 装箱即快照 | 装箱即快照 |

最后一行是模型里唯一"静默复制"的地方，所以它单独有预算（上一节的表）和一条纪律：**热循环里别装箱**。

## 七、拷贝、移动、借出、快照

四个词各管一件事，除此之外没有第五种传递方式：

| 词 | 做什么 | 谁拥有 | 出现在哪 |
|---|---|---|---|
| **拷贝** | 复制字节，两份互相独立 | 两边都是拥有者 | 可拷贝类型的值位置 |
| **移动** | 所有权转移，源位置作废 | 只剩目的地 | `@noCopy` 类型的值位置、临时量 |
| **借出** | 产生一个指向别处的坐标，不拥有 | 不拥有 | `ref`/`mut ref`/`slice`/`ndview`、`view()`、`[..]`、按引用传参 |
| **快照** | 把借用的内容变成一份自己的 | 新值拥有 | 显式 `snapshot()` / `clone()` |

三条默认：

1. **默认可拷贝**；只有标了 `@noCopy` 的类型才不能拷贝。
2. **值位置按类型分派**：值位置（`var x = e`、`return e`、实参、字段赋值、容器插入）上，可拷贝的拷贝、`@noCopy` 的移动。
3. **临时量永远移动**。判据是"源是不是一个 place"：不是 place 就没有"要保留的源"，直接接管。所以 `s = s + t`、`return make()` 零拷贝。**这条随 `buf<T>` 落地**；今天 `@noCopy` 只在绑定与结构体字面量字段上转移，实参与返回仍是"不许拷贝"（`arg_copy` 反例照旧）。

**`=` 不是运算符，是语句**，展开成固定的四步；用户能定制的是其中两个钩子，由标签选中，而不是重载 `=`：

```
x = v
 ① 求值 v：临时量 ⇒ 移动；命名 place ⇒ 拷贝（可拷贝）或移动（@noCopy）
 ② x 原来活着 ⇒ 释放旧值（@drop 类型的 drop，或内建归还存储）
 ③ 搬入：位搬（移动）或 clone（拷贝）
 ④ 移动则把源位置标死，之后再用它报错
```

| 标签 | 打开什么 | 钩子 | 没有它时 |
|---|---|---|---|
| `@noCopy` | 值位置 ⇒ 移动；禁止拷贝 | 无 | 可拷贝 |
| `@value` | 允许拷贝并定制 | `fn clone(self: ref Self) -> Self` | 逐字段深拷贝 |
| `@drop` | 覆盖与退出时释放 | `fn drop(self: mut ref Self)` | 不做释放，交给 place |
| `@place` | 字段存储借自板块、寿命挂当前 place | 无 | 字段内联 |

不重载 `=` 的理由：初始化与覆盖是两件事（C++ 的 rule-of-5 正源于此）；自赋值与部分写入要用户自己兜；而"移动是位搬"这条零成本性质，一旦允许改 `=` 就没有了。

**复合赋值是另一回事**：`x += y` 默认脱糖成 `x = x + y`，但类型可以定义 `fn +=`（接收者是
`mut ref`，返回 `void`）把它接管成一条**语句级的就地写入**。这就是"累加一个字符串"不必每轮
造新值的入口：

<!-- fragment -->
```extc
var s: string = string::from("")
s += "abc"          // 走 `fn +=`：就地 append，摊还 O(|abc|)、零垃圾
s = s + "abc"       // 走 `fn +` ：造新字符串再赋值，上一份存储留在原地
```

钩子按右操作数的静态类型分份重载（与 `+` 的重载集对应），没有定义钩子的类型照旧脱糖，所以
这条特性对已有代码是零影响。

**失效规则只有两条**：place 死了（编译期错误），或存储身份变了（增长、重置、提前归还）。

第二条今天只落地了一半：**同一块里**"借出视图 → 容器增长 → 之后又读这个视图"已经是编译错误；跨越块、跨函数、以及库内部提前归还存储的形状，要等冻结位（`buf<T>` 带来的所有权计数）才能变成运行期 trap。所以现在不存在"静默读旧字节"的常见形状，但也不宣称已封死。

**语义绑标签，不绑类型名**：编译器只读标签决定拷贝/移动/释放/存储位置，不按类型名字派发。`string` 与用户写的容器走同一条路；库里能写的就不进编译器。

### 已经能跑的那一半（`@value`）

| 情形 | 今天的行为 |
|---|---|
| `var d: T = c`，`T` 标记 `@value`，`c` 是变量/字段/元素（place） | 调用 `T::clone(&c)`，两个值各有自己的存储 |
| `var d: T = make()`（临时量） | 移动，不调用 `clone`（临时量没有第二个名字） |
| 结构体字面量字段、按值实参、按值返回 | 仍是位拷贝（还没接 `clone`）⇒ `@value` 类型暂时不要用在这三个位置 |

`@value` 与 `@noCopy` 互斥：一个说"拷贝要建成独立的值"，一个说"不许有第二个所有者"。
判据在 `tests/copy/`（4 项）：`clone_place`、`move_temp`，以及两条反例（缺 `clone`、与
`@noCopy` 同用）。

## 八、性能与元数据预算

面向对象不等于每处都多一层。四条硬规则，缺一条就会被"元数据膨胀"反噬：

1. **多态住在包装器里，不住在对象里。** 复合值的布局里没有虚表指针；多态只发生在 16 字节的载体上。所以"这个类型没有被子类化/装箱"时，为它付的元数据是 **0 字节**。
2. **描述符按需存在。** 一个类型只有在被装箱、被打印、被比较、被序列化、或通过载体被调用时，才需要描述符；其余类型不发射任何元数据。这是"存在"与"不存在"的区别，不是"多一点少一点"。
3. **静态派发永远优先且零成本**：具体类型上的方法调用就是一次直接调用，内联后归零。只有接收者本身是载体时才走描述符。
4. **装箱有上限**：≤8 字节内联、不分配；超过就进区域，代价就是一行的 5.4 ns。不允许"为了动态性而给每个值加头"。

## 九、现有特性归位

| 现有 | 属于 | 动作 |
|---|---|---|
| `vector` / `varArray` | 复合（字段含引用） | 二合一，一个名字，另一个当实现细节 |
| `hashMap` / `linmap` / `map` | 复合 | 对外一个家族，元素少时自动走线性 |
| `string` / `stringio` | 复合 | 合并，缓冲写入口只留一处 |
| `json` 的两套 | 复合 + 载体遍历 | 解析与输出保留两种用途，删重复的字段遍历 |
| `pool`、槽句柄、`@place`（旧拼写 `@poolObject`） | place 供应商 + 引用 | 池变纯库；句柄归入引用；取消编译器对"哪个类型拥有池"的硬编码 |
| 引用计数层 | —— | 删除：没有所有权图就不需要它 |
| `dyn` 与 `any` 两套派发 | 一个载体、两种视图 | 描述符合一张表，派发共用一条路径 |
| 闭包、函数指针 | 复合 / 值 | 不新增类型形态，符合现状 |
| 元素引用 `ref v[i]` | 引用 | 归入引用类，按 place 的寿命检查 |
| 定长数组、`buf`、枚举 | 复合 | 数组归一成 `array<T, N>`（`[N]T` 是糖）与 `buf<T>`；方法直接挂在类型上，不再先 `[..]` |
| `slice` 既当视图又当拥有者 | 引用 | 所有权移交给 `buf<T>`：`slice` 永远只借 |

## 十、剩下两处待拍板

1. **标量能不能有方法**：建议能（统一、便宜，实现已有），否则"给 `i64` 加一个工具方法"就得靠自由函数。
2. **`buf<T>` 的名字**：`buf` / `store` / `array`；`array<T, N>` 这个名字已经占了"静态长度"那一半。

已拍板：**装箱一律拷贝装箱**（载体里不放引用）。否则"类型说是 `any`、其实指向已释放内存"这条路就打开了，静态类型系统被动态绕过。

已拍板：**`array`（定长）与枚举都算复合**，因此数组不能自我引用。

## 十一、判断"该不该加"的五问

任何新特性先过这五问，答不上来就不加：

1. **它属于哪一类？** 答"哪类都不属于"＝ 不加。
2. **它能写成库吗？** 能，就不进编译器（池、哈希表、序列化都属这类）。
3. **它的失效规则与规则一、规则二冲突吗？** 冲突就改现有规则，不许再开第三条。
4. **热路径上它加几次间接、几个字节？** 答不出数字就不加。
5. **它的答案和现有的哪个重复？** 重复就先合并，再加。

## 十二、预算（防反弹）

超预算必须先删再加。

| 项 | 现在 | 目标 |
|---|---|---|
| 类型形态 | 三类 + 一个载体（本提案） | 保持不多于这个数 |
| 语言关键字 | 32 | ≤ 30 |
| 内建函数 | 40 余个 | ≤ 40 |
| 标准库模块 | 30 | ≤ 20 |
| 公开成员 | 525 | ≤ 300 |
| 每个需求的答案数 | 2–5 | **1** |

## 十三、三句话

1. **形态只有三类**：值是字节、引用是坐标、复合是字段；视图与句柄都是引用。
2. **所有权只有一处**：place 拥有存储，引用只借，载体只快照。
3. **多态只有一个入口**：装着描述符的复合值；对象布局里没有虚表。
