0.5 内存安全：承诺 × 现状

这一章回答一个问题：extC 到底承诺了什么，今天实现了多少。 每条都标了「实测状态」，不是设计愿望。

三条前提（一开始就定的）

#前提现在
G1内存自动回收 —— 用户永不写 malloc / free / close语言里连 malloc 都没有（生成的 C 里出现 0 次）
G2第一个真实用户是五子棋（不是自举）棋盘/五连判定/result 都能写
G3能自举🔸 修正：主人 2026-09-18 说「不一定完全自举」⇒ 降级成可选的验证手段

一条原则

P：凡是编译期能证明的，运行时不留痕迹。

它禁的是隐藏的机制（GC / 异常 / 运行时元数据 / 隐藏分配 / 运行时类型标签）， 不是数据拷贝（值语义的拷贝是写在类型上的、看得见的）。

P′（同一句话的另一面）：不能证明的，语法上必须看得见。

内存安全的九条承诺

#承诺状态说明
1无 GC、无引用计数从来就没有（运行时零分配）
2无异常、无栈展开失败归 result，? 展开成三句语句
3未初始化 UB 消失默认零初始化：var b: board 自动清零
4ref 不可为空没有 null；ref 也没有零值
5越界 = trap 带 extC 位置a[i] 越界 → trap: index 7 out of range (length 3) + 文件行号
6切片越界能证明的编译期报错，不能证明的运行时 trap 带位置
7只读 / 可写看得见ref T / mut ref T、slice<T> / mut slice<T>（见 §3）
8算术无 UB部分溢出用 -fwrapv 兜成确定行为；除零崩了没位置、移位超宽静默错（待补）
9引用不能活得比被指对象长（逃逸检查）词法深度 depth(r) ≥ depth(v)；参数 = 0、函数体 = 1、每层块 +1。比两个整数，不写生命周期

逃逸检查：唯一引用规则

若引用 r 指向值 v，则 depth(r) ≥ depth(v)。 人话：引用不能活得比被指对象长。
fn bad() -> slice<i32> {
    var a: [8]i32 = [1, 2, 3, 4, 5, 6, 7, 8]
    return a[..]        // error: this return value would hold a reference to a
}                       //   local variable that dies first (depth 1 > depth 0)

合法的三种写法（视图/引用照样好用）：

写法为什么可以
fn rowView(b: ref board, y: i32) -> slice<i32> { return b.cell[y][0..4] }借的是参数（深度 0）⇒ 活得比函数长
fn copyRow(...) -> [4]i32按值返回 ⇒ 拷贝，不带引用
局部视图只在函数内用同深度 ⇒ 一起生一起死

深度会递归地看进 struct/数组：return holder { s: a[..] } 同样被拦住。

以前故意不查的那条，现在查了：把引用传进函数、函数把它存起来。 这条曾经是欠账（「需要引用的传染性分析，比深度模型贵得多」）—— 现在做成了两条便宜规则，都不需要传染性分析：

#规则拦住什么
A函数调用的引用深度 = max(所有实参的深度)return identity(ref x) —— 转发把信息丢了 ⇒ 放行 ⇒ 实测打印 0（悬垂）
B借来的值不能存进 placeDepth == 0 的地方fn stash(s: slice<u8>) { G = s } —— 参数把「借来的」洗成了「自己的」

A 的一句话证明：被调函数能返回的引用只有两种来源 —— 它自己的全局/静态（深度 0），或者它的实参（深度 ≤ max(实参)）。 它返回不了自己的局部（那条规则单独就挡着）⇒ max(实参) 是精确上界

B 的判据：exprBorrowed —— 参数派生和调用结果是「借来的」； 全局和字面量不是（静态的，谁都存得下）

fn identity(r: ref i32) -> ref i32 { return r }        // 转发本身合法
fn bad() -> ref i32 {
    var x: i32 = 5
    return identity(ref x)   // borrowed from depth 1, but this can only hold up to depth 0
}
var G: slice<u8> = "x"
fn stash(s: slice<u8>) { G = s }   // cannot store a borrowed value into something that outlives this call

还有一条：s = a[1..3]（整体赋值给视图）= 换绑那两个词，

let 是给"已有的别名"降级的，不是"造一个不可变对象" let x = new T 会拿到一条只读引用，而只读引用提权不回来（ref *x / 传进 mut ref 参数 / x.f = v 全被挡）⇒ 这块存储谁也写不进去、永远是零 ⇒ 编译器给警告（不拦）： 想写就用 var；想要"只读视图"就 var w = new T + let r = w

不是「透过只读视图写元素」⇒ 合法。它和上面两条必须一起修 —— 这条以前误报，而误报让上面两条的反例写不出来（谁来触发洞的代码自己都编不过）

深度模型不是为今天设计的，是为内存模型设计的： 加上 arena（深度 0 的存储）之后，g.s = a[..] 这类照样被同一条规则挡住

还剩下的：算术 UB 三处

情况现状
有符号溢出-fwrapv 兜成确定的绕回
除零崩（SIGFPE）但没有 extC 位置
移位 ≥ 位宽静默算错（只有 gcc warning 漏出来）
