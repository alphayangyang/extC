# P1 · 四形状与 C++/Rust 的持平台账（goal 轮 2）

> 口径：`bench/gc/v2` 四形状，`build/extc` = `8af2a5e8`（v13），`src/back/reclaim.c` = `7151a431` / 4,212 行，`taskset -c 6`，11 回合交错 + 奇偶反向，`/usr/bin/time -f %M` 取峰值 RSS。**绝对毫秒只在同一轮内可比**（跨会话漂移 5–13%），本文件所有比值都取自同一轮。

## §1 结论（一句话）

三形状已快于两个对手（promote 对 C++ 0.33×、sizeratio 0.90–0.93×、cycleratio 0.40×），chase 仍慢于 C++ 最好写法 **2.5%–7.8%（配对中位）**；本轮把这条差距拆成两段：**GC 3.9% + 布局相位 1.9%**（v13 口径，9 回合交错），并更正上一轮「关掉 GC 也不更快」的结论——那是 v11 口径的旧观测，不再成立。轮 3 追加更正：轮 2 里「字段重排可吃掉 1.9%」的结论被同批二进制的 15 回合配对实验否掉（§5.2），1.9% 与字段顺序无关。

## §3 chase 差距分解（本轮主结果）

同一份 v13 生成 C，只把 `extc_rc_shouldSweep()` 改成 `return 0;`（A/B 补丁脚本 /tmp/fin/ab_nogc.py，9 回合交错 + 奇偶反向，`taskset -c 6`）：

| 臂 | min ms | 中位 ms | max ms | 峰值 RSS kB |
|---|---:|---:|---:|---:|
| extc 默认 | 125.60 | 132.55 | 143.86 | 67,740 |
| extc 关回收 | **120.64** | 124.88 | 138.28 | 65,240 |
| cpp:careful | 118.42 | 124.14 | 133.16 | 77,456 |

⇒ **GC 值 4.96 ms（3.9%）**；关掉回收后与 C++ 只剩 **2.22 ms（1.9%）**。后一段与上一轮的行级归因（取边行 1,549,294 vs 209,566 次 D1 miss，48 B 槽四拍相位）一致 —— 两段互不重叠。

GC 侧自证（`EXTC_RC_STATS=1`）：`[pause] collects=2`、`[step] n=633 total_us=5343.3`（两次全量标记，每次 ~1M 活 node、8.4 µs/step、8.2 ns/pop）、`[work] thr_max=63,438,892 scale_max=16 M_max_now=69,206,064 pressure_steps=429`、`mscap_max=524,288`（标记栈长到 4 MiB，`msp_max=305,873`）。

**为什么这 3.9% 难消**：chase 的活集是 1M 个 48 B node 的随机图，两次收集各自必须把整张图重扫一遍（4M 条边随机解引用），这是全量追踪型标记的定义成本；不收集就突破「内存有界」，少收集就要抬 thr。抬高 thr 的代价上一轮已经量过（`P1-SLAB-QUANTUM.md` §7 / §6.7.9）：活字节一变，`scale_max` 就螺旋到 64、堆翻倍。**所以 chase 的 GC 段在当前「内存有界」契约下是常数额，不是可优化量。**

## §4 promote 的 GC 是净收益（关键负结果）

同一个 A/B 卡具换到 promote 500k：

| 臂 | min ms | 中位 ms | 峰值 RSS kB |
|---|---:|---:|---:|
| extc 默认 | **38.38** | 40.45 | 5,724 |
| extc 关回收 | 93.31 | 101.43 | **121,116** |

⇒ 不回收反而慢 **2.43×**：RSS 从 5.7 MB 涨到 121 MB，缺页成本（~55 ms）远超 GC 自身（17.4 ms，见 `P1-STEP-TAIL.md` 的 promote 归因）。**这条负结果说明 promote 的 1.5 ms 差距不能用“少回收”去换**，它只能靠代际/记忆集（写屏障记录 old→young 边）这类多轮工程去换。

## §5 两个反证实验（都指向“不改编译器”）

### §5.1 标记时预取子对象：无效

在 `EXTC_RC_MARK_CHILD` 末尾加 `__builtin_prefetch(child, 0, 3)`（生成 C 打补丁，`/tmp/fin/ab_pf.py`，9 回合交错）：

| 臂 | min ms | 中位 ms | 峰值 RSS kB |
|---|---:|---:|---:|
| base | **124.50** | **131.72** | 67,736 |
| +prefetch | 124.72 | 135.17 | 67,740 |
| cpp | 112.82 | 127.17 | 77,576 |

stdout 一致；预取既不快也不慢到超出噪声，中位还更差 ⇒ 标记的访存延迟已经被乱序执行掩盖到极限，多一条预取指令只是多一份 Ir。**不采用。**

### §5.2 字段顺序：重排无效（原「min −2.8%」是单发噪声，本节旧结论作废）

把生成 C 里的 `struct node` 从 `{k, v, o}` 改成 `{o, k, v}`（等价于 B 选项对 `node` 的效果），用**同一批二进制**做 15 回合交错配对（`/tmp/q2/ab_reord2.py`，奇偶反向，`taskset -c 6`）：

| 臂 | min ms | 中位 ms | 配对中位（相对 extc 默认） |
|---|---:|---:|---:|
| extc 默认 `{k,v,o}` | **115.73** | 127.92 | 1.000 |
| extc `{o,k,v}` | 117.10 | 127.09 | **1.023（更慢）** |
| cpp:careful | 112.29 | 121.55 | 0.970 / 0.966 |

cachegrind 同一输入（`/tmp/q2/cg.cur` vs `cg.reord`）：Ir 319,713,318 → 319,733,951、**D1mr 10,414,120 → 10,440,174**（+0.25%，方向是变差）、DLmr 150,727 → 150,806。

⇒ **重排既不减少 miss 也不提速**。轮 2 记的「min −2.8%（122.31 vs 125.85）」是单发测量，落在跨会话漂移（5–13%）里，**已作废**。

为什么必然无效（相位算术）：48 B 槽、8 B 对齐、块基址 512 KiB 对齐 ⇒ 槽起点 `p mod 64` 只在 `{0,48,32,16}` 四拍里轮转。`{k,v,o}` 里 `o` 占 `[p+16, p+48)`，只有 `p=32` 时跨线；`{o,k,v}` 里 `o` 占 `[p, p+32)`，只有 `p=48` 时跨线 —— **两种顺序都是 1/4 跨线**，互换只是换了个拍子。旧推断「尾部 2/4、头部 3/4」是相位表算错了。

⇒ 连带作废 §7 的 **D 选项**（“应用层把引用数组声明在前”）：它对跨线率没有影响，不该作为建议写进文档。

## §6 为什么编译器不自动做字段重排

1. **确定性布局是语言硬约束**（用户 m01379：「本语言希望普通对象布局是确定性的布局」）：字段顺序必须由源码声明唯一决定，自动重排会让“同一份源码 → 不同布局”依赖优化决策，破坏可预测性与 ABI 稳定性。
2. **槽宽补到 64 B 已被否**：上一轮实测 pad64 让 chase 132 → 158 ms、RSS 73,696 → 97,504（`P1-SLAB-QUANTUM.md` / §6.7.9 归因），因为活字节 +33% 触发 `scale_max` 螺旋。
3. 因此在“确定性布局 + 紧凑槽”两条约束下，**chase 的 1.9% 是 48 B 槽跨 64 B line 的 miss 膨胀（每 4 个对象有 1 个的取边访问跨线），与字段顺序无关**（§5.2 已实测两种顺序都是 1/4 跨线，D1mr 不降反升），唯一能消掉它的办法是让整对象按 line 对齐（补到 64 B），而 pad64 实测净负（chase 132 → 158 ms、RSS 73,696 → 97,504）。加上 3.9% 的全量标记成本，chase 的残差在“确定性布局 + 紧凑槽 + 内存有界”三条约束下都是结构性的。

## §7 决策点（下一轮开头）

| 选项 | 内容 | 代价 | 归属 |
|---|---|---|---|
| A 接受现状 | chase 1.03–1.08×，其余三形状 0.33–0.93×，RSS 全低于对手 | 无 | 默认 |
| B 改布局规则 | 允许编译器按“引用密集度”确定性地选字段顺序（或把引用数组前置） | **已实测无效**（D1mr 10,414,120 → 10,440,174、配对中位 1.023 更慢，§5.2），且要改 ABI 说明 | 语言语义（已否） |
| C 代际 / 记忆集 | 写屏障记录 old→young，标记只扫 remembered set | 多轮安全工程（屏障已在，需增量标记 + 写回退化） | 运行时 |
| D 应用层建议 | 文档写明“引用密集结构把引用数组声明在前可减 1/4 跨线” | **作废**：两种顺序跨线率都是 1/4（§5.2 相位算术） | 文档（已否） |

B 与 D 已在 §5.2 被配对实验否掉，剩 **A（接受现状）与 C（代际 / 记忆集）二选一**，都需要用户决定。默认建议 **A**：残差 1.03–1.05× 已等于“GC 3.9% + 跨线 1.9%”，而 C 要用 RSS 67.7 MB → 约 130 MB 换 1–2%。
