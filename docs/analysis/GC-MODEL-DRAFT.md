## §0 一句话结论

extC 现有默认路径（静态分层 arena + 区域步进式 sweep，计数默认关）在 digraph@1M 上落在
**(λ=0.163 ns/B, a=0.53 GB/s)**，离 CPU 屋顶 6.15 GB/s 有 **11.6×** 余量 ⇒ **本语料是 mutator 受限，不是 GC 受限**；
真正逼近的硬墙只有一条：**存活比 σ 与 keep-up 上限 σ_max=b/(b+64)=0.800 的距离只剩 1.08×**
（实测 σ=0.742）。因此“内存有界 + 停顿有界”的设计题，不是“把 GC 做快”，而是
**在 (σ, P, M) 三面墙之间选触发点与步长**；闭式解见 §7，决策准则见 §9，标定清单见 §10。

五条要点：

1. **内存界现在是“条件成立”，不是硬保证**：`thr = max(2·live, floor)·scale`（`src/back/reclaim.c:2636-2642`），
   `scale` 在空扫后 ×4 且上限 `2^40`（`:143-151`）⇒ 无环负载**故意**让触发线退到无界侧。
2. **停顿界在热路径“按构造成立”**（`MARK_BATCH_MAX=256`、`SWEEP_BUDGET=8`，见 §4.2），
   但**契约入口（collect/settle/regionFree/account 查询）无界排空**，实测最坏单次停顿 2344 µs（§4.2 反例）。
3. **摊销界给出 λ_alloc=(c_t·σ+c_s_eff+κ/H)/(1-σ)**：σ→1 时发散，这是“高存活率形状”的根因，
   也是“增大 M 换 r”的唯一理由（§7 的 r_sat）。
4. **吞吐屋顶在这套语料上不是瓶颈**（11.6×），所以任何“优化 GC 常数”的工作必须先证明它能改变
   *内存界或停顿界*的可行域，否则只是把 8.6% 的税变成 7%。
5. **模型的第一价值是排除**：本图上 S4（复制/分代）被“地址静止”不变量否掉，S3（纯计数）被
   +100.9%~+455.2% Ir 实测否掉，分片被 `SHARDS=4` +327.7 ms / +220.2 MiB 实测否掉（§6）。

## §1 范围、口径与证据等级

### 1.1 三个必须分开的层

extC 的“内存管理”不是一个机制，而是三层叠在一起，混着算会得出错误结论：

| 层 | 机制 | 谁负责回收 | 停顿风险 | 本文记法 |
|---|---|---|---|---|
| **L1 静态 arena 层** | 每函数一个 `extc_arena __extc_a[N]`，每个词法层级一个 arena；块/循环退出 `extc_arena_release`，函数结束 `destroy`；块单链表 bump、cap 倍增、保一个 spare（`src/back/codegen.c:12119-12132,12151`） | **静态作用域**（编译期决定） | 释放是 O(#block) 次 `free`，与对象数无关 | S1 |
| **L2 区域 sweep 层** | 逃逸对象进静态 promotion level 的 region；1 MiB slab + 位图；步进式 mark（每 64 次分配推进）+ 步进式 sweep（每步 8 words）（`src/back/reclaim.c:887-914,1023-1037,2324-2382,2555-2575`） | 调用站点发射的触发（`codegen.c:4133-4143`） | 单步有界；契约入口无界 | S2 |
| **L3 计数层** | holder 计数（默认 **关**：`codegen.c:13787-13794` 默认 `rcNoCount=1`；`reclaim.c:2914` 发 `#define EXTC_RC_NOCOUNT 1`；`[rt:nocount]` 把计数入口变 no-op） | 引用计数归零 | 归零级联（若开） | S3 |

**对模型的意义**：Roofline 的横轴 λ 只能统计 **L2 的回收 CPU**；纵轴 a 若用“进程总分配率”，
会把 L1 的 bump 分配也计进来 —— 两者分母不同。本文明确给两套口径（§5.4），并把**决策口径**定为
`λ_alloc`（每回收字节）× `a_m`（受管分配率），因为只有这一对量纲一致。

### 1.3 默认路径 vs 开关路径（影响“这算不算当前模型”）

| 开关 | 默认 | 打开/关闭后发生什么 | 依据 |
|---|---|---|---|

## §3 现有模型的形式化（只用源码事实）

### 3.1 触发与轮次（控制律）

```c
/* src/back/reclaim.c:2636-2642 */
int64_t scale = r->scale > 0 ? r->scale : 1;
int64_t thr = r->live * 2;
if (thr < r->floor) thr = r->floor;
if (scale > 1 && thr > INT64_MAX / scale) { r->thr = 0; return; }
r->thr = thr * scale;
```

```c
/* src/back/reclaim.c:2646-2649 */
int64_t need = r->live > r->floor ? r->live : r->floor;
return r->allocBytes - r->roundVisitedBytes >= need;
```

```c
/* src/back/reclaim.c:2650-2659（节选） */
return r->bytes > r->thr && extc_rc_roundOk(r);
```

即 **触发 = 内存压力 ∧ 轮次信用**：

- 压力线 `thr = max(2·live, floor)·scale`，`floor = 1<<20`（`reclaim.c:140-141`），`scale ∈ {0}∪[1, 2^40]`（`:143-151`）；
- 轮次信用 `allocBytes - roundVisitedBytes ≥ max(live, floor)`：**上一轮开始以来新分配的字节数**必须够一个 floor，
  否则即使压力到线也不开轮；
- 空扫后 `scale *= 4`（`:2598-2609`，上限 `2^40`），有回收则归零 ⇒ 触发线**自学习式退让**。

**这条控制律的两个直接推论**（都被实测证实）：

1. **本语料的 r 由 floor 决定，不是由 2·live 决定**：实测触发字节 p50 = 1.049 MB ≈ floor 1 MiB
   （`MARK-MODEL.md:58-59`），而 `2·live` 的 p50 是 1.56 MB ⇒ 多数轮是“小活集 + floor 兜底”，
   于是 `r_eff = H/L = 1.349`、`σ = 0.742`。**要降低 λ，第一根杠杆是把 floor 抬高（增大 r），不是把 mark 写快**（§7.3）。
2. **触发线可以合法地变成无界**：无环负载每轮都是空扫 ⇒ `scale` 一路上涨 ⇒ `thr ≈ 8·live` 甚至 `2^40·floor`。
   注释自己说明了这是有意的：`reclaim.c:146-149` “one empty sweep puts the line at 8x the live set …
   it only affects loads that really have no cycles.”

### 3.2 一轮的生命周期（三个入口，三种界）

| 入口 | 位置 | 语义 | 单步是否有界 |
|---|---|---|---|
| `extc_rc_step` | `reclaim.c:2756-2763` | **热路径**：“advance one step only; finish on the spot once this round is done.” | **有界**（`stepBudget = MARK_STEP + min(wbDebt,64)` ≤ 72，`:1014-1018`） |
| `extc_rc_maybeCollect` | `reclaim.c:2777-2801` | 分配站点守卫：markAdvance / sweepStep 各推一步，或起新轮再走一步 | **有界**（同上 + `SWEEP_BUDGET`） |
| `extc_rc_collect` / `extc_rc_settle` | `reclaim.c:2765-2775` / `:2611-2622` | **契约入口**：“finish one round within the call” / “Push the round … to the end” | **无界**（`markStep(r, 0xffffffffu)` 直到 `!seedsDone && !msp && !scanObj`，sweep 同样排空） |

```c
/* src/back/reclaim.c:2765-2775（collect 的契约） */
while (!r->seedsDone || r->msp || r->scanObj) extc_rc_markStep(r, 0xffffffffu);
...
extc_rc_settle(r);   /* go on until the sweep is done too: the contract is one full round */
```

```c
/* src/back/reclaim.c:2856-2861（为什么 account 查询必然无界） */
/* the contract of `extc_rc_bytes/live` is "accounts are final when observed", so settle first,
 * and that would do an **unbounded drain** of the round in flight. */
```

⇒ **“停顿有界”在 extC 里是“热路径有界 + 契约入口无界”的混合命题**。任何声称 `P99 ≤ P_max` 的论证，
必须先声明它覆盖哪几个入口（§4.2 给反例）。

### 3.3 单步里到底做了什么（预算结构）

```c
/* src/back/reclaim.c:1023-1037 */
if (--r->markTick > 0) return;
...
r->markTick = EXTC_RC_MARK_EVERY;                        /* 64 */
size_t _debt = r->wbDebt > EXTC_RC_ASSIST_CAP ? EXTC_RC_ASSIST_CAP : r->wbDebt;   /* cap 512 */
size_t b = (size_t)EXTC_RC_MARK_EVERY * EXTC_RC_MARK_STEP + _debt;                /* 64*8+debt */
...
if (r->allocBytes - r->markStartAlloc > EXTC_RC_MARK_WINDOW) b *= 8;              /* 2 MiB 窗口 */
if (b > EXTC_RC_MARK_BATCH_MAX) b = EXTC_RC_MARK_BATCH_MAX;                        /* 256 上限 */
...
extc_rc_markStep(r, b);
r->wbDebt = 0;
```

步内三条预算（默认 `WORK_BUDGET=0` ⇒ **独立叠加**，`reclaim.c:1001-1013`）：

| 预算 | 常量 | 值 | 每步最多 |
|---|---|---|---|
| 走栈（对象数） | `MARK_BATCH_MAX` | 256 | 256 obj（`b` 已封顶） |
| 种子字扫描 | `SEED_WORDS` | 512 words | 512×8 B 的位图 |
| 种子压栈 | `SEED_PUSHES` | 256 | 256 项 |
| 清扫 | `SWEEP_BUDGET` | 8 words | 8×64 = 512 槽 |

> 源码注释对 `WORK_BUDGET` 的取舍写得很清楚：默认 0 时三条**叠加**，“So one step's total work is
> **bounded by construction to <= W**” 这句只在 `W>0` 时成立（`reclaim.c:1001-1013`）。
> **⇒ 默认档没有“单步总工作量”这一个数，只有三条各自的上界。** 这是本文档要求“停顿界必须按分量写”的源码依据。

### 3.4 mark / sweep 的执行形态（成本模型的两个常数）

- **mark**：浅栈（`msp ≤ MARK_SHALLOW=64`）逐条 pop、不分批；深栈按 `MARK_BATCH_POP=200` 先批量 pop +
  `__builtin_prefetch` 再扫描（`reclaim.c:2324-2382`）。注释解释了动机：LIFO 单 pop 是**串行指针链**，
  “a whole cache-miss latency lands on one object”（`:2320-2323`）⇒ **τ_t 的本质是 cache miss 延迟**，
  不是指令数；实测 `drain` 占 mark 的 99.5%（`MARK-MODEL.md:38`）。
- **sweep**：按位图**字**批量释放（`sweepWord`，`reclaim.c:2555-2565`：`dead = occ & ~mark`，一次
  `extc_rc_freeSlotWord`），步进 8 words/次（`:2569-2575`）。实测每槽 0.61–0.89 ns（`SWEEP-CENSUS.md:151`）。

## §4 四条界：形式化 + 判定 + 反例

先把四个命题写清楚，再逐条给出**在默认路径上是否成立**。全部推导见附录 A。

### 4.1 内存界（M-bound）

**命题 M**：对任意时刻 t，受管堆字节 `heap(t) ≤ M`。

**充分条件**（可计算形式）：

```
peak = r·L + k·L/b ≤ M          （触发点 + 在飞漂移）
⇔ σ ≥ L/(M − 64L/b)             （需 M > L + 64L/b）
```

其中 `k·L/b` 项是**在飞漂移**：mark 每 `k=64` 次分配推进一次、每次 `b` 个对象，
而每轮新增垃圾 `(r−1)·L`；要追平必须 `b ≥ 64/(r−1) = 64σ/(1−σ)`（推导见附录 A.1）。
把这条 keep-up 条件与上式联立，得到**双约束的最小堆预算**（本文最重要的闭式）：

```
M_min(b) = L·(1 + 128/b)        ⇒  b ≥ 128L/(M − L)  才可能双满足
```

**判定（默认路径）**：**条件成立，不是硬保证**。三种破坏方式都有源码/实测依据：

1. **触发线合法退让到无界**：`scale` 空扫 ×4、上限 `2^40`（`reclaim.c:143-151`）⇒ 无环负载永不扫，堆线性涨。
   实测反例：`SHARDS=4` 在 digraph@1M 上 **RSS +220.2 MiB**（默认档同形状是“有界（存活 + 阈值）”，
   `bench/gc/DIGRAPH.md:303`、`:456`）——分片把“一轮全扫”拆成“每片各扫”，keep-up 直接失效。
2. **keep-up 失效**：σ > σ_max = b/(b+64) 时 mark 永远追不上分配，`live` 与 `thr` 一起涨，
   而 `allocBytes − roundVisitedBytes` 的信用条件（`:2646-2649`）又不允许把轮开得更密 ⇒ 堆单调涨。
   当前语料 σ=0.742 / σ_max=0.800，**余量 1.08×**，这是唯一迫近的硬墙。
3. **在飞窗口只受常量约束**：`MARK_WINDOW=2 MiB` 只决定“要不要 ×8 加速”（`:904-905,1032-1033`），
   **不构成堆上界**；真正限制在飞量的是 `MARK_BATCH_MAX=256` 与 `b ≥ 64σ/(1−σ)`。

**反例场景（可构造）**：σ=0.85 的形状（大活集小垃圾）+ b=256 ⇒ σ_max=0.800 < 0.85 ⇒ 永不 keep-up；
若 floor=1 MiB 而 L=3 MiB，`thr = max(6 MiB, 1 MiB) = 6 MiB`，堆会稳定在 6 MiB 以上并继续涨，
**没有任何 trap 或上限拦住它**（`extc_rc_alloc` 走 slab/`calloc`，只有分配失败才 trap）。

### 4.2 停顿界（P-bound）

**命题 P**：任意一次 STW 步骤的墙钟 ≤ P_max，且 P99 ≤ P_max。

**按构造成立的分量**（热路径）：

```
P_step ≤ b·τ_t + SEED_WORDS·τ_w + SWEEP_BUDGET·64·τ_s + κ_step
       = 256·14.4ns + 512·τ_w + 512·0.63ns + κ_step
       ≈ 3.69 µs + 0.32 µs + κ_step ≈ 4 µs 量级
```

实测校验：**P99 = 3.7 µs**（`bench/gc/SPECTRUM-MATRIX.md:197`，P6 的 `[step]` 通道），
与 `b·τ_t = 3.69 µs` 吻合到 3% ⇒ **“单步停顿 ≈ b·τ_t”是一级近似，种子扫描与清扫是二阶项**。

**不成立的分量**：

1. `collect` / `settle` / account 查询：**无界排空**（`reclaim.c:2765-2775,2611-2622,2851-2861`）。
2. `regionFree`：暂停里做 `O(#slab)` 次 `free`，且**不排空、不扫描**（`reclaim.c:1970-2009`）；
   它的暂停不会因为“有 mark 在飞”而变小。
3. `abort` 只清 `marking/sweeping` 标志（`:1960-1969`），也不会缩短在飞轮次。

**实测反例**：停顿语料的**最坏单次停顿 2344 µs**（`persist_nodes`，`docs/changelog/2026-10.md:4235`），
比 `b·τ_t` 大 **634×**。这不可能来自 `[step]` 通道（该通道被 `MARK_BATCH_MAX` 硬封顶），
只能是契约入口/`regionFree` 造成的；**具体通道尚未归因 ⇒ §11 存疑 #2，E6 去测**。

因此命题 P 的正确表述是：

```
P_hot  ≤ b·τ_t + 二阶项                    （真，按构造，实测 3.7 µs）
P_any  ≤ P_max                             （假，除非把 collect/settle/regionFree/查询 API 也纳入预算）
```

### 4.3 摊销界（amortization）

**命题 K**：回收 CPU 占墙钟比例 `tax ≤ tax_max`（例如 10%）。

```
每轮成本   T = c_t·σ·H + c_s_eff·H + κ           （mark 走活集 σH；sweep 走 slab 面积 ≈ H）
每轮回收   R = (1−σ)·H                            （触发字节 − 存活字节）
每回收字节 λ_alloc = T/R = (c_t·σ + c_s_eff + κ/H)/(1−σ)
税率       tax = λ_alloc · a_m
```

⚠️ 注意与上文 `λ = λ_meas = T/H` 的区别：`λ` 是**每触发字节**（脚本图 (a) 的横轴），
`λ_alloc` 是**每回收字节**（决策口径）。两者差 `1/(1−σ) = 3.87×`。

**判定（默认路径）**：**成立，但余量不大且高度依赖 σ**。

- 实测：`λ_meas = (127.9 + 42.8) µs / 1.049 MB = 0.1627 ns/B`（`SWEEP-CENSUS.md:144`）；
- 换算：`λ_alloc = 0.1627/0.2585 = 0.630 ns/B`；
- 实测税：`collect` 合计 54.32 ms / 墙钟 497 ms = **10.9%**（同表），
  反解 `a_m = 0.109/0.630 = 0.173 GB/s`，与“330 轮 × 0.271 MB / 0.497 s = 0.180 GB/s”自洽（±4%）⇒ **口径闭合**。
- **非线性来源**：σ→1 时 `λ_alloc ≈ c_tσ/(1−σ) → ∞`。σ=0.9 时 `λ_alloc ≈ 0.180·0.9/0.1 = 1.62 ns/B`（2.6× 于当前），
  σ=0.95 时 3.42 ns/B（5.4×）⇒ **高存活率形状的 GC 税爆炸是模型的第一性结论**，也是 S4/S5 的唯一动机。

**反例场景**：σ=0.95、a_m=0.2 GB/s ⇒ tax = 3.42×0.2 = 68% ⇒ 摊还不成立（墙体）。

### 4.4 吞吐界（throughput / CPU roof）

**命题 T**：可持续分配率 `a_eff` 满足

```
a_eff = a/(1 + a·λ_alloc)  ≤  min(a_peak, ρ/λ_alloc)
```

- `ρ/λ_alloc` 是**CPU 屋顶**（GC 单线程 STW，`ρ=1`【源码】）；
- `a_peak` 是 mutator 自身的分配/计算平台（【待标定】）；
- 屋顶交点 `λ* = ρ/a_peak` 即 Roofline 的 **ridge point**（§5.3）。

**判定（默认路径）**：**成立且远未饱和**。v1 口径 `a=0.53 GB/s` vs 屋顶 6.15 GB/s ⇒ 差 **11.6×**；
v2 口径 `a_m=0.173 GB/s` vs 屋顶 `1/0.630 = 1.59 GB/s` ⇒ 差 **9.2×**。
两种口径都指向同一结论：**bench/gc 这套语料上 extC 是 mutator 受限，GC 不是吞吐瓶颈**。

**反例场景**：只有 σ>0.9 或 b 被压到 <64（P 极紧）时，`ρ/λ_alloc` 才会降到 GB/s 以下并成为主约束；
此时“优化吞吐”才等价于“优化 GC 常数”。

### 4.5 四条界汇总

| 界 | 命题 | 默认路径判定 | 关键条件 | 反例 |
|---|---|---|---|---|
| **M** 内存 | `heap(t) ≤ M` | **条件成立**（σ ≤ σ_max 且 scale 不涨） | `b ≥ 128L/(M−L)` | `scale` 涨到 2^40；σ=0.85>b=256 的 σ_max；SHARDS=4 +220 MiB |
| **P** 停顿 | 单步 ≤ P_max | **热路径真 / 全入口假** | 只看 `step`/`maybeCollect` | 2344 µs 的 persist_nodes；collect/settle/regionFree |
| **K** 摊销 | `tax ≤ tax_max` | 成立（10.9%），σ→1 发散 | σ ≤ 0.9 量级 | σ=0.95 ⇒ 68% |
| **T** 吞吐 | `a_eff ≤ min(a_peak, ρ/λ)` | 成立，11.6× 余量 | 单线程 STW | σ>0.9 或 b<64 |

**这张表就是“优化方案”的问题定义**：M 与 P 是**硬约束、当前只有条件成立**，K/T 是**软约束、当前不是瓶颈**。
任何优化提案必须说明它改善的是**哪一面墙的可行域**（而不是哪个常数）。

## §5 Roofline 映射：把 GC 策略画成一张图

### 5.1 横轴为什么是 λ（每字节回收成本），而不是“每次分配的净垃圾”

GPU Roofline 的横轴是**算术强度**（flop/byte）——把“算多少”与“搬多少”放在同一坐标里。
GC 的对应物有两个候选：

| 候选横轴 | 定义 | 优点 | 缺点（本文不选它的原因） |
|---|---|---|---|
| 净垃圾强度 | 每次分配带来的净垃圾字节 `(1−σ)` | 直观 | 它只是 σ 的函数，**不含成本**；两条不同策略会落在同一 x 上而不可比 |
| **每字节回收成本 λ** | 处理一个分配字节需要多少 GC CPU [ns/B] | 与纵轴（可达吞吐 GB/s）**量纲互为倒数** ⇒ 屋顶是双曲线，`ridge` 有定义 | —（本文采用） |

取 λ 后，横轴越左 = GC 越便宜；纵轴 = 可持续分配吞吐。**策略选择 = 在 (λ, a) 平面上找点**。

### 5.2 三条约束线

```
(1) CPU 屋顶   a ≤ ρ/λ                     —— 双曲线（log-log 下斜率 −1）
(2) mutator 平台 a ≤ a_peak                 —— 水平线（纯算力/带宽上限）
(3) 两面墙     λ ≥ λ_mem(M)  且  λ ≤ λ_keep(P)  —— 两条竖线（见 5.3）
```

实际性能 `a_eff = min(ρ/λ, a_peak, 墙内)`。

**ridge point**：`λ* = ρ/a_peak`，即 CPU 屋顶与平台线的交点。
本图 `ρ=1`、`a_peak=10 GB/s`【待标定】⇒ `λ* = 0.10 ns/B`。

- `λ < λ*`（GC 便宜）：水平线主导 ⇒ **mutator 受限**，优化 GC 无收益；
- `λ > λ*`（GC 贵）：双曲线主导 ⇒ **GC 受限**，每降 1% λ 换 1% 吞吐。

当前 extC `λ=0.163 > λ*=0.10` 落在**双曲线一侧的起点**，但由于 a 只有 0.53 GB/s（远低于 6.15），
它是**“已经越过 ridge 但还没顶到屋顶”**的状态：屋顶给了 11.6× 余量，实际吞吐由 mutator 自身决定。

### 5.3 为什么两面墙在 (λ, a) 上是竖线（严格论证）

`λ(r) = c_t/r + c_s_eff + κ/(rL)` 对 r 单调**减**（r 越大、GC 越便宜）。于是：

| 面墙 | 物理约束 | 对 r 的约束 | 对 λ 的约束 |
|---|---|---|---|
| **内存墙** | `rL + 64L/b ≤ M` | `r ≤ r_max = (M − 64L/b)/L`（**上界**） | `λ ≥ λ(r_max)`（**下界**） |
| **keep-up / 停顿墙** | `b ≤ P_max/τ_t` 且 `b ≥ 64/(r−1)` | `r ≥ 1 + 64/b_max`（**下界**） | `λ ≤ λ(1+64/b_max)`（**上界**） |

⇒ **可行域是一段 λ 区间** `[λ_mem(M), λ_keep(P)]`，两端各由一条墙封住：

```
λ_mem(M)  = λ(r_max)，r_max = (M − 64L/b*)/L     ← 堆太小 = 只能频繁回收 = λ 太贵
λ_keep(P) = λ(1 + 64/b*)，b* = min(256, P_max/τ_t) ← 停顿太紧 = b 太小 = 追不上分配 = keep-up 崩
```

**数值（本语料）**：

| 情景 | λ_mem | λ_keep | 可行 λ 带宽 | 当前 0.163 在带内？ |
|---|---|---|---|---|
| M=2 MiB, P_max=4 µs | 0.125 | 0.185 | [0.125, 0.185]，宽 1.48× | ✅ 靠上沿（距 keep 墙 12%） |
| M=2 MiB, P_max=2 µs | 0.125 | 0.164 | [0.125, 0.164]，宽 1.31× | ⚠️ 几乎顶到上沿 |
| M=2 MiB, P_max=1 µs | 0.125 | 0.123 | **空集**（下界 > 上界） | ❌ **不可行** |
| M=8 MiB, P_max=4 µs | 0.060 | 0.185 | [0.060, 0.185]，宽 3.1× | ✅ 居中偏上 |

> **这就是“内存有界 + 停顿有界”的定量含义：两面墙在 λ 上从两侧挤压，可行带宽只有 1.3–1.5×，
> M 每翻 4× 才放宽到 3× 带宽。** 图 (a) 的绿色带即此区间（以 M=2 MiB / P_max=2 µs 画出）。

### 5.4 两套口径：v1（脚本图）与 v2（决策）

| 量 | v1（图 (a) 现画法） | v2（决策口径，本文推荐） |

## §6 策略族的形式化参数化与可行域

每条策略给一个三元组 `(c, P_req, M_req)`：`c` = 每分配字节的回收成本、`P_req` = 单步/契约停顿需求、
`M_req` = 达到有界所需的堆预算。**判定列只写模型结论；实测否定另附。**

| 策略 | 机制 | c [ns/B] | P_req | M_req | 可行域 | 判定与证据 |
|---|---|---|---|---|---|---|
| **S1** arena+bump | 静态作用域 + bump，**无 GC** | 0.0027（纯 bump）～0.1424（每块 malloc/free）【实测】 | 0（无 GC 停顿；`drop` 是 O(#block) 次 free） | = 词法寿命峰值；**无 drop 点或无界循环则无界** | 只在“生命周期可由词法作用域证明有界”时可独占；逃逸/长活对象必须下放 L2 | churn 32e6 次分配：C 手写 bump 6.9 ms / 13.0 MB vs extC arena 364.5 ms / 13.0 MB（`bench/gc/FINDINGS.md:16,22`）⇒ **S1 的常数完全取决于“每块 free + 每对象 malloc”是否被消除** |
| **S2** 区域 sweep（现默认） | L2 全套 | **0.1627**（每触发字节）/ 0.630（每回收字节）【实测】 | 单步 `b·τ_t`=3.69 µs【实测 3.7】；契约入口无界 | `M ≥ L(1+128/b)=1.5L`（b=256）【估算】 | σ ≤ b/(b+64)=0.800 且 M ≥ 1.5L | 本语料可行（σ=0.742）；**这是唯一“已验证在跑”的策略**；瓶颈是 §4.2 的契约入口 |
| **S3** 计数归零 | L3 打开 | 0.3–1.0【估算】；Ir 税收 **+100.9%~+455.2%**【实测】 | ~0.1 µs【估算】（归零级联，环则失效） | = 活集（无环）；**有环需回退 S2** | 无环 + 高 churn 才可能赢 | TAXMAP：清扫侧只占 0–22%，计数价 100–455%（`TAXMAP.md:373-376`）；单价须从 `ownSlab ≈33 Ir/次`（`:388`）降到 ~3 Ir（`:436`）才可能翻盘 ⇒ **当前判负** |
| **S4** 复制/分代 | 半空间复制或分代 | ≥ 2·c_t + 搬运【估算，未实现】 | 复制字节/带宽；需增量化为 P 界 | ≥ 2L（半空间） | **需要“地址静止 + 无句柄”被解除** | 当前设计：逃逸对象在静态 promotion level 的 arena 里直接分配、**地址从不移动**（§3.1 分层模型的直接结果）⇒ 复制需全量重写指针，**当前不可行**；分代按区域也否：WCC 不可分（250k **50/50 次 collect 活集是单分量**，`MARK-MODEL.md:203-214,223`） |

### 6.1 策略族的第三个维度：分片/并行度

Roofline 里 `ρ` 是回收并行度。extC 是单线程 STW（`ρ=1`【源码】），提高 ρ 的候选是“分片”与“分区”：

| 维度 | 实测/模型结论 | 证据 |
|---|---|---|
| 分片 `SHARDS=4` | digraph 1M：**+327.7 ms 墙钟、+220.2 MiB RSS**（“分片在这形状上没界”） | `bench/gc/DIGRAPH.md:303` |
| 切片（把一次清扫切成 k 片） | 每片开销 **1.5 ns/片**【实测】；`digraph` p50 67 707 槽 / k=256 ≈ 264 片 ⇒ 开销只占被切停顿的 0.5–0.7% | `tests/reclaim-perf/SWEEP-SLICE-RECON.md:13,75,85` |
| 分区（按 WCC 切活集） | **不可行**：活集是单分量（p50 100%），分量数最高 3 509 > `EXTC_RC_REG_MAX=512` | `MARK-MODEL.md:203-214` |
| 并行回收（多线程） | 无原子、无并发标记协议；引入即改数据模型 | §3 的 `[rt:*]` 段全部单线程 |

⇒ **`ρ` 不是可调参数，而是“要么保持 1，要么重写运行时”的开关。** 模型里它留在公式中，是为了
说明“为什么 S2 的 λ 不能再降”的下限（`ρ/λ` 已足够大，加 ρ 只有 11.6× 中很小一部分可拿）。

### 6.2 结论：先撞哪面墙

按 §4.5 的表，当前顺序是 **σ 墙（1.08×）> 契约入口停顿（2344 µs 级）> 摊销（10.9%）> 吞吐（11.6×）**。
所以策略排序不是“谁更快”，而是：

1. **保 S2**，把 `P_max` 的论证范围从 `[step]` 扩到 **所有入口**（否则 P 界不成立）；
2. **只在 σ > 0.8 的形状上**考虑 S5/S4（此时 λ_alloc 才是主导项）；
3. **S1 永远是基线**：任何 L2 策略的 c 必须与 S1 的 0.0027–0.1424 比，而不是与 0 比；
4. **S3 单用必负**（除非无环 + 单价降到 3 Ir），只能作为 S5 的一个组件。

## §7 最优触发策略：闭式解与敏感性

### 7.1 问题陈述

给定 `(M_max, P_max)` 与形状参数 `(L, a_m, σ 分布)`，选三件事：

- **触发点** `H_trig = r·L`（等价于触发比 r，即 `thr` 的设定）；
- **每步工作量** `b`（对象数/次 markAdvance，≙ 停顿）；
- **回收频率** `f`（由前两者与 a_m 决定）。

目标是 **min λ_alloc**（等价于 max 可持续 a），约束 `peak ≤ M_max` 且 `P99 ≤ P_max`。

### 7.2 闭式解（推导见附录 A.4）

```
b*  = min(MARK_BATCH_MAX, floor(P_max/τ_t))        ← 用满停顿预算（b 越大 λ 越低）
可行 ⇔ 128L/(M_max − L) ≤ b*                       ← 两面墙相容的必要充分条件
r*  = (M_max − 64L/b*)/L                            ← 用满内存预算
σ*  = 1/r*
H*  = r*·L = M_max − 64L/b*                          ← 触发点 = 给在飞漂移留恰好 64L/b*
f*  = a_m/((1−σ*)H*)                                 ← 轮频（keep-up 自动满足）
w*_mark = b* obj/step；w*_sweep = SWEEP_BUDGET = 8 words/step（源码硬编码，非自由参数）
```

**为什么 b 要用满**：`λ(r)` 对 r 单调减，而 `r_max = (M − 64L/b)/L` 对 b 单调增 ⇒ 更大的 b 同时**降低漂移**
并**抬高可用的 r**，代价只是 P。所以“把停顿预算花光”在这套模型里是**最优**的——除非 P 本身成为瓶颈（§7.4）。

### 7.3 数值解（本语料 L=0.742 MiB，τ_t=14.4 ns）

| P_max | M_max | b* | 可行? | r* | σ* | λ*(ns/B) | 屋顶 a GB/s | 预测 P |
|---|---|---|---|---|---|---|---|---|

**三个可直接用的推论**：

1. **P 收紧到 1 µs 在 M=2 MiB 时不可行**：内存需要 `b ≥ 128L/(M−L) = 75.5` ⇒ `P_min = 1.09 µs`。
   要做 1 µs，M 必须 ≥ 2.12 MiB（或把 L 压小）。
2. **M 从 2→8 MiB 把 λ 砍半**（0.125→0.060，2.07×），这是**最便宜的性能来源**（不改一行运行时）；
   但超过 `r_sat = c_t/c_s_eff = 4.4` 后 λ 只剩 `c_s_eff=0.041` 的地板 ⇒ **M 超过 ~4.4L 后收益急剧衰减**。
3. **P 从 4→2 µs 只付 6% 的 λ**（0.1248→0.1327），因为在 M=2 MiB 下 b 仍 ≥ b_min；
   但 P 再收到 1 µs 就**跳变到不可行**——这是**非光滑的悬崖**，不是渐变（图 (d) 的 Pareto 前沿在白点处折）。

### 7.4 σ 的非线性：为什么“平均”会骗人

模型里的 σ 用 p50 代入，但实测分布有**重尾**：

- `marked` 的 p50 = 9 723 对象、p99 = 53 509、**max = 56 578**（**5.8×**，`MARK-MODEL.md:59,68`）；
- `collect` 停顿 p50 = 129.8 µs、p99 = **1.27 ms**、max = 1.54 ms（**11.8×**，同表）；
- 相关性：停顿 ~`marked` 的 r = **0.987**（250k）/ 0.937（1M），与“扫的槽数”只有 0.78 ⇒ **尾巴来自活闭包，不是扫描面积**（`:63-69`）。

⇒ **P99 必须用“活闭包尾部”而不是“平均 b”来估**。在热路径上 `b` 封顶保护了单步（3.7 µs ✓），
但**契约入口**（§4.2）不受封顶保护，尾部的 11.8× 正好落在那里 —— 这解释了 2344 µs 那种事件。

模型修正项（可选）：把 `P99 ≈ ζ·b·τ_t`，`ζ ≈ 1.0`（热路径）；契约入口另加 `P_contract ≈ T_round(p99)`。

### 7.5 参数灵敏度（一阶）

| 动作 | Δλ（一阶） | 备注 |
|---|---|---|
| `M` ×2（在 r<r_sat 区） | `λ ∝ 1/r`，约 −25%~−35% | 最便宜；天花板 `c_s_eff` |
| `P_max` ×2（b 未封顶时） | 0（b 已 ≥ b_min 时完全不付） | 只有跨过 b_min 才付 |

## §9 怎么用这个模型做决策（10 条可操作准则）

**R1（先量 σ，别看 λ）**：任何形状先测 `L/H_trig`。`σ > 0.8` 的形状直接进入“必须换策略”分支；
`σ < 0.5` 的形状永远不要碰 GC（屋顶余量 > 10×）。判据来自 §4.1：σ_max=b/(b+64)。

**R2（M 是第一根杠杆，且收益有天花板）**：只要 `r < r_sat = c_t/c_s_eff = 4.4`，`M` ×2 约换 λ −30%；
超过 `r_sat` 后 λ 趋 `c_s_eff=0.041` 的地板，**再给内存就是浪费**。对应 `M_max ≈ 4.4·L`（本语料 ≈ 3.3 MiB）。

**R3（P 收紧是非光滑的）**：可行条件是 `P_max/τ_t ≥ 128L/(M_max−L)`。跨过这个点之前收紧 P 几乎免费
（§7.3：4→2 µs 只付 6%），跨过之后**直接不可行**（1 µs @ 2 MiB）。设计停顿时限时先算这个比值。

**R4（b 用满，别留余量）**：`b* = min(256, P_max/τ_t)`。b 越大，λ 越低且漂移越小；
“为了安全留 50% 停顿余量”在模型上是**纯损失**（把 r* 压低）。真正的安全来自 R5。

**R5（停顿界的论证必须覆盖所有入口）**：`step`/`maybeCollect` 被 `MARK_BATCH_MAX` 封顶（3.7 µs 实测 ✓）；
但 `collect`/`settle`/account 查询/`regionFree` **无界**（§4.2）。若对外承诺 `P99 ≤ P_max`，
必须同时给这些入口加预算，否则 P99 由 2344 µs 级事件决定。**这是当前模型最大的“条件成立”缺口。**

**R6（什么时候把计数放进对象头）**：只有三个条件同时成立才值得：
(a) 形状**有环**（否则 S1/S3 已够）、(b) `σ` 高到 `λ_alloc > 1 ns/B`（即 σ ≳ 0.85）、
(c) 单价能从 `ownSlab ≈ 33 Ir/次`（`TAXMAP.md:388`）降到 ~3 Ir（`:436`）。缺一条就是负收益（+100.9%~455.2% 实测）。

**R7（不要用分片换 ρ）**：分片在单分量形状上把 keep-up 打破，digraph 1M 实测 **+327.7 ms / +220.2 MiB**
（`DIGRAPH.md:303`）；切片（时间维切分）才便宜（1.5 ns/片，占 0.5–0.7%，`SWEEP-SLICE-RECON.md:13`）。

**R8（吞吐优化只有在 λ>λ*=0.1 ns/B 且 a≈a_peak 时才值）**：当前 λ=0.163 已过 ridge，但 a 只有 0.53，
离屋顶 11.6× ⇒ **优化 GC 常数对吞吐无感**。要提速先看 mutator（分配快路径/内联），不要先看 mark。

**R9（触发线的 floor 是隐藏杠杆）**：`floor=1 MiB` 在本语料里**主导**触发比（r_eff=1.349 而非 2.09）。
把 floor 提到 2 MiB ⇒ r_eff≈1.8、λ −25%，代价 `M_min` +0.45L。**改一个常量换 25% 的 GC 税**，
但会改变空闲内存与触发相位 ⇒ 必须过 gate（golden + 空闲语料）。

**R10（决策顺序）**：① 测 σ 与 L（R1）→ ② 定 M_max 并按 R2/R3 取 r*、b*（§7.2）→
③ 验证 P 覆盖所有入口（R5）→ ④ 只有在 σ≳0.85 时才评估 S5/S4（R6/R7）→ ⑤ 最后才做常数优化（R8）。

## 附录 A：推导

**A.1 keep-up 条件 `b ≥ 64σ/(1−σ)`**

一轮里新分配字节 = `(1−σ)H = (r−1)L`，新分配对象数 = `(r−1)L/s̄`。
每 `k=64` 次分配推进 `b` 个对象 ⇒ 一轮内 mark 能推进 `b·(r−1)L/(64·s̄)` 个对象。
要追平活集 `L/s̄` 个对象：

```
b·(r−1)L/(64 s̄) ≥ L/s̄  ⇒  b ≥ 64/(r−1) = 64σ/(1−σ)
```

等价 `σ ≤ b/(b+64) = σ_max`。

**A.2 `M_min = L(1+128/b)`**

内存界 `σ ≥ L/(M − 64L/b)`，keep-up 界 `σ ≤ b/(b+64)`。两区间相交 ⇔

```
L/(M − 64L/b) ≤ b/(b+64)
⇒ L(b+64) ≤ bM − 64L
⇒ bM ≥ Lb + 128L
⇒ M ≥ L(1 + 128/b)   ∎
```

**A.3 `λ_alloc`**

`T = c_t·σH + c_s_eff·H + κ`，`R = (1−σ)H` ⇒ `λ_alloc = (c_tσ + c_s_eff)/(1−σ) + κ/((1−σ)H)`。
第一项在 σ=0.742 时 = (0.180·0.742 + 0.0407)/0.2585 = **0.674 ns/B**，κ 项只会再往上加。
实测 λ_alloc = 0.630 ns/B，比公式**低 7%** ⇒ `c_t`/`F` 里有一项被高估（或 λ 的 p50 口径偏保守）。
注意符号方向：κ 不能解释这个偏差，它只会让模型更高 —— 详见 §11 #3。

**A.4 最优 b、r**

`r_max(b) = (M − 64L/b)/L` 对 b 单调增；`λ(r)` 对 r 单调减 ⇒ 复合函数对 b 单调减 ⇒ `b* = min(256, P_max/τ_t)`。
然后 `r* = r_max(b*)`。可行性来自 A.2：`M ≥ L(1+128/b*)`。∎

**A.5 双墙 λ 区间**

`λ_mem = λ(r_max(b*))`（下界，因为 r ≤ r_max ⇔ λ ≥ λ(r_max)）；
`λ_keep = λ(1+64/b_max)`（上界，因为 r ≥ 1+64/b_max ⇔ λ ≤ λ(...)）。
区间非空 ⇔ A.2 的 `M ≥ L(1+128/b*)`。∎
