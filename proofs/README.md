# extC 内存模型：健全性及其边界（机械化证明）

> 这份目录回答一个问题：**在什么假设下，"检查器接受的 extC 程序不会解引用已死存储"是可证的；
> 而每一条假设各自又不可省（去掉就有反例）？**
>
> 证明是机器检查的：Lean 4（`lean --version` = 4.34.1），三份文件、零 `sorry`、
> 零自定义 `axiom`；另有一份 Z3 小规模交叉复核（第二套工具、第二条推理路径）。
> 复核命令：`bash proofs/verify.sh`。

---

## 0. 一句话结论

> **区域档的健全性 = 四条假设的合取**：
> ① 记账是真实深度的**上界**；② 每个**活着的**区域要么属于当前激活、要么活过当前激活（**CC**）；
> ③ 同时活着的局部区域在**同一条嵌套链**上（**ChainOK**）；④ 释放**向下封闭**。
> 四条缺一条都有机器检查的反例轨迹；而这四条**恰好就是**池、任务、跨函数转手、
> 并发这四类扩展各自会破坏的那一条。

## 1. 形式化的是什么

### 1.1 静态几何：`Frame`（`ExtCRegion.lean` §1）

| 记号 | 含义 | 对应 extC |
|---|---|---|
| `outlives r s` | r 活得 ≥ s | 区域序（文档的 `⊒`） |
| `Local r` | r 属于**当前激活** | 本帧的栈帧 / 块 arena |
| `Ground r` | r **活过当前激活的全部** | 程序级、参数所指、调用者选的落点 |
| `depth r` | 记账深度，**越小活得越久** | `placeDepth` / `exprRefDepth` 的那个数 |

公理：`outlives` 是预序；`depth_mono`（活得久 ⇒ 深度不大）；`depth_ground`（Ground 记 0）；
`ground_outlives`（Ground 活得比任何局部区域久）。**只有四条**，每条都能在区域树上直接验。

### 1.2 动态状态与两条不变量（§2）

```
INV-I（Containment）  每个单元持有的指针，其目标区域活得 ≥ 该单元的区域
INV-L（LiveClosed）   活着的区域，其"祖先"也活着   ⇔  释放向下封闭
```
主引理 `World.safe_of_invariants`：**INV-I ∧ INV-L ⇒ 安全**（活单元里的指针都指向活单元）。
这就是"区域纪律"的全部内容 —— 安全不是靠检查器逐个语句保证的，而是靠这两条不变量在运行中被保持。

### 1.3 规则层语义与主定理（§3–§4）

```
Step.store : dr ≤ depth(目的地)  ∧  depth(目标) ≤ dr        -- 检查器接受 + INV-H
             ∧ 目的地活着且是局部  ∧ 目标活着
             ∧ CC(目标)  ∧ ChainOK                          -- 两条边界条件
Step.kill  : k 向下封闭                                      -- 第三条边界条件

Runs.safe : 初始满足 INV-I ∧ INV-L  ⇒  沿任意 Runs，每一步 Safe
```

`Runs.safe` **不依赖任何公理**（`#print axioms` 输出 `does not depend on any axioms`）。

**模型 ↔ 实现的三个接口**（写在 `ExtCRegion.lean` 顶部，避免被误读）：

* `dr` 是"**已记录深度**"的抽象；`depth(目标) ≤ dr`（INV-H）是**检查器的义务**，
  在模型里以前提出现 ⇒ 定理是"记账正确 ⇒ 检查正确"，不是"记账天然正确"。
* **目标活性是推出来的**，不是外加假设：`World.target_alive_of_read` 由"值取自活单元"+ 两条不变量
  推出（实现里检查器确实只比两个静态数，从不问"目标区域是否已释放"）。
* **`CC` 就是 `ARENA_HOME` 那一类记账的去处**：模型**没有**"深度 0 ⇒ 必属 Ground"这条断言；
  把调用者的块 arena 记成 0，正是 CC 失败的世界 —— 由 `necessity_CC` 覆盖（证明它一旦出现就不健全）。

单指针单元只是最小化：`linearization_all_targets` 把结论搬回**聚合值**（一个值里多个指针，
记的那个数必须是每一个目标深度的上界）—— 也就是检查器字段表 + `otherDepth` 真正要答的问题。

### 1.4 池：换代契约（`ExtCPool.lean`）

池是**另一套**存储（块可单独回收/搬家、槽可复用），区域公理对它无效。它只剩一根支柱：

```
GoodStep : 世代单调不减 ∧ 占用状态一变世代必须严格增长
handle_does_not_rebind : 世代不变 ⇒ 句柄仍指向签发时那个对象
```
这正是"要么读到当年那个，要么 trap"的全部理由，也就是 `INV-G` 的形式化。

### 1.5 记账的接口（`ExtCModel.lean` §A/§E）

定理必须量化"**每个分配站点选了哪只区域**"（`AllocPlan.region`）—— 否则证的是
一个编译器并不执行的规则；以及"**判定读到的那张表**"（`AbsWorld.fact`）与它的写点刷新。

## 2. 边界：逐条必要性

每一条都是**机器检查的轨迹**：初始满足两条不变量 → 检查器放行一步 → 最终世界不安全。

| # | 假设 | 去掉后的反例（Lean） | 它对应 extC 的什么 |
|---|---|---|---|
| ① | **INV-H**：记账 ≥ 真实深度 | `Undershoot.necessity_INVH` | `ARENA-SOUNDNESS` §4 的三处**覆盖式更新**、§5 反例 A–G；"记小 = 洞" |
| ② | **CC**：活着的区域 ∈ Local ∪ Ground | `ForeignRegion.necessity_CC` | 池**块**（`give`/`resize` 让它失效/搬家，与区域嵌套无关）、**挂起任务的地方**、并发线程 |
| ③ | **ChainOK**：同时活着的局部区域同链 | `chainOK_independent`（独立性） | 文档 `ARENA-FORMAL` §5.1/§6 记为"欠一个证明"的那一条 |
| ④ | **释放向下封闭** | `LooseKill.necessity_kill_closed` | **非 LIFO 释放区域**：任务 zone 被弹出而别的活任务仍指着它（P0-20 / 定案 99） |
| ⑤ | **单一权威**：运行时按检查器算的 α 分配 | `Model.necessity_single_authority` | 定案 68（检查器与 codegen 各算一遍）；`ARENA_HOME` 被当成深度 0 |
| ⑥ | **未知 ⇒ ⊤** | `Model.no_sound_finite_fallback` | INV-U；`placeDepth` 兜底答 `0`（0 的语义是"活得最久"） |
| ⑦ | **多路查询都必须是上界** | `Model.accept_sound_iff`、`either_query_must_be_upper` | INV-I（一个事实一个指称）；P0-1/P0-2/P0-16/P0-17 的"接缝" |
| ⑧ | **写点刷新** | `Model.stale_fact_breaks_invh` / `writeFact_preserves_invh` | INV-K（写点完整性）；出参 publication |
| ⑨ | **池换代契约** | `Pool.necessity_generation` | INV-G（槽粒度） |
| ⑩ | **世代不回绕** | `Pool.wrap_not_good` | 池的"毒化 / 拒绝 / 重建"阶梯 |
| ⑪ | **校验不只看世代** | `Pool.generation_only_check_unsound` / `validAt_rejects_dead` | "死池报 0 世代"与活池 0 世代撞上 ⇒ 必须同时查占用/存活/对象表模式 |

第 ⑥ 条尤其值得单独看：它证明**不存在"安全的有限兜底"** ——
任何固定的兜底深度 `c` 都有一个真实深度更大的值让检查漏过。
所以对"未识别"的唯一健全处置是**拒绝**（记 ⊤），而不是挑一个"看起来保守"的数。
这条一次覆盖了"兜底方向反了"那一整族（`placeDepth` 返 0、`needsHome` 早退等）。

第 ⑦ 条是个**当且仅当**：判定 `dr ≤ dest` 可靠 ⟺ `dr` 是真实深度的上界；
若判定可能读到两路查询，则**两路都**必须是上界（等价于它们的最小值仍是上界）。
这就是"同一个事实有多条查询路径"为什么会致命：只要有一路记小，`min` 就被拉下去。

## 3. 模型设计层面另外两条结论

**提升 / 降低不对称**（`ExtCModel.lean` §B）：

* `amplification_preserves`：把分配搬得更长寿**永远安全**，**不需要任何别名信息**；
* `strong_update_indistinguishable`：存在两个世界，在**分析可见的一切**（区域帧、活区域、
  地址→区域映射、记账表）上完全相同，却一个满足 INV-I、另一个不满足。
  ⇒ 只读记账表的判定**不可能**既健全又接受"把记账降低"这一操作。

这两条合起来给出一条设计结论：**模型是单向的**（analysis ⇒ semantics），
**误拒不是实现缺陷，而是这个抽象层的定理级后果** —— 要么保守，要么付别名分析的代价。

**放大引理的诚实边界**（`ExtCRegion.World.contains_retarget`）：
把一个对象搬到更长寿的区域，只有在它**没有出边**（或整组一起搬）时才保持 INV-I ——
搬长寿之后，它**自己持有的指针**也必须活得更久。文档里"命题 7.1：放大永远安全"的
证明只看"谁会持有它"，没看"它自己持有什么"。

## 3.5 精度：可证的部分与可算的部分

### 可证（[ExtCPrecision.lean](proofs/ExtCPrecision.lean)）

三条定理把"精度"钉死：

| 命题 | 陈述 | 含义 |
|---|---|---|
| `best_store_rule` | `(∀ t, t ≤ dr → t ≤ destD) ↔ dr ≤ destD` | 检查器那条判据**就是**该抽象的最大健全规则 ⇒ **规则层零松弛** |
| `store_reject_iff` | `(∃ t, t ≤ dr ∧ ¬ t ≤ destD) ↔ ¬ (dr ≤ destD)` | 拒绝 ⟺ 存在一个不安全的一致情形（不多不少） |
| `any_sound_rule_le_maxSound` / `loss_is_forced` | 抽象点里混进不安全具体化 ⇒ **任何**健全规则都必须拒绝 | 损失不可能来自"规则写保守了"，**只能来自"抽象太粗"** |
| `store_granular_loss` | 同一刀存储：后续覆盖 ⇒ 安全；后续释放 ⇒ 不安全 | 逐存储纪律**必然**误拒"坏指针先被覆盖"那一族 |

### 可算（[precision.py](proofs/precision.py)，穷举）

| 量 | 数 |
|---|---|
| 程序空间 | 单元数 2–3、区域链 0⊃1⊃2、操作 `P a b`（带检查的一刀）与 `ite`；作用域按真实语义由内向外结束 |
| 总程序 / 具体安全 | 296,910 / 136,758 |
| **健全性缺口**（放行 ∧ 不安全） | **0 / 296,910** ✅ |
| **精度**（安全中被接受） | 129,426 / 136,758 = **94.64%** |
| 精度损失（拒绝 ∧ 安全） | 7,332（占安全程序 5.36%） |
| 其中"同一检查轨迹下存在不安全孪生" | 7,332 / 7,332 = 100% |
| 无分支片段误拒 | 138 例，**138/138 = 100%** 都是"坏指针在被指区域死之前被同单元覆盖" |

读法：**规则层是精确最优的（可证）；剩下的 5.36% 里，无分支的那一族（"坏指针先被覆盖"）
是可以通过细化抽象去掉的，其余由 §2 保证是抽象层被迫的。**

## 3.6 引入（分支）路径敏感之后

关键是把"路径敏感"拆成作用在两个不同地方——结论**相反**：

| 作用在哪 | 结论 | 命题 |
|---|---|---|
| **检查**（store 规则读的那个事实） | **判定完全不变**（既不更健全也不更宽） | `joinAccepts_iff_pathAccepts`：合流后通过 ⟺ 每条路径都通过（may-合流 = max，检查对事实单调） |
| **分配区域的选择**（α） | **接受集严格变大 + 内存严格变小** | `path_sensitivity_accepts_more`（逐路径可行 ∧ 合流不可行）；`path_choice_never_shallower` / `path_choice_strictly_deeper` |
| **新护栏** | 条件必须与路径一致 | `unstable_condition_unsound`：条件被改写或有副作用 ⇒ 挑中的区域活不过目的地 ⇒ 悬垂 |

**健全性的义务因此换了形状**：从"一只区域满足所有路径"变成
"**每条路径各自满足 + 条件在分配点可重放（纯、同作用域、同值）**"。

实测（[pathsensitivity.py](proofs/pathsensitivity.py)，47,304 个程序，检查会读到合流后的记账）：

| 量 | 合流版 | 路径版 |
|---|---|---|
| 判定不一致的程序数 | — | **0** ✅ |
| 健全性缺口 | 0 | 0 |
| 精度（安全中被接受） | 98.46% | 98.46% |

⇒ 路径敏感的收益**不在健全性、也不在检查的精度**，而在**分配区域的自由度**：
它同时买到接受集与内存，代价是三条新护栏。

## 3.7 距离「无显式标注 + 静态分配控制」类上限的精度距离

**上限的定义**（这是关键，含糊了数字就没意义）：

> `Opt(P)` ≝ **存在**某个静态区域分配 α，使 P 的所有执行都安全
> —— 这一类允许"完美推断"，所以是任何健全分析都超不过的天花板。

三层对比（`Inferred ⊆ Best ⊆ Opt`，脚本断言）：

| 层 | 含义 |
|---|---|
| `Opt(P)` | ∃ 允许落点集内的安全分配 |
| `Best(P)` | ∃ 分配使**模型判据**放行（神谕分配）⇒ 与 Opt 的差 = **规则层距离** |
| `Inferred(P)` | 模型用**自己的推断**（从最深处出发只往下调 = 约束系统的最大解）⇒ 与 Best 的差 = **推断层距离** |

**实测**（[precision_gap.py](proofs/precision_gap.py)，1,234,250 个程序实例，含"栈局部区域定死 / `new` 可提升"的真实结构）：

| 量 | 数 | 占上限 |
|---|---|---|
| `Opt` | 870,642 | — |
| `Best` = `Inferred` | 855,370 | — |
| **① 规则层距离** | 15,272 | **1.75%** |
| **② 推断层距离** | 0 | **0.00%** |
| **总距离** | 15,272 | **1.75%** |
| **⇒ 相对上限的精度** | | **98.25%** |

* **推断层恒为 0 是可证的**（[ExtCGap.lean](proofs/ExtCGap.lean)）：约束都是 `x ≤ y` 形状
  ⇒ 解集对逐点取 max 封闭（`max_of_sols`）；允许落点是区间 ⇒ 盒内解集也封闭（`box_sol_closed`）
  ⇒ 逐点最大解存在 ⇒ **最大解放行 ⟺ 存在放行解**。
* **规则层那 1.75% 全部是同一族**：`store_granular_loss` 的
  「坏指针在被指区域死之前就被覆盖」——判据是**逐存储**的，安全是**逐状态**的。
  这 1.75% 是**可去掉的**（细化抽象），不是被迫损失。

> ⚠️ 范围：这是**过程内、事实精确**的 arena 片段上的距离。
> 跨函数的效果摘要（`Addr` 当成非空那一族）**不在这个模型里**，
> 文档记录的那些误拒（`#34`、规则 ④ 过强、"造完返回容器"）都住在那里 —— 尚未测量。

## 3.8 **内存**精度差距：阈值定律与全类别

上面 §3.7 算的是**接受集**精度。内存精度是另一回事——arena 只能整块释放，
所以"每轮分配、却留在长命区域"会线性累积。

**阈值定律**（[ExtCMemGap.lean](proofs/ExtCMemGap.lean) 两侧都证了）：

```
内存差距 ≈ n / (|E| + 1)        n = 循环轮数，E = 真正逃逸的轮次集合
⇒ 差距超常数 ⟺ |E| = o(n)
```

`gap_unbounded_of_rare`：|E| 有界 ⇒ 差距可任意大（不是 O(1)）。
`gap_bounded_of_frequent`：|E| ≥ n/2 ⇒ 差距 ≤ 2 倍。

**全类别**（[memory_gap.py](proofs/memory_gap.py)，n = 64…4096，对数-对数拟合定阶）：

| 逃逸集合 E | vs 逐路径最优（类内上限） | vs 逐对象理想（覆盖式使用） |
|---|---|---|
| `E = ∅`（从不逃逸） | Θ(1) | Θ(1) |
| `E = [n]`（每轮逃逸） | Θ(1) | **Θ(n)** ← 覆盖式使用 |
| `|E| = n/2` | Θ(1) | **Θ(n)** ← 覆盖式使用 |
| `|E| = √n` | **Θ(√n)** | Θ(n) |
| `|E| = log n` | **Θ(n/log n)** | Θ(n) |
| `|E| = 1`（首轮或末轮） | **Θ(n)** | Θ(n) |

⇒ 有**两个互相独立**的差距来源：

1. **对类内上限**：差距超常数 ⟺ 逃逸**可能发生**（E ≠ ∅）但次数 **o(n)**。
   两端的 Θ(1)（从不逃逸 / 经常逃逸）都不浪费。**可由路径敏感消除。**
2. **对逐对象理想**：只要长命区域里有"**可达但已死**"的对象就超常数 ——
   典型是**覆盖式使用**（`head = obj` 每轮覆盖），此时**与逃逸频率无关**，
   恒为 Θ(n)。这一条**路径敏感消不掉**，需要逐对象回收（池/GC）。

> ⚠️ 比例：脚本枚举的 7 种逃逸族里，对类内上限有 4/7 超常数、对逐对象理想有 6/7。
> 但这是**枚举选择的分布**，不是语言的固有概率；真实分布取决于逃逸频率的分布，
> 而"可能但罕见逃逸"（守卫、错误路径、缓存、开关）在真实程序里很常见 —— 那是经验判断，未测量。

## 4. 不是定理、而是**前提**的部分

主定理的结论是 **S1（时间安全）**。完整的内存安全还需要另外三个维度，

| 维度 | 内容 | 本证明是否覆盖 |
|---|---|---|
| **S1 时间** | 引用的目标存储仍然活着 | ✅ 本证明 |
| **S2 空间** | 地址与访问范围在界内 | ❌ 属于运行期检查/trap 的义务（O6） |
| **S3 类型与布局** | 无类型混淆、跨界布局一致 | ❌ 属于"派发键决定布局"（O5）与 `@frozen` 契约 |
| **S4 初始化** | 读到的字节是确定值 | ❌ 属于零初始化策略 |

顶层声明的形状因此必须写成（每一项都是**显式前提**，不是被吞掉的公理）：

```
接受(P) ∧ 无 `!` ∧ 无 `@unchecked` ∧ 所有 extern!/fn 签名诚实
        ∧ 无数据竞争 ∧ 翻译正确（⟦P⟧ 保语义）∧ 编译器资源前提成立
   ⇒  P 的每一步要么保持 S1..S4，要么走 trap 转移
```

其中"S1 之外的三项"、"签名诚实（TCB）"、"翻译正确（编译器正确性）"、
"并发（`parallel::run` 的分块不重叠）"都必须各自成为一条**独立义务**；
本目录只证明了 S1 那一条，以及它的边界。

## 5. 与现有文档的差异（机械化过程中发现的修正）

| # | 文档说的 | 实际成立的形式 |
|---|---|---|
| **C1** | `ARENA-FORMAL.md` §2.2 引理 1 写作 `H ⊒ ρ_p` | 方向应反过来：**被存对象的区域 ⊒ 容器区域**（同文 §3.2 的 C1 写对了）。方向写反会让证明链断开 |
| **C2** | 定理 2："解一定存在 ⇒ 不需要注解" | 只有**下界（freshness）片段**保证有解；加上地址流的上界约束后系统**可能无解**（`sneaky` 正是这种）。"不需要用户注解"这个结论仍然成立，但理由要换成"最小解可算 / 无解可报" |
| **C3** | §5.1 把深度线性化记为"欠一个证明" | 它是一条**独立的假设**（`ChainOK`），既不能被其它公理推出（`chainOK_independent`），也不是近似 —— 在"同一激活、同时活着"的范围内它是精确的 |
| **C4** | 命题 7.1："放大区域永远安全" | 对**有出边的对象**不成立；正确形式是"没有出边，或整组一起搬"（`contains_retarget`） |
| **C5** | `CONCURRENCY.md` §2.2/§2.3："协程/任务不需要新机制" | 与形式化冲突：**挂起的任务**会让两个区域同时活着且不可比 ⇒ `ChainOK` 失效。定案 99 的"能逃出任务的引用一律编译错误"因此不是实现选择，而是**必需的新义务** |

## 6. 怎么复核

```bash
bash proofs/verify.sh        # 1) 编 Lean  2) 扫 sorry  3) 查公理依赖  4) Z3 交叉复核
```

* Lean 安装（免 root）：`curl -sSfL https://elan.lean-lang.org/elan-init.sh | sh -s -- -y`
* Z3（可选）：`pip install z3-solver`，或把 wheel 解包后 `PYTHONPATH=<目录>`。
* `#print axioms` 的输出应当只有 `propext` / `Quot.sound` 这类 Lean 核心公理；
  出现 `sorryAx` 即说明证明没写完（脚本会判红）。

## 8. 这套证明**没有**做什么（逐条列清，避免被当成已证）

* **记账（INV-H）是前提，不是结论。** 模型把"这个值有多深"`dr` 当作**自由参数**并假设
  `depth(目标) ≤ dr`；定理说的是"**记账正确 ⇒ 检查正确**"。记账本身为什么正确，
  要由（显式的）分析义务给出：上界性、单调性、载体穿透、写点完整性、单一指称 ——
  其中最后两条本目录给了定理（§2 的 ⑦⑧），前三条是**待证的实现义务**。
* **不是"某一份 C 实现遵守这些规则"。** 模型是规则层的；把实现对齐到模型，
  需要额外的 simulation 引理（每个查询函数是模型 `fact` 的上界），那属于审计，不属于模型设计。
* **L1（语法侧）没有机械化。** `ChainOK` 只是线性化的**语义半边**；
  另一半是 ARENA-FORMAL §6.2 的 L1 ——"可命名的绑定只出现在祖先链上"，
  它是**语法**性质，本模型里没有语法与作用域，所以没有覆盖。两半合起来才是那笔欠账。
* **池档只覆盖句柄身份。** `GoodStep` 是 INV-G 的槽粒度充分版；
  **INV-A（块不搬家/只追加）在本模型里无法陈述**（那需要块级概念），
  **INV-V（视图不进池，因为裸 `slice` 没有世代）也完全没有覆盖**。
  含 `compact` 的重编号、以及"池仍活着 + 对象表"这两个前提，都还在模型之外。
* **目标活性不再是外加假设**（`World.target_alive_of_read`）：它由前状态的两条不变量推出。
  于是 `Step.store` 的前提里只剩 **CC、ChainOK、INV-H** 三条不是检查器当场能查的。
* **`LiveClosed` 是理想化下界。** 实现比它更保守（同块/更深的方向还会被调用点那条规则挡），
  模型只要求"释放必须连子树一起放"，不要求更强的东西。
* 它只覆盖 **S1**；S2/S3/S4 与并发、FFI、编译器正确性都是**独立义务**（§4）。
* 它**不证完备**，而且第 3 节证明了在这个抽象层里完备性**做不到**。
