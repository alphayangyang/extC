## 2. 逐条提取

### 定案 59（只有尾部）· 扩容因子 = 倍增
- **出处**：`docs/DECISIONS.md:1801–1831`（标题 `:1769`，单元外）。
- **一句话**：在"arena 没有 `free`"的模型下，最坏累计分配比 `R = r²/(r−1)` 的下确界是 **4**，**倍增**正好达到 ⇒ `varArray<T>` 保持倍增；分块（chunked）严格更优但留 v2（PLAN #29）；运行时原地扩（`realloc` 式，bump 分配器可零拷贝）**现在不选**（PLAN #30）。
- **状态**：已定案（倍增）；**待定**（chunked，PLAN #29）；**已定案不选**（运行时自适应，PLAN #30）。
- **约束了什么**：扩容策略、`varArray` 的引用失效语义（引用 MANUAL §7.9）、以及后续 `#31`/定案 61 的关系。
- **主题**：主 T1（次 T6）。
- **备注**：PLAN #29 的状态与本条冲突，见 §4-6。

### 定案 60 · 连续性是一等公民 —— chunked 如果做，是新类型，不是替代品（2026-09-21，主人拍板）
- **出处**：`docs/DECISIONS.md:1834–1853`。
- **一句话**：`varArray<T>` **永远保持连续**（它是 `vector` 对标物，4n 累计分配是"买到连续性"的价钱）；chunked 若落地是**另一个类型**（deque/大数组增长），两者共存；关联动作是补 `asSlice()`/`asMutSlice()`，但**先修 `#31`**。
- **状态**：已定案。
- **约束了什么**：容器类型划分（连续 vs 分块）、`slice<T>` 作为公共接口的位置、以及 `asSlice` 的上线顺序依赖。
- **主题**：主 T1（次 T2/T6）。
- **备注**：`#31` 已修（PLAN §0.6），`asSlice`/`asMutSlice` 已在库中（`stdlib/prelude.extc:219,240`）；PLAN #29 后来把"分块化"整格标作废（§4-6）。

### 定案 61 · 修 PLAN #31 用「甲′」（2026-09-21）
- **出处**：`docs/DECISIONS.md:1856–1888`。
- **一句话**：带 `mut ref` 实参**且被调者会分配**的调用 ⇒ 把实参那个绑定的有效深度抬到 ≥ 这一刀的**家深度**（`Sym.refDepth = max(refDepth, homeDepth)`），此后现成的逃逸检查会挡住"让它逃出去"；配套**惰性 `funcAllocates`**（`FuncDef.allocState` + 环保护，拿不准当"会"）与**指路的报错文案**。
- **状态**：已定案（已落地）；**自认缺口**：#34 保守假阳性（容量够的容器其视图也返回不了）。
- **约束了什么**：容器/出参的逃逸判定必须把"被调者往里塞过东西"记回容器；摘要查询必须惰性且保守。
- **主题**：主 T1。
- **备注**：原文"丙（owner depth）不 sound"的推导在 `ARENA.md §9`；PLAN 把 #33/#34 都记为"已随摘要消失"。

### 定案 62 · 让 checker 真的用定理（效果摘要 + E 分析 + 惰性闭包）（2026-09-21）
- **出处**：`docs/DECISIONS.md:1892–1907`。
- **一句话**：落地 `PLAN-REGION.md` 档 1 = 每个函数发布 **`Addr`/`Cont`/`Home` 效果摘要** + **E 分析**（哪些局部会被搬出本函数）+ **惰性传递闭包**（memo + 环保护 + `effUnknown`）；**只有"摘要完整"才允许跳过规则 ④**（不完整时"Addr 全空"是假的 ⇒ 收窄即放行悬垂）；分类器必须区分"指针形参本身（地址流）"与"从容器读出的指针（内容流）"。

### 定案 63 · 块级逃逸提升：`new` 存到更外层 ⇒ 提升 arena，不拒绝（2026-09-22，主人拍板）
- **出处**：`docs/DECISIONS.md:1911–1987`（落地记录 `:1952–1987`）。
- **一句话**：`new` 用的 arena 从"当前块"改成 **`arenaLevel = min(当前块深度, 所有目的地 place 的深度)`**（赋值 / 结构体字段 / `return` / 实参四条边回填），只往深处存则行为完全不变；返回值那条出口已有 `needsHome`，这是把它下沉一层。
- **状态**：已定案（已落地）；**自认缺口（⑤）**：`alloc<T>(n)` 不参与提升（原语行为保持原样）。
- **约束了什么**：所有 `new` 的落点、`Expr.arenaLevel`、`promoteInto`/`noteOrigin`/跳数上限、以及"最坏 = 函数级自动清理的堆"这一代价。
- **主题**：主 T1（次 T5：目的地取 min）。
- **备注**：三个坑：`placeDepth` 答错了问题 ⇒ 新增 `storeLayer`；有家函数里层数不可信 ⇒ codegen 以 `hasHome` 为准（后被定案 68 收编）；来路链会断 ⇒ 压平根 + 跳数上限。

### 定案 65 · `@overwrite`：复用一块存储（2026-09-22，主人拍板）
- **出处**：`docs/DECISIONS.md:2022–2131`（一 `:2024`、二 `:2041`、三 `:2063`、四 `:2081`、五 `:2097`、五′ `:2107`、六 `:2118`、七 `:2127`）。

### 定案 82 · 运算符重载：就是「方法名写成运算符」+ 实例化时检查（2026-09-24，主人拍板四条）
- **出处**：`docs/DECISIONS.md:3183–3311`（落地 `:3226–3271`；补记 `<<`/`>>` 与按右操作数精确匹配 `:3273–3311`）。
- **一句话**：可重载集合 = 比较 `== != < <= > >=` + 算术 `+ - * / %`（补记加 `<< >>`）；**签名形状固定、编译器按形状认**（`fn ==(self: ref T, other: ref T) -> bool`，与定案 79 认 `close`、prelude 认 `data`+`len` 同一招）；**内建类型上的运算符不许用户改**；**不做隐式转换**（重载只看精确类型）；泛型体里**定义时放行、实例化时检查**（诊断点名实例），把已为 `==` 建好的那套（时机 + 诊断 + 文案）推广到 `<`/`!=`/… 与普通协议方法。
- **状态**：已定案 + 落地；**自认边界（主人要驳就驳）**：① 不做派生（`!=` 由 `==` 取反**保留**，`>` **不**由 `<` 换来）② 运算数类型必须精确（补记**放宽**为"按**右操作数**的精确类型匹配"：一个运算符名可在一个类型上出现多次，比较/算术同理）；**方法重名唯一例外**，边界写在定义点（同一类型同一右操作数定义两次 ⇒ `two \`*\` for \`vec2\``）。
- **约束了什么**：**C 名字发射契约**：`cSymName` 补齐 `<`→`lt` · `<=`→`le` · `>`→`gt` · `>=`→`ge` · `+`→`add` · `-`→`sub` · `*`→`mul` · `/`→`div` · `%`→`rem` · `<<`→`shl` · `>>`→`shr`（**一个运算符字符都不许漏进 C 标识符**）；后缀规则 `opOverloadSuffix`：只有一个实现 ⇒ 不加后缀，两个以上才加**右操作数类型**后缀，**定义点与调用点共用同一个函数**；**模板只有一个节点、多个实例** ⇒ 延迟检查里**只标 used、不动节点**（#64：`func` 存进模板会让别的实例调到错的方法）。
- **主题**：主 T2（次 T9 实例化检查、T10 协议形状、T5 求值一次、T6 发射）。
- **备注**：顺手修掉了 `#58`（`if (!ec->owner) goto done;` 跳过自由函数那一半 ⇒ 泛型与具体类型两套判据）。

### 定案 97 · 新绑定路径必须复用 `declare` 的收窄契约（2026-09-29，主人「分析那里，为什么不能够复用已有的框架？」）
