# 手册契约提取（面向用户的语义承诺）

> **单元**：`docs/manual/` 全部 `.md`（31 个文件、4317 行；`html/` 是生成副本，不计）。
> **用途**：为"审计后的设计裁定"提供**用户可见语义**基线 —— 设计裁定必须与手册口径一致，或明确写出"手册要改哪一句"。
> **配套材料**：`docs/reviews/COMPILER-AUDIT-2026-09-30.md`（下称**报告**）＋ `.audit/findings-index.tsv`（173 条，编号 P0-x / P1-x / P2 / P3）。
> **口径**：每条给「陈述 ｜ 出处（文件:行）｜ 性质 ｜ 与审计发现的冲突」。
> **性质二分**：
> - **承诺** = 手册以"是 / 会 / 必须 / 语义 / 永不"的口气对用户行为做的保证（含"已知限制"里明确说"不会崩"的那类）。
> - **现状说明** = 手册自称"今天实现了多少 / 实测 / 进行中 / 还没实现 / 会滞后"的段落（`01-safety` 整章就是"承诺 × 现状"双栏，其中标"实测状态"的按现状说明读）。
> - **承诺+现状** = 一句里既有保证又有进度标注（最典型的是 `01-safety:40`）。
> **复核**：带「实测」的条目由本单元 2026-09-30 用 `build/extc`（commit 时点构建）当场跑过；其余引报告条目编号。
> 报告条目在正文引用格式：`P0-18 (codegen.c:1379)`。
