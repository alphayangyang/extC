## A. 开头「需要主人拍板」区（第 11–75 行）

### N01 · 引用语义 = 形状 3 + `mut ref`
- **出处**：`docs/DECISIONS.md:13-27`（§① 已拍板，2026-09-18）
- **一句话**：值位置自动解引用（读 `p` 得 `T`）、`p = v` 写进所指处、可见性由类型承担（`ref T` 只读 / `mut ref T` 可变）。
- **状态**：已定案（2026-09-18 主人拍板）；其中「放弃换指向」一条**被 D38/⑬ 取代**。
- **约束**：`ref T` 只读、`mut ref T` 可写，不再靠标点标记；引用字段的初始化不算换指向（`slice<T>::data: ref T` 依赖此条）。
- **主题**：T1、T6
- **备注**：同一表第 23 行「换指向：放弃」后来被 §⑬ 推翻（M5）。

### N02 · 待定：整数的算术语义（溢出 / 除零 / 移位）
- **出处**：`docs/DECISIONS.md:29-41`（§① 待定）
- **一句话**：有符号溢出建议**绕回**（靠 `-fwrapv`）、除零建议 **trap 带位置**、移位 ≥ 位宽建议**按位宽取模**（当时都还没定）。
- **状态**：**部分已定**——除零 / `INT_MIN / -1` / 移位超宽在 §㉒（第 533–550 行）改成 **trap 带位置**；**有符号溢出至今只靠 `-fwrapv`**，文档没有一句"正式定案"（T-01）。
- **约束**：算术 UB 不得继承自 C；驱动必须带 `-fwrapv`（代码：`src/main.c:608,635`）。
- **主题**：T4

### N03 · 待定：`let` 的「浅」要不要靠「可变性进类型」收口
- **出处**：`docs/DECISIONS.md:43-75`（§① 待定）
- **一句话**：`let` 只挡直接写入，拷进 `var` / 传参 / `self: ref T` 三条路还能写；要不要加 Rust 式 `&`/`&mut`（改每个签名）当时请主人拍。
- **状态**：**已被后续决策取代**——`let` 侧改用 N45（㊶㊷㊳ 三条 + 两条正交轴）收口，**没有**加 `&`/`&mut` 关键字。
- **约束**：可写性只看类型、绑定只决定能否换绑（N45）；短期不加只读/可变引用两种标记。
- **主题**：T1、T2

- **出处**：`docs/DECISIONS.md:1542-1571`
- **一句话**：`e?` 求值一次 + 判 tag + return；`e ?? d` 可能没有 ⇒ 用兜底（C 三元）；`e!` "我签字"直接给（`e.u.some._0`，对 `?ref` 一个字都不生成）。规则：`??` 左边必须是 option/result/`?ref T`；`??` 左边必须**没有副作用**（保守语法检查：树里出现调用就不许 ⇒ 报错教你拆行，同时是"不需要前缀机制"的担保）；`??` 只算一边；`!` 只对 option/result/`?ref T` 有意义（对非空 `ref` 签字也报错）；`!` 是"错了算我的"不是宽松检查（真没有值 ⇒ UB；prelude 不给 `unwrap`）。深度/借用：`p!` 跟着主体的被指深度走；`a ?? b` 取两边较深、任一边借来就算借来。
