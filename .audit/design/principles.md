## 1. 上位原则（原则性承诺）

- **P-01 · P：凡是编译期能证明的，运行时不留痕迹。这是唯一的原则，其余都是它的推论或边界。** — 出处：SPEC.md:29,147-149；DESIGN.md:30-38,846 — 硬性要求：不得引入"用户看不见、也无法从源码推断"的机制（GC、异常展开、vtable、运行时类型标签、隐藏分配、隐藏全局态）；判决任何"要不要加运行时机制"的方案，默认答案是**否**，除非它只用于"证明不了"的部分且被 P′ 显式化。 — 可能违反：**[实测]** 常量下标仍生成检查 `a.data[extc_checkedIndex((int64_t)(0), 4, …)]`（`src/codegen.c:2498`，产物见 /tmp/p_idx.c:129）⇒ DESIGN.md:660「可证明在范围内 ⇒ 不生成任何检查，P 完美达成」未达成；范围类型在编译器里根本不存在（`grep TY_RANGE src/*.h` 无命中）；[审计] checktop-1 `src/check_top.c:6024`（home arena 深度用 0 当"未设置"）、codegen-2 `src/codegen.c:3642`（块层数少算 ⇒ 隐藏的 arena 账与检查器不一致，破坏 SPEC.md:339-342 的"接缝"）、ast `src/ast.h:824`（线程上下文隐含）、codegen-1 `src/codegen.c:630`（泛型方法 C 名按调用者上下文生成 ⇒ 隐藏的分派差异）。
- **P-02 · P 的界线：禁的是"隐藏的机制"，不是"数据拷贝"。** — 出处：DESIGN.md:40-47,55-58；SPEC.md:161 — 硬性要求：判据是"这件事是不是一个用户看不见、且无法从源码推断的机制"；值语义拷贝、默认零初始化、memset 都不算违反；只有能证明"马上会被完全覆盖"时才允许把 memset 消掉（那正是 P 在起作用）。 — 可能违反：把"arena/TLS arena/池"当例外时要有边界：**[实测]** `extc_tls_arena` 是运行期选择分配落点的隐藏上下文（`src/check_expr.c:108,149`），[审计] checkexpr-1 `src/check_expr.c:149` 在 worker 链上被普通调用时解引用 NULL ⇒ 隐藏上下文为空时行为不可推断。
- **P-03 · P′：不能证明的，语法上必须看得见（P 的逆否命题，与 P 等价）。** — 出处：SPEC.md:163-172；DESIGN.md:62-66 — 硬性要求：可能失败处类型可见（`result`/`option`）；越界等运行时失败必须"失败得响亮"；危险必须能从源码读出来；诊断必须给出精确 span。 — 可能违反：[审计] checkexpr-2 `src/check_expr.c:1684`（`p[i]` 对 `?ref [N]T` 直接解引用 null，零诊断）、checkexpr-1 `src/check_expr.c:1376`（`<` 左边是 ref 时静默生成指针比较）、checktop-3 `src/check_top.c:4865`（`fn` 字段静默零值 ⇒ 空函数指针）。
- **P-04 · `!`：我签字——它是唯一的逃生舱标记，而且必须可数、稀缺（一个仓库应当个位数）。** — 出处：SPEC.md:174-183；DESIGN.md:68-82 — 硬性要求：所有"编译器证不了、只能人担保"的地方语法上带 `!`；`!` 的处数可审计；`!` 一旦长出几百个就失去意义。 — 可能违反：**[实测]** `grep -rn 'extern!' stdlib --include=*.extc` 命中 91 行（非注释行约 75 处），远超"个位数"；**[实测]** 文档给的审计命令 `grep -c '!' src/*.c`（SPEC.md:180）数的是 `!=`（`src/codegen.c` 命中 343 行），**该指标今天不可用于它声称的用途**；[文本] "唯一"在三份文档里指三样东西（SPEC.md:177 `!` / DESIGN.md:737 `extern` / WHY-EXTC.md:64 三种签字方式）⇒ 指标定义需先统一。
- **P-05 · P″：没有手动分配，就没有手动释放——自动回收的释放时机必须是编译期已知的 ⇒ 释放只能由词法作用域触发。** — 出处：SPEC.md:185-188；DESIGN.md:84-90 — 硬性要求：用户永不写 `malloc`/`free`/`close`；释放点只能是词法作用域（块/帧）出口；任何"由运行期决定何时释放"的设计（GC、引用计数）一律出局。 — 可能违反：[审计] coro P0 `src/coroutine.c:84`（任务结束按 LIFO 弹"任务的地方"，把仍存活的任务 zone 一起弹掉 ⇒ ASan UAF）、codegen-2 P0 `src/codegen.c:3642`（域块未计入 `blkMaxLevel` ⇒ `__extc_a[2]` 越界写）、checktop-1 P0 `src/check_top.c:6024`（实参寿命算错 ⇒ 传入比目标短的 arena）——三者都是"释放时机/层数算错"，直接打在 P″ 上。
- **P-06 · arena = 词法作用域；唯一分配规则（资源属于某个 arena，arena 结束一起死）＋唯一引用规则（`depth(r) ≥ depth(v)`，引用不能活得比被指对象长）。** — 出处：SPEC.md:331,354-362,354；DESIGN.md:98-113；WHY-EXTC.md:23-36 — 硬性要求：深度是纯词法属性（参数 0、函数体 1、每进一层块 +1），只比两个整数；方向不可反；正确性只由词法嵌套担保，不依赖流分析；调用返回引用的深度 = `max(所有实参)`（精确上界）。 — 可能违反：**这是被违反最多的一条**——[审计] escape-1 `src/check_escape.c:649`（借用经载体洗白存进全局）、`src/check_escape.c:147`（root 不是绑定时 placeDepth 答 0="永生"）、`src/check_escape.c:726`（按参数**名字**比较 ⇒ 遮蔽即认错）、escape-2 `src/check_escape.c:1447`（`needsHome` 早退放行全局存借用）、checktop-2 `src/check_top.c:2022`（EX_TRY 不进逃逸集合）、`src/check_top.c:2497`（`fresh` 集合从不失效）、`src/check_top.c:2476`（效果掩码 32 位，第 33 个参数起不检查）、checktop-1 `src/check_top.c:6024`、internal `src/check_internal.h:497`（`mut ref` 出参写入不产生 publication）、lookup `src/check_lookup.c:105`（`mut ref self` 调用后非空证明不失效）；以上多条已由 Lead 用 ASan 实测 heap-use-after-free / stack-use-after-scope。
- **P-07 · arena 永远是词法的，不是动态的（写死）；region 只是"给一个词法作用域起个名字"，不改变被调用者的分配归属。** — 出处：DESIGN.md:115-131,124 — 硬性要求：拒绝任何"一个 region 覆盖整棵调用子树"的动态 arena 语义；`@recursive` 的帧数组跟着函数所在 arena 走。 — 可能违反：**[实测]** 并行路径下 `new` 的落点由运行期 TLS arena 决定（`src/check_expr.c:108,149`；DESIGN.md:246-255 自认"worker 里的 `new` 走 `extc_tls_arena`"）⇒ "纯词法"在并行路径上被运行期上下文旁路；这是**已知的、被文档承认的偏离**，但它必须由一条新原则正面覆盖（见 §3.3），不能靠旧段落默认。
- **P-08 · 引用安全的总承诺：extC 里不存在「已经被归还的存储」；保证「没有悬垂」，不保证「没有别名意外」。** — 出处：SPEC.md:117-122,431-433,132；WHY-EXTC.md:66 — 硬性要求：引用只可能指向活着的存储，或者根本不存在（编译期挡住）；"过期"只意味着内容变了，永远不意味着地址坏了——**不崩、不是 UB、不是野指针**；别名/旧数据抓不住是定位的必然代价，靠 API 形状与语法显式化缓解，不靠检查。 — 可能违反：**P0 级**——[审计] escape-1/2、checktop-1/2、internal、lookup、coro 的 UNSOUND 条目（见 P-06 列表）已实测产出真实 UAF；[审计] checkexpr-2 `src/check_expr.c:1684` 甚至不需要别名就空解引用。⇒ 今天"没有悬垂"是**未兑现**的承诺，不是稳定的上位事实。
- **P-09 · 零初始化是 P 的胜利：每个类型都有零值，`var x: T` 就是它；含 `ref`/`fn` 的类型没有零值（`var p: ref i32` 是编译错误），tag 0 的载荷不能含 `ref`。** — 出处：DESIGN.md:58,194；SPEC.md:71,298-313 — 硬性要求：未初始化 UB 从语言里消失；零值检查必须在**产生的地方**（声明/实例化记录点）查，不能推迟到消费处；`new T[n]` 读作 0 是语言承诺（清零点在分配器里，SPEC.md:140-141）。 — 可能违反：**[实测]** 生成物清零已落实（`extc_arena_alloc` 用 `calloc` + 复用块 `memset`，产物 /tmp/p_alloc.c:130-155；`src/codegen.c:7241`）；但 [审计] checktop-3 `src/check_top.c:4865`（自由泛型 `fn mk<T>() -> T` 不记录零值检查 ⇒ 生成 `(cellfn){0}` 并调用空函数指针，实测 SEGV）、lookup `src/check_lookup.c:671`（聚合里的 `coroutine<T>`/`dyn` 句柄未被当作"没有零值"）、checkexpr-2 `src/check_expr.c:1684`（可空引用无窄化检查）。
- **P-10 · 显式优于推导：类型写在名字后、关联函数写全、泛型要写实参、转换要写出来；只有无损拓宽是隐式的。** — 出处：SPEC.md:190-202,315-317；DESIGN.md:190-191 — 硬性要求：不做类型推导、不下推字面量类型、不隐式截断、不做 `as` 链；唯一例外是 `return` 位置裸写 `success(v)`/`failure(e)`（定案 49，SPEC.md:201-202）。 — 可能违反：[审计] checkexpr-1 `src/check_expr.c:359`（字面量适配先于隐式拓宽、失败即报错 ⇒ 同一表达式因左右位置不同一收一拒）、checkexpr-2 `src/check_expr.c:3150`（`option<T>`/`result<T,E>` 形参的泛型函数永远调不了）、types `src/types.c:483,961`、checktop-2 `src/check_top.c:289,857`。
- **P-11 · 失败分类：能消灭的消灭，消灭不掉的必须失败得响亮（trap + 源码位置），根本抓不住的用语法显式化。** — 出处：SPEC.md:64-91,84-91；DESIGN.md:237-239,338-349 — 硬性要求：悬垂/空引用/未初始化/隐藏机制要在编译期消灭；越界/溢出/除零/移位要么证明要么 trap 且带位置；**trap 不是 UB**；禁止静默错值。 — 可能违反：**[实测]** 除零与越界 trap 带位置成立（`/tmp/p_div.extc:3: trap: division by zero`；`/tmp/p_trap.extc:5: trap: index 7 out of range (length 4)`）；但 [审计] differential `src/codegen.c:2649`（u64↔i64 换符号检查恒真、永不 trap）、`src/codegen.c:2605`（f64→i64 在 2^63 漏检、`src/codegen.c:7278`）、codegen-2 `src/codegen.c:2203`（f64 整值字面量当整数常量 ⇒ `1.0/2.0` 得 0）、stmt `src/check_stmt.c:1085`（`return e?` 载荷类型从不比较 ⇒ 静默截断）。
- **P-12 · 失败是值，不是控制流：没有异常、没有栈展开；可恢复失败 = `result` + `?`，bug = trap。** — 出处：SPEC.md:512-530；DESIGN.md:185,217-230,236-239；WHY-EXTC.md:62 — 硬性要求：`?` 编译期展开为三句语句（求值一次 + 判断 + return），只在四个"整语句可重写"的位置合法；穷尽 `match` 必须报缺变体；**不得把 bug 做成可捕获的异常**；`?` 的错误类型兼容是已知缺口（没有 `From`）。 — 可能违反：[审计] escape-2 `src/check_escape.c:2381`（`?` 的操作数只查 `targs.len>0`，非 option/result 的泛型被当 option 解包）、stmt `src/check_stmt.c:1085`；**[实测/文本]** `!` 的实现**不产生任何检查**（`src/codegen.c:2837-2851`「`p!` is that pointer itself; nothing is emitted」）⇒ 签字失败 = 裸空指针解引用（C UB），而 WHY-EXTC.md:63 承诺"trap 不是 UB"——这条张力文档从未列为代价（见 T-24）。
- **P-13 · 没有隐藏的全局状态：不做 GC、引用计数、`errno`、`static` 局部变量；禁止行为取决于你没写的一行。** — 出处：SPEC.md:151-159,630-635；DESIGN.md:184-188 — 硬性要求：类型信息编译期用完；分配必须能从源码推断归属；语言里没有 GC/RC/异常/反射/`any`。 — 可能违反：[审计] ast `src/ast.h:824`（`extThreadMask` 文档缺省值 1 未实现，无 `effects` 的 `extern!` 被当 Thread=0 ⇒ worker 可静默调用碰共享状态的 C 函数，TSan 实测 data race）、checkexpr-1 `src/check_expr.c:108,149`（TLS arena）、misc `src/base.h:12`（编译器自身"没有可变全局状态"的不变量与 `dbgOn` 缓存相反）；**[实测]** 生成物运行期确实带静态全局（`extc_pools`/`extc_zones` 等，`src/pools.c` 运行期文本）⇒ 只能在 WHY-EXTC.md:17「需要相信的只有编译器与一份很小的运行期」这个口径下成立，不能宣称"零全局态"。
- **P-14 · 单态化：每个实参组合一份代码 ⇒ 没有间接调用、没有虚表、没有运行时类型信息；闭集分派用枚举 + match + 穷尽检查；开集注册曾判"永久不做（违反 P）"。** — 出处：SPEC.md:551-554,569-585；DESIGN.md:187,376-388 — 硬性要求：语言级多态不做运行时分派；"哪个函数被调用"必须静态可查；若确需运行期注册，只能用可校验的稳定句柄（`pool<dyn Trait>`）且必须写明它引入了受控间接调用。 — 可能违反：**[实测]** 该"永久不做"已被 SPEC.md:582-585 自己改判（`pool<dyn Tag>` 实测可用）、WHY-EXTC.md:107 又写"计划中"、代码里 `dyn` 已在（`tests/instimpl/t_dyn.extc`、`stdlib/std/sys/pool.extc`）⇒ 三份文档三种口径；[审计] codegen-1 `src/codegen.c:630`（泛型方法定义与调用点的 C 名不一致）、checktop-3 `src/check_top.c:5596`（泛型调用点单遍解析 ⇒ 调用未生成的 `f_T`）、checkexpr-3 `src/check_expr.c:3457/3459`（`dyn` 派发实参检查错误）、lookup `src/check.c:176`（名字修饰撞名）。
- **P-15 · 能在 extC 里写的东西，就在 extC 里写（prelude/标准库优先；只有语言里写不出来的才进编译器）。** — 出处：DESIGN.md:397,491-519,421 — 硬性要求：容器/字符串算法/错误类型放标准库；编译器只留语法、类型系统、内存模型与"生成代码"；新能力先问"这句能不能用 extC 写出来"。 — 可能违反：无直接违反；**裁定价值**在于：任何"把库塞进 codegen"或"用 C 宏绕过 prelude"的方案应被驳回，除非证明 extC 写不出来（如"遍历所有字段"的 derive，DESIGN.md:508-509）。
- **P-16 · 编译器"生成"代码 ≠ 把库塞进编译器：derive（打印/结构化 `==`）生成的是数据（每类型一份类型描述 + 全程序一份通用器），不是每类型一段代码。** — 出处：DESIGN.md:506-513,351-360 — 硬性要求：每类型只出描述常量；通用打印器/比较器全程序一份；理由是实测（每类型一段 printf 曾占生成 C 的 22.9%，改数据后端到端 −45%）。 — 可能违反：无直接违反；作为裁定原则：反对"给每个类型派生一段 C 函数"的提案。
- **P-17 · 编译器不得静默退化：处理不了就报错；不许偷偷退化成真递归、不许"报成功但产物编不过"。** — 出处：DESIGN.md:615-618,634,439；SPEC.md:88 — 硬性要求：变换失败必须报错；诊断要指向源码；"编译器说成功"是硬承诺（生成的 C 必须能编）。 — 可能违反：**面最广的一条**——[审计] CRASH 4 条（`src/check_expr.c:3027`、`src/check_top.c:4528`、`src/codegen.c:768`、`src/codegen.c:8402`）、HANG 7 条（`src/codegen.c:5798`、`src/parser.c:2394/2457`、`src/check_top.c:901/3091`、`src/codegen.c:3632`×2）、NONTERMINATION 1 条（`src/parser.c:2457`）、MISCOMPILE 27 条中"报成功产物编不过"的族（checktop-3 `src/check_top.c:6750` 无 yield 协程不生成帧布局、`src/check_top.c:5596`）、**[实测]** F-03 嵌套 30 层块 codegen 指数爆炸不返回、F-04 深嵌套输入让编译器 SIGSEGV。

## 2. 明说的代价 / 损失（trade-off 清单）

- **T-01 · 同帧别名失效查不出** — 出处：SPEC.md:81,89-91,387-433,647 — 含义：两个同层视图指向同一块缓冲、第二次写覆盖第一次，编译器**故意**不报（抓它要生命周期标注，那是另一门语言）；缓解靠 API 形状（读 = 调用者给 buffer + 返回长度）与语法显式化。 — 对实现的意义：**不许**把"读到旧内容"当 UNSOUND 上报；这类审计项应被重新分类为"能力缺口/文档承诺边界"。
- **T-02 · 不能把借来的引用存进「参数指向的对象」**（`fn bind(s: mut ref slot, t: mut ref i32) { s.r = t }` ⇒ 拒） — 出处：SPEC.md:81 — 含义：比 Rust 严（Rust 写个 `'a` 就过去），因为两个参数寿命互不相关而函数体只检查一次；出路是"同一帧里改 / 构建并返回 / 大状态放同一帧"。 — 对实现的意义：任何"放宽它"的补丁都等于引入生命周期标注 ⇒ 违反定位，应直接驳回；反之，[审计] escape-1/2 是"绕过检查"，不是"限制过严"。
- **T-03 · 存储深度 vs 引用深度的保守（精度缺口）** — 出处：SPEC.md:376-385,649 — 含义：检查器看"名字的存储深度"而非"里面的引用指哪"，于是 `fn g(m: slice<u8>) { let v = m  return v }` 被误挡；已定修法是把 `Sym.depth` 与 `Sym.refDepth` 分开，且**必须保证 `ref v` 仍用存储深度**（否则引入真悬垂）。 — 对实现的意义：误拒里有一类是被批准的；但 24 条 FALSE-REJECT 必须先与这条代价对账（哪些属于保守、哪些是实现错）。
- **T-04 · 运行期换实现（插件表/策略容器/热替换）曾判"永久损失"** — 出处：SPEC.md:576,636,648；DESIGN.md:384 — 含义：需要间接调用 ⇒ 违反 P。 — 对实现的意义：**该代价已被 SPEC.md:582-585 自己改判**（`pool<dyn Trait>` 可用、lambda+单态化可用）⇒ 引用此代价时必须同时引用改判，否则会得出"dyn 的存在违反原则"的错误结论。
- **T-05 · arena 帧内留垃圾；帧 = 释放点** — 出处：SPEC.md:439-441,650 — 含义：反复 `push` 留旧 buffer 到作用域结束；想更早释放要么拆函数、要么等块级 mark/release。 — 对实现的意义：**口径已升级**——块级细化已落地（SPEC.md:334-342,716：进块 reset、出块 release，循环里分配上界 = 一次迭代）⇒ 引用"帧=释放点"这句时必须标注它是**改之前**的口径。
- **T-06 · 容器拷贝 = 共享存储** — 出处：SPEC.md:651；WHY-EXTC.md:60 — 含义：拷贝一个容器，两份指向同一块（`@sharesStorage`）。 — 对实现的意义：要有文档或显式 `clone`；审计时先确认是"按协议共享"还是"意外别名"。

## 3. 分主题：承诺了什么 / 明确不承诺什么

### 3.1 内存模型

**承诺**
- `栈 + arena + 静态` 复合模型：局部/定长值在栈；`new` 的在 arena（块级：每个 `{}` 一只，层数编译期算好，栈上定长 `extc_arena __extc_a[DEPTH]`）；全局/常量深度 0（SPEC.md:323-342；WHY-EXTC.md:26-30）。
- 用户永不写 `malloc`/`free`/`close`；没有手动分配就没有手动释放（SPEC.md:56,185-188）。
- 引用规则唯一且可判定：`depth(r) ≥ depth(v)`，参数 0、函数体 1、每进块 +1；调用返回引用深度 = `max(实参)`（SPEC.md:354-374；DESIGN.md:98-113）。
- 三档兜底：能证明的证明（深度账）→ 不能证明的运行期查（池句柄 `{slot, gen, ep}`，陈旧句柄当场 trap）→ 不能查的让你签字（`extern!`/`!`/`subView`）（WHY-EXTC.md:23-36,48-54）。
- 池两种被检查的模式：容器板（可替换/归还，`realloc` 原地长，峰值最优）、对象表（只追加，`give`/`resize` 直接 trap）；`reset` 即换代（WHY-EXTC.md:48-54）。
- 零初始化为语言规则：`new T[n]` 读作 0；清零点在分配器（SPEC.md:136-141,300-313；**[实测]** 已落实：`calloc` + 复用块 `memset`）。
- 资源（文件）也归帧：`open()` 返回 `mut ref file`（深度 1），逃逸检查一行都不用改（SPEC.md:499-508）。
- 承诺的边界一句话：**没有悬垂；不保证没有别名意外**（SPEC.md:431-433）。

**明确不承诺**
- 不保证"内存不浪费"：帧内增长留垃圾、arena 的垃圾等到作用域结束（SPEC.md:352,435-441）。
- 不保证"栈上放得下大东西"：默认栈 8 MB，超大数组要放全局或 `new`（SPEC.md:349-351）。
- 不保证抓住同帧别名/旧数据（SPEC.md:81,387-433）。
- 不保证"没有堆"是字面意义：**[实测]** 生成物在需要运行期时含 `malloc/calloc/free`（/tmp/p_alloc.c），正确口径是"语言/用户没有堆 API"（SPEC.md:56 的"生成物 malloc 0 次"字面不成立，见 D-05）。
- 不保证池今天"永远不会被静默用错"：运行期有世代校验，但 [审计] `src/pools.c:46,51,118` 三处使该承诺在边界形状上失效。
- 硬性要求（裁定用）：**检查器判引用用的"块深度"与生成 C 选 `__extc_a[k]` 用的"块深度"必须是同一个数**（SPEC.md:339-342）——任何让两边分歧的优化一律驳回；[审计] `src/codegen.c:3642` 正违反此条。

### 3.2 错误处理模型

**承诺**
- 失败是**类型的一部分**：`result<T,E>`/`option<T>`，`match` 穷尽检查（SPEC.md:512-545）。
- `?` 编译期展开为"求值一次 + 判断 + return"，无栈展开；四个合法位置（SPEC.md:526-530）。
- 可恢复失败用 `result`+`?`，**bug 用 trap**（越界、除零、移位、陈旧句柄、池误用），trap 带源码位置与值（DESIGN.md:236-239,338-349；WHY-EXTC.md:63；**[实测]** `/tmp/p_div.extc:3: trap: division by zero`、`/tmp/p_trap.extc:5: trap: index 7 out of range (length 4)`）。
- 有损转换必须写出并命名失败方式：回绕/就近/报错（SPEC.md:265,315-317；DESIGN.md:191,521-527）。
- 整数溢出 wrap 且有定义（`-fwrapv`）；除零/移位超宽 trap（SPEC.md:75-77；WHY-EXTC.md:19）。

**明确不承诺**
- 不承诺"没有运行时错误"：越界/溢出/除零/移位只能"失败得响亮"（SPEC.md:64-91）。
- 不承诺别名/旧数据检查（SPEC.md:89-91）。
- 不承诺 `?` 的错误类型自动转换（没有 `From`）（DESIGN.md:241-242）。
- 不承诺 `!` 失败会 trap：**[实测]** `!` 不产生任何检查 ⇒ 失败是 UB（T-24）；"trap 不是 UB"这条只在有 trap 的路径上成立。
- 不承诺所有 trap 都到位：**[实测/审计]** 64 位换符号转换与 f64→i64 边界漏检（`src/codegen.c:2622-2651,7278`）。
- 硬性要求：**报告"成功"必须以"产出的 C 合法且语义一致"为准**（DESIGN.md:615-618 的必然推论）；trap 消息必须含 `file:line` 与具体值。

### 3.3 并发 / 线程模型

**承诺**
- 每条线程一条自己的 arena 链（bump 分配器不是线程安全的）；worker 里的 `new` 走 `extc_tls_arena`（DESIGN.md:246-255）。
- 跨线程共享内存允许，安全性来自**分块互不重叠**（`parallel::run` 给每个 worker 自己的 `[lo,hi)` 输出段）（DESIGN.md:252-254）。
- 结构化 fork-join + 显式归约：每个 worker 产出一个值，父线程用显式合并函数合并；不需要冲突检测、不需要读集跟踪（读集跟踪违反 P）（DESIGN.md:281-311）。
- 合并函数可结合可交换 ⇒ **1 个线程与 8 个线程结果一模一样**（DESIGN.md:304-311）。
- 纪律：worker 里做纯计算，有副作用的活（I/O）留父线程（DESIGN.md:316）。
- 已作废：**"引用不过线程"不是红线**（DESIGN.md:246-260 明确作废）；"共享 = 拷贝 / 只做消息传递 / 永远不做共享内存+锁"降级为一种可选用法（DESIGN.md:253-255,274）。

**明确不承诺**
- 不承诺"数据竞争在类型层面不可表达"（该口号已作废）（DESIGN.md:246-260）。
- 不承诺语言层面的锁/共享内存模型：只提供 fork-join + 归约这一种形状（DESIGN.md:274）。
- 不承诺引用可跨线程，也不禁止；不承诺 worker 内可做 I/O（那是纪律，不是检查）。
- 硬性要求（今天可执行的三条）：① worker 体内只许调用声明为 `Thread=0` 的东西；② 未声明 `effects` 的 `extern!` 必须按**最坏情况**（碰共享状态）处理；③ `new` 在 worker 链上必须落在该 worker 的 arena 链上。
- 可能违反：**[实测/审计]** ②被违反（`src/ast.h:824` + `src/check_expr.c:108`：缺省 0 被读成"作者签了 Thread=0"，TSan 实测 race）；③被违反（`src/check_expr.c:149`：worker 链上函数被普通调用时 `extc_tls_arena` 为 NULL）；①被违反于崩溃路径（`src/check_expr.c:3027`：`parallel::run()` 空实参让编译器 SIGSEGV）。
- **文档缺口（必须补）**：SPEC.md 与 WHY-EXTC.md 对并发**零描述**，唯一表述在 DESIGN 且被自我作废过一次 ⇒ 裁定并发争议时，只能引 DESIGN.md:246-260 的复核段。

### 3.4 C 交互模型

**承诺**
- 编译到 C11，生成物契约固定：C11、`-O2` 默认、整数回绕有定义（`-fwrapv`）（WHY-EXTC.md:19；**[实测]** `src/main.c:635` 给 `ccArgv` 加 `-fwrapv`）。
- 三档机制：① 编译器原语（IO/arena/trap，看不见）② stdlib 用 `extern` 包好且 `reserved` 保护 ③ 用户 `extern!` 边界声明（看得见且必须签字）（SPEC.md:589-599）。
- `extern!` + `effects Addr=0 Cont=0`（以及 `Thread`）说明外部函数对地址/继续执行/共享状态的影响（WHY-EXTC.md:90；DESIGN.md:730-750）。
- 两个方向都通：extC 调 C，C 也能调生成的函数（生成物是普通 C）（WHY-EXTC.md:93）。
- 标准库实现可以调 libc（由编译器生成），用户代码不能；"P 没被违反：用户手上的逃生舱依然只有一个"（DESIGN.md:741-750）。
- 生成物可读、`#line` 可关（`--no-line-map`）（WHY-EXTC.md:91；**[实测]** `src/main.c:163,364`）。

**明确不承诺**
- 不承诺第 3 档之内安全（安全从绝对变成默认）（SPEC.md:599）。
- 不承诺"无堆/无全局态"是字面意义（运行期有一份簿记代码与静态池表；WHY-EXTC.md:17 只说"需要相信的只有编译器与一份很小的运行期"）。
- 不承诺暴露 C 的全部：`str*`、`errno`、`scanf`、`qsort`、`rand`、`assert`、`limits` 明确不包（判据：它的价值是不是来自 C 的某个缺失）（SPEC.md:606-612）。
- 不承诺 `owned` 的外部内存归属（计划中）（WHY-EXTC.md:95）。
- 硬性要求：**"没签字 = 最坏情况"**；`extern!` 的 `effects` 缺省必须保守（[审计] `src/ast.h:824` 是反例）；用户代码不得直接调 libc。
- 可能违反：[审计] checkexpr-1 `src/check_expr.c:108`（worker 白名单把无 `effects` 的 `extern!` 当 Thread=0）。

### 3.5 诊断与可观测性

**承诺**
- 诊断教人：缺方法指出该 `use` 哪个模块，重名指出先前那一处，跨模块漏限定给出该写什么（WHY-EXTC.md:117；SPEC.md:105）。
- 错误信息是语言的一部分（DESIGN.md:761）。
- trap 报告要有位置 + 值 + 层层调用，像语言的一部分而不是段错误（DESIGN.md:335,338-349）。
- `--checks=all` 调试模式：release 下能证明的检查被消掉，调试模式一个都不消、契约断言打开（DESIGN.md:363-365）。
- 调试三层次：① 挡在编译期 ② 运行时留最好现场（trap）③ 交给 gdb 但让它看到 extC（`#line` + 调试友好的 C）（DESIGN.md:319-369）。
- 可观测开关：`--dump-tokens`/`--dump-effects`、`--explain-memory`、`EXTC_DBG_ARENA`/`EXTC_SELFCHECK`（WHY-EXTC.md:115；**[实测]** --help）。

**明确不承诺**
- 不自建调试器、不做 REPL（DESIGN.md:371-374）。
- 不承诺多错误报告（待做）、不承诺 trap 的层层调用栈（还没有）（DESIGN.md:334-335）。
- 不承诺错误位置总在用户代码（零值毒标记类错误会落在 prelude，SPEC.md:78 自认欠账）。
- 硬性要求：**编译器永远不崩、不挂**（"处理不了就报错"的另一面，P-17）：CRASH/HANG 不是诊断失败，是原则失败（[审计] 4 CRASH + 7 HANG + 1 NONTERMINATION）。
- 可能违反：**[实测]** DESIGN.md:363 的 `--checks=all` **不存在**（`./build/extc --help` 无此开关，只有 `--check-c`）⇒ 该承诺未实现；[审计] misc `src/main.c:355` --help 漏 `--explain-memory`。

### 3.6 性能承诺

**承诺**
- 零成本的一等公民：`p!` 在 C 里就是那个指针；`@inline` 直达 `always_inline`；运算符与方法就是普通函数调用（WHY-EXTC.md:70；**[实测]** `src/codegen.c:7304`）。
- 单态化泛型：`vector<i32>` 与 `vector<string>` 两份代码，无装箱、无间接跳转（WHY-EXTC.md:71）。
- 连续布局：池底容器内容连续、可整体交给 C；`map` 是 ORDER=16 的 B 树，`lowerBound`/`rankAt` O(log n)（WHY-EXTC.md:72；**[实测]** `stdlib/stl/map.extc:33,282,307`）。
- 缓冲与批量：`reader` 一次 `read(2)` 填一整块；`append` 整段移动；`copyInto<T>` 切片级批量拷贝（WHY-EXTC.md:73；**[实测]** `stdlib/std/io.extc:28,322`）。
- 生成物可再优化：交出的 C 可继续 `-O3`/LTO/PGO（WHY-EXTC.md:74）。
- 资源友好：无 GC 元数据、整块回收、按需可收缩（1.5 倍增长 + `shrink`）、槽位复用不向系统要新页、峰值可控（容器板原地换块）（WHY-EXTC.md:78-86；**[实测]** `stdlib/stl/vector.extc:97`）。
- 性能天花板就是 C 的天花板：没有 VM/解释器/GC 停顿（WHY-EXTC.md:14）。

**明确不承诺**
- 不承诺"能证明的"不用付出成本：不能证明的索引/转换必须留检查（除非范围类型真推得出来，DESIGN.md:660-665）。
- 不承诺单态化不膨胀代码（T-07）。
- 不承诺 `dyn` 之后仍无间接调用（WHY-EXTC.md:76）。
- 不承诺编译时间上界：**[实测]** 30 层嵌套块让 codegen 指数爆炸不返回、深嵌套输入让编译器栈溢出（F-03/F-04）；[审计] 2 条 PERF。
- 硬性要求：性能优化**不得**以削弱 P′ 为代价——"能证明才消检查"；发布模式也不许把不可证明路径的检查删掉（DESIGN.md:660-665 的裁定方向；`--checks=all` 本就该是这条的调试面）。

## 5. 裁定表：当实现细节有争议时，按哪条上位原则裁定

> 用法：先定位争议类别 → 用"裁定依据"栏的原则判 → 若两边都能引原则，按**优先级序**取上位的（P > P′ > P″ > 主题承诺 > 代价清单 > 品味）。

**优先级序（硬性）**
1. **P（P-01）** 与 **P′（P-03）**：禁止新增隐藏机制；不能证明的必须语法可见。二者等价，冲突时按"哪边更少隐藏"裁。
2. **P-06/P-08（引用与悬垂承诺）**：一切涉及寿命、arena 层数、池句柄的争议，先满足"引用不能活得比存储长"，再谈性能/易用。
3. **P-09（零值）/ P-11（失败分类）**：涉及"能不能静默给个默认值/静默错值"的争议，一律取"报错或 trap"。
4. **P-05（P″）**：涉及释放时机的争议，取"编译期已知的词法释放点"。
5. **主题承诺（§3）**：内存 > 错误处理 > C 交互 > 诊断 > 性能。
6. **明说的代价（§2, T-xx）**：已被接受的代价不得被当成新缺陷上报；反之，未被记入代价清单的损失（如 T-24）必须先补记账再谈实现。
7. **品味（DESIGN.md:771-781）/ 预算（DESIGN.md:759）**：不得用于裁定，只能标注。

**逐条裁定查询**

- **争议：某优化要新增运行时元数据/簿记/全局状态** → 按 **P-01/P-13**，默认驳回；唯一出路是"能证明（编译期消掉）"或"语法上看得见（P′）"。读集跟踪、乐观锁重试就是被这条否掉的样板（DESIGN.md:295-298）。
- **争议：某个检查要不要删（性能）** → 按 **P-01 + P-11**："能证明才删"；证明不了就保留检查（`a[i]` 的 trap 语义本身就是 P′ 的可见性），并给出 `a.at(i)?` 的显式替代（DESIGN.md:660-665）。
- **争议：某个值该不该有零值 / 要不要默认初始化** → 按 **P-09**：有零值就默认零初始化；含 `ref`/`fn` 的类型**没有零值**，缺失必须报错——[审计] `src/check_top.c:4865`、`src/check_lookup.c:671` 是反例。
- **争议：错误该 trap 还是该 `result`** → 按 **P-12**：可恢复 ⇒ `result`+`?`；bug ⇒ trap（带位置）；两者都不是 ⇒ 只能 `!` 签字，且必须计入可数清单并记明后果（今天后果是 UB，T-24）。
- **争议：某处该不该做检查（越界/空/寿命）** → 按 **P-03/P-06**：涉及寿命 ⇒ 必须查（编译期）；涉及越界 ⇒ 证明则消、不能证明则 trap；涉及别名 ⇒ 不查（T-01），改用 API 形状。
- **争议：编译器遇到处理不了的形状怎么办** → 按 **P-17**：报错。绝不静默退化、绝不"报成功产物编不过"、绝不崩/挂（[审计] D-13 全部按此裁定为缺陷）。
- **争议：某能力（可空/泛型/运算符/多态）要不要加** → 按 **P-19**：先判定它是否引入隐藏机制；若是"用户扩展点"而非"失败方式命名"，按 DESIGN.md:529 拒绝；若只是"暂时难"，标为延期而不删。**注意**：SPEC.md:576/636 的"永久不做"已有两处被自己改判（X-02/X-16），引用前必须复核。
- **争议：库功能放编译器还是放 extC** → 按 **P-15/P-16**：能写 extC 就写 extC；只有"语言里写不出来"（如遍历所有字段的 derive）才进编译器，且优先生成**数据**而非代码。
- **争议：C 交互的边界** → 按 **P-21**：用户只有一个 `extern!` 入口且必须签字；`effects` 缺省一律取最坏情况（[审计] `src/ast.h:824` 是反例）；标准库内部用 libc 由编译器生成，不算逃生舱。
- **争议：并行/线程行为** → 按 **P-24**：线程各自 arena 链、分块不重叠、显式归约、结果与线程数无关；"引用不过线程""共享=拷贝""永远不做共享内存"**已被作废**，不得引用；同时必须承认 SPEC/WHY-EXTC 对并发无描述（文档缺口，优先补）。
- **争议：arena 层数/深度怎么算** → 按 **P-06 + SPEC.md:339-342 的接缝**：检查器与 codegen 必须用同一个数；主绑定（home/提升）只允许出现在有明确规则的地方（X-08），且必须记账为 P′ 例外。
- **争议：生成物可读性 vs 编译器方便** → 按 **P-20**：形态 1:1、名字可读不冲突（修 D-03 的撞名而不是放弃可读性）、`#line` 默认开、避免语义宏；允许 `always_inline` 这类"只影响优化不影响语义"的属性宏。
- **争议：文档与代码不一致时信谁** → 按 **SPEC.md:17**：设计口径信 SPEC/DESIGN/WHY-EXTC，**实现状态信实测**；引用"永久/不做"前先查是否已被改判（P-19）。本文件的 §4 就是这张对账表的当前快照。
