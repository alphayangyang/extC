## 一、golden 降级（所有者决定 → 定案 98）

**为什么必须降级（用证据说话）**：

| 编译器 | 与 `tools/golden.sha256` 逐字节相符 | 不符 |
|---|---|---|
| HEAD（`git worktree` 干净检出 `95e7526`） | 252 / 414 | **162** |
| P0–P2 修复之后 | 241 / 414 | 173 |

- 那份哈希清单**在 HEAD 上就已经过期**（不是本次修复引入的）——它已经红着，却没人知道；
- "逐字节不变"这个判据在修复期的净效果是：**改对了变红、错着不动变绿**；
- 而 P0–P2 的每一条修复都**要求**产物变化（浮点字面量补 `.0`、窄类型回截、`for` 步进标签、
  空视图保护、循环条件临时量）；本批相对 HEAD 的 34 份差异可 100% 归因，
  且 414 份产物**没有一份是非法 C**。

## 二、P0-9：泛型重载后缀用调用方的替换上下文

| 项 | 内容 |
|---|---|
| 位置 | `src/codegen.c` `opOverloadSuffix`（定义侧 `cFuncName` 与调用侧 `cMethodName` 共用） |
| 根因 | 后缀由 `subst(g, p1->type)` 算，即读**环境里**的替换上下文。定义侧的环境是实例上下文（`substEnterInst` 进来过）⇒ 发 `w_i32_eq_i32`；调用侧在非泛型函数 `main` 里没有上下文 ⇒ `T` 不被替换 ⇒ 发 `w_i32_eq_T`。生成物直接编不过：`implicit declaration of function 'w_i32_eq_T'` |
| 后果 | 带"泛型结构体 + 运算符重载 + 第二个参数是 `T`"的程序**完全无法编译**（不是错值，是编译失败，但诊断把锅甩给用户的程序） |
| 修法 | 拆出 `opOverloadSuffixIn(g, f, params, args)`：定义侧仍用环境上下文（那里是对的），调用侧 `cMethodName` 显式传**被调方**的上下文——方法实例的 `tmpl->typeParams`/`targs` 优先，否则**接收者实例**的 `sdef->typeParams`/`targs`（`cMethodName` 正是知道接收者的地方） |
| 证据 | 新正例 `examples/operator-overload-generic.extc`（修前 parrun 判"编译/运行失败"红，修后 `i32eq=true u8eq=false i64eq=true`）；生成物里定义与调用名字一致（`w_i32_eq_i32` / `w_i32_eq_u8` / `w_i64_eq_i64`）；`--check-c` 通过 |

**影响面**：只有"泛型接收者 + 同名运算符多份重载"才会走新路径（`same > 1` 且接收者是泛型实例），
其余情况 `params/args` 为 NULL 或后缀为空字符串，与修复前逐字节相同。
