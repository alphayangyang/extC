## 一、P0-19：`return e?` 的载荷不做相容比较 ⇒ 静默窄化

| 项 | 内容 |
|---|---|
| 位置 | `src/check_stmt.c:1085`（`return e?` 分支） |
| 根因 | 该分支用 `wb->kind == TY_GENERIC` 判断"外层类型带载荷"，而 `option<T>` / `result<T,E>` 是**枚举实例**（`TY_ENUM` + `targs`）⇒ 条件恒假、载荷从不比较 |
| 后果 | `fn f(o: option<i64>) -> option<u8> { return o? }` 把 `some(1000)` 静默变成 `some(232)`；而直接写 `option<u8>::some(1000)` 会被正确拒绝——**同一件事两个答案** |
| 修法 | 条件加上 `TY_ENUM`（`targs[0]` 就是两个族的成功载荷类型），走与普通 `return` 相同的 `checkAssignable` |
| 证据 | 新反例 `tests/errors/try_payload_narrows.extc`（修前 parrun 判"应该报错但通过了"，修后 `error: return value expects u8, found i64`）；合法方向 `option<i64> -> option<i64>` 仍通过（`v=1000`） |

**同族排查**（顺手做，结论：无洞）：变量经 `return`、赋值、结构体字段、函数实参四条路都正确拒绝跨实例赋值
（`argument expects option<u8>, found result<i64, i32>`）。排查中出现过一次假警报——我用 `head` 截断了
输出、并读了 `head` 的退出码而不是编译器的，看起来像"实参不检查"；干净复验后确认一直是拒的。

## 二、P0-7：循环条件里的临时量被提升到循环外 ⇒ 死循环/结果错

| 项 | 内容 |
|---|---|
| 位置 | `src/codegen.c` `eqOperand`（写语句前缀）+ `ST_WHILE`（发 `while` 前冲刷前缀） |
| 根因 | 数组/切片 `==` 的非"地方"操作数物化成临时量写进**语句前缀**；前缀在 `while (...)` **之前**被冲刷 ⇒ 只执行一次，而条件每轮读那个临时量 |
| 后果 | `while a == mk() { n = n + 1  if n > 100 { break } }` 实测 `rounds=101`（正确 1）：条件永远拿第一次的返回值比较 |
| 修法 | 发条件后若前缀非空，改发 `while (1) { <前缀>; if (!(cond)) break; <体> }` —— 条件的求值次数与源码一致；前缀为空时仍发原来的 `while (cond) {`，**其余生成物字节不动** |
| 证据 | 差分闸门新增探针 `while_eq_temp`（修前 `extC rc=1 vs C rc=0` 红、修后绿）；新正例 `examples/while-condition-temps.extc`（`rounds=1 iter=3 scaned=3`） |
