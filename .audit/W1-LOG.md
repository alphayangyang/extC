## 一、"逃出任务的引用"是否真的被拒？——**大体被覆盖，但发现一条新缺口**

探针（`/tmp/rev/w1/`）：

| 探针 | 形状 | 结果 |
|---|---|---|
| a3 | worker 把**指向自己帧内局部**的引用写进共享 `out` 视图（`out[0] = ref n`） | **拒绝** ✓ `this reference would hold a reference…` |
| a4 | worker 把 TLS 分配的指针写进**模块级全局** | **拒绝** ✓（契约里的"模块级 `var` 一律拒绝"确实生效） |
| 既有 `tests/errors/coro_view_lives_across_yield.extc` | 局部视图**跨挂起点存活** | **拒绝** ✓（规则②） |
| 既有 `coro_forge_*` | 拿帧值当句柄 | **拒绝** ✓（规则①） |
| **c2（新）** | `yield ref n`：把**指向协程帧内局部**的引用当**载荷**交给调用方（`coroutine<?ref node>`） | ✗ **被前端接受** |

**新缺口（P0-6e）**：`n` 是 C 栈局部（规则②的原话："没写 `new` ⇒ 不进 arena，`yield` 一返回这次调用的 C 栈就没了"），
把它 `yield` 出去就是把悬垂指针交给调用方 —— 现存规则只覆盖"局部**留着**跨挂起点"，**没覆盖"把引用当载荷交出去"**。

**它后面还压着第二层缺陷**：这条程序连**生成物都是畸形 C**：

```c
EXTC_UNUSED static node * extc_coro_value_node *(extc_coro *h, const char *f, int l) {
EXTC_UNUSED static bool extc_coro_send_node *(extc_coro *h, node * v, const char *f, int l) {
```

载荷类型的 C 拼写以 `*` 结尾时，包装函数的 `*` 被拼到**函数名**后面 ⇒ gcc 直接报 `expected '=' … before '*' token`。
（闸门① 没抓到它，因为语料里从没有 `coroutine<?ref T>` 的实例 —— 这也是"语料即判据"的又一次印证。）

**收进闸门**：`tools/escape-corpus/P0-6e_coro_ref_payload.extc`（必须拒绝），基线 1 条；
`tests/run.sh` 325/0；闸门⑤ 18 份语料 0 新增 0 过期。

**下一步（顺序不能反）**：
1. 先定**语义**：引用型协程载荷是"一律拒绝"还是"允许但要证明所指活过句柄"？规则②的既有口径偏向后者，
   但"帧内局部"这一档没有可证明的寿命 ⇒ 至少这一档应当拒绝。
2. 再修 **codegen 拼写**（否则修了前端也只是把畸形 C 藏起来）：载荷类型是引用/视图时，
   `extc_coro_value_*` / `extc_coro_send_*` 的返回类型要有正确拼写 —— 并且**加一条正例**：
   `coroutine<?ref T>` 的合法用法（若语义定为允许）必须能生成合法 C。
3. 判据：P0-6e 拒绝；正例编译+ASan 干净；`tests/coro` 全绿。

## 二、深度查询的两处 `return 0` 兜底：**没造出复现，但弄清了一条结构性事实**

`exprRefDepthPure` 开头：`if (!e || hops >= 40) return 0;` 与环检测 `return 0`
（0 的语义是"活得最久"⇒ 方向反，与 P0-6c 同族）。

我试了两条路，**都被别的机制挡住了**：

| 探针 | 形状 | 结果 |
|---|---|---|
| b1b | 45 跳**拷贝链**（`var aK: ?ref node = aK-1`）后存进全局 | **拒绝** —— 判它的是 `exprBorrowed`（来源链**无**跳数上限），不是有 40 跳预算的 `exprRefDepth` |
| c1 | 45 跳拷贝链后 `return` | **拒绝** —— 原因是 `noteOrigin` 把来源**压平**了（拷贝链塌成一步），40 跳预算**根本走不到** |

⇒ 结构性事实：**拷贝链这条路到不了那个预算**（`noteOrigin` 压平 + `exprBorrowed` 无上限）。
仍未被探索的一条路是**非压平的递归**：`EX_FIELD`/`EX_INDEX`/`EX_SLICE` 的嵌套链
（例如 40 层嵌套结构体 `s40.a.a.….a.x`），那才会真的走 40 跳。

**不靠复现也成立的结论**（Lean ⑥：不存在安全的有限兜底）：兜底必须变成 ⊤（拒绝），
**但"⊤ 在实现里取哪个值"要看调用者** —— `exprRefDepth` 的结果既被拿去比较（`d > at` ⇒ 拒绝），
也被 `promoteInto2(src, want)` 当**层**用。把耗尽情形改成"一个大数"能满足比较那一侧，
却会污染提权那一侧。所以正确做法是**区分两种用法**（查询失败要么报错，要么走一条专门的 ⊤ 路径），
而不是挑一个数字。这一步需要单独探针（人为把预算调到 1，看哪些调用者会看到它）。
