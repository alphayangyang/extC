# Heap 原型（连续板 + 一道门）

**它回答四个问题，只打印数字。** 跑法：`./run.sh`（`gcc -O2 -std=c11 -fwrapv -Wall -Wextra -Werror`，
与产物同一套编译契约）。`host.c` 是宿主，`plugin.c` 编成 `plugin.so` 由 `dlopen` 进来 —— 模块只看得见
宿主递来的那张表，按**普通指针**语义工作。

## 实测（本机，单线程；一次 run 的原始输出见下）

| # | 问的 | 数 |
|---|---|---|
| 1 | 保留 4 GiB 连续区、按需 commit | 保留本身 **RSS +192 KB**（不占物理页）；`mmap`+commit 自身 **5 µs**；首次触碰 **1609 ns/页**；触碰 64 MiB 后 RSS 67552 KB |
| 2 | 每次分配调用加一次区间检查 | 200 万次 malloc+free：裸 `malloc` **3.2 ns/op** · 板+检查 **3.1 ns/op** ⇒ **检查本身测不出来** |
| 2b | 门的正反例 | `free(宿主指针)` → **拒绝**；`copyOut(区内指针, 超出长度)` → **拒绝**；合法 → 接受 |
| 3 | close 即 munmap | 旧指针再用 ⇒ **SIGSEGV**（硬缺页，不是悄悄读到新数据）|
| 4a | 大输入：拷进板 | **1830 MB/s**（64 MiB ≈ 35 ms）；之后读板内 22 GB/s |
| 4b | 大输入：只读借出（`mprotect`）| 读 **21.6 GB/s 零拷贝**；两次 `mprotect` 各 **369 / 376 µs**；写它 ⇒ **SIGSEGV** |
| 4c | 大输入：直接给宿主指针（可写）| 读 22 GB/s（对照）|
| 5 | `dlopen` 插件 + 表 + 指针 | 模块在板里建 10 万元素、返回**板内指针**；宿主一次区间检查通过并求和正确；宿主栈指针递进 `copyOut` ⇒ **拒绝** |

**由 4a/4b 得到的一条可直接用的规则**：`mprotect` 借出的固定代价 ≈ 0.75 ms（64 MiB 时），而拷贝按
1830 MB/s ⇒ **交叉点在 ~0.7 MiB**：**大于它，只读借出更便宜（零拷贝）；小于它，拷进板更便宜。**

## 这些数字**不能**说明什么（重要）

* 分配器是个玩具：只用 size class（16B–8KiB）+ 大块 bump，**没有合并、没有原地增长**。第 2 行**不是**
  "我们的分配器比 malloc 快"，而是"**那道门的代价低于测量噪声**" —— 这正是要验的那一点。
* 分配模式对双方都友好（LIFO、尺寸集中、单线程）。glibc 的 tcache 在这种模式下极快；更碎的模式
  （多尺寸、长寿命混杂）需要另测。
* `1609 ns/页`是**按需 commit** 的缺页代价 ⇒ 工作集若预先 commit 掉就没有它；这是策略旋钮，不是常数。
* `mprotect` 的 370 µs 随**区间大小**走（每页一份），并且会引起别的线程的 TLB 抖动 —— 这里是单线程。
* 借出/校验都是**每次调用**级别，不是每次解引用级别 —— 这是整个设计成立的前提（C ABI 生态）。
