## 怎么读这张表（很重要，不然会误读）

1. **主组四行是苹果对苹果**：四个语言**手写同一套归并排序 + 同一套 CDQ + 同一套树状数组**，
   连比较顺序都一模一样 ⇒ 差的那点就是**语言/编译器**的差 ✓
2. **对照组三行不是**：C `qsort` / C++ `std::sort` / Rust `sort_unstable_by` 是三种不同的排序，
   只该横着看"这家标准库的排序值多少"，不该当成语言快慢 ✗
   （extC **没有 std 排序** ⇒ 它只在主组里，这是**语言能力差异**，不是它慢）
3. **RSS 那一列才是语言的常驻开销**：四家都是同一套数组，所以数字应当非常接近；
   差得多就说明有隐藏分配（Rust 的 `Vec` 就是显式的堆分配，extC 是全局数组）✓
4. **二进制大小不能只跟 C 比**：Rust 默认静态链接 std ⇒ 十几 MB；
   `-C prefer-dynamic` 或 `strip` 之后才可比 ✓
5. **源码行数反映写法长度**：extC 没有 `+=` / `++` / `for` ⇒ 同样算法要多写十几行 
   （这是**刻意的显式**，见 DECISIONS）✓
6. **extC 的构建要拆两段看**：前端（extC→C，几毫秒）+ 编它吐的 C（大头）——
   用户感受到的是两段之和 ✓
