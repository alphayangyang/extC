# `any` 的成本

两个层面各测一次：**C 原型**（`proto.c`、`many-types.c`，纯 C，用来在改编译器之前定形状）和
**语言实现**（`extC` 自己，用来确认没有实现走样）。全部 `taskset -c 0`、`-O2`、多轮取最小。

## 语言实现（extC，`tests/any/` 的同一套代码）

| 操作 | 每次 |
|---|---|
| 内联装箱 + 拆箱（≤8 字节） | **0.59 ns** |
| 装箱 16 字节结构体（走 arena） | **5.4 ns** ← 主成本，每 op 分配 16 B |
| 动态派发（≤8 候选，`if` 链） | **0.9 ns**（热循环里常被内联成直接调用，低至 0.1 ns） |
| 动态派发（12 / 40 候选，排序表二分） | **2.0 / 4.0 ns** |
| 静态直接调用 | ≈0（内联掉了） |

装箱 5.4 ns 里大头是分配与缺页：每箱 16 字节，一千万次就是 160 MB，全留在 region 里
（`docs/usage/language.md` §3.9 因此写明"热循环别反复装箱"）。真正省掉它需要"箱子有死亡时间"，
那是引用计数的事，不在 v1 范围。

## C 原型（定形状用）

描述符 = `{ id, size, flags, 字段表 }`，一个 walker 服务打印/相等/JSON：

| | 静态直写 | 描述符遍历 |
|---|---|---|
| 打印一条 4 字段记录 | 22.3 ns | 28.9 ns（+0.5–0.85 ns/字段）|
| 相等 | 3.10 ns | 12.98 ns（逐字段分派，只该用于边界）|
| 深拷贝 32 B 无引用 | 0.54 ns | 1.57 ns |
| 深拷贝 48 B 含 1 个动态引用 | — | 7.18 ns |

类型分派（`many-types.c`）：id 跳表 0.34–0.45 ns 与类型数无关；链式比较 16 个 2.7 ns、64 个 9.2 ns、
256 个 25.3 ns；按 id 二分 0.78–3.6 ns。**语言实现最后选的是"地址排序表 + 二分"**：不需要在描述符里
存 id 也能拿到 log 复杂度，只在候选 >100 时才值得换成真跳表。

代码体积（8 类型 × 6 字段）：每类型手写打印 13.9 KB 代码 → 描述符表 + 一份 walker 1.2 KB 代码 +
1.7 KB 表，**4.87× 更小**。

## 怎么跑

```
cc -O2 -Wall -Wextra -o /tmp/proto proto.c && taskset -c 0 /tmp/proto walk
cc -O2 -Wall -Wextra -o /tmp/many many-types.c && taskset -c 0 /tmp/many
```
