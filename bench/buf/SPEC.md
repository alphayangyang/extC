# bench/buf —— `buf<T>` 对 `std::vector` 的五条形状

> 数字与结论在 [`RESULTS.md`](RESULTS.md)。这里只有判据、形状的意图、和怎么跑。

## 1 这个卡具为谁而设

R4a 把 `buf<T>` 的存储从「池块」换成**预留地址 + 原地增长**（见 `docs/design/BUF-INVARIANT.md`）。
新的不变量给了两个承诺，这个卡具就量这两个承诺：

1. **增长不拷贝元素**（预留之内）——元素地址是 `base + i*sizeof(T)`，搬家次数 `relocations()` 只随
   超过预留的次数增长，而不是随几何翻倍增长。
2. **容量能还给系统**（`shrink(0)` / `release()`）——峰值由 `len` 决定，不由历史最高 `cap` 决定。

对手选 `std::vector`（用户指定「主要跟 C++ 打」）：它是同一份工作量下最成熟的对照，
而且它的增长语义是**几何翻倍 + 整段重分配**，正好是这两个承诺的反面。

## 2 判据（`run.sh` 自己判，不靠人看表）

1. **同形状各臂打印的 `n` / `sum`（及 `bad`）必须逐字节相同**。不一致即红——那是卡具或实现错，
   不是性能差异。
2. **时间是交错多轮的**最小值**（`bash time` 的 `%3R`，10 µs 分辨率）。最小值而不是均值：
   这台机器有背景噪声，均值由环境决定，最小值才是臂的下界。
3. **峰值 RSS** 取 `/usr/bin/time -f %M` 单跑一次（`ru_maxrss` 本身是确定值，不必多跑）。
4. 全部 `taskset -c 6`；`REPS` 默认 5。任一臂编不过 = 红（不静默跳过）。

## 3 五条形状

| 形状 | 臂 | 工作量 | 它想证什么 | 它不能证什么 |
|---|---|---|---|---|
| S1 | `s1_buf.extc` / `s1_vec.cpp` / `s1_vecres.cpp` | 从 cap=4 逐个 `push` 到 8e6 个 i64（64 MiB）；第三臂是 `vector::reserve(8e6)` | 无预留时的增长代价，以及预留把代价消掉多少 | 小于 2 MiB 预留的小数组（那边预留是免费的一跳） |
| S2 | `s2_buf.extc` / `s2_vec.cpp` | 100 万个短命缓冲区，每个 64 个 i64（512 B），用完即释放 | 短命容器的构造/归还成本：应命中 buddy 复用，不产生 `mmap`/`munmap` | 长命容器的容量记账（那是 S1/S3 的事） |
| S3 | `s3_buf.extc` / `s3_vec.cpp` | 装满 8e6 → `shrink(4096)` → 原地长回 8e6 | 「容量能还」的价：还页之后重写要付缺页 | 归还的收益（这张表只量代价；收益是峰值 RSS，见 S1 的 RSS 列） |
| S4 | `s4_buf.extc` / `s4_vec.cpp` | 24 字节结构体元素 2e6 个，逐字段填 | 元素大小不影响零拷贝增长（`moves` 仍应是 2） | 含引用元素（那是 R4b） |
| S5 | `s5_buf.extc` / `s5_vec.cpp` | 16e6 个 i64（128 MiB）顺序扫一遍 + 用确定序列随机索引扫一遍 | 连续布局兑现：视图地址就是 `base + i*sizeof(T)`，顺序扫能向量化、随机扫没有间接层 | 分块/句柄化实现（任何把元素搬去 chunk 链的方案都会在这里交税，而 buf 不交） |

形状选得**偏向 C++** 的只有 S3（`std::vector` 的容量只增不减，`shrink(4096)` 对它没有对应动作，它的增长全靠翻倍，所以它反而少付一次还页）；其余四条都是同一工作量。

## 4 怎么跑

```
make -j8                       # build/extc
REPS=5 bash bench/buf/run.sh   # 完整一轮，写 bench/buf/RESULTS.tsv
bash bench/buf/run.sh --reps 9 --pin 6
```

`RESULTS.tsv` 的字段：`shape / arm / sec / rss_kb / verdict / output`。
`output` 是那一臂自己打印的最后一行（校验和与 `moves=` / `cap=` / `leak=`）。

## 5 已知边界

- **单机、单线程、绑核 6**；数字只在本机与本工具链（`cc`/`g++ -O2`）下有意义。
- 只对 C++。Go/Rust 的对照在 `bench/realsvc`、`bench/gc`，不在这个卡具里。
- **不测回收器**：`buf` 是 T0 基质（程序不向回收器要内存），所以这里没有 `EXTC_RC_*` 档。
- S3 的对照臂并不等价：`std::vector` 没有「还容量」这个动作，`shrink_to_fit()` 走重新分配
  （`moves=12`）。S3 量的是「还页 + 重写」的价，两边的阶段表与量级在 `RESULTS.md` §3；
  要用「还页」换「峰值」时，这笔账必须按形状算，不能一刀切。
